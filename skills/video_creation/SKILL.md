# 视频创作 Skill

本 SKILL 涉及的所有参考文件路径：`/workspace/.skills/video_creation/refs/`

**⚠️ 执行第一铁律（先于本文件其余全部内容）**：加载本 Skill 后的**第一个动作是按 §0.4 完成路由并 `sandbox_read` 读取唯一 workflow 文件**，不是调用生成工具。**本根文件不含单段/多段的执行细节**——Duration 取值、素材绑定、Prompt 自检、质量尾注、确认门全部在 workflow 文件里，跳过加载即等于丢失这些规则，生成必然缺项。

## 〇、进入点判定

### 0.1 三层模型

用户输入映射到三个信息层，下层服从上层：

| 层级 | 关注 | 满 | 部分 | 空 |
|------|------|----|----|----| 
| **意图** | 题材、目的、面向谁 | 题材+目的均可判定 | 有题材但目的模糊，或有目的但题材不明 | 两者都缺 |
| **创意** | 调性、风格、叙事结构、角色、故事线、剧本设计 | 角色、故事线、剧本设计三项都比较明确：知道谁参与、故事如何起承转合、每段/关键剧情拍点是什么 | 三项中缺任一项，或只有风格/题材/故事梗概但无法直接写出剧本设计 | 三项都缺 |
| **分镜** | 镜头、运镜、参考图、台词分配、时长 | 有可执行的镜头级描述（分镜表/时间轴/逐段脚本） | 有部分镜头描述或动作细节，但不够执行 | 无镜头级信息 |

**完整内容描述**判据（满足任一即成立）：含分镜表/时间轴；含动作描写+角色对白的完整剧本/小说片段；含逐段画面描述的详细脚本。成立与否的处理见 §0.2 时长预算规则。

素材横切三层：产品图填意图（广告对象）、参考图填创意（调性画风）、首帧图约束分镜（构图）。读懂素材 = 判断它替用户填了哪层。

### 0.2 路径路由

**加载 skill 后第一件事**：逐层标注填充度（空/部分/满），确定路径。

**台词时长预计算（只计算，不分流）**：若用户输入中包含明确的台词、对白、旁白或内心独白文本，必须先用 `sandbox_bash` 调用 `count_chars.py` 获取每段声音文本的耗时区间：

```bash
python3 /workspace/.skills/video_creation/refs/tools/count_chars.py "台词1" "台词2" "旁白内容" ...
```

执行要求：
- 每段独立台词/旁白/内心独白作为一个独立参数传入，禁止把多段合并成一个参数
- 一次命令批量传入多段文本，禁止逐句串行多次调用
- 诗词体裁的诗句原文（吟诵腔呈现）单独一次调用并加 `--mode slow`（吟诵口径，目前仅诗词场景使用）；自创文本/讲解词仍用默认口径
- 只统计用户输入中已经明确写出的声音文本，禁止为 Agent 后续可能新增的旁白或台词预估
- 这一步只产出台词耗时参考，**不直接决定** scope、总时长、单段/多段，也不替代后续时长预算规则
- 后续写 `creative_design.md`、构造单段 Prompt、调用分镜规划工具或执行 storyboard 自审时，必须引用这次工具输出的耗时区间，禁止手算或按固定语速重新估算

**scope 自检**（在意图层定）：这个创意能否在一次 `sandbox_generate_video` 调用里自然演完（允许内部切镜和跨场景转场，但叙事节拍不超出单次调用的信息密度上限）？能 → 单段 scope；不能 → 多段 scope。**模糊意图的 scope 默认收敛到单一想法**——不替用户加戏。

| 判定结果 | 路径 |
|---------|------|
| scope ≤ 单段 + 时长 ≤{{ .max_video_duration }}s | **单段流程**（§0.4 → `workflow/single-segment.md`）：无需 creative_design.md/参考图/storyboard.md。§1.2 交互控制该问还问（风格缺就问）；是否命中直通由该 workflow Step 2 判定（直通命中时风格缺也不问） |
| scope > 单段 或 时长 >{{ .max_video_duration }}s | **多段流程**（§0.4 → `workflow/multi-segment.md`）：从第一个非满层开始逐层补齐，已满的层保留原样跳过对应步骤 |

**不对称容错**：判不准时偏向更低层（更模糊）。错向多问 = 多一道确认，可恢复；错向更具体 = 跳过澄清烧生成，不可逆。

**时长预算规则**：

**内容量估时（估算式唯一定义，后文"按内容量定时长""推荐时长"一律引用本式）**：
`估算时长 = 用户声音文本耗时下限累加（count_chars.py 输出）+ 未被声音文本覆盖的独立画面段落数 × 4-6 秒`。**本式的画面段落按无声叙事事件逐个计数**：用户原文中未伴随台词的阶段性动作事件（动作戏的亮兵器、一轮交锋、僵持对峙、外力介入、脱身等）各计一段，禁止因"同一场景"折叠为一段——②的段落合并规则只用于多段门槛判定，不用于本式计数。受众偏好快节奏：画面段落单价默认取 4；无任何内容锚点（无声音文本、无画面段落描述）→ 估算时长 = {{ .max_video_duration }} 秒；估算结果落在两个候选档位之间时取低档，禁止向上凑档。

- 用户指定了时长 → 用用户的。**台词超载拦截**：台词时长预计算显示用户原文声音文本耗时下限累加 > 用户指定时长 → 禁止静默超时、禁止删减台词，立即用 `dynamic_questionnaire` 让用户二选一：①延长至内容量估时结果（推荐，注明估算秒数）；②维持原时长，用户在输入框指定删减哪些内容。用户选择前不进入后续流程；用户选①后以新时长按本节末尾锁定流程重判单段/多段
- **未指定 → 默认 {{ .max_video_duration }} 秒单段**，仅以下例外成立时才建议更长：
  ① 前序台词时长预计算结果显示，用户已提供台词/旁白/内心独白的耗时区间超过 {{ .max_video_duration }} 秒
  ② 内容量估时 > {{ .max_video_duration }} 秒，**且**用户描述中不可快切合并的独立画面段落 ≥3 个——同一场景内的连续动作、可加速快切的场景切换、同一主体/同一支舞/同一动作的多视角多机位均不计入段落数。**段数解耦（唯一定义，后文一律引用此名）**：用户写的段数/镜头数/视角数/每段秒数，以及"用于剪辑""做素材/备选镜头"等用途声明，都是画面组织描述——不计入独立段落数、不决定调用次数、禁止用"段数×每段秒数"反推总时长；用户上传的素材份数同理，多张素材在单段内分阶段/切镜引用，不推多调用；总时长只由内容量估时式定，段数只由分镜阶段的分段规则定
- 满足例外 + 已有完整内容描述 → 直接进入多段流程，总时长 = 内容量估时结果，**不问用户**。发现台词预计算遗漏时，必须立即补跑 `count_chars.py`
  - "完整内容描述"判据同 §0.1。用户贴全文 = 希望还原全文，agent 按内容量估时定总时长，不问用户
- 满足例外 + 内容不完整（仅有主题/梗概/零散描述） → 禁止自行决定更长时长，在问卷中给时长选项让用户选择，推荐档 = 内容量估时结果就近向下取档
- 段数不在此步定，是分镜层产物

**⚠️ 高频误判拦截**：以下情况**不构成超 {{ .max_video_duration }} 秒的理由**：

| 用户描述特征 | 错误推理 | 为什么是 {{ .max_video_duration }} 秒单段 |
|------------|---------|------------------|
| 连续多个动作 | "动作这么多，需要多段" | 同一场景内的连续动作，模型单次调用就能快切完成 |
| 描述很详细/很长 | "内容丰富，{{ .max_video_duration }}秒装不下" | 描述详细≠需要更长时长，动作可以加速快切 |
| 多个场景切换 | "场景跨度大，需要多段" | 模型擅长单次调用内场景转场，比跨调用拼接更流畅 |
| 涉及特效/技能释放 | "特效复杂，每个特效要单独一段" | 特效是画面元素不是时间元素，一个镜头内可叠加多种特效 |
| 用户写"N 段/N 个视角/多机位""每段 X 秒"，或声明用途"用于剪辑""做素材" | "用户要 N 段独立素材，就得 N 次调用" | 段数解耦（§0.2）：同主体多视角单次调用内切镜完成，加总 ≤{{ .max_video_duration }} 秒一律单段 |

时长确定后锁定流程：
- 总时长 ≤{{ .max_video_duration }} 秒 → **单段**。一次 `sandbox_generate_video` 调用，无需 `creative_design.md` / `storyboard.md`，无需参考素材，无需加载 `narrative-arc.md`
- 总时长 >{{ .max_video_duration }} 秒 → **多段**。按 §0.4 加载 `workflow/multi-segment.md`

### 0.3 编辑回合

**前置分流（先于层级判定）**：成片已交付后的修改指令，**以及用户携带现有视频（含上传视频）提出的修改/编辑/后处理诉求**，先判诉求性质——**保留式修改（用户对现有画面满意，只做有界调整：删段/换序/字幕开关/回退/加换 BGM、删/换/加画面元素、整片换风格换色调）**、需专项处理（超分/去字幕/段内区间编辑）或工具面无通路的诉求 → 读 `review/post-delivery.md` 按其路由表执行，**禁入下表**；**重做式修改（否定现有内容本身：换题材/换故事/重做镜头）**→ 按下表层级判定；两者判不清 → 读 `review/post-delivery.md` 按其"拿不准就问"规则出双路径问卷（含积分成本对比）。

用户发修改指令时，复用进入点判定——查修改打在哪层，只从那层往下重解，保留其余层：

| 修改信号 | 命中层 | 行为 |
|---------|-------|------|
| "换个题材""不做短剧了做广告" | 意图 | creative_design.md/storyboard.md/参考图全部废弃重建 |
| "换风格""换调性""改成水墨风"（否定当前呈现、要求推倒重来时；对画面满意只想整片转风格的属保留式修改，走前置分流） | 创意（风格） | 保留意图层和 creative_design.md 故事，重生 style_anchor + 参考图，重写 prompt 风格后缀 |
| "换个故事""结局改成悲剧" | 创意（叙事） | 保留意图层，从 creative_design.md 开始重写 |
| "第 N 个镜头改成特写""把台词换一句""某段太长了" | 分镜 | 保留意图+创意，走 KEEP/CHANGE 协议（`review/quality-control.md` §一）修改特定镜头 |
| "重新生成""再来一次"（无修改内容） | 分镜（抽卡） | 复用相同参数重新生成 |
| "再戏剧一点""加一些冲突" | 创意（叙事） | 保留意图层，修改 creative_design.md 叙事结构后重建下游分镜 |

**与 KEEP/CHANGE 的关系**：层级判定在上游做分流——先确定"只改分镜"，才进入 KEEP/CHANGE 的镜头级处理。命中创意层以上时不走 KEEP/CHANGE。

### 0.4 Workflow 选择与加载

**本次运行参数**（唯一声明处，下游全部引用本表，禁止另行推断）：

| 参数 | 取值 | 用途 |
|---|---|---|
| 单次生成上限 | **{{ .max_video_duration }} 秒** | 单段/多段分流阈值；`sandbox_generate_video` 的 `Duration` 上限；workflow 文件中"单次生成上限"一词均指此值 |
| `max_shot_duration` | **{{ .max_video_duration }}**（只能是工具支持的 15 或 30） | 分镜规划时的单镜头时长上限；本值不是 15/30 时停止并请求确认 |

**workflow 文件不做模板渲染**——其中的"单次生成上限"是指针，读到后一律代入上表数值。

**路径路由**（§0.2 判定完成后立即执行，四选一，只加载一个）：

| 条件 | 唯一 workflow |
|---|---|
| §0.3 前置分流命中保留式修改 / 专项处理 / 工具面无通路 | `review/post-delivery.md`（按其 §〇 路由表分轨，不进下面三行） |

| scope > 单段 或 总时长 > 单次生成上限 | `workflow/multi-segment.md` |

**加载锁**：判定完成后的**下一个工具调用必须是 `sandbox_read` 读取选定的 workflow 文件**，读取成功前禁止调用任何生成类工具（`sandbox_generate_video` / `sandbox_generate_image` / `sandbox_generate_audio` / `render_video`）、禁止调用 `creative_agent` 或 `generate_shot_video_prompt_plan`、禁止写 `creative_design.md` 或 `storyboard.md`。**在思考、todo 或工具任务描述中写出路径不算加载**，只有实际读取成功才算。

**直通不是加载锁的例外**：用户给出完整脚本时同样先读 `workflow/single-segment.md`，直通的判据、两种执行体和"不读任何知识 ref"的禁令都写在该文件 Step 2 里；读完 workflow 后才按其指引跳过后续知识 ref。

**权威顺序**：System Prompt > 本根文件 > 当前 active workflow > 阶段 ref。同层冲突或规则缺失 → 停止执行并向用户说明，禁止自行取舍。流程中途需要换 workflow（如多段回退单段）时，必须重新 `sandbox_read` 新文件；读取成功后新文件成为唯一 active workflow，旧文件立即失效。

## 一、创作流程

### 1.0 核心铁律

**用户指定的时长是第一公民**。所有分段规划、镜头合并、调用次数的决策都必须服从用户要求的总时长。宁可多拆一段，也不能压缩时长；绝对不能超出用户要求的时长。时长预算规则详见 §0.2。

**调用次数最少化**。`sandbox_generate_video` 单次调用内部可以完成分镜切换、场景转场、景别变化，且内部转场远比跨调用拼接更顺滑。因此：**能用一次调用完成的，绝不拆成两次；能用两次的，绝不拆成三次。** 用户要"N 段素材/片段用于剪辑"时同样适用（§0.2 段数解耦）：独立调用生成的片段之间主体、场景、光影必然漂移，用户想剪也拼不上；多机位/多片段在单段内用切镜表达才连贯，用户可对成片自行截取。**禁止以"交付 N 个独立文件"为由拆分调用**。

| 总时长 | 最大调用次数 | 每段时长要求 |
|--------|------------|------------|
| ≤{{ .max_video_duration }} 秒 | **1 次**（零例外） | — |
| 16-20 秒 | **最多 2 次** | 每段 ≥8 秒 |
| 21-40 秒 | 按自然断点拆分 | 每段尽量 10-15 秒 |
| >40 秒 | 按自然断点拆分 | 每段尽量 10-15 秒，禁止大量 4-5 秒碎段 |

|--------|------------|------------|

| >{{ .max_video_duration }} 秒 | 按自然断点拆分，每多出约 {{ .max_video_duration }} 秒增加一次调用 | 拆分只决定段数（禁止大量 4-5 秒碎段）；段长按段内容量取值，禁止为凑满 {{ .max_video_duration }} 秒拉长 |

**Prompt 做减法**。模型对信息密度有硬天花板——单段 Prompt 塞得越多，每条指令被执行的概率越低。写 Prompt 时用户需求中"想要什么"和"模型能做到什么"之间必须取舍。优先保证核心画面（主体动作+关键情绪），其次是运镜，最后才是环境细节。复杂场景宁可少写两个次要动作让核心动作准确执行，也不要面面俱到导致全部走样。做减法只允许删减 Agent 自产的冗余修饰、低优先级环境细节和不可执行文学描述；禁止以"做减法"为由删掉用户明确要求的片段、动作、主体、声音要求或结尾方式。

**内容密度保底**。我们的受众偏好快节奏，空镜缓推配一句旁白的"冥想式"节奏是大忌。不达标时必须二选一，两个方向 agent 均可自主执行：①充实内容——补讲解、加对白、增旁白（如教学视频加逐句解读/互动提问，诗词视频加意象讲解/背景铺垫），**但 agent 自产的旁白/台词只能在既定时长预算内填充，禁止以自产内容为由抬高总时长**；②缩短时长——用户未指定时长时直接下调（单段缩 Duration，多段下调总时长预算，随创意/分镜确认门一并展示给用户），用户已指定时长时才需征求同意。禁止用空镜注水凑时长。

**≤{{ .max_video_duration }} 秒禁止拆段（零例外）**。即使用户输入写了 5 个时间段、涉及完全不同的场景，只要加总 ≤{{ .max_video_duration }} 秒就必须一次 `sandbox_generate_video` 调用完成。用户写的时间段描述（0-2s/2-5s/5-8s…）是给 Prompt 内部分镜用的，不是拆成多次调用的依据。违反此条 = 浪费用户积分 + 跨调用拼接破坏转场流畅性。

**旁白/台词语言与用户一致**。用户用中文写的台词，Prompt 中的旁白必须是中文；用户用英文写的台词，Prompt 中必须是英文。禁止自行翻译、改写语言或混用中英文。

**安审失败立即停止，禁止自行重试或排查触发词**。`sandbox_generate_video` / `sandbox_generate_image` 返回安审错误（如 `security_filter_error`、版权限制 `code=12002`）时，**不重试、不改词重试、不删参考图重试、不移除用户素材重试、不做触发词二分排查**——直接告知用户该镜头审核未通过（含错误原因），询问用户是否修改描述/更换素材后重试或跳过该镜头。即使 Agent 判断拦截原因是用户素材触发版权检测，也**必须先告知用户再由用户决定**，禁止擅自移除用户素材后静默重试。

### 1.0b 保真铁律

1. **硬约束账本先行**：进入流程后，必须从用户输入与问卷结果中提取硬约束账本，字段包括：风格、总时长、语言、字幕、BGM、视频比例、素材使用。只记录用户明示或问卷确认的信息；用户未提及的字段写"未指定"，禁止把工具默认值、Agent 推断或执行偏好写成用户要求。**总时长保留原表述精度："N秒左右"与"N秒"是不同约束等级（软/硬），账本、creative_design.md 预算行与后续工具输入全链路禁止去掉"左右"转硬**。后续创意设计、分镜规划、视频生成与成片合成只能补齐账本落点，禁止隐式改写账本
2. **用户输入优先**：用户明确写出的主体、场景、片段顺序、动作、镜头/景别、场景元素、上传素材用途、音效/BGM、氛围、结尾方式，都是创意设计和分镜规划的优先约束。用户输入不完备时，只补齐未指定缺口；补齐内容不得覆盖、替换、重排或削弱用户已明确的信息。**用户写的段数、每段秒数不决定总时长或生成调用次数**（§0.2 段数解耦）；段数解耦只约束画面打包方式，用户明确指定的上传素材用途、绑定对象、使用场景、动作或时间范围仍属于硬约束，必须原样承接
3. **已填的层不回问**：§0.2 填充度判定中标注为"满"或"部分"中的已知部分，后续流程原样使用，禁止反问确认
4. **用户文本保真**：用户原文中的台词/对白/旁白在 creative_design.md 和 Prompt 中逐字保留，禁止精简、删减、合并、改写语言。用户原文中的动作描写在 creative_design.md 中按原顺序完整承接；写入 Prompt 时必须保留主体、动作链、顺序和结果，可转译为可执行视觉描述，禁止删减、重排或改成相反含义
5. **用户素材必须使用**：用 `sandbox_bash` 执行 `ls upload/` 确认实际上传文件，每个文件必须被 creative_design.md 引用。用户上传的角色照片默认直接用作参考图（跳过四视图生成），仅质量过低或主体不完整时才标注"仅供风格参考"——**风格差异不是跳过用户素材的理由**。Prompt 中仅描述素材中可见的内容，禁止推测或编造素材中不存在的特征
6. **语言保真**：台词、旁白使用与用户输入相同的语言，禁止翻译或混用中英文
7. **花钱门兜底**：调用 `sandbox_generate_video` 前必须过花钱门。多段流程两道停顿门必设：创意与素材确认门（创意定稿与参考素材连续做完后、分镜规划前一次确认，见 `workflow/multi-segment.md` Step 2）与 storyboard.md 确认门；单段流程生成前用简明方案说明代替确认门

### 1.1 单段流程

单段视频（scope ≤ 单段且总时长 ≤{{ .max_video_duration }} 秒）的完整执行流程见 `workflow/single-segment.md`——入口复核、直通分叉（含程序直传与抄录直通）、Prompt 知识加载、素材绑定与构造、生成、按需渲染、质检交付共 7 个 Step，以及 Duration 取值与提交前自检清单全部在该文件内。**单段/多段判定只看 §0.2 的 scope + 时长，不看剧情复杂度**：`sandbox_generate_video` 单次调用就能在 {{ .max_video_duration }} 秒内完成多个分镜、切镜、转场和多句台词——"有故事线""有镜头切换""有冲突转折""场景跨度大"都不构成走多段流程的理由。

### 1.2 交互控制

**提问规则**：

| 层级状态 | 行为 |
|---------|------|
| 意图层空/部分 | 必须提问补齐题材/目的 |
| 创意层空 | 必须提问（至少确认风格方向，从 `creative/style-master.md` 速查表选 3-4 个推荐） |
| 创意层部分 | 可提问补缺口，也可按已有信息推进（推进时在方案中说明假设） |
| 分镜层空/部分 | 不提问，agent 填充。仅当用户已给部分分镜但有歧义时才问 |
| 比例/风格缺失 | 用 `dynamic_questionnaire` 补齐，每次新请求最多调 1 次 |

**极简意图先搜热点灵感**：用户输入删去体裁词（故事/短剧/视频/广告…）与泛化修饰词（简单/好玩/有趣/搞笑/温馨/随便/爆款…）后**不剩任何具体内容锚点**（无主体、无主题、无场景、无情节、无指定风格）→ 发创意问卷前先用 `pippit_omni_search`（`Type: "hotspot"`）搜一次灵感，Query 用体裁词＋泛化修饰词组合成 1-2 个短词（如 `短剧`、`搞笑 故事`），禁止长句。从结果中取 2-3 条与体裁匹配的热点，各提炼成一句创意方向（题材＋核心看点/冲突）作为问卷「视频创意」选项，另保留自定义入口；选项只写创意本身，不写热度值、不带链接、不照抄热点标题。搜索失败或无结果 → 照常自行发散，禁止重试；用户要求跳过提问/确认时搜索照常执行，agent 自选一条方向并在方案说明中一句话带过。输入含任何具体内容锚点（如"赤壁之战""我家的猫"）→ 不触发本条，按上表走。

**提问禁令**：
- 禁止连续 >2 轮追问——将所有缺口合并到同一次问卷
- 已填的维度禁止再问（§1.0b 第 1 条）：风格词已有 → 问卷不含风格；比例已有 → 不含比例；时长已有 → 不含时长
- 不询问是否使用字幕，默认不使用；用户明确要求字幕时，通过成片合成的 `show_subtitle` 参数实现（见 §二 render_video），不写入视频 Prompt
- 用户提供了完整文本时，不询问"内容取舍/聚焦重点/内容密度偏好"——用户贴全文 = 希望还原全文，精简是 agent 的执行能力问题，不是用户的决策问题
- 问卷是否含时长选项，只看两条：用户已指定时长 → 不含；§0.2 完整内容描述直接进入路径 → 不含（时长由内容量决定）。其余场景（含未指定时长走默认 {{ .max_video_duration }}s 的）问卷照常含时长选项，推荐档按 §0.2 内容量估时取
- **但即使以上维度都已提及，仍可包含创意方向/补充信息等其他维度**——只要问卷中去除已确定维度后仍有需要确认的内容，就应调用

**风格选项必须来自速查表**：选项使用 `creative/style-master.md` 中的具体风格名（如"赛博朋克""3D国漫CG""手绘吉卜力风"），禁止使用"动漫风""3D动画"等模糊大类。

**问卷标题与提问必须简短**：`dynamic_questionnaire` 的标题和每个 question 字段都是一句话短提问（如"分镜规划确认""确认创意方案？"），禁止把创意/分镜摘要、多行清单、`①②③` 编号列表、`\n` 换行塞进标题或 question。需要展示的方案/分镜内容一律走 `present_sandbox_file` 推送文件，问卷只负责让用户做选择。

常见确认维度（用户已提及的无需再确认）：
- 是否需要旁白：默认为需要。若需要，确认音色偏好（如温柔女声/磁性男声/童声），默认根据题材自动选择。**旁白偏好只控制 Agent 额外添加的旁白，不影响用户原文中已有的角色台词/对白**——用户选"不需要旁白"或"纯音乐"时，仅意味着不额外配旁白解说，用户原文中的台词（如"再来一杯威士忌"）必须完整保留到 `creative_design.md`、`storyboard.md` 和 Prompt 中
- 视频时长：选项：推荐时长、15s以内、30s以内、60s以内、60s以上。**推荐档 = §0.2 内容量估时结果就近向下取档**，禁止凭直觉或按叙事模板推荐。用户已指定时长时不包含此选项。**时长选项只写时长数字，禁止附带分段方案**（如"15秒（3段拼接）"是错误写法，正确写法是"15秒"）——分段数由 §1.0 调用次数规则在执行阶段决定，不在问卷阶段预设
- 视频比例：16:9、9:16、4:3、3:4
- 视频风格：从速查表按题材选取
- 视频创意：根据用户输入发散预制的视频创意；命中上方「极简意图先搜热点灵感」时选项来自热点提炼
- 补充信息：text 类型选项

**下一步建议规则**：完成关键步骤后，给出 2-3 个编号建议。每个建议必须是 agent 能直接执行的操作，默认推荐项标注"（推荐）"。

| 完成步骤 | 建议内容 |
|---------|---------|
| creative_design.md 定稿+参考素材完成 | ①确认创意和素材继续制作（推荐） ②修改剧本（附可调项：角色/结局/时长） ③调整角色/场景形象或配音音色 |
| storyboard.md 定稿推送 | ①确认分镜开始生成（推荐） ②修改特定镜头 ③调整整体节奏/时长 |
| 视频生成完成 | ①修改某个镜头重新生成 ②调整风格/氛围重新制作 ③基于此继续做续集 |
| 单段视频完成 | ①满意则结束 ②修改画面/动作 ③换个风格试试 |

**确认门原则**：
- 必设的是花钱前门（多段：创意与素材确认 + storyboard.md 确认；单段：简明方案说明）
- 上游门按不确定性加——仅当 agent 引入的不确定性高、晚发现很贵时才加
- 任何路径 ≤2 道确认门
- **用户明确要求跳过确认**（"直接生成""马上开始做""不用确认"等）→ 全部停顿门降级为简明说明、不停顿；硬约束缺口仍按 §1.2 问卷补齐

| 特效创意 | 特效/转场/变身/魔法 |
| VFX/动作特效 | 打斗/功夫/武打/对决/战斗/格斗/追逐/爆炸/超能力/武术 |

| **分镜图生成（多宫格 storyboard）** | **分镜 / 分镜图 / 分镜表（仅指图像形式，用户自称"写了个分镜表"的纯文字稿不算）/ 分镜宫格图 / N 宫格分镜图（三/四/六/九/十二/十六/二十五宫格）/ 故事板 / 故事版 / storyboard / 导演分镜 / 连环画分镜 / 漫画分镜**，且带「生成 / 先出 / 先画 / 先来一版 / 想先看」分镜图的诉求；或用户上传了多宫格分镜图 / 故事板，要据此继续生图或做视频 |

**CRITICAL - 「分镜图生成」进/不进判定**：意图须同时指向**分镜图(图像)生成 / 已有分镜图**才进入——即"生成 / 先出 / 先画 / 先看 分镜图、N 宫格分镜图、storyboard、故事板"，或用户已上传分镜图/多宫格图；**只给了文字分镜脚本 / 四栏表并要求生视频、未提"生成分镜图"的，不进入本意图，走常规视频流程。** 命中后的加载、出图与"已上传分镜图→参考图还原不改图"等执行规则见 §1.2c 加载总表。

**模糊意图 + 人物素材**：当用户提供人物参考图且意图不明确时（如"用这张图做个视频"），scope 默认单段，但画面必须有人物动作和情节——禁止仅生成"图片微动"式的纯画面平移/缩放。**只要出现「分镜图生成」信号，一律优先按分镜图意图进入子流程**。

**素材理解规则**：用户上传含人物的图片时，默认意图是**使用图中人物形象**，而非复刻图片中的背景场景。仅当用户明确要求使用原图场景时，才将图片同时作为场景参考。

**物种保真（铁律，全路径含单段直出生效）**：用户上传的是动物/宠物照片时，成片中该主体必须保持**动物形象**，禁止将其"转换为人类面孔/人体"。即使用户把它套进人类角色设定（如镖客、大官、拉弓、穿盔甲），也是让**动物**去演这些角色，按 `creative/pet-anthro.md` 的拟人化层级处理（保留动物头脸与体型，通过服饰道具、口型、直立姿态实现拟人），而非改物种。仅当用户明确要求"把这只猫/狗变成人""以这张动物脸做人物"时才转人形。

### 1.2c Ref 知识加载

通过 `sandbox_read` 读取 `/workspace/.skills/video_creation/refs/{路径}`。**同一阶段命中的多个 ref 必须在单条消息内并发发起 `sandbox_read` 一次性读完，禁止读一个想一下再读下一个的串行方式。**

**加载原则：**

1. **流程优先**：当前 active workflow（§0.4 选定的 `workflow/*.md`）是流程的唯一入口。先按 workflow 判断当前 Step 与路径，再到 §四查该阶段需要读取的 ref。
2. **分阶段加载，禁止提前读**：创意设计、素材生成、分镜规划、质量复核各阶段只读本阶段 ref。禁止在创意设计阶段提前读素材生成或分镜规划 ref；禁止在素材生成阶段提前读分镜规划 ref。
3. **权威顺序**：§0.4 权威顺序在 ref 层继续生效——ref 与根文件或 active workflow 有差异时，以上层为准。体裁专章的结构/时长配比与 `narrative-arc.md` 冲突时，以体裁专章为准。
4. **触发宁可命中、不可漏**：§四中的触发词是语义示例而非穷举白名单。只要语义沾边就算命中，判断不准时倾向命中。
5. **超配看优先级**：每阶段建议加载 ≤3 个 ref（信息密集场景可放宽到 4 个）。触发数超出时按 P0>P1 取前几个。被丢弃的 ref 只在该阶段自审摘要中记 `⚠️ 未加载 {文件}`，不写入交付给用户的正文产物。
6. **单段直通豁免**：命中 `workflow/single-segment.md` Step 2 直通时，除该 workflow 文件本身外**不读任何知识 ref**——含 `prompt-craft.md`、`dialogue-rules.md`、体裁分册及 ref 内部的"未加载时补加载"条款。这些文件通篇是改写与密度指令，读入即诱导重写用户脚本；程序直传由系统直取用户原文，抄录直通所需的口型句式与尾注已内联在该文件 Step 2 中。

**禁止**：跳过检查直接创作 / 同义替换 ref 中的关键词 / 向用户暴露 ref 文件名 / 在创意设计阶段提前加载分镜规划阶段的 ref / 超配时凭主观丢文件而不按优先级。

### sandbox_generate_video

| 参数 | 说明 |
|------|------|
| `ModelName` | 模型名，默认 `seedance_2.0_fast` |
| `Prompt` | 视频描述，用 `@图片N` `@视频N` `@音频N` 引用 ImageList/VideoList/AudioList 中的素材 |
| `UseRunPrompt` | 布尔。`true` 时系统把**当轮用户消息全文**逐字作为生视频提示词（优先于 `Prompt`，此时 `Prompt` 传空字符串）。仅用于 `workflow/single-segment.md` Step 2 直通·程序直传；其余场景一律不传 |
| `ImageList` | 参考图片路径列表（非 URL） |
| `VideoList` | 参考视频路径列表（非 URL） |
| `AudioList` | 音色参考音频路径列表，用 `@音频N` 在 Prompt 中引用 |
| `Duration` | 时长 4-{{ .max_video_duration }}s |
| `TaskType` | 任务类型，仅三类：`edit`（视频编辑）/ `extend`（视频延长）/ `keyframe`（首帧或首尾帧锁定），非此三类不填（默认 auto）。`edit`/`extend` 必须传 VideoList；`edit` 的 Duration 与最长参考视频实际时长一致（±1s 内）或不传 |
| `Ratio` | 视频比例：16:9、9:16、4:3、3:4，默认自适应 |
| `Resolution` | 分辨率：480p、720p_lite（默认）、720p、1080p |

**关键规则**：
- 多素材时 ImageList/VideoList/AudioList 按 Prompt 中 @图片N/@视频N/@音频N 的顺序排列；`UseRunPrompt: true` 时 Prompt 为空，@引用规则不适用，素材列表照常传入
- 修改/增强已有视频时，必须在 VideoList 传入该视频
- 使用素材路径而非 URL
- <4s 自动设为 4，>{{ .max_video_duration }}s 需拆分为多镜头
- AudioList 中的音频用 `@音频N` 引用，禁止只传 AudioList 不传 ImageList（至少传入角色参考图或场景参考图）
