# 工作流模式（Workflow Patterns）

## 顺序工作流（Sequential Workflows）

对于复杂任务，把操作拆分为清晰、顺序的步骤。通常在 SKILL.md 开头给 agent 一个流程概览会很有帮助，并以能力的方式（而非点名内部工具）描述每个步骤:

```markdown
填写 PDF 表单包含以下步骤:

1. 分析表单，列出它的字段
2. 创建字段映射（字段名 -> 值）
3. 对照表单的字段校验该映射
4. 用映射好的值填写表单
5. 把填好的表单展示给用户
```

> 产出的技能不打包脚本:把每个步骤表达为一条描述要做什么的自然语言指令，
> 让 agent 驱动它自己的工具去执行。
> 不要打包脚本，正文里也不要点名工具(工具只在 frontmatter 的 tools 字段声明)。

## 条件工作流（Conditional Workflows）

对于带分支逻辑的任务，引导 agent 走过各个决策点:

```markdown
1. 判定修改类型:
   **创建新内容?** -> 遵循下面的"创建工作流"
   **编辑已有内容?** -> 遵循下面的"编辑工作流"

2. 创建工作流: [步骤]
3. 编辑工作流: [步骤]
```
