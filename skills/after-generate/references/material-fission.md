# 素材裂变规则

本文件用于 after-generate 的素材裂变分支：确定保留项、测试变量、问卷选项、变体规划与复用下游能力的方式。

## 1. 素材裂变的目标

素材裂变不是“随便多做几条”，而是围绕可投放母版建立一组可测试变体。

默认目标：

- 保留母版中已经有效或用户满意的核心表达；
- 一次改变一个主变量；
- 让每条变体对应一个清晰测试假设；
- 不新增未经验证的事实型主张；
- 最终交付可直接用于投放或二次筛选的视频变体。

## 2. 不变量

除非用户明确要求改变，以下内容默认保持不变：

- 商品、品牌、App、服务的基本事实；
- 已验证卖点、优惠、规格、功效、认证、价格与活动信息；
- 用户已确认的人物/达人/商品素材身份；
- 当前母版中用户满意的主体内容和核心购买理由；
- 视频比例、语言、平台方向；
- 合规边界和不能说的内容；
- 主要 CTA 路径，如商品卡、搜索词、直播间、下载、预约。

如果裂变变量会影响以上不变量，必须先说明影响并询问用户是否允许改变。

## 3. 可裂变变量

### 3.1 Hook

测试开头 1-3 秒的停留能力。

可变方式：

- 痛点开场；
- 结果先行；
- 反差/误区；
- 人群点名；
- 提问式；
- 视觉奇观；
- 快速证明预告。

默认保持正片内容不变，只重构开场和必要 bridge。

### 3.2 卖点角度

测试不同购买理由。

可变方式：

- 省时/省力；
- 质感/审美；
- 专业/可信；
- 性价比；
- 场景适配；
- 情绪价值；
- 礼赠/关系价值。

只能使用已验证或安全推断的卖点，不凭空新增事实。

### 3.3 证明方式

测试“用户为什么相信”。

可变方式：

- 使用过程演示；
- 前后对比；
- 达人亲身体验；
- 场景结果；
- 第三方或用户反应；
- 产品机制可视化；
- 细节微距与材质证明。

证明必须先于 CTA，不要只改口播而没有可见证据。

### 3.4 场景或人群

测试不同受众或使用情境。

可变方式：

- 通勤、居家、旅行、办公室、节日、直播间；
- 新手、宝妈、学生、小商家、健身人群、职场人；
- 不同地域/语言/文化场景。

如果新场景暗含未经验证的用途或效果，先请求依据或改成安全表达。

### 3.5 角色或达人表达

测试不同信任来源或剧情载体。

可变方式：

- 达人测评；
- 闺蜜推荐；
- 专家/店主解释；
- 用户第一视角；
- 剧情主角；
- 吉祥物或拟人角色。

涉及真人身份或达人相似度时，必须遵守既有素材授权与身份边界。

### 3.6 视觉风格

测试不同内容包装。

可变方式：

- UGC 手机实拍感；
- 品牌大片；
- 剧情短剧；
- 教程/开箱；
- 测评对比；
- ASMR/感官；
- 高能卡点。

Style 只能改变表达方式，不能替代商品证明或改变事实。

### 3.7 口播/字幕

测试不同文案表达。

可变方式：

- 第一人称体验；
- 问题-答案；
- 反差句；
- 强利益句；
- 情绪句；
- 更短/更直接字幕。

如果视频生成工具支持直接音画生成，口播应写入视频生成提示词；不要默认另做完整 TTS 轨。

### 3.8 CTA

测试收束动作。

可变方式：

- 点商品卡；
- 搜索品牌/商品词；
- 进直播间；
- 下载 App；
- 预约/报名；
- 收藏/评论/私信。

营销/投放视频默认 CTA 应可听，不只靠屏幕文字。

### 3.9 版式适配

测试不同投放渠道的画面版式适配。

可变方式：

- 9:16 竖版；
- 1:1 方版；
- 16:9 横版。

版式变化应保持商品事实、核心表达和原有节奏不变。

## 4. 默认问卷

进入裂变前，如果刚刚生成了视频产物，Agent 应在交付产物的同一轮主动说明“当前视频可以作为投放母版继续裂变”，不要假设用户已经知道裂变能力，也不要等用户追问“还能做什么”。

推荐引导语：

```text
这条视频已经有商品、人物和基础表达，可以继续做投放素材裂变：保留商品和主体素材不变，批量测试不同开头 Hook、卖点、场景、人群或 CTA。你可以先选一个方向，我也可以默认先做 3 条高价值变体。
```

进入裂变分支时，如果用户没有明确指定变量，优先用一份简短问卷或对话选项：

```text
你想优先测试哪类投放变量？
1. 换开头 Hook：只测试前三秒吸引点
2. 换卖点角度：测试不同购买理由
3. 换证明方式：测试不同可信表达
4. 换场景/人群：测试不同受众情境
5. 换表达风格：UGC/剧情/品牌/教程等包装
6. 换 CTA/口播收束：测试转化话术
7. 自由发散：基于母版设计一组变体
```

然后确认：

- 生成几条，默认 3 条；
- 是否保持原比例，默认保持；
- 是否允许改口播，默认允许改与变量相关的口播；
- 是否允许重生成画面，默认允许重生成受影响片段。

如果用 `dynamic_questionnaire`，候选题必须加入“自定义 / 其他”，整份问卷末尾必须有自由文本补充入口。

## 5. 变体规划格式

下游执行前，Agent 应在对话中用简洁形式确认裂变计划：

```text
我会保留：商品事实、主体素材、原比例、核心卖点。
本次只测试：开头 Hook。
计划生成 3 条：痛点版、结果先行版、反差版。
确认后我会复用当前母版结构生成对应变体。
```

不要把内部 JSON、source_element id、manifest 路径直接展示给用户，除非用户明确要求实现细节。

## 6. 按结构来源复用能力

### 6.1 营销视频结构来源

如果母版来自营销视频创作链，按以下方式处理：

- Hook 裂变：改 story-script 前几秒和 final-generation-info 对应开场/bridge；
- 卖点裂变：回到营销策略或 story-script 的卖点排序；
- 证明方式裂变：修改 story-script 中证明节拍和素材需求；
- 场景/人群裂变：可能影响故事、素材、场景和 final-generation-info；
- 风格裂变：通常保留故事，重建视觉体系和生成提示；
- CTA 裂变：修改收尾文案、声音、画面和 final-generation-info。

遵守原营销视频链的确认门和修改路由。已经确认的文件如果发生实质变化，必须重新确认后再生成。

### 6.2 参考视频复刻结构来源

如果母版来自复刻链或只有最终成片，应复用反解/Plan 能力：

- 用反解结果识别爆点、关键元素、source_elements、route、content_blocks；
- 选择裂变变量时，不要破坏必须保留的核心爆点；
- 对 R2V_REQUIRED 的源元素替换，必须明确替换对象和目标；
- 对 SEMANTIC_RECREATE 的变体，可保留爆点和视听指纹，重建人物、场景、主题或文案；
- 对 CORE_CONTENT / WRAPPER_CONTENT 分块视频，默认只裂变 CORE_CONTENT，除非用户明确要求包装内容也变化。

复刻 Plan 返回几段就生成几段，Agent 不按镜头或内容块自行二次切割。

### 6.3 仅有最终成片

若没有任何结构化产物：

1. 把母版作为参考视频；
2. 调用反解取得结构；
3. 根据用户选择的裂变变量构造给 Plan 的补充指令；
4. 由 Plan/Checker 生成最终片段 prompt；
5. 串行生成并合并。

不要在未反解的情况下凭肉眼概括母版结构并批量生成。

## 7. 变体数量控制

默认 3 条。除非用户明确要求批量矩阵，否则首轮不要超过 5 条。

推荐组合：

- 3 条 Hook 版：痛点 / 结果先行 / 反差；
- 3 条卖点版：省时 / 质感 / 可信证明；
- 3 条场景版：居家 / 通勤 / 礼赠；
- 3 条风格版：UGC / 剧情 / 品牌感。

如果用户要求多变量矩阵，先确认变量组合和总条数，避免生成不可解释的大量视频。

## 8. 交付说明

交付时必须说明每条变体测试什么：

```text
变体 A：痛点 Hook，测试前三秒停留。
变体 B：结果先行，测试即时收益感。
变体 C：反差开场，测试好奇心点击。
```

不要交付内部中间片段、临时裁剪素材或 Checker 结果。生成失败的变体不混入最终交付；如果部分失败，说明哪些成功、哪些失败以及是否需要重试。
