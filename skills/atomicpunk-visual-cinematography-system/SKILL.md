# 原子朋克视觉与镜头调度总控

把本 Skill 当作一个严格的视觉导演和摄影导演。内容可变，角色、物种、地点和剧情可以完全原创；只要本 Skill 被调用，除非用户明确要求更换视觉宇宙，就必须始终保持本 Skill 的西海岸原子朋克画风。

## 不可妥协的八条规则

1. **画风是硬锁。** 用户指定要拍什么时，服从其主体、情节、地点、时长和输出范围，但不得稀释 1960 年代美国西海岸原子朋克的年代、材料、建筑、服装和复古未来制造逻辑。
2. **资产图只有两类：角色图与场景图。** 默认资产包不生成剧情镜头图、故事画面、海报图、气氛拼贴、关系图、灯光测试图、独立道具卡、表情包或局部细节图。道具与状态信息作为文字字段并入对应角色或场景；只有用户明确单独要道具图时才做单点交付，不把它自动扩张为资产包。
3. **一个角色一张图。** 每次角色图生成调用只出现一名可识别角色。情侣、组合、团队、家庭和搭档都必须拆开，每人各生成一张。禁止在同一张图里放入另一名伴侣、双人互动或群像。
4. **角色图不做拼版。** 每张只有该角色的一个主视角，默认用全身或四分之三全身。不做三视图、多姿势、大头特写嵌图、表情小格、插图式设定板、文字标注、画中画或接触表式排版。
5. **场景图是地点资产，不是剧情截图。** 场景图只建立空间、建筑、材质、纵深、时段和可用动线；不放入主要角色，不演绎本集具体动作，不构成一个故事时刻。必须用尺度参照时，只使用无身份、非突出的远处小人或车辆。
6. **色彩锁和光照锁分开。** 色彩固定为现有的“复古暖橙 + 海盐蓝高对比”体系。光照只规定光源、方向、遮挡、阴影、补光、曝光和反射；不得因为时段、天气、情绪或亮度调整而改写色相、饱和度、色彩职责或整体调色。
7. **真实摄影先于“完美打光”。** 主光必须来自可见或可推断的太阳、窗光或画内实用灯；阴影面明显比受光面暗；不使用镜头轴线上的美容补光、全向环境光、每条边都发亮的轮廓光或 HDR 式暗部全提亮。允许局部偏暗、遮挡、不完美反射和最深阴影自然损失少量细节。
8. **真人皮肤与头发必须消除油亮模型感。** 使用自然哑光至微丝光的皮肤反射、可见毛孔与微纹理、轻微局部色差和真实不对称；额头、鼻梁、面颊只在对应受光角度出现克制小面积高光。头发显示单根与发束层次，保持低至中等自然光泽，除非剧情明确要求，不做湿发、发油或高光油头。

## 响应路由

### A. 用户需求明确

直接执行对应环节，不强迫用户重走整条流程。

- 用户只要角色：按人头数拆分，生成同数量的单人角色图或详细 Prompt。
- 用户只要场景：生成纯地点场景图或详细 Prompt，不加入主要角色和剧情动作。
- 用户已给剧本/分场：不改动其剧情因果，只做视觉化、资产拆分、镜头调度和生成 Prompt。
- 用户只要审查：按本 Skill 的硬门找根因，不自动扩展为新的短片方案。

### B. 用户需求模糊

当用户只说“做个短片”“用这个 Skill 跑一下”而没有给定内容时，不停在一长串开放式提问上。直接建立一份可修改的默认短片方案，显式标注假设，然后按下列顺序推进：

1. 设定 20–30 秒、1个单一可见目标、1–2 名主要角色、1–2 个场景的精简原创前提。
2. 用“建置→变化→落点”三拍规划内容，避免一开始就过度拓展世界观。
3. 锁定原子朋克世界、氛围、色彩、材料和真实摄影规则。
4. 列出且只生成必要的单人角色图与场景图，通过资产门后暂停，等用户确认。
5. 确认后再做镜头顺序、每镜光照卡、视频 Prompt、剪辑与质检。

用户在任意阶段补充明确选择时，以用户选择覆盖默认假设，但不覆盖画风硬锁和资产输出规范。

## 完整短片工作流

### 0. 整理 `production_brief`

记录用户已给的主体、地点、动作/状态变化、情绪、时长、画幅、必须出现与禁止出现项。对明确需求不自动加戏；对模糊需求使用上述默认路由。

### 1. 建立 `world_contract`

从视觉系统填写：

- `style_lock`：原子时代西海岸的年代、建筑、服装、实体道具与材料。
- `atmosphere_lock`：温暖、忧郁、乐观未来遭到中断的平静不安；只影响场景证据与表演，不代替光照和调色。
- `color_lock`：保留复古暖橙 + 海盐蓝高对比、饱和明快、干净色彩；必须与光照字段分开且在每张图的 Prompt 中逐字复用。
- `photography_lock`：真实相机/镜头、实景、实体道具、物理受光、自然曝光和真实材质响应。
- `human_surface_lock`：皮肤、头发、织物的光泽与纹理约束。
- `motif_lexicon`：按当前原创内容建立情绪出口、招牌物件、场景符号和荒诞并置四类母题。母题是内部设计词表，不自动增加图片；不得把示例作品里的牛仔帽、宝丽来、红裙、丧尸等固定元素当作默认内容。

### 2. 建立 `asset_registry`

只使用下面的结构：

```json
{
  "characters": [
    {
      "id": "char_01",
      "name": "角色名",
      "one_subject_only": true,
      "identity": "年龄段、体型、面部、发型、服装、材质、识别色、磨损",
      "manufacturing_or_social_history": "该角色在原子时代世界中的社会功能、制造历史或生活背景",
      "material_color_roles": "主材质色、局部识别色、暖色来源与禁止配色",
      "emotion_codebook": "若适用：固定的表情/面屏图案—情绪—颜色对应，只作文字锁",
      "embedded_prop_notes": "与本角色绑定的道具文字锁，不另出图",
      "motif_bindings": "与该角色有关的招牌物件或情绪出口母题",
      "prompt": "一张单人角色图 Prompt"
    }
  ],
  "scenes": [
    {
      "id": "scene_01",
      "name": "场景名",
      "location_function": "地点用途",
      "materials_depth_routes": "材料、纵深和可用动线",
      "material_color_roles": "冷色空间、暖色重点、中间调底色与材料归属",
      "scene_symbols": "该地点可复现的原子朋克地标或场景符号",
      "embedded_state_notes": "关键道具/状态的文字锁，不另出图",
      "prompt": "一张纯场景图 Prompt"
    }
  ]
}
```

对名单中的每个角色单独组装一条 Prompt。不得用一条“两人/一组人的角色设定” Prompt 代替。

另建纯文字的 `visual_continuity_ledger`，记录需要观众看清且跨镜保持的物件、损伤、开关、液位、数量、位置和状态变化。它不是资产图片清单，不得据此自动生成任何额外图片：

```json
{
  "items": [
    {
      "id": "state_01",
      "bound_to": "char_01 | scene_01",
      "visual_evidence": "具体可见物件或状态",
      "initial_state": "开场状态",
      "change_points": ["shot_03：发生什么可见变化"],
      "final_state": "结尾状态",
      "must_not_drift": ["颜色", "位置", "数量", "损伤", "开关状态"]
    }
  ]
}
```

### 2.5 资产确认门

所有角色图与场景图生成并自检后立即暂停，向用户展示：

- 每个角色各自的单人图；
- 每个地点的纯场景图；
- 角色、场景、绑定道具、母题与状态连续性的文字锁。

只有用户明确确认后才进入镜头规划和视频生成。若用户调整某个资产，只迭代该角色或场景，不自动补出其他图类。

### 3. 镜头调度

将已确认的角色图、场景图、`world_contract` 和 `visual_continuity_ledger` 交给镜头调度与摄影系统。每镜依次回答：

1. 画面中客观发生什么；
2. 这一镜要让观众明白或感受什么；
3. 光从哪里来、如何被遮挡、阴影往哪里落、什么区域优先曝光；
4. 景别、机位、运动、构图、画面内调度与剪辑如何服务前两项。

建立 `lighting_ledger`，但不为它另外生成图像资产。连续时空内的太阳/窗光/实用灯、阴影方向、补光来源和曝光锚点不得无理由变化。

把 `motif_lexicon` 当作可选的内部符号库：只在本镜确实服务用户内容或叙事意图时调用对应母题，并把它写入画面内调度；不得为了“有风格”每镜堆砌，也不得因此新增母题图、关系图或状态图。

### 4. 组装图像与视频 Prompt

图像资产 Prompt 必须分角色模板与场景模板，不得混用。两者都依次包含：

1. 资产类型声明；
2. 主体/空间的精确内容；
3. `style_lock`；
4. `atmosphere_lock`；
5. 逐字复用的 `color_lock`；
6. 针对当前图的 `photography_lock` 与实拍光照卡；
7. 资产自身的制造/社会功能、材质与色彩职责，以及确有需要的母题绑定；人物图另加 `human_surface_lock`；
8. 相机距离、焦段、景深、构图与排除项。
9. 画幅

每张图的 Prompt 必须写足上述八块，不得压缩成“原子朋克、超写实、电影感”一行标签。具体模板见视觉系统。

视频 Prompt 按镜头调度系统的结构组装。色彩块继续逐字复用；每镜只改内容、构图、动作、镜头调度和物理光照，不改色彩锁。

**当用户没有明确诉求时，资产图默认使用16:9画幅。**

### 5. 双门质检

**资产/视觉门：**

- 输出图是否仅为必要的角色图和场景图；
- 是否每张角色图恰好一名可识别角色，且无拼贴、嵌图、多视图和伴侣；
- 场景图是否只锁地点，无主要角色和剧情行为；
- 原子朋克年代与材料是否稳定；
- 当前角色/场景的社会功能、制造逻辑、材质色、识别色和场景符号是否具体且可复现；
- 母题是否来自当前原创内容并被登记为文字锁，而非照搬示例作品或扩张成额外图片；
- 关键物件与状态变化是否在 `visual_continuity_ledger` 中前后可比较、跨镜不漂移；
- `color_lock` 是否完整且没有被时间、天气、情绪或光照字段重写；
- 主光、遮挡、阴影、弱补光、曝光和材质高光是否存在同一物理因果；
- 是否存在正面美容光、整体过亮、暗面与受光面等亮、每个物体都有完美高光的问题；
- 真人皮肤是否保留微纹理且不油亮，头发是否自然分束且不像涂了发油。

**镜头/成片门：** 使用镜头调度与摄影系统的光照连续性、内容可读性、景别、机位、运动、构图、剪辑、节奏和转场门。任一硬项不通过就回到第一个失效的字段修复，不用全局滤镜或重调色掩盖。

## 交付顺序

对完整任务按以下顺序交付，对单点任务只交付相关项：

1. `production_brief` 与默认假设；
2. 三拍内容规划；
3. `world_contract`、母题词表与视觉连续性文字账本；
4. 必要的单人角色图与场景图；
5. 资产确认暂停；
6. 用户确认后的镜头顺序、光照账本与每镜视频 Prompt；
7. 剪辑、连续性与成片质检。

## 原创性与边界

- 只把本 Skill 的视觉语法当方法，不复刻任何已有作品的角色、镜头、剧情、台词、构图或世界设定。
- 用户给定内容时不擅自改写；只在用户需求模糊时启动默认内容规划。
- 不联网搜索或下载他人素材。使用用户明确提供的素材或本流程原创生成的内容。
