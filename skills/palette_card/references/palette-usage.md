# 色卡 → 创作转写规范（palette-usage）

**前置门**：本文件的转写规范只在你**即将真实调用** `sandbox_generate_image` / `sandbox_generate_video` 时使用。当前工具面无这两个工具时，禁止依据本文件产出任何生图/生视频 Prompt 文本——写得再合规也是无处可用的空转，且会被用户误认为已进入制作。

色卡确认后，三步转写适用于**每一次** `sandbox_generate_image` 与 `sandbox_generate_video`——含角色参考图、故事板、场景资产、正片各段。**参考图是色彩源头，漏转写等于全片漏转写，无豁免。** 该规则叠加在任何垂类 skill 的 Prompt 规范之上，两者同时满足。

每次调用前逐格自检：

| ① ImageList 带色卡（末位） | ② Prompt 有色系定义句 | ③ Prompt 有防入画尾注 |
|---|---|---|
| ☐ | ☐ | ☐ |

三者缺一即该次调用非法，重写后再发。

## 一、为什么要转写

- **色卡参考图是唯一的锁色手段**：纯文字描述色调（"高级""电影感"）是感受不是标准，跨镜头会漂；色卡作为参考图能显著减少帧间色彩闪烁和逐段色偏。参考图就用 `card_*.png` 本身。
- **Prompt 只需一句定义句，不逐色叙述**：色彩信息由色卡本身传递，在 Prompt 里复述色名/hex 是冗余，且文字与色卡不一致时反而引入歧义。色名只用于给用户看的展示与收口文案。

## 二、三步转写（每次生成必做）

### 2.1 ImageList 带上色卡

把选定的 `card_*.png` 色卡图加入 `ImageList`，与该镜头原有的角色图/场景图并存，**色卡放列表末位**（重要主体在前）。角色/场景参考图的数量与顺序照垂类 skill 原规范，不因色卡改变。

### 2.2 Prompt 写色系定义句

在 Prompt 的风格/成像段落插入一句（`N` 为色卡在 ImageList 中的实际序号）：

```
将@图片N定义为全片色彩基调，全程统一色彩风格与调色，避免帧间色彩闪烁。
```

要点：
- **就这一句，不追加色名/hex/明暗叙述**——色彩由色卡传递，文字复述多余。
- **句首禁止加"参考"二字**——`参考<素材N>` 是 Seedance 参考任务的触发句式，会让色卡被当成内容素材画进画面，与防入画尾注语义打架。**口径说明**：该禁令只针对**色卡的色系定义句**；垂类 Prompt 里对角色图/场景图写"参考@图片N中的主体"属参考任务的合法句式，不受此限。
- **图片引用符号以所加载创作 skill 的规范为准**（通常为 `@图片N`）。禁止用 `<图片N>`——`<>` 在 Seedance 规范里是**音效符号**，有被解析成音效的风险。
- 多段/多镜头视频：**每一段的 Prompt 都写这一句、每一段的 ImageList 都带同一张色卡**，不允许"第一段带了后面省略"。
- **段数越少色系越稳**：拆段前先确认是否触发垂类"禁止拆段"条件，能一次生成绝不拆——色卡跨段漂移风险随段数线性上升。

### 2.3 防入画尾注

紧跟色系定义句后加：

```
@图片N 仅作为色彩参考，画面中不要出现色卡、色条、色块拼接图形及其上的文字。
```

不加这条时模型可能把色卡当成场景元素画进画面（墙面色块、彩条背景等），或把卡面的 hex/标题文字带进画面。

### 2.4 参考图也要转写（角色图/场景图/故事板）

角色参考图是后续所有段落 ImageList 的首图——**源头没锁色，全片跟着偏**。生图版示例（用「**整体**色彩基调」而非"全片"——它们不是成片，写"全片"会让模型误以为要出多镜头画面）：

```
一只橘色虎斑猫的全身立绘参考图，站姿自然，毛发细节清晰，纯色干净背景。
将@图片1定义为整体色彩基调，统一色彩风格。
@图片1 仅作为色彩参考，画面中不要出现色卡、色条、色块拼接图形及其上的文字。
橘猫保持其固有橘白毛色，@图片1 的色彩基调只作用于环境光、背景与整体调色，不改变主体本身颜色。
```

（末句为固有色豁免句，仅当 §三判定需要豁免时加——参考图与正片一样需要豁免，源头变色全片跟着变。）

### 正/误对照

| | 写法 |
|---|------|
| ✅ | `将@图片3定义为全片色彩基调，全程统一色彩风格与调色，避免帧间色彩闪烁。` |
| ❌ | `参考@图片3的色彩基调`（"参考"触发参考任务，色卡会被当内容素材） |
| ❌ | `将<图片3>定义为……`（`<>` 是音效符号） |
| ❌ | `将@图片3定义为全片色彩基调：主色调为深湖蓝，辅以雾紫，低饱和……（主色#30587B）`（逐色叙述多余，与色卡冲突时引入歧义） |

## 三、主体固有色保护

色卡约束的是**环境与整体调色**，不该把主体的固有色（橘猫毛色、人物肤色、品牌产品色）也强行压进色板——否则用户会拿到"灰玫色的橘猫"。

- **色卡确认后、进垂类前**：判据可执行——**主体固有色所属色相族（按 §四对照表归族）是否出现在色板 6 色的色相族集合中**；归族时 **S<25% 或该色相族在色板总占比 <15% 视为该族不在场**（低饱和暗色对"橘猫毛色"这类高饱和固有色没有代表性）。不在场或不确定时，**必须在选卡/确认色卡的那次 `dynamic_questionnaire` 里合并一道单选题**（不另起问卷、不得只在推理文本里单方面声明就往下走）：
  - A：换一张包含主体色相的色卡（如暖橙系）；
  - B：保留主体固有色，色卡只锁环境色（推荐）——选 B 时 Prompt 色系定义句后必须补豁免句：
     ```
     {主体}保持其固有{毛色/肤色/产品色}，@图片N 的色彩基调只作用于环境光、背景与整体调色，不改变主体本身颜色。
     ```
- 固有色与色板冲突不是缺陷，也可以是玩法——见 `palette-play.md` 玩法 F（孤色主体），豁免句写法与本节共用。

## 四、色名词库（转写时查用）

**归族与取词全部以脚本 stdout 为准**：stdout 每色一行已印出 H/L/S、色相族与「可选色名」列表（近黑→墨黑/炭灰、近白→雾白/米白、高明度 L>75 →米白/浅沙/奶油黄等浅色词、其余→该族词库词）。**色名只能从该行"可选色名"里挑**，可加"深/浅/柔"明度前缀（近黑/近白禁叠）；不自行估算色相、不从记忆里取词、贴边色相不豁免。压线反例：`#743A4C`（H341，粉族）取红族"酒红"即违规——距族界 4° 也不豁免，stdout 印的是"烟粉/蜜桃粉/珊瑚粉"就只能从这三个里挑。

## 五、与垂类 skill 的衔接清单

进入创作类 skill（如萌宠、剧情短片等，以会话实际可用列表为准）流程后：

- [ ] 垂类流程里**每一次**生图/生视频调用都执行 §二三步（含角色参考图、场景资产、故事板、正片各段）。
- [ ] 垂类 skill 自身的 Prompt 骨架、红线、参考图规则、确认门**全部保留**，色卡三步是追加不是替换。
- [ ] 主体有固有色时按 §三处理（提示 + 豁免句）。
- [ ] 若用户中途更换色卡：**其后的**生成一律改用新色卡图；已生成片段不返工，除非用户要求重生成。
- [ ] 交付按 SKILL.md「五、交付收口」执行，顺序化：色卡入 `render_video` 片尾 → **先** present 分享卡 + 固定文案（interrupt=false）→ **最后**由垂类 present 成片（interrupt=true）收尾。
