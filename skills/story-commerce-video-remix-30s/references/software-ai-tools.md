# Apps / Software / AI Tools

Use for mobile apps, SaaS, AI tools, creator tools, productivity software, editing/design tools, automation products, ecommerce tools, and digital workflows.

## Buying Psychology

- Users buy speed, capability, fewer tools, lower skill barrier, saved headcount, trend advantage, output quality, and confidence under deadlines.
- Screen recording alone is weak. Start with human pressure, then use the screen as the proof mechanism.
- The output artifact matters more than the interface. Show what the tool produces or changes.

## Best Formulas

- **Efficiency Crush**: old workflow is slow, expensive, or team-heavy; software compresses the process.
- **Professional Nanny Tutorial**: beginner follows a few steps and reaches a usable output.
- **Status Reversal**: underestimated junior/solo user produces work that changes the room's attitude.
- **Social Flex**: early adopters know the workflow; others ask for the prompt/tool/link.
- **Dream Fulfillment**: especially for creative AI tools that make imagined scenes, characters, products, or edits visible.

## Proof Forms

- Time saved, number of outputs, before/after artifact, published result, client approval, side-by-side old workflow, generated asset, automation log, order/result dashboard where appropriate.
- Show inputs and outputs clearly. Avoid tiny UI text that cannot be read on mobile.

## Hook Patterns

- "老板当众说十分钟做不出来就走人。"
- "别人还在切软件，他已经交了三版。"
- "不会写、不会剪、不会设计，也能先做出能发的一条。"
- "大家都以为她通宵了，其实她只跑了一遍流程。"

## Example Routes

- AI tool: a team faces an impossible deadline; the tool compresses a messy workflow into a visible finished asset.
- Mobile app: a user avoids a recurring life admin task; the app turns it into a 30-second action and the proof is the confirmation/result.
- SaaS: an operator is blamed for a data mistake; the dashboard reveals the hidden issue and prevents a costly decision.

## Risks

- Do not make impossible "one-click" claims if the product needs setup.
- Avoid long feature tours. Use one workflow, one proof, one payoff.
- If using AI outputs, disclose uncertainty through realistic process beats when needed; do not imply perfect first try unless true.
