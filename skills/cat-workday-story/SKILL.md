# 打工猫的一天

## 核心原则

不要只给小猫穿职业服装摆拍——要构建一只猫真正"打工一天"的完整故事链，让职业梗通过画面行为而非字幕体现，让观众在每 15 秒里看到身份建立、职业建立、梗推进和情绪回收四重表达。

持久引擎（因果链）：

**小猫照片 → 多模态视觉DNA分析 → 小猫气质与职业适配 → 职业人格定型 → 工作日故事大纲 → 每15s表格分镜 → 用户确认 → 资产生成 → 视频Prompt构建 → 视频片段生成 → 时间线合成 → 打工猫名场面**

### 质量测试（可证伪）

创意只有通过这条测试才算成立：

**如果去掉这只猫的职业身份和职场梗，这段视频就失去了存在理由——不能只是一只猫坐在镜头前，而必须让观众在每 15 秒内同时看到"这是用户的猫"和"它在干这个职业的活并遭遇这个职业的梗"。**

## 输入诊断

生产前，识别或合理假设以下维度：

- **小猫照片**：是否至少有1张能清楚识别脸部、毛色、花纹和整体气质的图片。若无，立即终止并要求上传。
- **多猫处理**：若上传多张猫图，需确认是同一只猫的不同角度、不同猫、还是姿势/场景参考。
- **拟人化程度**：轻拟人（仅表情姿势拟人）/ 中拟人（加职业道具和轻微服装）/ 强拟人（完整职业服装+道具+场景）。
- **职业方向**：用户是否有指定职业，或需要根据小猫气质推荐。
- **视频总时长**：15s（单职业单梗高浓度）/ 30s（标准工作日）/ 45s（完整职业流程）/ 60s（系列感剧情）。
- **画面比例**：默认 9:16 竖屏；可选 16:9、1:1、4:5。
- **发布平台**：抖音、小红书、视频号、B站、TikTok。
- **搞笑程度**：轻松可爱 / 中度搞笑 / 职场扎心 / 夸张反差。
- **字幕与文案**：默认不加大段字幕，可选少量贴纸式职场梗短句。
- **音乐偏好**：默认轻快俏皮职场喜剧BGM；用户可上传自定义音乐。
- **禁用项**：是否有禁用职业、禁用道具或禁用元素。
- **分辨率**：默认 720p；用户要求高清时使用 1080p 或平台可用最高。
- **合规敏感点**：不得表现真实动物受伤、被惩罚、过劳虐待、危险机械伤害；职业刻板印象只能使用职场文化梗，不得涉及受保护群体歧视。

若用户给的上下文很少，做合理假设并继续。仅当小猫照片缺失、或职业方向确实无法推断时才发问。

## 阶段角色边界

本技能按12个阶段执行，每个阶段有明确角色边界。角色名仅作为流程内职责标识，不构成独立模块。

| 角色标识 | 职责 | 禁止事项 |
|---|---|---|
| 分析层 | 分析小猫照片，输出视觉DNA JSON | 不生成职业方向、故事、分镜或素材 |
| 规划层 | 流程控制、职业推荐、故事大纲、表格分镜、规格文档 | 不直接注册分镜、不生成素材、不写Prompt |
| 分镜注册层 | 在用户确认表格分镜后注册Storyboard Shot | 不设计分镜、不删减压缩改写分镜内容 |
| 素材层 | 绑定和生成图片资产、音乐、视频片段 | 不改写剧情与分镜 |
| Prompt层 | 将已确认内容转写为生成Prompt | 不新增剧情、职业、场景或道具 |
| 合成层 | 按Shot顺序合成视频 | 不改变镜头顺序、职业内容或剧情结构 |

## 工作流（12阶段）

### 阶段 1｜素材接收与多模态分析

**角色：分析层**

硬性启动条件：必须存在至少1张用户上传的、能清楚识别小猫脸部、毛色、花纹和整体气质的图片。小猫照片可以是正脸、侧脸、半身、全身、趴姿、坐姿、站姿、生活照、棚拍照、AI生成猫图、插画猫图、卡通猫图。

若用户上传多张猫图，必须先判断：同一只猫 / 不同猫 / 同一只猫不同角度 / 参考姿势 / 参考场景。

若无小猫照片，立即终止流程，提示用户上传小猫照片后再继续。无照片时不得生成任何后续内容。

使用多模态分析能力分析小猫照片，读取本技能下的 `references/formats/cat-visual-dna.md` 获取输出JSON规范。

输出 JSON，至少包含：
- `cat_visual_dna`：毛色、花纹、脸型、眼睛、耳朵、体型、姿势、表情、身份锚点。
- `cat_identity_anchors`：最不能改变的识别特征。
- `cat_temperament_profile`：性格推测、职场人格潜力、反差萌潜力。
- `anthropomorphic_potential`：拟人化程度建议。
- `profession_fit_candidates`：至少5个职业候选（含适配理由、职场环境、职业梗潜力、反差萌点）。
- `workplace_environment_candidates`：职场场景候选。
- `daily_gag_candidates`：日常梗候选。
- `generation_risks`：生成风险列表。

本阶段只分析，不生成职业方向、故事、分镜或素材。

### 阶段 2｜第一轮问询：小猫主角与基础参数确认

**角色：规划层**

基于阶段1的JSON，输出小猫视觉摘要，进入第一轮确认。必须询问或确认：

- 哪张小猫照片作为 [Cat_Main]。
- 是否严格保持真实小猫外貌。
- 拟人化程度：轻拟人 / 中拟人 / 强拟人。
- 是否允许职业服装、帽子、工牌、眼镜、围裙、白大褂等。
- 是否允许职业道具：电脑、咖啡机、合同、听诊器、直播灯、相机等。
- 视频总时长：15s / 30s / 45s / 60s。
- 画面比例：默认 9:16，也可 16:9、1:1、4:5。
- 发布平台：抖音、小红书、视频号、B站、TikTok。
- 搞笑程度：轻松可爱 / 中度搞笑 / 职场扎心 / 夸张反差。
- 是否需要字幕梗或贴纸文案。
- 是否有禁用职业、禁用道具或禁用元素。

**必须暂停，等待用户确认。**

### 阶段 3｜第二轮问询：职业方向确认

**角色：规划层**

读取 `references/industries/profession-library.md` 获取职业库。

用户确认基础参数后，提出3个职业方向。每个职业方向必须包含：
- 职业标题。
- 一句话职业设定。
- 适合这只小猫的原因。
- 典型职场环境。
- 职业刻板印象。
- 职场日常动作。
- 职场梗。
- 小猫反差萌点。
- 可能的3s视觉钩子。
- 可能的7s高潮点。
- 结尾名场面。

**必须暂停，等待用户选择、混合或修改职业。**

### 阶段 4｜第三轮问询：小猫工作日故事方向

**角色：规划层**

用户确认职业后，提出3个"小猫工作的一天"故事方向。每个方向必须包含：
- 标题。
- 故事类型：标准工作日 / 高浓度职场梗 / 反差萌剧情 / 加班崩溃 / 摸鱼被抓 / 职业名场面合集。
- 一天时间线。
- 开头钩子。
- 核心职场梗。
- 情绪曲线。
- 7s高潮点。
- 结尾反差点。
- 是否适合做系列。

**必须暂停，等待用户确认。**

### 阶段 5｜前期故事大纲与职场梗脚本

**角色：规划层**

用户确认故事方向后，输出前期故事大纲。必须包含：
- 标题、总时长、主角小猫身份锚点。
- 职业身份、工作场景。
- 一天时间线。
- 分段情节（每段含工作内容、职场日常动作、职业梗、小猫表情与行为反应）。
- 情绪曲线。
- 传播名场面。
- 结尾收束方式。

故事大纲不是正式分镜表，不得注册为Storyboard Shot。

**必须暂停，等待用户确认故事大纲。**

### 阶段 6｜正式表格分镜

**角色：规划层**

读取 `references/formats/storyboard-table.md` 获取表格分镜规范。

用户确认故事大纲后，输出正式表格分镜。每15s输出一个独立表格分镜表。

**每张表必须完成的四重表达：**
1. 小猫身份建立：让观众看清这是用户上传的小猫，保留毛色、脸型、眼睛和神态。
2. 职业身份建立：通过服装、道具、场景和动作，让观众一眼看出职业。
3. 职场梗推进：至少出现一个该职业的日常梗或职业刻板印象。
4. 情绪/笑点回收：每15s至少有一个小猫反差萌、崩溃、犯困、摸鱼、无辜或得意的情绪点。

**节奏要求：**
- 每2-3s必须有一个视觉重点。
- 每7s必须有一个笑点、梗点、职业名场面或情绪高潮。
- 开头0-2s必须建立职业钩子。
- 结尾必须形成可截图传播的"打工猫名场面"。

**表格字段：** 镜头序号、时间段、景别与视角、运镜方式、画面内容、小猫动作与表演、职业身份锚点、职场环境/道具/光影、职场梗/文案点、转场逻辑、首尾衔接策略、生成注意事项。

**首尾衔接规则：**
- 每张表首行说明：如何承接上一段，或如何从小猫照片进入工作日开场。
- 每张表尾行说明：如何为下一段预留动作、道具、镜头方向或情绪接口。
- 最后一张表必须以封面级名场面结束，不能黑屏、白屏、淡出或无意义空镜。

**强制暂停：** 先输出完整正式表格分镜，等待用户确认。任何分镜修改必须重新输出完整表格分镜并再次等待确认。用户未确认分镜表前，严禁编写规格文档、注册Storyboard Shot、生成资产、构建Prompt、生成视频或合成。

### 阶段 7｜编写规格文档

**角色：规划层**

仅在用户确认正式表格分镜后执行。编写 `Final_Cat_Workday_Spec.md`，必须包含：

- 标题、视频类型、职业类型。
- 比例、总时长。
- 小猫身份锚点。
- 职业身份设定、职场环境。
- 职场梗策略。
- 故事情绪曲线。
- 分镜表确认版本。
- 资产策略。
- 音频策略。
- 模型偏好（视频使用Seedance 2.0；图片资产使用GPT Image 2；音乐使用Suno 5模型）。
- 分辨率。
- 负向约束。

规格文档不得改写已确认的故事大纲和正式分镜表。

### 阶段 8｜Storyboard Shot 注册

**角色：分镜注册层**

仅在用户确认正式表格分镜并完成规格文档后执行。将每个15s表格分镜完整注册为一个Storyboard Shot。

每个Shot必须包含：
- `shot_id`：如 `Shot_01_0-15s`
- `source_table_id`：如 `Table_01_0-15s`
- `duration`：如 `15s`
- `asset_references`：`["Cat_Main", "Profession_Main", "Workplace_Main", "Profession_Props", "Music_Master"]`
- `confirmed_storyboard_table`：完整表格分镜原文，不压缩不改写
- `cat_identity_requirement`：严格保持Cat_Main的毛色、脸型、眼睛、耳朵、体型和神态
- `profession_requirement`：严格执行已确认职业、职场环境、道具和职场梗
- `continuity_requirement`：严格执行首尾衔接和镜头顺序

key_elements 注册列表：
- 必须包含：`[Cat_Main]`、`[Profession_Main]`、`[Workplace_Main]`、`[Profession_Props]`、`[Music_Master_User]`或`[Music_Master_Auto]`。
- 可选包含：`[Cat_Main_Reference]`、`[Cat_Work_Costume]`、`[Workplace_Alt]`。

不得删减、压缩、改写、换序或改变表格格式。

### 阶段 9｜资产绑定与必要资产生成

**角色：素材层**

绑定用户上传小猫照片为 `[Cat_Main]`。`[Cat_Main]`是全片最高优先级身份参考。

必要时生成以下资产：
- `[Cat_Main_Reference]`：若小猫照片不完整、角度不适合、身体被遮挡，生成身份参考图锁定毛色、脸型、体型。
- `[Workplace_Main]`：若职业需要明显环境，生成主要工作场景图。
- `[Profession_Props]`：若职业道具跨多个镜头重复出现，生成道具参考图。
- `[Cat_Work_Costume]`：若需要职业服装，生成服装参考图。

**身份保护硬规则：** 职业服装与道具不得遮挡小猫核心身份特征（毛色、花纹、脸型、眼睛、耳朵）。若服装会遮挡识别特征，不得使用，必须优先保持小猫可识别。生成任何资产时必须保持小猫毛色、花纹、脸型、眼睛、耳朵、体型和神态一致，不得换猫、不得变成人类。

**资产生成完成后必须暂停，等待用户确认。**

### 阶段 10｜视频提示词构建

**角色：Prompt层**

读取 `references/formats/video-prompt-grammar.md` 获取Prompt文法。

仅在正式表格分镜确认、Storyboard Shot注册、必要资产确认后执行。每个Storyboard Shot生成一条视频Prompt。

Prompt必须保留：小猫身份锚点、职业身份、工作场景、职场梗、每段小猫动作、镜头语言、首尾衔接、负向约束。

**不得新增未确认的职业、场景、人物、道具、字幕或Logo。**

Prompt模板（完整文法见 `references/formats/video-prompt-grammar.md`）：

```
严格参考 [Cat_Main]，保持同一只小猫的毛色、花纹、脸型、眼睛、耳朵、体型和神态。当前职业是 [Profession_Main]，场景为 [Workplace_Main]。画面中小猫正在进行 {具体工作动作}，使用 {职业道具}，体现 {职场日常/职场梗}。镜头采用 {景别与运镜}，光影为 {职业场景光线}，小猫表情为 {困/无辜/严肃/崩溃/得意}。动作按时间推进：先 {动作1}，然后 {动作2}，最后 {动作3或pose}。结尾为下一镜头预留 {动作/道具/镜头方向}。
负向约束：no cat identity drift, no different cat, no human transformation, no wrong fur color, no wrong fur pattern, no extra cat, no random person, no animal abuse, no dangerous injury, no blood, no horror, no random text, no watermark, no unauthorized logo, no profession mismatch, no distorted cat face, no missing limbs, no extra limbs, no subtitles unless requested.
```

### 阶段 11｜视频生成

**角色：素材层**

每个15s Storyboard Shot生成一个视频片段。视频片段必须参考 `[Cat_Main]`、必要职业资产、工作场景和该Shot的Prompt。

**视频生成方式：** 时长≤15s的片段用一次视频生成即可拿到完整成片。只有当总时长超过15s时，才拆成多个≤15s片段分别生成，再做后处理拼接。每个15s表格分镜的beat（0-2s/3s/7s等）是同一次生成内部的时间轴描述，不等于要多次调用。

**身份一致性硬规则：** 必须保持小猫身份一致，不得换猫、变成人、随机新增第二只猫、改变毛色。

**禁止事项：** 禁止虐待动物画面、危险劳动伤害小猫、小猫被惩罚/被打/被困危险设备中、真实血腥恐怖痛苦表现、随机文字水印未授权Logo、职业场景与职业不匹配。

### 阶段 12｜时间线合成

**角色：合成层**

按Storyboard Shot顺序合成所有视频片段为完整短片。

**合成顺序：** 按Shot顺序推送至时间线。不得插入未确认镜头，不得改变职业逻辑和故事时间线。

**音频规则：**
- 若用户上传音乐，使用 `[Music_Master_User]` 作为主音轨。
- 若系统生成音乐，使用 `[Music_Master_Auto]` 作为主音轨。
- 视频片段原声默认静音或弱化，避免随机噪声。
- 职场音效可以很轻：键盘声、咖啡机声、扫码声、打印机声、消息提示音、会议提示音。不得让音效覆盖主音乐。

**合成前必须检查：**
- 小猫身份是否一致（毛色和花纹是否稳定）。
- 职业场景是否清晰，职业梗是否能被看懂。
- 镜头顺序是否符合一天工作流程。
- 结尾是否形成打工猫名场面。
- 是否出现随机文字、水印、未授权Logo。
- 是否存在动物伤害或危险画面。

**节奏建议：**
- 开头0-2s：职业钩子。
- 中段：工作日常 + 职场梗推进。
- 7s左右：第一次笑点或崩溃点。
- 结尾：下班、瘫倒、得意、老板凝视或反差萌定格。

- 阶段3输出职业方向后暂停。
- 阶段4输出故事方向后暂停。
- 阶段5输出故事大纲后暂停。
- 阶段6输出正式表格分镜后强制暂停。
- 阶段9若生成职业资产或小猫参考资产，必须暂停确认。
- 每次职业修改必须重新输出职业方向和故事方向。
- 每次分镜修改必须重新输出完整表格分镜并暂停。
- 未经用户确认，不得跨越到下一阶段。

## 默认视频规格

- 默认视频类型：小猫工作的一天 / Cat Workday Story / 萌宠职场小剧场。
- 默认比例：9:16 竖屏，适配抖音、小红书、视频号、TikTok、Instagram Reels。
- 默认时长：30s。
- 可选时长：15s（单职业单梗高浓度）/ 30s（标准工作日）/ 45s（完整职业流程）/ 60s（系列感剧情）。
- 默认风格：轻喜剧、反差萌、职业梗、短视频节奏。
- 默认音乐：轻快、俏皮、职场喜剧感BGM；用户上传音乐时使用用户音乐。
- 默认字幕：不添加大段字幕；可选少量贴纸式职场梗短句。
- 默认旁白：不添加旁白；用户需要时可加入轻松吐槽旁白。
- 默认模型偏好：视频使用 Seedance 2.0；图片资产使用 GPT Image 2；音乐使用 Suno 5 模型。
- 默认分辨率：720p；用户要求高清时使用 1080p 或平台可用最高分辨率。

## 任务边界

本技能的核心是"小猫职业拟人化职场短视频"：
- 不是普通宠物写真。
- 不是单纯让猫穿衣服。
- 不是产品广告。
- 不是真实虐待动物场景。

视频中：
- 小猫可以拟人化工作，但必须保持小猫主体身份与可爱感。
- 不得把小猫变成人类。
- 不得让小猫从事危险、痛苦、虐待或真实伤害动物的行为。
- 不得表现真实动物受伤、被惩罚、过劳虐待、危险机械伤害。
- 职场梗可以夸张，但必须轻喜剧化、拟人化、视觉化。
- 职业刻板印象只能使用职业场景与职场文化梗，不得涉及受保护群体歧视。

## 核心概念

- **小猫视觉DNA**：由多模态分析输出，锁定小猫毛色、花纹、脸型、眼睛、耳朵、体型、表情、姿势、神态、气质和身份锚点。
- **职业DNA**：由规划层输出，定义职业身份、工作场景、职业道具、工作流程、职场刻板印象、职场日常、职业梗和职业名场面。
- **小猫职业人格**：由规划层基于小猫视觉DNA和职业DNA组合形成，确定这只猫是"困困程序员猫""暴躁设计师猫""元气咖啡店员猫""淡定老板猫"等。
- **小猫工作的一天**：核心故事结构，必须包含上班/到岗、开工、工作日常、职场梗点、情绪高潮和下班收尾。
- **正式表格分镜**：由规划层输出，每15s一个独立表格，用户确认后才能进入注册。
- **Storyboard Shot**：仅由分镜注册层在用户确认正式表格分镜后注册，不得删减、压缩、改写或重排。

## 职业梗设计原则

每个职业方向必须结合以下四类内容：

1. **职业刻板印象**：该职业在大众短视频语境中的典型印象。
2. **职场环境**：办公室、工位、咖啡吧台、诊室、教室、直播间、厨房、会议室、便利店、前台等。
3. **职场日常**：开会、回消息、打卡、写日报、接单、改稿、接待、做表、催进度、补货、备课、查房、开播等。
4. **职场梗**：摸鱼、加班、需求变更、甲方改稿、老板画饼、顾客催单、KPI、日报、周会、已读不回、工位崩溃、下班冲刺等。

**职场梗必须通过画面行为体现，不能只靠字幕解释。** 例如"程序员猫改bug"不能只写字幕，而要设计为：小猫蹲在电脑前，屏幕蓝光照脸，爪子乱拍键盘，咖啡杯堆满桌，最后趴在键盘上睡着。

## 输出契约

### 正式表格分镜模板

每15s一个独立表格，字段如下：

| 镜头序号 | 时间段 | 景别与视角 | 运镜方式 | 画面内容 | 小猫动作与表演 | 职业身份锚点 | 职场环境/道具/光影 | 职场梗/文案点 | 转场逻辑 | 首尾衔接策略 | 生成注意事项 |
|---|---|---|---|---|---|---|---|---|---|---|---|

- 每张表总时长严格为15s；最后一段不足15s按实际剩余时长成表并标明。
- 每张表建议包含8-15个镜头或内部切镜，信息密度高。
- 每张表必须覆盖完整"小猫工作日"动作链，而不是静态职业造型展示。

### 视频 Prompt beat 结构

每个15s片段的Prompt内按时间轴组织beat：

```
0-2s: {职业钩子建立，小猫身份+职业身份第一眼可辨}
2-3s: {视觉重点推进}
3-7s: {工作日常+职场梗铺垫}
7s: {笑点/梗点/职业名场面/情绪高潮}
7-12s: {情绪延续或升级}
12-15s: {情绪回收或反差萌定格，为下一段预留接口}
```

**视频生成方式：** ≤15s的片段用一次视频生成即可拿到完整成片，上述beat是同一条Prompt内的时间轴描述。只有成片超过15s时，才拆成多个≤15s片段分别生成再后处理拼接。

## 静默自检

交付前内部跑清单并重写弱项。除非用户要求点评，否则不外显。

- 小猫照片是否存在且可识别脸部、毛色、花纹？
- 视觉DNA分析是否输出了完整JSON（含至少5个职业候选）？
- 基础参数是否经用户确认（拟人化程度、时长、比例、平台）？
- 职业方向是否提出3个且经用户确认？
- 故事方向是否提出3个且经用户确认？
- 故事大纲是否包含完整一天时间线和分段情节？
- 正式表格分镜是否每15s一张、包含全部12个字段？
- 每张表是否完成四重表达（身份建立/职业建立/梗推进/情绪回收）？
- 每7s是否有笑点或高潮？开头0-2s是否有职业钩子？结尾是否形成可截图名场面？
- 首尾衔接是否每张表首行说明承接、尾行说明预留？
- 分镜表是否经用户确认后才进入注册？
- 规格文档是否完成且不改写已确认内容？
- 资产生成是否保持小猫身份一致（毛色/花纹/脸型/眼睛/耳朵/体型/神态）？
- 职业服装是否遮挡小猫核心识别特征？
- 视频Prompt是否保留所有已确认要素且未新增未确认内容？
- ≤15s的片段是否作为一次生成的完整片段而非分段拼接？
- 合成后小猫身份是否一致？职业梗是否能被看懂？
- 是否存在动物伤害、危险画面、随机文字或水印？
- 全文语言是否与目标市场一致、无混杂？
