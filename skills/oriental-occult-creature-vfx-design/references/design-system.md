# 视觉设计系统(方法层)

本文件只负责**把视觉语言转成原创设计图资产、锁定包与交付物的方法**。美学决策以其它文件为准,不重复:

- **两层世界、材质光线、角色设计、Prompt 组织** → `visual-grammar.md`。
- **真实勘景、场景身份、干净底板与怪物背景配对** → `environment-continuity.md`。
- **怪物开大攻击态设计图(一图定形)** → `monster-design.md`。
- **符咒施法与打斗特效、能量色表、用户 Prompt 接入位** → `vfx-and-talisman.md`。

本文件补充三样通用工具:全片视觉契约、呈现层次、交付格式。所有资产统一 16:9。

## 1. 全片视觉契约

先写一句能约束所有画面的总述,再锁定下列八项,写成**全片锁定词**原样挂到每条 prompt 末尾(与 `visual-grammar.md` 的锁定词块保持一致,不另起一套)。

示例总述:

> 一个湿冷民俗的东方现实层(时代可现代/近代/古代),藏着一条会施加代价的灵异规则;当符燃、铃响、地脉迸发,画面翻入铁锈红的诡域层,一头由废车锈铁与岩层聚合的巨大怪物显形、卷吸废料开大,暗金符链与幽蓝寒气在真实空间里对撞——东方、克制、有据,而非血浆猎奇、霓虹乱炸或仙侠掐诀。

| 变量 | 需要决定什么 | 推荐基调 |
|---|---|---|
| **两层世界** | 现实层与诡域层各自的情绪/材质/光 | 现实层湿冷民俗 + 单一暖光;诡域层铁锈红/坍塌/能量异色 |
| **场景身份** | 这是哪个真实地点,什么永远不变 | 唯一 `SCENE_ID`;固定空间骨架、主光、损坏、天气;同机位用 `PAIR_ID / CAMERA_SLOT` |
| **空间母题** | 灵异反复出现在哪 | 旧宅/神龛/戏台/水道/矿洞/档案室,选 2–3 个反复出现 |
| **材质物理** | 什么使它一眼属于此世界且能被真实拍到 | 2–3 种主材料各写粗糙度、反光、局部湿度、破损和积尘;保留安静大面 |
| **主色温与光源** | 光从哪里来、如何衰减 | 冷黑蓝为底,锁死实景主光位置/方向/色温;能量仅为局部高饱和异色 |
| **能量语汇** | 符/法器/特效的能量长什么样 | 每种能量固定 色+形+意象(见 `vfx-and-talisman.md` 能量色表);去仙侠掐诀 |
| **摄影底片** | 画面以什么真实成像逻辑成立 | 真实电影现场摄影、合理焦段/机高、有限景深、空气透视、接触阴影和地面受力 |
| **禁忌项** | 什么会破坏世界 | 游戏引擎/纯3D展示感、抛光CGI、全场湿亮、同质材质、全局锐化、均匀裂纹、无来源漂浮特效、满屏乱色、仙侠掐诀、专有IP |

锁定词是所有设计图共享的视觉 DNA,不在同一项目中随意改写。

## 2. 图片清单与积分确认门

视觉契约和文字卡完成后,先规划图片,不得立即生成。向用户展示逐张清单,至少写明 `图片 ID / 内容与用途 / SCENE_ID 或纯设计背景 / 母版或派生图 / 必选或可选 / 张数`,并汇总“必选 X 张 + 可选 Y 张;全选 Z 张”。说明图片生成会消耗积分,等待用户明确批准准确清单。

- 未确认时只输出文字规划和 Prompt,不得调用图片生成/编辑工具。
- 空镜不默认生成;只有下游确实需要同地点空镜并被用户批准时,才生成一张 `scene_master_<SCENE_ID>`。
- 任何新增、变体、重抽、补图或失败重生成都视为新增图片,先报告新增清单与新增张数并再次确认。
- 实际交付不得超出批准的图片 ID 和数量。

## 3. 呈现层次(控制显现强度)

用三段层次控制「灵异/能量/怪物显现到什么程度」,避免每张图同一强度:

1. **潜隐(现实层)**:异常只含蓄可辨——一处水渍、一枚旧符、雾气渗入;空镜或近景就能感到不寻常。
2. **显现**:规则显形,能量出现、怪物现身,现实层被侵入。
3. **主导(诡域顶点)**:怪物开大、符咒爆发、特效对决主导整体;通过门洞、柱距、车辆、栏杆或砖块模数等环境量尺建立巨物压迫,空间气质翻转。

每张设计图只升级一个变量:呈现层级、能量强度、特效层级或主体距离。

## 4. 建议交付格式(设计图资产 + 视觉锁定包)

本环节只交付**视觉设计包**,不写剧情、对白、事件时间线或逐镜分镜(交给 video creation)。除非用户要求更短版本,按以下顺序给出:

1. 一句视觉总述与主视觉命题(长什么样、什么气质,非故事)。
2. 全片视觉契约(八项)与每个地点的场景身份卡。
3. 怪物卡、符咒本体卡、文字版符咒/打斗特效规划、角色卡、地点卡,各 3–7 条(规则见各专项文件)。
4. 调色/材质/镜头/特效规则与禁忌项——作为视觉约束。
5. **已批准的设计图资产**(默认精简):每只怪一张扎进真实 `SCENE_ID` 的无人物开大攻击态图,用环境量尺和地面受力证明体量;每位角色一张综合参考卡,在同一画布内含正/侧/背三视图和头部特写,不另出头像;符咒类静帧默认只生成一张未激活的 `talisman_core_reference.png`,不生成符咒特效图。空镜与怪物图继续遵守既定母版配对规则。
6. **视觉锁定包**:WORLD / SCENE / CHARACTER / CREATURE / TALISMAN / TALISMAN-VFX / MATERIAL / LIGHT / CAMERA + 排除项;`TALISMAN` 锁符纸本体,`TALISMAN-VFX` 保存使用时调用的动态规划。
7. **图片用量记录**:列出用户批准张数、实际生成张数和对应图片 ID;不得把未批准试错图计入交付。

> **动态归下游**:本环节只交付静帧设计图,不生成任何视频。巨怪开大与符咒施法的动态表现由 video creation 生成;怪物开大或符咒实际被使用时,读取各自既定设计与特效锁定词。

每份交付写明交接说明:接下来由全能创作Agent(video creation)基于本视觉设计包规划剧情、分镜与成片。符咒本体图只锁定道具外观;施法镜头实际出现时读取文字版 `TALISMAN-VFX`,不得把本体卡改造成预制特效展示图。空镜与怪物镜头仍遵守既定配对规则。遇重特效场景确需补图时回到本环节,重新展示新增图片清单并取得确认。

> 若用户尚未提供特效 Prompt,先完成不依赖图片的 `TALISMAN-VFX` 基础规划并标注“待用户 Prompt 归一化”;不要把特效参考图加入默认图片清单。核心符咒本体图及其它图片仍只有在对应清单和张数得到明确确认后才能生成。
