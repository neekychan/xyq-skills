# 像素游戏创作规划

## 核心原则

像素游戏创作的本质是：**把模糊的游戏想法，转化成一套可以直接生成、可剪辑、可审核的 8bit 像素复古游戏图片与视频资产方案。** 所有产出必须像真正的复古街机游戏画面——不是普通插画、不是高清 3D、不是马赛克滤镜。

持久引擎（因果链）：

**用户输入 → 需求理解 → 游戏主题定位 → 像素风格方案 → 资产表规划 → 图片提示词 → 分镜表 → 视频提示词 → 剪辑音效建议 → 审核返修**

每一步的产出是下一步的输入。跳过任何一步都会导致最终素材不统一或风格漂移。

## 质量测试（可证伪）

**如果生成的画面看起来像现代插画、高清 3D 或加了马赛克滤镜的普通图片，而不是一张真正可玩的复古街机游戏截图——则不通过，必须重做。**

判定标准：
- 像素颗粒是否统一大小
- 边缘是否清晰无抗锯齿
- 色板是否限制在 8-12 色
- 画面是否像横版卷轴游戏截图
- 是否有清晰的 UI、平台、敌人、道具

## 输入诊断

生产前必须明确或合理假设以下维度：

| 维度 | 说明 |
|------|------|
| 产出类型 | 单张图片 / 角色 sprite / 场景关卡 / 首帧 / 5 秒图生视频 / 15 秒完整短片 |
| 画面比例 | 16:9 横版 / 9:16 竖版 / 1:1 |
| 是否需要 UI | 血条、金币数、分数、生命数、关卡名等 |
| 是否需要视频 | 仅图片 / 5 秒图生视频 / 15 秒短片 |
| 是否有参考图 | 有则分析提取风格规律，无则主动给创意方向 |
| 提示词语言 | 中文 / 英文 / 双语 |
| 游戏类型 | 横版卷轴冒险 / 平台跳跃 / 射击 / 解谜 / 跑酷等 |
| 像素尺寸 | 16x16 / 24x24 / 32x32 / 48x48 / 64x64 / 96x96 / 320x180 / 384x216 / 640x360 |
| 色板方向 | 森林 / 城堡 / 宇宙 / 地下城 / 城市夜景 / 雪山 / 火山 |
| 风格方向 | 见路由表中的 8 个预设方向 |
| 合规敏感点 | 不生成过度恐怖、暴力或不当内容 |

自动补齐设定（用户未指定时）：
- 主角：轮廓简单、颜色鲜明、适合 sprite 的角色
- 关卡：横版卷轴 tile-based 关卡
- 敌人：1-3 个小怪，动作简单
- 道具：金币、钥匙、宝箱等
- UI：血条、金币数、分数、关卡标题
- 结尾：通关定格或进入传送门

## 强制加载 reference（硬规则）

落 prompt 前，**必须**按路由结果加载对应 references。不得跳过、不得凭记忆。

**必读（每次产出前）：**
- references/asset-spec.md —— 像素尺寸、色板、场景层级、资产命名规则
- references/prompt-templates.md —— 所有图片和视频提示词模板

**条件读取：**
- references/style-directions.md —— 无参考图时必读（8 个预设方向 + 参考图分析规则）
- references/storyboard-spec.md —— 生成视频时必读（5 秒/15 秒分镜结构 + 动作库）
- references/post-production.md —— 需要剪辑/音效/BGM 建议时必读
- references/qa-checklist.md —— 审核与返修时必读

**Hard rule：** 若最终输出包含视频提示词，则本轮必须已读过 references/storyboard-spec.md；若输出包含分镜表，则必须已读过 references/prompt-templates.md 中的视频提示词模板。

## 工作流（10 步 SOP）

### Step 1：需求理解

先判断用户要做什么，输出结构化需求摘要：

```
用户想要制作：
- 类型：
- 风格：
- 主题：
- 时长：
- 比例：
- 是否需要 UI：
- 是否需要视频：
- 是否有参考图：
```

自动补齐设定（用户未指定项填默认值）：
- 主角 / 关卡 / 敌人 / 道具 / 目标 / UI / 结尾

### Step 2：游戏主题定位

将用户想法转化为清晰的游戏设定，必须输出：
- 游戏类型
- 视觉关键词
- 主角目标
- 关卡目标
- 核心互动
- 适合的像素尺寸
- 适合的色板
- 适合的视频结构

### Step 3：像素风格方案设计

读取 `references/style-directions.md`，从 8 个预设方向中匹配或推荐。

**无参考图时**，必须主动给 3-5 个创意方向，每个方向包含：名称、主角、关卡、敌人、道具、核心玩法、视觉重点。最终推荐一个方向。

**有参考图时**，先分析参考图（像素尺寸倾向、色板倾向、角色比例、轮廓、UI 特征、场景层级、关卡结构、动作帧特征），提取可借鉴方向，但必须原创化处理——不照抄参考图。

### Step 4：资产规划

读取 `references/asset-spec.md`，按以下清单规划资产：

每个项目至少规划：
- 主角 sprite 资产
- 敌人 sprite 资产
- NPC 资产（可选）
- 道具资产
- 场景/关卡资产
- UI 资产
- 首帧资产
- 尾帧资产
- 特效资产（可选）

资产命名规则：`PX-[类型]-[序号]-[名称]`
类型代码：HERO / ENEMY / NPC / PROP / LEVEL / UI / START / END / FX

输出标准资产表（字段见 `references/asset-spec.md`）。

### Step 5：资产表规划

将 Step 4 的资产清单整理为标准资产表，每个资产行包含：资产编号、资产名称、资产类型、用途、像素尺寸建议、色板建议、图片提示词、负面提示词。

### Step 6：图片提示词生成

读取 `references/prompt-templates.md`，按资产类型选择对应模板，填入具体角色/关卡/道具设定。

媒体生成顺序（严格按序）：
1. 主角 sprite → 2. 敌人 sprite → 3. 道具 sprite → 4. 关卡/场景 → 5. UI 资产 → 6. 首帧 → 7. 尾帧

**生成图片时**，将提示词模板填入具体内容后用于图片生成。≤15s 的视频用一次生成即可拿到完整成片；只有成片超过 15 秒时，才拆成多个 ≤15s 片段分别生成，再做后处理拼接。

### Step 7：故事板/分镜表生成

读取 `references/storyboard-spec.md`，根据视频时长选择结构：

- **5 秒图生视频**：一个简单动作闭环（走路+捡金币 / 跳跃+平台 / 挥剑+击退小怪）
- **15 秒短片**：0-3s 展示关卡 → 3-7s 移动/遇敌 → 7-11s 收集/触发机关 → 11-15s 通关/定格

输出标准分镜表，每行包含：镜头编号、时长、画面、角色动作、敌人动作、道具、关卡、UI、镜头滚动、音效、用到资产、视频提示词。

### Step 8：视频提示词生成

读取 `references/prompt-templates.md` 中的视频提示词模板，为每个分镜生成视频提示词。

每个镜头的视频提示词必须包含：视频时长、画面比例、使用资产、画面描述、动作、UI 变化、镜头、风格保持、负面要求。

**5 秒视频用一次生成即可拿到完整片段。15 秒短片也用一次生成完整成片。** 上面的 beat 分镜（0-3s/3-7s/…）是同一次生成内部的时间轴描述，不等于要多次调用。

### Step 9：剪辑、音效、UI 动效建议

读取 `references/post-production.md`，输出：
- 剪辑节奏建议（硬切、像素闪白、屏幕跳帧、关卡标题卡、复古游戏边框）
- 音效建议（8bit 音效清单）
- BGM 建议（chiptune / 8bit loop）
- UI 动效建议（金币数变化、分数变化、血条闪烁、STAGE CLEAR 等）
- 屏幕效果建议（CRT 扫描线、轻微闪烁、低帧率跳帧）

### Step 10：审核与返修判断

读取 `references/qa-checklist.md`，按三类审核清单检查：
1. 像素风审核（是否真正像素风、颗粒是否统一、边缘是否清晰、有无高清 3D 污染）
2. 游戏逻辑审核（是否有横版关卡、平台/敌人/道具、UI、游戏目标、通关反馈）
3. 视频动作审核（是否像逐帧动画、低帧率感、无丝滑动画、无 3D 旋转、角色比例稳定）

不通过时按返修格式输出问题和补强句。

## 输出契约

每次执行本技能，最终必须输出以下 8 项：

| 序号 | 产出项 | 说明 |
|------|--------|------|
| A | 需求理解 | 结构化需求摘要 |
| B | 像素游戏创意方向 | 3-5 个方向 + 最终推荐 |
| C | 资产表 | 标准资产表（含提示词） |
| D | 图片提示词 | 按资产顺序的中英文提示词 |
| E | 故事板/分镜表 | 标准分镜表 |
| F | 视频提示词 | 每镜头的完整视频提示词 |
| G | 剪辑音效建议 | 剪辑节奏 + 音效 + BGM + UI 动效 |
| H | 审核清单 | 三类审核 + 返修建议（如需） |

## 静默自检（出稿前，不外显）

交付前内部检查以下各项，弱项直接重写：

**风格一致性：**
- [ ] 所有提示词是否包含核心风格关键词
- [ ] 色板是否限制在 8-12 色
- [ ] 像素尺寸规格是否合理匹配资产类型
- [ ] 是否有清晰的前景/中景/背景/UI 层级

**资产完整性：**
- [ ] 资产表是否覆盖所有需要的资产类型
- [ ] 资产命名是否遵循 PX-[类型]-[序号]-[名称] 规则
- [ ] 每个资产是否都有图片提示词和负面提示词

**视频逻辑：**
- [ ] 分镜表是否遵循横版卷轴从左向右推进
- [ ] 每个镜头是否只做 1-2 个动作
- [ ] 动作是否来自动作库（无复杂格斗/真实跑酷/3D 旋转）
- [ ] 是否有明确结尾和通关反馈
- [ ] 视频提示词是否包含完整的 9 个字段

**提示词质量：**
- [ ] 中文和英文提示词是否都包含核心风格关键词
- [ ] 负面提示词是否覆盖高清 3D/写实/普通插画/马赛克滤镜等常见问题
- [ ] 是否使用了正向措辞而非堆砌否定式约束

**审核闭环：**
- [ ] 是否输出了完整的审核清单
- [ ] 不通过项是否有明确的返修方向和补强句

**视频时长：**
- [ ] ≤15s 的成片是否标注为一次生成完整片段（而非分段拼接）
- [ ] 若 >15s 是否已拆成多个 ≤15s 片段各自生成再拼接
