# 统一项目制作单：Project_Brief.md

本文件把原流程中的剧本提取、内容分析和制作规格合并为一份权威产物 `Project_Brief.md`。剧情短片灵感参考也写入同一文件，不再生成 `script_extraction.md`、`content_analysis.md` 或 `Final_Video_Spec.md`。

合并只改变文件组织和开场流程，不删减原有信息，也不改变后续元素资产、故事板、镜头视频、音频层和最终剪辑阶段。

## 一、输入与起草

### 用户已上传剧本

忠实解析剧本，只做技术性整理、拆分和字段化。严禁虚构情节或改写台词；发现逻辑冲突时写入待确认项。

### 用户未上传剧本

最多使用两轮卡片收集信息：

第一轮收集视频主题/故事核心、视频类型、主要角色数量与关系；第二轮收集视觉风格与基调、目标时长、画幅、特殊要求和参考作品。收到回复后起草完整剧本，包含场景划分、角色对话和动作描述。

每轮最多询问 3 个真正会改变制作方案的问题。

## 二、证据优先级与字段状态

字段冲突时按以下优先级处理：

```text
用户最新确认 > 用户原始输入中的明确要求 > 已确认 Project_Brief.md > 直接解析 > 合理推断 > 默认建议
```

重要字段使用以下状态：`confirmed`、`explicit`、`parsed`、`inferred`、`recommended`、`missing`、`conflict`。

推断和建议不得覆盖明确要求。冲突必须保留双方内容并进入待确认项。

## 三、旁白与画面角色分离

在 Project Brief 中统一定义实体：

| 字段 | 说明 |
|---|---|
| `entity_id` | 唯一 ID |
| `source_name` | 剧本中的名称 |
| `entity_type` | character / narrator / crowd / sound_only / text |
| `visual_presence` | on_screen / off_screen / conditional |
| `audio_presence` | dialogue / narration / group_vocal / vocal_sfx / none |
| `appears_in_scenes` | 场景级出现范围 |
| `visual_asset_required` | 是否需要视觉资产 |
| `voice_asset_required` | 是否需要音色或音频资产 |

旁白功能不自动产生画面出场。剧本没有明确描述旁白本人出镜时，必须设置：

```text
entity_type=narrator
visual_presence=off_screen
audio_presence=narration
visual_asset_required=false
voice_asset_required=true
```

`off_screen` 旁白不得写入角色外貌表、画面角色表或 ImageList，不生成角色参考图，不要求视频角色口型；只进入 voice reference、storyboard 的 narration/audio_entities 和后期 audio_layers。

同一人物既在画面中扮演角色又承担旁白时，必须分别记录其画面状态与旁白功能。只有明确出镜的场景才能将其列为可见角色。

## 四、内容分析

在同一 `Project_Brief.md` 中完成以下判断；详细判断规则读取 `shortfilm-content-analysis-rules.md`：

- 内容结构：叙事类、非叙事类、混合型或待确认；
- 内容目的：娱乐、信息、教育、表达、商业传播、记录等；
- 内容载体：独立短片、连续短剧、单元短剧、电影/长片、MV、广告/品牌片、纪录片、Vlog 或其他；
- 呈现形式：剧情演绎、旁白/画外音、视觉叙事、纪实跟拍、氛围 Montage、图文/动画可视化、表演等；
- 体裁、题材、核心情感、调性和最终内容类型名称。

“短”只是时长，不自动等于短剧；“有音乐”不自动等于 MV；“有产品”不自动等于广告。只输出简洁结论和依据，不重复整份剧本。

## 五、剧情短片灵感参考

基于同一份 Project Brief 的剧本与内容分析，使用 `pippit_omni_search` 搜索相关灵感参考。优先使用 `Type=inspiration`，必要时补充 `Type=hotspot` 或 `Type=text`。

至少提炼 2 条可落地手法，并写入 Project Brief：来源、原文片段、可复用手法、应用到哪个角色/场景/镜头/叙事节奏。展示灵感结果并等待用户确认是否采用，确认后继续完善同一份 Project Brief 的制作规格部分。

## 六、制作规格

制作规格必须覆盖原 `Final_Video_Spec.md` 的信息范围：

### 6.1 项目基本信息

标题、一句话项目描述、制作目标、内容分析结论、目标受众、发布平台或使用场景、地区/文化背景或时代设定、项目版本。

### 6.2 基础交付参数

目标时长及允许误差、画幅比例、横屏/竖屏/方形、分辨率、帧率、输出格式、对白语言、旁白语言、字幕语言和交付变体。

### 6.3 视觉媒介与整体方向

真人、二维动画、三维动画、定格动画、动态漫画、混合媒介或待确认；整体风格标签、时代感、地域感、真实度、画面关键词和禁止方向。

### 6.4 摄影、成像与色彩

分别记录 `imaging_texture`、`color_palette`、`lighting`、`composition`、`camera_language` 和 `editing_rhythm`。禁止压缩成单一“视觉风格”字符串。

### 6.5 参考作品映射

每个参考作品对应具体借鉴属性：色彩、光线、构图、节奏、表演、时代感或声音。未说明借鉴点时保留作品名，并将借鉴属性标记为 `missing`。

### 6.6 叙事实现规格

记录叙事结构摘要、主/辅呈现方式、对白/旁白/视觉动作/字幕/音乐等信息通道、各段目标时长、必须保留内容，以及是否允许改写、压缩、合并或新增。

### 6.7 角色与旁白规格

画面角色逐个记录名称、身份、年龄段、外貌、体型、发型、标志特征、服装、配饰、道具、表情、动作、表演风格、对白语言、音色、语速、情绪、首次出场、连续性和禁止变化项。

旁白单独记录 narrator_id、是否出镜、语言、音色、年龄感、语速、情绪和出现段落。旁白不得混入画面角色制作规格。

### 6.8 场景制作规格

逐场景记录场景 ID、时间、地点、室内/室外、日内时间、季节天气、画面角色、关键动作、必须保留信息、布景、道具、视觉要求、灯光、镜头策略、对白/旁白/环境声/音效/音乐和连续性。

场景表的“画面角色”列不得包含 `off_screen` 旁白；旁白只写入声音提示。

### 6.9 道具、资产与连续性

记录角色资产、服装资产、道具资产、场景资产、交通工具或动物、图形/字幕/品牌资产，以及需要跨镜头保持一致的颜色、形状、位置、破损和状态变化。

### 6.10 声音设计

分开记录 `dialogue`、`narration`、`ambience`、`sound_effects`、`music`、`silence` 和 `mixing`。输入未指定配乐时，`music` 填 `null`，不得根据视觉参考自动指定音乐。

### 6.11 管线、约束与验收

记录文本/脚本、角色或场景图像生成、视频生成、旁白与角色语音、音乐与音效、剪辑、调色、字幕、后期、质量检查、最终导出、必须保留项、禁止项和技术/内容验收标准。

## 八、统一确认门

输出 `Project_Brief.md` 后暂停并让用户确认：

```json
{
  "title": "确认短片剧情与制作规格",
  "questions": [
    {
      "id": "project_brief_status",
      "title": "故事理解、内容定位、角色与旁白定义、参考手法和制作规格是否确认？",
      "type": "radio",
      "options": [
        {"label": "✅ 确认，继续元素资产", "value": "approved", "selected": true},
        {"label": "✏️ 需要修改", "value": "revise"}
      ]
    }
  ]
}
```

收到明确确认前不得进入元素资产阶段。用户要求修改时，更新同一份 `Project_Brief.md`，提高 `project_revision`，分析影响范围并重新确认，不得恢复生成三个旧产物。
