# 游戏化格斗设计指南

适用于街机横版格斗、第三人称 ACT、Boss 战、像素格斗、等距视角、游戏 UI 与 KO 结算。先确定一种游戏镜头和一套规则反馈，再设计动作。

## 一、子类型路由

| 子类型 | 视角 | 核心观感 | UI 策略 |
|--------|------|----------|---------|
| 2D 街机格斗 | 固定侧视 | 距离、攻防、连击、必杀和 KO | 可用双血条、能量条、回合或 KO |
| 2.5D 竞技场 | 侧视为主、轻微景深 | 3D 场景与横向对战规则 | 简洁固定 UI |
| 第三人称 ACT | 侧后跟拍为基础，处决/大招切特写或环绕 | 闪避、格挡、连招、处决和推进 | 可无 UI，或只保留少量技能提示 |
| Boss 战 | 主角侧后方或远距跟随 | 读招、躲避、弱点窗口、阶段变化 | Boss 血条可选，变化绑定真实命中 |
| 像素格斗 | 固定侧视或横版卷轴 | 像素轮廓、有限帧、夸张特效 | 像素字体和条形 UI，文字极少 |
| 等距或俯视动作 | 固定高角度 | 空间路线、群体控制、技能范围 | 技能范围和目标状态清楚 |
| 游戏电影化片段 | 第三人称动态跟随 | 保留玩法逻辑，同时增强电影镜头 | 默认隐藏 UI，避免像录屏杂乱 |

真第一人称游戏需追加 `fight-pov.md`，并保持主观视角到底。

## 二、游戏规则先于特效

Prompt 开头固定：

1. 镜头：固定侧视、第三人称肩后、等距或真第一人称。
2. 场地：边界、平台、高低差、障碍物和可破坏物。
3. 角色定位：速度型、力量型、反击型、远近混合或 Boss。
4. 核心机制：格挡反击、闪避窗口、破防、连击、空中追击、处决等，只选 1 至 2 项。
5. UI：是否显示、显示哪些元素、颜色和位置。
6. 结算：击倒、KO、Boss 阶段结束或悬念。

视觉特效要服务命中判定、破防、技能范围和状态变化。

## 三、UI 状态同步

用户明确需要游戏 UI 时遵循：

- 双方血条颜色和屏幕位置全程固定。
- 血量只在可见命中后下降，格挡成功时不应大幅下降。
- 能量条在技能释放后减少，不能随机闪动或重置。
- 连击数随连续命中增加，中断后消失或归零。
- KO、胜利或阶段结算只在终结动作和受击结果之后出现。
- 限制文字为用户指定的短标签，保持无随机乱码和无额外菜单。
- 用户没有要求 UI 时默认隐藏，保留游戏相机和动作逻辑即可。

## 四、不同视角的动作设计

### 固定侧视

- 角色始终面向对手，左右位置交换需要清楚跳跃或穿越动作。
- 攻击轨迹和受击框保持在同一平面，避免无原因向镜头深处移动。
- 背景可有视差，但不改变竞技场边界。
- 必杀技可短暂改变构图，结束后回到固定侧视。

### 第三人称 ACT

- 战斗循环期以主角侧后方跟拍为基础机位，敌人保持在可读范围；禁止写"镜头始终位于/锁定侧后方"——锁死视角会压掉关键节点的演出镜头。
- 闪避、转身和追击驱动相机；目标切换需要角色视线、身体转向和镜头跟转共同完成。
- 处决、大招与破防窗口切特写或短弧环绕（实机游戏在这些节点本就切电影化演出镜头），演出结束回到侧后跟拍；普通交换中不乱切。
- 处决动作只安排一次，完整展示命中与敌人落点。

### Boss 战

- 先展示 Boss 的读招信号，再展示主角应对。
- 大范围攻击给出清楚边界和躲避路线。
- 破防窗口由 Boss 招式落空、护盾破裂或部位受损造成。
- 阶段变化最多一次，变化前后保留 Boss 身份锚点。

## 五、像素与极简游戏风格

- 固定像素尺寸感、有限色板、清楚轮廓和阶梯边缘。
- 动作使用少量强关键帧、拖影色块和屏幕闪色。
- 角色身份依靠固定颜色、头部轮廓和武器，不堆细小服饰。
- 粒子也保持像素块状，禁止突然变成光滑 3D 粒子。

## 六、Prompt 示例

### 示例 A：2D 赛璐璐街机格斗

```text
2D 赛璐璐街机格斗画面，固定侧视镜头，干净线稿、平涂色块和两级硬边阴影。主体A始终位于画面左侧起步，穿蓝白短外套，使用快速拳脚和闪避反击；主体B始终位于右侧起步，穿黑红护甲，使用沉重挥拳和地面震击。竞技场是雨夜高架桥下，战斗平面和左右边界固定。

屏幕顶部只保留两条稳定血条，左侧蓝色对应主体A，右侧红色对应主体B，无其他文字。主体B踏前用重拳压迫，主体A后滑避开，红方攻击落空后地面溅起像素化水花；主体A立刻前冲完成两次快速命中，蓝白拖影短促出现，主体B血条在可见接触后小幅下降。主体B抬臂格挡第三击并反向肩撞，主体A向左滑退，蓝方血条只下降一次。主体A抓住主体B收招停顿，跃起旋踢命中头盔侧面；接触出现极短黑白冲击帧和像素火花，主体B被击退倒地。角色落地并恢复标准比例后，右侧血条归零，画面中央才出现清楚的 `KO`，不生成其他文字。

<街机拳脚音效><格挡声><像素火花><KO短音>
```

### 示例 B：第三人称巨型 Boss 战

```text
高品质第三人称动作游戏电影化画面，无 UI。镜头以主体A侧后方跟拍为基础机位，保持主体A和巨型主体B同时可见。主体A是黑色轻甲剑士，右手持一柄长度固定的银色长剑，以闪避和反击为主；主体B是四臂岩石守卫，胸口有唯一的橙色裂纹核心，四条手臂和石质轮廓全程固定。

圆形遗迹竞技场，地面有同心裂纹和四根断柱。主体B抬起上方两臂，橙色核心先明亮，随后双拳砸向主体A当前位置；主体A向画面右侧翻滚，镜头沿同一方向跟随，拳头砸地形成清楚的圆形碎石范围。主体A从翻滚末端起身，沿Boss右侧冲近，长剑连续两次削击同一条石臂，石屑飞落但手臂没有断裂。主体B下方手臂横扫，主体A用剑格挡仍被推退，镜头短暂跟随受力方向。主体B核心在收招后暴露，主体A踏上断柱残块跃起，镜头切至核心特写，双手下劈命中橙色裂纹；核心局部破裂、Boss四臂向外失衡，镜头拉到广角展示主体B单膝跪地。结尾主体A落地举剑警戒，Boss核心仍有微弱橙光，保留下一阶段悬念。

<石拳砸地><长剑削石><格挡重响><核心裂开><竞技场回声>
```

## 七、单段策略

- 固定侧视：3 至 5 个明确攻防节拍，位置交换最多一次。
- 第三人称 ACT：一次接近、一次防守转换、一次终结；终结演出可切一次特写。
- Boss 战：一轮读招、一次躲避、一个弱点窗口和一次结果。
- 单片最多一次阶段变化、一次处决或一次 KO。
- UI、角色、动作、特效同时复杂时，减少 UI 元素，保持命中状态同步。

## 八、专用尾注

```text
保持选定游戏视角、竞技场边界、角色朝向和目标关系稳定，不无原因切换为其他游戏镜头。
所有 UI 状态只在对应动作发生后变化，血条、能量条、连击和 KO 不提前、不随机跳动。
不生成额外菜单、乱码、随机按钮、主播边框和水印。
```
