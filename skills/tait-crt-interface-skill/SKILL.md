# tait-crt-interface-skill

## Mode Policy

使用一条共享内容管线。解析可选命名风格预设，确定色卡，确定比例，检视一次，锚定主体清单，构建一份抽象蓝图，应用匹配的预设配方或选择一组普通变体配方，编译一条内部提示词，生成一次，完成检视，返回一张图片。

## Two-Stage Intake Gate

在任何图片生成调用之前，从当前请求和保留的对话状态中解析 `palette` 和 `aspect_ratio`。选择、展示、推导或验证颜色时，读取 `references/palettes.md`。

1. 如果 `palette` 缺失，使用 `references/palettes.md` 中的紧凑文本列表，请用户回复一个色卡名称或「如图」，然后停止本轮。不要在同一轮中询问比例，不要生成。
2. 色卡已知后，如果 `aspect_ratio` 缺失，仅询问：`请选择生成比例：3:4 / 4:3 / 9:16 / 16:9，也可以直接输入其他比例。` 然后停止本轮，不要生成。
3. 仅当两个字段都已知时才立即生成。如果初始调用提供了一个字段，跳过该问题；如果提供了两者，跳过整个收集过程。不要重新确认有效选择。

识别 `经典`, `粉黛`, `极客01`, `极客02`, `复古01`, `复古02`, `游戏01`, `游戏02`, 和 `如图` 为色卡值。对于 `如图`，从上传参考图的视觉氛围、情绪基调和情感色调中推导一组连贯的 2-5 色色卡；使用不超过五种色相，无需再进行审美问卷。如果没有可用的图片，请求提供缺失图片作为唯一的阻塞性例外。

## Optional Style Preset Router

仅当用户明确选择了一个精确值——`街头怪诞`、`巨像符号` 或 `冷面几何`——作为当前生成的请求风格时，才激活 `style_preset`，例如「用街头怪诞生成」或将其与色卡和比例一起列出。被引用、否定、比较、文档化或仅被提及的名称不会激活或持续。一旦为某次生成明确选择，在色卡/比例收集轮次中保留它，并在构建蓝图前读取 `references/style-presets.md`。将其固定风格块与上传主体自身的清单、身份锚点、动作和物体合并；不要复制示例道具或编造缺失特征来模仿预设示例。

预设仅锁定其列出的主体塑造轴。从普通变体引擎中选择所有剩余的界面/布局轴，使结果仍然适配参考图、主体数量和所选比例。除非裁切或覆盖范围必须扩展以保持每个清单成员和交互，否则保持锁定的风格轴不变。如果当前生成未明确选择预设，不要提及、提供、推荐或询问预设，不要隐式加载一个，继续使用原始抽象蓝图和普通变体引擎。不要在一张图中混合预设；如果用户明确用另一个精确名称替换保留的预设，使用最新的显式名称。

## Non-Negotiable Invariants

- 以选定比例和工具原生分辨率生成恰好一张最终图片。不要制作低分辨率预览、请求特定低分辨率、缩放、增强、生成变体、自动重试或暴露提示词。
- 仅将上传图视为少量身份锚点的来源，绝不作为抠图蒙版、描摹模板、轮廓图、细节清单或自动像素化的来源。使独立创作的位图主体成为第一视觉优先级：通过少量锚点集保持识别度，然后重新设计其他一切。漫画、抽象、成人编辑个性和复古插画品质优先于字面保真度。不要保留匹配源的服装结构、装饰图案、珠宝清单、褶皱、纹理、面部建模或局部轮廓，除非某一项是明确的身份锚点。在多主体参考中，将每个锚定人物保持为独立身份；不要遗漏、融合身体或面部、交换身份或在人物间转移特征。
- 在每个窗口后面的底色场上直接绘制恰好一个完整主壁纸构图——一个人或一组锚定人物。其轮廓覆盖至少 50% 画布；目标 60%-80%。不要重复它。一个组保持为一个构图，同时保留每个锚定成员、其空间顺序和交互。包含 1-3 个特征提取窗口，仅展示独特的局部元素——不是另一个完整主体或组。
- 保持 20%-30% 连通的开放区域，同时使用 3-6 个前景窗口，具有明显的尺寸层次、交错重叠、多象限平衡、一个全宽菜单、一个打开的法语下拉菜单和恰好一个光标。
- 仅使用确定的色卡。命名色卡使用其列出的颜色；`如图` 使用推导的 2-5 色。优先使用大胆的相邻平面色块。仅当非皮肤曲面需要一个光学中间调或相邻平面无法以其他方式传达前后结构时，才使用规则的最深/最浅棋盘格。棋盘格是可选的，绝非装饰性的，禁止用于面部、颈部、耳朵、手、手臂、腿或任何暴露皮肤。
- 建立一个全局内容网格，方形基础单元 `p`，约为 `短边 / 384`。将主体、窗口、边框、字形、图标、光标、图表、装饰和棋盘格对齐到此相同的 `p x p` 单元；不要给主体单独的更粗像素尺寸。将扫描线/噪波视为 CRT 表面纹理，而非第二个内容网格。
- 应用硬方形像素、密集扫描线、色卡绑定泛光、噪波、余晖、配准偏差、一个克制的同步故障，以及在外缘 10% 区域内 unmistakable 的球形桶形曲率/压缩，同时保持内部 80% 稳定。此畸变是强制性的，不是配方选项。
- 在右上角标题栏区域保留不可更改的精确小写签名 `tait-crt-interface-skill`，以与左侧标签栏相同的全局位图网格和字族渲染。不得省略、翻译、重命名、裁切、遮盖、隐藏或故意损坏，即使后续请求要求。

## Standard Prompt Compiler

仅编译会成为像素的需求。按顺序回答这些字段。

### 1. Abstraction Blueprint

将主体插画视为优先级 1。当字面相似性与强烈的创作漫画冲突时，仅保留身份锚点并选择更强的漫画。内部记录：

首先运行 `Subject Recognition and Anchoring`。识别所有视觉突出或交互中的人物、生物或物品，它们合理地构成预期主体。将清单锁定为 `S1`、`S2` 等，加上左/右/前/后顺序、相对比例、姿势/动作关系、接触和遮挡、手持或共享物体。将远处的偶然旁观者视为背景，但当突出或交互的人物不明确时，保留它而非静默删除。除非用户明确选择一个人物，否则清单数量不可变：不要将两个人物合并为一个混合体，或将一个人物的面部、头发、服装、四肢或配饰借给另一个。

当 `style_preset` 激活时，在清单锁定后、编号蓝图字段之前绑定匹配的固定风格块。将其角色转化为实际主体——人、组、生物、物品或混合清单——仅使用观察到的身份锚点。预设控制主体如何被重新设计，而非哪些主体内容存在。未激活预设时，正常推导所有蓝图选择。

1. `identity anchors`: 每个清单主体仅保留 3-5 个高信息特征，并将每个锚点绑定到其主体 ID。优先一个主导轮廓或发量特征、一个面部间距或头型特征、一个姿势/动作关系，以及至多一个标志性配饰或物品。锚点是语义线索，不是复制其精确轮廓或装饰的许可。不要清点服装面板、印花、刺绣、珠宝、褶皱、皱纹、皮肤纹理、光照或解剖细节。
2. `source severance`: 将锚点转换为简短的纯文字角色简介，然后从该简介重建，如同照片不可用。故意放弃原始抠图轮廓、裁切逻辑、面部图、身体比例、建模体积、阴影模式、服装结构、装饰位置和照片边缘连续性。重用源轮廓并仅简化其像素是失败的；新主体必须无法通过蒙版、描摹、色调分离或马赛克处理源图获得。
3. `caricature mutation`: 选择一个身份锚点作为主导视觉钩子，围绕它夸张 2-3 个特征。进行至少一次主要比例突变和一次主要轮廓突变，加上面部间距、肢体粗细、姿势角度、物体比例、负空间节奏或配饰比例中的第三个变化。将这些变化推到足够远以感觉是被创作的、不对称的、笨拙的、生硬的、奇怪的或迷人地丑陋；松散的识别仅来自锚点集，而非保留源解剖结构。
4. `mass plan`: 从 5-9 个平面互锁色块重绘每个主体，优先 5-7 个，具有一个明确的主导色块、一个对色块和几个支撑块。将头部和面部简化为几个阶梯簇的粗糙面具；将头发简化为一到两个色块，每件服装简化为一到三个宽平面，四肢简化为钝结构形状。主要用对比平面色、剪切、负空间、直边刻面和硬轮廓断裂替换体积。将棋盘格保留给不可缺少的非皮肤曲面或平面间模糊接触。删除每个非锚点印花、装饰、接缝、褶皱、发丝、毛孔、皱纹、高光、指甲、微妙表情和装饰性微特征，而非将其转化为像素。
5. `authored style lock`: 将主体渲染为成人 1980 年代位图编辑漫画或地下终端插画——棱角分明、工业感、图形化、略带怪诞、明显从零设计。偏好不均匀的视觉重量、有目的的不对称、压缩解剖、突兀的阶梯轮廓、面具式面部构造、富有表现力的负空间、低面数、直线段、倒角、楔形、矩形和钝多边形。将曲线视为高风险细节通道：默认无曲线；当主体变得不可读时，仅允许一两个由几条直线段构建的大阶梯弧。禁止流畅轮廓、重复圆角特征、写实像素肖像、精磨游戏精灵解剖、动漫/Q版比例、可爱吉祥物语言、圆润友好的儿童读物形状、装饰性时尚插画、干净的矢量卡通风线条和通用剪贴画角色设计。
6. `hand topology`: 为每只可见的手，在简化之前绑定左/右归属、腕部连接、手掌朝向、接触或遮挡以及任何清晰可见的手指数。使用可读的块状手掌和符合解剖学的手指分组。如果网格无法支持独立手指，使用有意的手套或分组轮廓，无假指尖；不要创建多余或缺失的手指、融合手、脱离的手掌、反转关节、不可能的腕部连接或手物穿透。
7. `pixel topology`: 为整个界面选择一个全局方形基础单元 `p`，约为 `短边 / 384`。仅将约 `30 x 30` 规划网格用作主体的轮廓/特征复杂度预算，然后将每个主体形状构建为 UI 和文本使用的相同 `p x p` 单元的完整整数对齐排列。用水平/垂直排列、有意的阶梯对角线、倒角、楔形和低边多边形构造。尽可能使用无曲线几何配方；任何不可缺少的曲线成为由 3-6 条直线段组装的一个粗糙阶梯弧，而非平滑或连续变化轮廓。不允许半单元、拉伸或旋转单元、子单元碎片、偏移行、破损棋盘图案、意外裂缝、孤立碎片、混合像素尺寸或平滑过渡像素。不要渲染或调整中间图像尺寸。

在编译提示词前，运行八项拒绝测试一次。`清单完整性`：每个锚定主体保持独立、正确排序、通过自身锚点可识别。`手部完整性`：每条可见手臂到达正确的手腕和手，每个描绘的手指分组合理。`轮廓分歧`：重建的主体不得与照片的连续外轮廓、比例和姿势紧密对齐。`细节截断`：除非是声明的签名锚点，否则不得保留源服装结构、图案、装饰、褶皱、珠宝清单、面部建模或局部轮廓。`滤镜移除`：在心理上移除 UI 和 CRT 纹理后，主体仍须读作独立创作的平面漫画，绝非像素化下的照片。`风格独立`：主体须读作棱角分明的成人位图编辑插画，而非写实像素肖像、精磨游戏精灵、动漫/Q版艺术、可爱吉祥物艺术、儿童读物插画或通用剪贴画。`皮肤洁净`：每个面部和暴露皮肤区域仅由实心色卡平面构建，无棋盘格、点画、影线或斑点纹理。`曲线节制`：几何以直线、刻面和低边为主；无配方包含流畅轮廓或小可变弧链，任何不可缺少的阶梯弧都是大的、稀疏的和结构上必要的。如果测试失败，通过删除保真度、棋盘纹理或曲线并增加平面几何重设计来修正蓝图一次，而非添加纹理、细节或另一个生成循环。

分配宽阔的色调平面，使用大胆的实色色卡碰撞。仅在最小必要的非皮肤区域添加规则的 50% 最深/最浅棋盘格：需要光学中间调的曲面或前后关系否则不可读的相邻平面。零棋盘格是有效的。不要将其放在面部或暴露皮肤上，不要将其用作全面纹理。不要依赖写实渲染、抠图、像素滤镜、自动像素化、模糊、抗锯齿、渐变过渡、平滑曲线或照片边缘连续性。

### 2. Attention and Interface Geometry

- 使用配方将单个壁纸构图——一个人或一组锚定人物——偏离中心放置；其最终轮廓在可能时占据 60%-80%，包括窗口遮挡后不低于 50%。
- 给窗口明显的大/中/小层级；主导约 1.8 倍中等，最小的不超过中等的一半。将中心分布在至少两个象限，优先三个，不要在一侧堆叠三个相似窗口。
- 将选定窗口重叠 5%-20%，穿过主体边界，保持整体视觉质量平衡。不要框住主体或将其放在肖像/位图查看器窗口中。
- 使用方形边框、标题栏、关闭框、滚动轨道、原始表格/图表、简短法文位图标签、顶部菜单/下拉菜单和一个光标。
- 包含 1-3 个放大镜式特征提取窗口。隔离可识别的局部元素，将每个显示为紧密裁切。通过为裁切分配更多共享网格单元来放大，不要将其单元扩大到 `p` 之外。多个提取时，外部尺寸和纵横比都不同；没有两个共享相同尺寸或比例。

### 3. Color and Pixel Construction

- 仅应用确定的色卡。使用其最浅和最深颜色作为场/墨对比和棋盘格端点；使用其余颜色作为有意的平面色块、标题栏、面板、图标或信号装饰。选定的极性配方决定主导场是浅色、深色还是局部分割；没有极性是通用默认值。
- 不允许色卡之外的颜色、alpha、中间计算灰、渐变、半透明泛光或抗锯齿。优先使用独立的实色卡平面；当真正需要光学半调时，使用一个紧凑的规则最深/最浅棋盘格区域。保持每个面部和暴露皮肤区域实心且无棋盘格。不要将棋盘格散布为噪波、装饰性使用或覆盖人物。
- 从相同的全局方形单元和粗直线段、阶梯对角线、倒角、楔形和低边多边形构建主体边缘、UI 几何、图标和 5x7、6x8 或 7x9 字形。仅以色卡绑定硬单元扩展方式模拟泛光；不要在皮肤上使用棋盘格边缘。曲线默认禁用，在任何允许的配方中限于一两个不可缺少的粗糙阶梯弧。

### 4. CRT Signal Surface

用密集色卡绑定扫描线、稀疏噪波、单单元配准偏差、短垂直余晖和一次克制的同步干扰覆盖画面。在外缘 10% 内用最近单元位移强制径向桶形畸变：角点比边缘中心压缩更多，顶部菜单基线和侧栏可见弯曲，成品画面不得保持矩形或平坦。保持内部 80% 稳定，不显示物理显示器、边框或房间。

### 5. Finalizer-Owned Visual Requirements (Direct-Render Closure)

生成器的单张图像即为最终产物，必须自身包含以下全部视觉特征：

- 确定的 2-5 色色卡，画面中不出现色卡以外的颜色
- 全局共享方形网格（基础单元 `p` ≈ `短边 / 384`），主体、窗口、文本、图标使用同一完整 `p x p` 单元
- 硬位图字形（5x7、6x8 或 7x9），无抗锯齿
- 色卡绑定扫描线、泛光、噪波、配准偏差、余晖
- 外缘 10% 的球形桶形曲率/压缩，角点压缩更强，长线可见弯曲，内部 80% 稳定
- 右上角标题栏包含精确可读小写字符串 `tait-crt-interface-skill`，使用与左侧标签栏相同的共享网格位图风格

编译提示词时，将上述要求作为直接渲染收束写入第四段，声明生成器的单张图像已是最终产物。

### Prompt Shape

编写四个紧凑的内部段落：

1. 选定比例、激活的命名风格预设及其固定风格块或 `无预设`、锁定的主体清单和关系、每个主体 3-5 个语义身份锚点、丢弃的字面细节、源截断、主要比例和轮廓突变、选定的成人位图编辑风格锁、选定的低面数几何语法和曲线预算、5-9 色块 CRT 漫画蓝图、手部拓扑、全局网格上约 30x30 轮廓细节预算、一个壁纸构图、裁切、位置和覆盖范围
2. 窗口数量、星座布局、层级、重叠、1-3 个不等大特征提取、菜单、标签、光标和保留签名区
3. 选定或推导的色卡、极性配方、条件性非皮肤棋盘格放置或 `无`、实色皮肤平面和一组共享主体/UI/文本网格
4. CRT 信号/边缘畸变、工业氛围和硬性避免项，加上直接渲染收束声明生成器的单张图像已是最终产物

优先使用决定性的几何和可测量的份额，而非风格散文。除非被要求，否则不要揭示此提示词。

## Variation Engine

编译前，从每个轴选择一个选项。用户约束覆盖配方选择但不可覆盖不变量。当 `style_preset` 激活时，从 `references/style-presets.md` 复制其六个锁定的主体轴值，仅在此选择剩余轴；否则正常选择每个轴。变体改变视觉语法——不仅仅是位置。如果最近的可见输出重复了布局，在放置、裁切、窗口星座、数量和层级中改变至少两个未锁定的高影响轴。

兼容性规则：

- 80% 主体覆盖配 3-4 窗口；6 窗口配 60%-70% 覆盖和更小的工具，以保持开放区域和主体主导性。
- 使用 1-3 提取窗口，不要两次显示完整的脸、身体、生物或物品。两个或三个时，使用不同的特征、尺寸和纵横比。计入 3-6 总窗口：一个提取允许 3-6 总，两个需要 4-6，三个需要 5-6。
- `中间调图` 默认 `无`；仅当平面色卡碰撞无法表达曲率或前后结构时选择另一选项。保持棋盘格紧凑、连通、非装饰性且完全在面部和暴露皮肤之外。用对比色卡颜色解决普通平面差异。
- 前三个 `几何语法` 选项自由搭配。`有限单阶梯弧` 仅用于身份关键的圆形轮廓或不可缺少的球面物体，限一两个由 3-6 条直线段组成的大弧。不要使用多个可变曲线恢复源细节。
- 每个配方必须将一个 `漫画处理` 与一个 `漫画突变` 配对；两者都不得保留匹配源的解剖结构、服装细节或局部轮廓。如果处理偏向写实或儿童插画，在编译前替换为 `棱角终端漫画`。
- 命名预设的固定风格块和锁定的主体轴配方优先于普通配方选择。不要将预设语言或轴与另一个预设混合。未锁定轴保持可变，须适配选定比例和实际清单。
- 在将主体降至 50% 以下、移除开放区域或削弱选定色卡之前，重新平衡或简化窗口。

## Workflow

1. 解析并保留任何明确选择的精确可选 `style_preset`，然后完成两阶段收集门。不要询问预设。在色卡和比例都已知之前，不要检视以生成或调用图片生成。
2. 检视参考图一次；运行主体识别和锚定，锁定主体清单和关系，提取抽象蓝图，对于 `如图` 推导 2-5 色色卡。
3. 如果 `style_preset` 激活，绑定其固定风格块和锁定的六轴主体配方，然后选择剩余轴一次。否则选择一组完整的普通配方。不要讨论替代方案或反复默认同一布局。
4. 预检一次：确认锁定的主体数量和关系、每个主体的身份绑定无遗漏或混合人物、合理的手部归属/腕/掌/手指拓扑、源截断、每个主体仅 3-5 个语义身份锚点、无复制的服装/装饰/褶皱/局部轮廓细节、一次主要比例突变、一次主要轮廓突变、至少一个额外结构变化、通过全部八项拒绝测试的 5-9 色块成人位图编辑漫画、全局网格上约 30x30 轮廓细节预算、完整的方形整数对齐全局单元无破损拓扑或平滑子单元过渡、选定低面数几何语法且曲线禁用或紧密预算、实心无棋盘格面部和暴露皮肤、棋盘格设为 `无` 或一个合理的紧凑非皮肤结构区域、一个无边框壁纸构图、60%-80% 目标覆盖、1-3 不等大特征提取、选定比例/色卡、清晰的右上角签名区，以及无写实/滤镜/描摹/儿童插画语言。
5. 编译提示词一次，将直接渲染收束写入第四段，以原生分辨率调用图片生成能力恰好一次。
6. 生成后，将图片视为最终产物。不要调用依赖工具、探测或安装包、运行任何脚本、创建中间图像或发起第二次生成/编辑。
7. 对照质量门检视一次。不要自动重新生成。仅返回原始生成图片。

## Quality Gate

- 两个收集字段在生成前已确定；画布匹配选定比例，最终色卡匹配命名或推导选择。
- 如果提供了精确风格预设，编译的蓝图包含其固定风格块和所有六个锁定的主体轴值，同时其余轴适配实际参考和比例。如果未提供，未提及或隐式应用预设，使用普通蓝图/变体引擎路径。
- 优先级 1 在界面打磨前通过：主体立即可读为独立创作的成人 1980 年代位图编辑漫画——棱角分明、图形化、不对称、个性丰富，可选地奇怪、有趣、笨拙、怪诞或迷人地丑陋。每个清单成员仅保留 3-5 个语义身份锚点；一次主要比例突变、一次主要轮廓突变和至少一个额外结构变化清晰可见。5-9 个大色块，而非复制的局部细节，承载识别度。无非锚点服装结构、印花、装饰、珠宝清单、褶皱、面部建模或照片轮廓保留。其轮廓无法紧密叠加在源上，移除 UI/CRT 纹理不能揭示写实像素肖像、描摹或滤镜照片、精磨游戏精灵解剖、动漫/Q版艺术、可爱吉祥物艺术、儿童读物插画或通用剪贴画。
- 锁定清单完整：每个突出或交互的源主体作为独立人物出现一次在单个壁纸构图中，具有正确的空间顺序、比例关系、交互和主体绑定特征。无人物被遗漏、融合、交换或转化为混合体。每只可见的手属于正确的手臂，通过合理的腕和掌连接，尊重接触/遮挡，并具有正确的可见手指数或有意的未分割分组轮廓——绝无畸形的假手指。
- 主体复杂度读起来像约 30x30 规划网格，但每个显示像素使用与窗口边框、图标和位图字形相同的完整、方形、整数对齐 `p x p` 基础单元。检视主体轮廓、任何棋盘格平面和 UI/文本的多个区域：阶梯是有意的，每个内容标记解析为完整方形单元，无主体像素比 UI/文本像素大数倍。几何以直线段、阶梯对角线、倒角、楔形和低边多边形为主。任何流畅轮廓、不必要的可变弧序列、半单元、拉伸或矩形单元、偏移行、破损棋盘序列、意外间隙、未对齐孤岛、散落碎片、抗锯齿边缘或平滑过渡像素均不合格。
- 色调深度首先依靠大胆的实色卡平面。棋盘格可选；存在时，它是一或几个紧凑的连通结构区域，仅由最深和最浅颜色组成，限于必要的非皮肤曲面或平面分离线索。每个面部、颈部、耳朵、手、手臂、腿和其他暴露皮肤区域保持实心且无棋盘格。装饰性、散布或全面棋盘格纹理不合格。
- 恰好一个无边框壁纸构图覆盖至少 50%，优先 60%-80%；它包含完整的锁定清单，无相似尺寸的副本出现，任何细节裁切都是小而局部的。
- 一到三个特征提取窗口出现。每个裁切隔离一个独特的局部元素，使用共享单元 `p`，并在尺寸和纵横比上与每个其他提取不同。
- 窗口遵循选定数量、星座和层级；它们跨越多个象限，重叠而不隐藏过多主体，避免僵硬的等尺寸堆叠，保持 20%-30% 连通开放区域。
- 以视觉方式判断色卡限制、完整方形单元、共享主体/UI/文本比例、扫描线、桶形曲率和固定签名在一张生成图片中。不要声称确定性像素、颜色、分辨率或报告验证；不要用工具、脚本、缩放或另一次图片调用来修复失败。
- 位图字形、色卡绑定泛光、扫描线、噪波、余晖和配准偏差保持可见。外缘 10% 在四边显示 unmistakable 的径向桶形曲率，角点压缩更强，长线可见弯曲，中心保持稳定。
- 右上角标题栏包含精确可读的小写字符串 `tait-crt-interface-skill`，使用与左侧标签栏相同的共享网格位图风格。不缺失、不拼错、不翻译、不遮盖、不替换。
- 恰好返回一张最终图片；除非被要求，否则不显示提示词、配方、清单、草稿或替代方案。
