# 成片后路由

本文件用于 after-generate 的前半段：在视频产物生成完成并交付的同一轮，由 Agent 主动提供修改/结束/素材裂变入口，确认母版状态，判断修改/结束/素材裂变路径，并选择可复用的结构来源。

## 1. 母版确认

母版是后续所有动作的来源。可接受的母版包括：

- 当前会话刚生成并交付的最终视频；
- 用户上传的完整视频；
- 用户明确指定的已生成视频结果；
- 复刻链或营销视频链生成的最终合并成片。

不要把单张图片、未完成片段、临时裁剪视频、内部参考素材当作母版。用户只给意图而没有视频时，应先让用户生成或提供视频。

## 2. 满意度路由

成片刚生成或刚交付时，Agent 不应只等待用户主动提出“裂变”，也不应只交付视频链接后结束。如果当前视频属于营销/投放/带货/推广场景，Agent 必须在交付视频产物的同一轮主动把“基于当前成片做素材裂变/多版本测试”作为下一步选项之一给出，并列出可选方向。

推荐成片后默认表达：

```text
这版视频已经生成了。接下来你可以：
1. 先修改当前视频里不满意的地方
2. 把当前版本作为投放母版，继续做素材裂变/多版本测试
3. 暂时不继续，直接交付当前版本
```

营销/投放视频更推荐表达：

```text
视频已生成。这个版本可以作为投放母版继续放大，我可以继续帮你做这些方向：
1. 换开头 Hook，测试前三秒停留
2. 换卖点角度，测试不同购买理由
3. 换 CTA，测试搜索词/商品卡/评论引导
```

如果用户问“还能做什么/继续/下一步”，Agent 应主动解释：素材裂变可以在保留商品事实、主体素材和核心 CTA 的基础上，批量测试不同 Hook、卖点、场景、人群或 CTA。但理想情况下，不应等到用户追问才首次介绍这个能力。

先判断用户对母版的态度：

| 用户信号 | 路由 |
| --- | --- |
| “满意”“可以”“继续投放”“多做几版”“裂变一下” | 进入营销/投放判断 |
| “不满意”“这里要改”“换一下”“太慢/不像/卖点错了” | 进入修改路由 |
| “下载”“就这样”“结束” | 结束或普通交付 |
| 没有说明 | 询问是否满意以及下一步 |

默认问法：

```text
这版视频你想先怎么处理？
1. 先修改当前视频
2. 当前版本可以用，继续做投放素材裂变
3. 暂时不继续
```

如果用户已经明确表达裂变意图，不要重复询问满意度；把“继续裂变”视为当前母版可作为裂变起点。

## 3. 修改路由

如果用户要修改，after-generate 只负责把修改交还给正确链路，不孤立重写 Prompt。

### 3.1 来源于营销视频创作链

把修改路由到最早受影响产物：

```text
输入/事实
→ story-brief.md
→ story-script.md
→ final-generation-info.md / final-generation-info-XX.md
→ 关键参考素材
→ 中间视频 / 成片
```

示例：

- 商品卖点错了：回到输入事实或 story-brief；
- 镜头、文案、时序错了：回到 story-script；
- 只是生成参数、Prompt、拼接错了：回到 final-generation-info；
- 人物/商品素材不对：回到素材完整性检查；
- 只要同方案重生：复用已确认最终生成信息。

### 3.2 来源于参考视频复刻链

按复刻协议定位：

- 参考视频或 manifest 错了：回到取得参考视频 / 反解；
- 做同款范围错了：回到 RecreateScope / ChangeScope 判断；
- 替换对象或素材绑定错了：回到 source_elements 映射或 Plan；
- 某片段生成失败或不满意：按 Plan 的生成视频脚本处理，不自行改写片段 Prompt；
- 只是重新生成同一片段：复用 Plan Checker 返回的 prompt 与素材列表。

### 3.3 来源不明或只有最终成片

不要猜测原始结构。把当前成片视为参考视频：

1. 调用参考视频反解能力获取爆点、关键元素、source_elements、route、content_blocks；
2. 根据反解结果判断修改或裂变应走语义重建还是视频编辑；
3. 再进入复刻规划。

## 4. 营销/投放判断

强营销/投放信号：

- 用户明确说投放、广告、推广、素材、素材矩阵、裂变、A/B 测试、CTR、CVR、GMV、带货；
- 视频创作目标包含商品、品牌、App、服务、活动、优惠、CTA；
- 来源是营销视频创作链；
- 用户要求多版本测试不同 Hook、卖点、场景、CTA 或人群。

弱信号：

- 视频里出现商品但无明确转化目的；
- 有品牌露出但可能只是内容表达；
- 有教程或展示但不确定是否推广。

非营销信号：

- 纯纪念、纯娱乐、纯艺术、纯故事分享；
- 用户明确自用或不投放。

策略：

- 明确是营销/投放：主动提示可以进入素材裂变，而不是等待用户先说“裂变”；
- 明确不是：不主动推裂变；
- 不确定：只问一句是否用于投放/推广。

## 5. 结构来源选择

进入裂变前，按以下优先级选择结构来源：

### 5.1 优先继承营销视频结构

当存在已确认的营销视频生产产物时，优先使用：

- 故事脚本和分镜结构；
- 最终生成信息；
- 商品事实与卖点边界；
- 已确认素材绑定；
- 原视频片段与拼接关系。

这些结构比对最终成片做视觉反解更可靠。

### 5.2 其次继承复刻结构

当存在参考视频反解或 Plan 结果时，优先使用：

- 爆点；
- 关键元素；
- source_elements；
- route；
- content_blocks；
- 生成视频脚本；
- source_element_mappings；
- material_usages。

### 5.3 最后反解最终成片

如果只有最终成片，把它作为参考视频反解。反解只用于获得结构，不代表用户已经授权自由替换所有元素。

## 6. 面向用户的状态表达

不要说“我在读 JSON / manifest / final-generation-info”。使用生产语言：

- “我先确认这版是否可以作为投放母版。”
- “这版视频已经生成了，如果你准备投放，我可以继续基于它做多版本素材裂变。”
- “视频已生成。这个版本可以作为投放母版继续放大，我可以帮你做 Hook、卖点、场景、人群或 CTA 的裂变版本。”
- “如果这版母版可用，我会只改变一个投放变量来做可测试变体。”
- “我会优先沿用当前视频已经确认的商品事实、素材和节奏，不重新发散。”
- “这条只有最终视频，我会先把它当参考视频拆解出可裂变元素。”
