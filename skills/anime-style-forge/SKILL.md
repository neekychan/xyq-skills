# Anime Style Forge — 二次元风格锻造

用户描述一个角色/场景 + 指定画风 → 生成对应风格的图片。  
或上传一张图 + 指定画风 → 转换为目标二次元/动漫画风。

本 Skill 的核心原则是：先定位画风，再选择生成路径；先保障单图与风格准确，再进入迭代；默认禁止任何字幕或画面文字，只有用户明确要求时才允许加入字幕，并必须先完成字幕风险自检。

---

## 核心理念

- **画风溯源驱动**：先判断参考图/目标风格属于哪个画风谱系（时代、流派、制作方式），再匹配最优 prompt 写法。
- **10 维 → 3 维坍缩**：内部用 10 维分析画风特征，再坍缩为用户可感知的「画风 / 角色 / 调性」3 维。
- **风格档案库**：每种画风沉淀完整视觉基因（prompt 模板 + 负向词 + 踩坑提醒），不靠猜测。
- **结果优先**：一句话 + 一张图（可选）→ 直接出图，先给结果，再按用户反馈迭代。
- **字幕安全优先**：默认画面不出现字幕、标题、台词框、气泡文字、招牌文字、水印、logo 或其他可读文字；用户明确要求字幕时，先做完整性风险自检，再严格按用户确认执行。

## 全局硬约束

### 文件与输出

- 中间产物存储在 `./assets/` 目录下。
- **单图输出**：每次生成只输出 1 张完整图片。Prompt 中严禁出现 `grid`、`collage`、`2x2`、`4-panel`、`multiple panels` 等多图拼贴词。
- 输出文件必须是用户可直接使用的最终图像，不交付调试草稿。

### 信息屏蔽

- **禁止向用户暴露任何底层模型/引擎名称**。
- 对用户使用能力描述替代，例如「最适合该风格的生成方式」「擅长 3D 渲染的风格路线」「擅长日系动漫的风格路线」。
- 内部路由表（`references/model-knowledge-base.md`、速查表等）仅供决策参考，**不得向用户展示**。

### 参考图策略

- **图生图路径**：风格微调 / 局部编辑专用 → 传入参考图，prompt 使用编辑指令式。
- **人脸锁定路径**：传入原图锁住面部特征。
- **文生图路径**：不传参考图，纯文字 prompt 重建内容。
- 参考图始终先用于分析提取角色特征，但只有图生图 / 人脸锁定路径在生成调用时传入。

### 字幕与画面文字

默认规则：

- **默认禁止画面出现字幕**。
- 默认也禁止可读文字、标题、台词气泡、弹幕、歌词、屏幕 UI 文案、招牌文字、水印、logo、伪文字。
- 即使用户没有提到字幕，也必须在 prompt 或负向描述中加入无字幕约束。

默认负向约束建议：

```text
no subtitles, no captions, no on-screen text, no readable text, no speech bubbles, no dialogue text, no lyrics, no watermark, no logo, no typographic elements, no malformed letters
```

中文 prompt 可追加：

```text
画面中不要出现字幕、标题、可读文字、气泡文字、招牌文字、水印或 logo
```

仅当用户明确要求「加字幕 / 加台词字幕 / 加歌词 / 画面上出现文字 / caption / subtitle / on-screen text」时，才允许启用字幕流程。用户只是描述角色台词、剧情对白或视频内容时，不等于要求把文字显示在画面上。

## 字幕请求处理流程

### 0. 字幕意图判定

先判断用户是否明确要求字幕：

| 用户表达 | 是否视为字幕请求 | 处理方式 |
|----------|------------------|----------|
| “生成一个角色说：你好” | 否 | 作为剧情/动作理解，默认不在画面显示文字 |
| “视频里加字幕：你好” | 是 | 进入字幕自检 |
| “画面底部显示‘欢迎回来’” | 是 | 进入字幕自检 |
| “加歌词字幕” | 是 | 进入字幕自检 |
| “做成漫画对白框” | 是 | 进入字幕自检，并提示文字准确性风险 |

若用户意图不清，必须先问一句：

```text
你希望这些文字真实显示在画面上，还是只作为剧情/台词设定、不出现在画面里？
```

### 1. 字幕内容完整性检查

用户要求字幕时，生成前必须先提取并确认字幕文本：

- 字幕必须有**完整、精确、可复制的原文**。
- 不得自行补写、改写或扩展字幕。
- 如果用户只说“加一句鼓励的话”“加中文标题”但没给具体文本，必须先询问具体字幕内容。
- 如果涉及多句字幕，必须保持顺序、标点、语言一致。
- 不允许把字幕拆成多个不确定版本。

确认模板：

```text
我将只在画面中显示这段字幕：“[完整字幕文本]”。请确认是否完全按这句话生成。
```

### 2. 字幕风险自检

在生成前必须对字幕复杂度进行风险分级。自检维度如下：

| 风险项 | 低风险 | 中风险 | 高风险 |
|--------|--------|--------|--------|
| 字符长度 | 中文 ≤ 10 字；英文 ≤ 3 个词 | 中文 11-24 字；英文 4-8 个词 | 中文 > 24 字；英文 > 8 个词 |
| 行数 | 1 行 | 2 行 | 3 行及以上 |
| 字幕数量 | 单条字幕 | 2 条短字幕 | 多条字幕、逐句字幕、歌词字幕 |
| 字体要求 | 无特殊字体 | 简单字体要求 | 花字、书法字、复杂排版 |
| 画面运动 | 静态或轻微运动 | 中等运动 | 快速运动、镜头切换频繁 |
| 语言复杂度 | 单语言常用字词 | 中英混排 | 多语言、特殊符号、生僻字 |
| 安全区域 | 底部单行 | 底部两行 | 分散在多个位置 |

只要命中任一高风险项，就判定为「字幕损坏高风险」。高风险包括但不限于：

- 字幕过长，容易缺字、错字、乱码、截断。
- 字幕行数过多，容易排版错位或被画面裁切。
- 歌词字幕、逐句字幕、双语字幕、多段字幕。
- 用户要求复杂字体、发光描边、手写字、竖排字、环绕排版。
- 视频镜头变化剧烈，字幕需要随时间连续出现。

### 3. 高风险告知与用户确认

如果自检为高风险，**必须暂停生成**，提前向用户说明风险，并让用户选择下一步。不得直接生成。

风险告知模板：

```text
这段字幕内容偏长/字幕数量较多，当前生成可能出现缺字、错字、截断、排版错位或字幕不完整的问题。为了保证效果，我建议改为以下方式之一：

1. 缩短字幕，只保留 1 行短句。
2. 先生成无字幕画面，再用后期方式叠加字幕，完整性更稳定。
3. 继续按原字幕生成，但需要接受字幕可能不完整的风险。

你希望采用哪一种？
```

用户选择前，不得调用生成工具。必须严格参考用户意见再生成。

### 4. 字幕生成规则

若用户确认要加字幕，prompt 必须包含：

- 明确写出完整字幕原文。
- 指定只出现这一段字幕，不出现其他文字。
- 指定字幕位置在安全区域，优先底部居中。
- 指定字幕完整、清晰、不截断、不缺字、不乱码。
- 对复杂字幕，优先建议用户改为后期叠加。

字幕 prompt 示例：

```text
Add exactly one subtitle line at the bottom safe area: "[完整字幕文本]". The subtitle must be fully visible, complete, correctly spelled, not cropped, not broken, not duplicated. No other text appears anywhere in the image/video.
```

中文 prompt 示例：

```text
画面底部安全区域只显示一行字幕：“[完整字幕文本]”。字幕必须完整、清晰、无缺字、无错字、无遮挡、无裁切、无乱码；画面中不得出现其他文字。
```

### 5. 生成后复检

生成后必须检查结果：

- 是否出现未授权字幕或多余文字。
- 指定字幕是否完整显示。
- 字幕是否有错字、缺字、乱码、截断、重影。
- 字幕是否被角色、道具、画面边缘遮挡。
- 是否与用户确认的原文完全一致。

如果用户没有要求字幕但画面出现可读文字，应优先重新生成或明确说明需要重做。

如果用户要求字幕但复检发现字幕不完整，必须如实告知：

```text
这版画面的字幕存在不完整/错字/截断问题，不建议作为最终版。我建议改为无字幕版本，或先生成画面后再用后期方式叠加字幕。
```

不得把字幕错误的结果包装成成功交付。

## Phase 0: 输入

### 输入模式

| 模式 | 输入 | 示例 |
|------|------|------|
| **纯文字生成** | 角色/场景描述 + 目标画风 | “画一个国漫玄幻风格的男角色，黑袍持剑” |
| **风格转换** | 参考图 + 目标画风 | 上传照片后说“改成吉卜力风格” |
| **画风识别** | 参考图（无指定风格） | 上传图后说“这是什么画风？帮我出同风格的” |
| **字幕/文字画面** | 明确字幕文本 + 目标画风 | “生成视频，底部字幕写‘欢迎回来’” |

### 输入缺口处理

- 用户已描述内容 → 继续流程。
- 用户只给风格没给内容 → 问“你想画什么角色或场景？”
- 用户只给参考图说“同风格” → 问“保留原图内容还是换新内容？”
- 用户提到字幕但没给具体字幕 → 问“请提供要显示的完整字幕文本。”
- 用户给了长字幕或多段字幕 → 执行字幕风险自检，必要时先暂停并提示风险。

## Phase 1: 画风定位

### 分支判断

- **用户已指定画风**（如“国漫3D”）→ 直接跳到 1c 风格匹配。
- **用户上传参考图但未指定画风**（如“这种风格”）→ 执行 1a + 1b 分析。
- **用户说“动漫化”但没说哪种** → 执行 1a 分析后推荐风格。
- **用户指定多个画风对比** → 并行匹配多个 style_id，但每张图仍保持单图输出。

### 1a. 画风溯源

分析参考图的画风来源，对照 `references/style-fingerprints.md`。

内部分析要点：

- 线条处理方式
- 上色技法
- 人物比例
- 面部画法
- 色彩体系
- 年代感
- 媒介质感
- 文化圈来源

内部输出字段：

```text
style_family / style_id / confidence / clues / era_feel / production / alt_style
```

### 1b. 10 维画风分析

1. **线条 Linework**：粗细、清洁度、可见度、描边风格。
2. **上色 Coloring**：赛璐璃、渐变、水彩、厚涂、平涂。
3. **人物比例 Proportions**：头身比、写实度、Q版程度。
4. **面部画法 Face**：眼睛大小/画法、鼻子处理、嘴巴风格。
5. **色彩体系 Palette**：饱和度、色温、主色调、配色逻辑。
6. **光影处理 Shading**：二分阴影、柔和渐变、无阴影、戏剧性光影。
7. **背景风格 Background**：写实、简化、纯色、氛围化。
8. **年代感 Era**：哪个年代的画风特征。
9. **媒介质感 Medium**：数码、传统、3D、混合。
10. **文化圈 Origin**：日系、国风、韩系、欧美、混合。

### 1c. 坍缩为画风 / 角色 / 调性

| 维度 | 对应底层 | 含义 |
|------|----------|------|
| **画风** | 线条 + 上色 + 媒介 + 年代 | 用什么技法画 |
| **角色** | 人物比例 + 面部画法 + 光影 | 人物长什么样 |
| **调性** | 色彩 + 背景 + 文化圈 | 整体什么感觉 |

取子维度 score 加权平均，确定画风的**灵魂轴**，即最有辨识度的 1-2 个维度。

### 1d. 风格匹配

匹配优先级：

1. style_id 精确匹配。
2. style_family + era_feel + production 组合匹配。
3. 10 维特征向量最近邻匹配。
4. 无法匹配 → 列出 Top 3 相近风格供用户选择。

## Phase 2: 快选

### 展示画风定位结果

向用户展示定位结果时，不暴露模型名称和内部路由。

```text
🎨 画风定位
  风格：[style_name]（[style_id]）
  家族：[style_family] · [era_feel] · [production]
  置信度：[confidence]
  判断依据：[top 3 clues]
  灵魂轴：[soul_summary]

🛠️ 推荐方案
  Prompt 策略：[针对该风格的关键词方向]
  预期效果：[该风格的视觉特点描述]
```

### 任务类型维度决策

风格路由表只解决“用什么画风出图”，但一致性、指令遵循、输出格式会覆盖风格路由优先级。必须先走任务类型决策，再查风格路由表。

#### 决策三问

**Q1：这张图需要参考上一张或其他已生成图吗？**

- 是 → 必须走图生图路径，传入参考图。
- 否 → 继续 Q2。

**Q2：这个任务的输出会被下一步复用为参考图吗？**

- 是 → 确保单图输出，并避免画面文字污染参考图。
- 否 → 继续 Q3。

**Q3：一致性 vs 风格极致，哪个是第一优先级？**

- 一致性优先 → 走图生图路径，传入前序图片作为参考锁定角色和构图。
- 风格优先 → 走文生图路径，进入画风路由表。

### 任务类型速查

| 任务类型 | 核心需求 | 生成路径 | 推荐 |
|----------|----------|----------|------|
| **分镜/多帧连续** | 跨图一致性 + 构图可锁定 | 图生图，传前序帧作参考 | 参考图锚定路径 |
| **构图固定只改变量** | 构图锁定 | 图生图 | 参考图锚定路径 |
| **表情差分** | 角色一致性 | 图生图，传角色图锁面部 | 参考图锚定路径 |
| **三视图 / 多角度立绘** | 角色一致性 | 图生图，传正面图锁角色 | 参考图锚定路径 |
| **单张独立图** | 风格准确度 | 文生图 | 画风路由表 |
| **风格转换** | 参考图传递 + 风格重建 | 文生图路径 | 目标风格首选策略 |
| **带字幕视频/画面文字** | 字幕完整性 + 指令遵循 | 先字幕自检，再生成 | 高风险先征询用户 |

常见错配：

- 看到“分镜”就直接查画风路由表走文生图，会导致多帧角色漂移。
- 看到“加字幕”就直接生成，会导致缺字、错字、截断或乱码。
- 用户没要求字幕时放任画面出现伪文字，会污染最终图和后续参考图。

### 生成路径选择

根据任务类型选择路径。向用户解释路径时，不提具体模型名。

- **文生图重建（风格转换首选）**：分析原图提取所有特征，然后用目标风格的最优 prompt 纯文字重新生成。画质和风格深度最高。跨风格转换优先走此路径。
- **局部编辑（仅限细微修改）**：传入原图 + 编辑指令。仅适用于改发色、改服装颜色、加配饰等不改变整体风格的局部修改。
- **人脸锁定**：传入原图锁住面部特征 + 风格 prompt。人物更像，但风格转化程度可能不如文生图彻底。
- **多策略对比**：同一内容用 2-3 种 prompt 策略各出一张，对比挑选最佳。

### 快捷指令

- `换风格`：保留内容，只切换画风。
- `出立绘`：全身/半身角色立绘。
- `出头像`：方形头像构图。
- `多风格`：同一内容出 N 种画风对比。
- `多策略`：同一风格用多种 prompt 策略各出一张对比。
- `无字幕`：明确强化无字幕、无文字、无水印约束。
- `加字幕`：进入字幕自检流程，必须先确认完整字幕文本。

### 风格转换路径选择

风格转换时，如果用户没有说明优先级，先问：

```text
你更在意人物像原图，还是画风更到位？如果两者都要，我可以分别按两条路线各出一版供你对比。
```

| 用户优先级 | 路径 |
|------------|------|
| 要像原图的人 | 人脸锁定路径 + 目标风格 prompt，或文生图路径 + 精细角色描述 |
| 要画风到位 | 文生图路径，不传参考图，查速查表选首选 prompt 策略 |
| 两者都要 | 两条路径各出一张，让用户对比挑选 |

## Phase 2.5: 字幕自检门禁

只要用户明确要求字幕、画面文字、视频字幕、歌词字幕、对白框、标题条，必须在 Phase 3 之前执行本阶段。

### 字幕门禁步骤

1. **确认是否真的要显示文字**：区分剧情对白和画面字幕。
2. **提取完整字幕文本**：不得改写，不得补写。
3. **检查字幕复杂度**：按长度、行数、数量、语言、排版、镜头运动判定风险。
4. **高风险先暂停**：向用户告知缺字、错字、截断、排版错位风险。
5. **等待用户选择**：缩短字幕、无字幕生成后期叠加，或接受风险继续。
6. **写入 prompt 约束**：只显示用户确认的字幕，不出现其他文字。
7. **生成后复检**：发现字幕损坏则如实说明，不把错误字幕当成成功结果。

### 字幕风险分级输出

内部判断后，对用户只展示必要信息：

```text
字幕自检：这段字幕属于 [低/中/高] 风险。
原因：[长度较短 / 字幕偏长 / 多行多段 / 中英混排 / 画面运动较多]
建议：[可直接生成 / 建议缩短 / 建议先生成无字幕版本再后期叠加]
```

若为低风险，可继续生成。若为中风险，简短提醒后可继续。若为高风险，必须等待用户确认。

## Phase 3: 出图

### Prompt 构建

从 `references/style-bank.md` 加载匹配风格的完整档案，按以下结构组装：

```text
最终 Prompt = [风格锚点词] + [角色/场景描述] + [画风细化词] + [画质增强词] + [字幕/无字幕约束]
负向描述 = [风格专属负向词] + [通用负向词] + [无字幕/无文字负向词]
```

默认必须追加无字幕约束：

```text
no subtitles, no captions, no on-screen text, no readable text, no speech bubbles, no watermark, no logo
```

如果用户明确要求字幕，则改为字幕专用约束：

```text
Only display this exact subtitle: "[用户确认的完整字幕]". No other text. The subtitle must be complete, correctly spelled, fully visible, not cropped, not broken, not duplicated.
```

### 各风格轴对 Prompt 的影响

| 灵魂轴 | Prompt 侧重 |
|--------|-------------|
| 画风 | 线条描述、上色技法、媒介关键词、年代风格标签 |
| 角色 | 头身比、面部特征、服装细节、姿势动作 |
| 调性 | 色彩关键词、光影描述、氛围形容词、背景处理 |
| 字幕 | 默认禁止；明确要求时保证完整、清晰、单一、安全区域显示 |

### 角色描述规范

二次元角色描述按重要性包含：

1. **性别/种族/年龄段**：少女、少年、成年、幼儿等。
2. **发型发色**：例如“黑色长直发，刘海遮住右眼”。
3. **眼睛**：颜色、大小、特殊特征。
4. **服装**：材质、款式、颜色、装饰。
5. **姿势/动作**：静态姿势或动态动作。
6. **表情**：情绪状态。
7. **配件/道具**：武器、饰品、宠物等。

### 尺寸规则

| 用途 | 推荐比例 |
|------|----------|
| 头像 | 1:1 |
| 立绘/角色卡 | 2:3 或 3:4 |
| 场景/横版 | 16:9 |
| 手机壁纸 | 9:16 |
| 条漫/Webtoon | 9:16 |
| 带字幕画面 | 优先 16:9 或 9:16，并保留底部安全区域 |

若有参考图，默认跟随原图比例。必须用工具测量或读取元数据后映射，**禁止猜测**。

### 生成执行

- 按生成策略分别执行，查阅 `references/model-knowledge-base.md` 获取每种策略的专属 prompt 写法。
- 向用户解释时只说“我会用最适合这个风格的方式生成”，不提具体模型名。
- 输出保存到 `./assets/` 目录下。
- 任何生成都要遵守单图输出和字幕门禁。

## Phase 4: 迭代

展示结果后询问满意度：

| 选项 | 动作 |
|------|------|
| 满意 | 进入 Phase 5 输出 |
| 微调 | 在 prompt 层调整，不回 Phase 1 |
| 换风格 | 切换到另一个 style_id，保留内容描述 |
| 混搭 | 组合不同图的线条、配色、角色比例等维度重新生成 |
| 字幕错误 | 建议无字幕重出，或改为后期叠加字幕 |

### 微调映射表

| 用户反馈 | Prompt 动作 |
|----------|-------------|
| “线条再粗一点” | 增强 `bold outlines, thick lineart` |
| “颜色太鲜了” | 降饱和，加 `muted`, `desaturated` |
| “眼睛画得不对” | 细化眼睛描述，加 `detailed {style} eyes` |
| “不够二次元” | 增强风格锚点词权重，加 `anime`, `2D` |
| “太二次元了/想半写实” | 减弱风格词，加 `semi-realistic` |
| “背景太复杂” | 加 `simple background`, `solid color background` |
| “动作不自然” | 重新描述姿势，加 `natural pose` |
| “像AI画的” | 加 `hand-drawn feel`，去掉过度修饰词 |
| “想要某某番/游戏的感觉” | 切换到对应作品相近风格档案 |
| “字幕少字/错字” | 不继续微调原图，建议缩短字幕或无字幕生成后期叠加 |
| “不想要字幕” | 强化 `no subtitles`, `no text`, `no watermark` |

## Phase 5: 输出

```text

  灵魂轴：[soul_summary]
```

如果字幕生成存在风险或复检问题，必须在交付中明确说明，不得省略。

### 可选操作

- **风格入库**：将本次成功的风格参数存入风格档案库，供未来复用。
- **多风格对比**：同一内容用 2-3 种画风各出一组。
- **继续变体**：基于最满意的一张继续出变体。
- **无字幕干净版**：当字幕效果不稳定时，优先生成无字幕画面供后期叠加。

## 最终行为原则

- 用户没要求字幕：默认无字幕，并主动通过 prompt 抑制所有画面文字。
- 用户要求字幕：必须先确认完整字幕文本。
- 字幕过多或复杂：必须提前说明风险，等待用户选择。
- 用户坚持复杂字幕：严格按用户确认执行，并在交付时说明风险。
- 生成后字幕损坏：必须如实告知，不得把错误字幕当成成功结果。
- 跨风格转换优先保证画风深度；多帧连续优先保证角色一致性；字幕任务优先保证文字完整性与用户确认。
