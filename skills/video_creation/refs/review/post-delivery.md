# 成片后编辑与后处理

> 成片已交付后，或用户携带现有视频提出修改/编辑/后处理诉求时读本文件。先查 §〇 路由表定轨道，再跳对应轨道条目执行。重做式内容修改（否定现有内容本身：换题材/换故事/重做镜头）不在本文件——走根文件 §0.3 层级判定。

## §〇 路由总表

| 信号（语义示例，沾边即命中） | 轨道 | 条目 |
|---|---|---|
| "删掉第 N 段""去掉那一段" | A 成片合成 | §A1 |
| "把第 N 段挪到开头""调整顺序""倒叙" | A 成片合成 | §A2 |
| "加上字幕""把字幕去掉"（成片级开关） | A 成片合成 | §A3 |
| "用回上一版""还是之前那版好" | A 成片合成 | §A4 |
| "配上这首歌""换成我上传的音乐""把背景音乐去掉"（有现成音乐文件） | A 成片合成 | §A5 |
| "把其中一个人去掉""删掉画面里的 X""把 A 换成 B"（保留式，局部） | R 参考编辑 | §R |
| "改成水墨风""调成暖色调"（保留式，全片属性） | R 参考编辑 | §R |
| "第 N 段改成 X""某段重做"（改镜头内容） | B 重生成 | §B1 |
| "再来一次""重新生成"（无修改内容） | B 重生成 | §B2 |
| "出个英文版""换成日语" | C 批量重生 | §C1 |
| "改成竖版/横版""9:16 改 16:9" | C 批量重生 | §C2 |
| "换个声音""音色换低沉的" | C 批量重生 | §C3 |
| "变清晰""提到 1080p/4K""画质增强" | E 移交处理 | §E1 |
| "去掉视频里的字幕"（画面内已烧录字幕） | E 移交处理 | §E2 |
| "把第 X 到 Y 秒重做"（段内区间，非整段） | E 移交处理 | §E3 |
| "帮我生成/配一段 BGM"（无现成音乐文件）/ 调色滤镜 / 变速 / 修口型穿帮 / 加字卡 / 去水印 | D 降级边界 | §D |

**轨道判定原则**：两个维度先后判——
1. **保留意愿**：用户对现有画面满意吗？指令是"在满意的画面上做有界修改"（删/换/加元素、变属性）→ 原片是资产，走 R 轨参考编辑（原片入 VideoList）；指令否定画面本身（"重做""不好看""换个故事"）→ 原片是废稿，走 B/C 轨重生成或根文件 §0.3
2. **修改程度**（在轨内作为参数，不改变轨道）：只动段落取舍/字幕/BGM 不动画面 → A 轨零生成；动画面 → R 轨内再分局部（单段）/全片属性；需帧级/像素级处理 → E 轨；工具面无通路 → D 轨

**拿不准就问**：保留意愿判不清（如只说"把这段改好看点"，看不出对现有画面满意与否）时，禁止押注任一路径，按双路径确认的问卷格式（含两条路径的积分成本与效果差异说明）询问用户后再路由。

**公共判据：双路径确认（R 轨全片属性、C 轨适用）**。诉求波及全片且现有成片可作为编辑对象时，禁止默认执行任一路径，出二选一问卷：
- 选项 1：**基于现有成片编辑**（原视频入 VideoList + 编辑句式）——保留当前画面呈现，效果更稳（推荐），但参考视频时长计入积分，**成本更高**
- 选项 2：**重新生成**——积分更省，但画面会与当前版本产生差异

红线：必须向用户讲清"贵的更稳、便宜的会变"这组权衡；用户未选择前禁止调用生成类工具。

**复合请求编排**：一条指令含多个诉求（如"删掉那个人 + 加字幕 + 配上这首歌"）时，先拆成原子诉求逐个按路由表定轨，再按固定顺序执行：
1. 画面类先行：R 参考编辑 / B、C 重生成 / E 专项处理，产出各段最终版本
2. 合成类收口：`render_video` **最后一次性完成**段序 + 字幕开关 + BGM，禁止中途多次重拼
3. 更新成片状态账本

红线：字幕与 BGM 必须放在最终合成步，先合成再做画面编辑会导致字幕/音乐被编辑或超分误处理；同一段的多个兼容修改（如"删人 + 换背景"）合并进一次编辑调用，禁止逐项多次编辑同一段。

## §A 成片合成（纯 render_video，零生成）

**总判据**：只动段落取舍/顺序/成片级字幕/BGM、不动任何段内画面 → **禁止调用 `sandbox_generate_video`**，只重调 `render_video`。所有 `shot_NN.mp4` 生成后都留在 sandbox，可直接复用。

### A1 删段

- 前置判定：`sandbox_bash` ls 确认各段文件仍在
- 执行：`render_video` 传去掉该段路径的 `video_paths`，输出新文件（如 `output_v2.mp4`），不覆盖原成片
- 红线：删段导致相邻两段衔接突兀属预期内，无需重生过渡段；用户主动要求补过渡时才转 B 轨

### A2 换序

- 执行：`render_video` 按新顺序传 `video_paths`
- 红线：⇐ 衔接链相邻段（后段以前段尾帧起手）被拆开后画面起点会不连贯，重拼前须告知用户此影响

### A3 成片级字幕开关

- 执行：`render_video` + `show_subtitle: true/false` 重拼一次。字幕内容 = 各段台词/旁白原文，仅整片二元开关，无样式可调
- 画面内已烧录的字幕不归本条 → §E2

### A4 版本回退

- 前置判定：确认目标旧版文件路径存在（见成片状态账本）
- 执行：`render_video` 用旧版路径重拼

### A5 添加/替换/移除 BGM（有现成音乐文件）

- 前置判定：音乐文件已在 sandbox（用户上传或此前已有）。用户想要配乐但**没有现成文件** → 不归本条，走 §D（音乐生成未开放，提示用户上传音乐文件后回本条）
- 执行：`render_video` + `bgm_audio_path: {音乐文件路径}` 重拼；移除 BGM 则不传该参数重拼
- 红线：**`bgm_audio_path` 只接受用户提供或项目既有的音乐文件**——禁止用 `sandbox_generate_audio`（任何类型，含 tts 音色样本）的产物冒充音乐填入；禁止用 ffmpeg 合轨；无文件时唯一出路是请用户提供文件，禁止"先生成个音频试试"。音量/淡入淡出/进入时点等细节参数工具面不支持，禁止向用户承诺

**成片状态账本（全轨公共基建）**：任何段被修改后产出 `shot_NN_v2.mp4`（递增 v3/v4…），禁止覆盖旧文件。每次重调 `render_video` 前先列出**当前成片状态**并完整继承——
- 段顺序与每段生效版本（段号 → 生效文件路径）
- `show_subtitle` 当前值
- `bgm_audio_path` 当前值（有则必须带上，防止删段/换序后丢音乐）

任一状态项在重拼时被遗漏 = 用户已确认的效果被静默回退，属违规。

## §R 参考编辑（保留式修改，原片入 VideoList）

**机制统一**：用户对现有画面满意、只做有界修改时，把要保留的视频作为参考传入 VideoList 编辑。**修改范围只是参数**，不改变机制：

| 范围 | 信号 | 执行 |
|---|---|---|
| 局部（单段内删/换/加元素） | "双主角只留一个""把 A 换成 B""换件衣服""加只猫" | 该段原视频入 VideoList，`严格编辑@视频N：{删除/替换/增加描述}，其余画面、运镜、表演保持不变`；多段成片只编辑受影响段，完成后按状态账本重拼。**不出问卷直接执行** |
| 全片属性（风格/色调） | "整片改成水墨风""调成暖色调" | 先过双路径确认（§〇）。选编辑路径：逐段入 VideoList + `严格编辑@视频N：整体转为{目标属性}，画面内容、运镜、表演保持不变`；选重生路径：按根文件 §0.3 创意层(风格) 重建 |

**分流判据（删除测试）**：把用户点名要改的对象从画面里拿掉，剩下的画面用户是否满意？满意 → 本轨；不满意或整体否定 → §B。

红线：
- **禁止改走重生成**——重生成会重抽场景/光影/表演，用户满意的部分全部丢失；局部编辑的参考时长积分属预期成本
- 参考范围最小化：只传受影响段，禁止把整片当参考去改单段内容
- 被删主体若有台词，其台词归属须先与用户确认（删除/转移给保留角色）
- 用户明说"画面/故事不要变"时已表明保留意愿，全片问卷推荐项标在编辑路径

## §B 重生成（单/少数镜头重做，原片不入 VideoList）

### B1 修改镜头内容

用户否定镜头呈现并说了改什么（"重做""不好看"+ 修改内容）。执行走 `review/quality-control.md` §一 KEEP/CHANGE 协议（先读 tasks/ 原始参数，点名字段入 CHANGE，其余逐字 KEEP）。本条只补协议之外的两条义务：

1. **重拼义务**：修改段确认后必须按成片状态账本重调 `render_video` 产出新成片，禁止只交付单段就结束
2. **衔接链重截判定**：被改段若是 ⇐ 衔接链的前置段，重生成后必须重截其尾帧、重生依赖它起手的后续段；不在衔接链上则只重生本段

### B2 同参数重抽（抽卡）

用户不满意但未说改什么 → 复用完全相同的 Prompt/参数重新生成。红线：**禁止把上一次产物放入 ImageList/VideoList**（放入即变成编辑任务，会锚定旧结果）；原始参考素材照传。

## §C 批量重生（波及多段/全片，先过双路径确认）

### C1 换语言版本

- 影响范围：**只重生含台词/旁白的段**，纯画面段直接复用原文件
- 执行：翻译各段台词（保持原意与时长量级，重生前用 `count_chars.py` 复核耗时下限 ≤ 段时长）→ 逐段重生 → 状态账本更新 → 重拼
- 红线：告知用户口型、表演会随重生变化，非仅替换音轨

### C2 转比例

- 适用双路径确认（§〇 公共判据）。选项 1 编辑路径：按 §R 机制整片入 VideoList，Prompt 用编辑句式声明目标比例；选项 2 重生路径：沿用 creative_design + 参考图按新 Ratio 逐段重生
- 红线：两路径都不是裁切——画面构图必然变化，须提前告知

### C3 换配音音色

- 澄清话术先行：**这不是后期换音轨，而是重新生成**——人声由视频模型随画面产出，换音色 = 换音色锚定后重生该角色所有含台词段
- 执行：改 `creative_design.md` 音色定义 → `sandbox_generate_audio` 重做音色锚定 → 重生相关段 → 重拼

## §D 降级边界（无通路，统一话术）

**话术模板**：`目前无法{诉求}。可以为你{替代方案}，是否需要？`

| 诉求 | 为何无通路 | 可提供的替代 |
|---|---|---|
| 从零生成 BGM/配乐（无现成文件） | 音乐生成功能未开放 | 请用户上传/提供音乐文件，转 §A5 用现成文件合成 |
| 调色/加滤镜（后期） | 无成片调色工具 | 参考编辑转色调（转 §R 全片属性）或重生成写色调 |
| 变速/慢动作/倒放 | 无时间重映射工具 | 重生成该段并在 Prompt 中描述慢动作（转 B 轨） |
| 修口型/穿帮/肢体畸形 | 无像素级局部修复 | 同参数重抽该段（转 B2，不保证修复） |
| 片尾字卡/落版/标题叠加 | 成片无字卡合成参数 | 重生成末段并在 Prompt 中设计落版画面（转 B 轨） |
| 去水印 | 平台禁令（见 system prompt） | 无，直接回复无法处理 |

红线：D 轨诉求**禁止用 ffmpeg 处理成片画面/音轨来变通实现**、禁止用 `sandbox_generate_audio`（任何类型，含 tts）的产物冒充音乐；降级话术发出后即停，等用户提供素材或明确选择替代方案，禁止自行"换个思路再试"；替代方案涉及重生成/编辑时，须说明积分成本后经用户确认。

## §E 移交处理（专项流程，二跳加载）

### E1 视频超分

- 信号："变清晰""提分辨率"；前置判定：目标分辨率高于源视频（仅支持向上超分）
- 执行：读 `review/video-enhance.md`

### E2 擦除画面内字幕

- 信号：去除已烧录在画面里的字幕（非 `show_subtitle` 开关）
- 执行：读 `review/video-enhance.md`

### E3 段内区间局部编辑

- 信号："把第 X 到 Y 秒重做/换掉"，区间小于一个完整段
- **前置判定（来源分流，先判再跳）**：
  - 多段项目成片（各 `shot_NN.mp4` 在 sandbox）→ **不走本条**：定位区间所在段，按保留意愿转 §R（保留式）或 §B1（重做式）处理该段后重拼——有原始参数与参考图，保真度更高
  - 单段直出视频 / 用户上传的现有视频 → 读 `review/video-partial-edit.md` 执行切分→编辑→render_video 拼接
