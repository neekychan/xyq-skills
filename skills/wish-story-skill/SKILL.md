# 中文小说剧本改编

作者：MinX旭

## 一、用途

这个 skill 用来把中文小说、故事梗概、人物设定、章节片段或连载素材，改编成可拍摄、可表演、可检查的中文剧本。

输出目标不是文学润色，也不是普通总结，而是把叙事文字转成剧本语言：场景、动作、对白、画外音、屏幕文字、音效、转场和每场戏的变化。

适用对象包括真人短剧、影视剧本、漫剧脚本、动画分镜前稿和 AI 视频生成前的剧情拆解稿。

## 二、触发场景

当用户提出以下需求时，使用本 skill：

- 把小说章节改成剧本。
- 把故事梗概拆成分集、分场或短剧脚本。
- 把大段叙事改成动作、对白、音效和画面。
- 检查某版改编剧本是否忠于原文。
- 把故事素材整理成适合拍摄、剪辑、AI 视频生成的文本。
- 根据原文重排剧集节奏、爽点、反转、悬念和场景推进。

## 三、改编原则

默认遵守五条原则：

1. **忠于原文**：不擅自改变人物关系、剧情因果、关键设定、线索结论和重要台词。
2. **可拍摄**：把抽象叙事转成看得见、听得见、演得出来的内容。
3. **有结构**：分集、分场、时间、地点、人物、动作和场景变化要清楚。
4. **能表演**：对白和动作分开写，演员能看懂谁在说、怎么动、此刻要达成什么。
5. **可复查**：原文中的关键台词、内心独白、屏幕信息和重要旁白要能在剧本中对应找到。

## 四、默认流程

1. 先通读原文，确认人物、地点、时间线、道具、事件、冲突、转折、台词、内心独白和结尾状态。
2. 在正式写剧本前，内部建立“原文话语清单”：记录所有原文台词、明确内心话、重要旁白和屏幕文字，防止改编时漏掉。
3. 判断用户需要的是“忠实改编”还是“创意改编”。
   - 忠实改编：尽量不扩写，不改动事实，不删改关键话语。
   - 创意改编：可以在用户允许范围内压缩、重排、补桥段、增强钩子和场景冲突。
4. 先做分场规划。每场戏必须明确时间、地点、出场人物、主要动作、冲突点和结尾变化。
5. 再写正文剧本，把小说叙事转成动作、对白、旁白、内心声、画外音、屏幕文字和音效。
6. 写完后执行自检，确认没有无依据新增、关键台词遗漏、场景不可拍或节奏断裂。

## 五、默认输出结构

当用户要求完整剧本时，默认开头使用：

```text
剧名：《》
类型：
改编模式：忠实改编 / 创意改编 / 分集拆改
画面风格：
篇幅要求：
总集数：
预计时长：
```

正文默认使用：

```text
## 一、改编判断
## 二、人物表
## 三、分集 / 分场大纲
## 四、正文剧本
## 五、改编自检
```

如果用户只要求某一场、某一集、剧本检查、格式转换或分镜前稿，只输出对应内容，不强行补完整模板。

## 六、场景标题格式

剧本正文中，场景标题统一使用：

```text
### 第1集 1-1｜日｜内景｜出租屋客厅
### 第1集 1-2｜夜｜外景｜医院门口
```

每个场景标题尽量包含：

- 第几集或第几段。
- 场次编号。
- 日 / 夜 / 清晨 / 傍晚 / 同时 / 稍后等时间信息。
- 内景 / 外景。
- 具体地点。

如果原文缺少某项信息，可以基于上下文谨慎推断；如果推断会影响剧情理解，标注 `[待确认]`。

## 七、剧本元素标签

默认使用这些简单标签：

- `画面：` 静态环境、物体状态、空间关系、场景氛围。
- `动作：` 人物身体动作、表情变化、走位、可见行为、镜头可读的动作。
- `对白：` 画面中角色直接说出的话。
- `旁白：` 不属于画面中角色当下开口的叙述声音。
- `内心声：` 角色明确的心理话、心声或第一人称内在独白。
- `画外音：` 声音存在，但说话人不在当前画面中。
- `屏幕文字：` 手机消息、文件内容、合同、系统提示、新闻标题、门牌、字幕等可读信息。
- `音效：` 对剧情有作用的声音，例如敲门、脚步、震动、广播、机器声、门锁声。

不要为了显得丰富而堆标签。只有会影响表演、画面、声音或剧情理解时，才写出来。

## 八、原文话语保护规则

忠实改编模式下，以下内容属于重点保护对象：

- 原文中明确出现的对白。
- 原文中明确写出的内心独白、心理话和第一人称想法。
- 被改成旁白、内心声或画外音的原文叙述。
- 原文中的关键信件、聊天记录、系统提示、新闻、合同、牌匾、报告等文字信息。

处理规则：

- 原文话语进入剧本后，尽量保持原句。
- 长句可以拆成连续多句，但顺序不能改变。
- 不要把不同人物的话合并成一个人的话。
- 不要因为“更顺”就删掉重复称呼、停顿、脏话、口头禅、疑问、感叹、威胁或情绪词。
- 不要把关键信息改成意思相近但证据不同的新说法。
- 如果说话人不清楚，可以临时写成 `男人甲`、`护士乙`、`旁人`、`系统声` 等中性称呼。
- 如果因为发布、安全或平台规则不能原样保留某句话，保留位置并写 `[原文台词待处理：原因]`，不要静默改写。

创意改编模式下，可以压缩或重写对白，但必须保留关键事实、人物立场、承诺、威胁、线索、误会和反转逻辑。

## 九、扩写边界

忠实改编模式下，不要新增：

- 原文没有的人物关系。
- 原文没有的过往经历。
- 原文没有的地点和重要道具。
- 原文没有的关键动机。
- 原文没有的证据、线索和结论。
- 原文没有支撑的强烈情绪和价值判断。

可以补极少量必要动作，让场景能被拍出来，例如进门、转身、坐下、拿起原文已有物品、走向原文已出现地点等。

创意改编模式下，新增内容必须服务于：

- 场景衔接。
- 强化开场钩子。
- 把内心戏外化为冲突。
- 压缩重复信息。
- 增强短剧集尾反转。
- 让下一集有明确追看动力。

## 十、小说语言转剧本语言

把抽象叙事转成具体可拍内容：

- 情绪变化：转成动作、停顿、眼神方向、手部动作、沉默、物品处理或内心声。
- 背景信息：转成屏幕文字、对白、文件、广播、手机消息、环境痕迹或结果呈现。
- 人物关系：转成称呼、距离、打断、座位、钱物交换、回避动作、习惯动作或冲突方式。
- 危险压力：转成脚步声、门锁声、手机震动、灯光变化、群众反应、道具位置或急促对白。
- 时间跳转：转成场景标题、屏幕文字、旁白、服装变化、物品状态变化或地点变化。

优先写“角色做了什么、听到什么、看到什么、说了什么、读到什么、藏起什么”，少写抽象判断。

## 十一、对白处理

对白要能演，不要像解释材料。

- 每句对白要有说话人。
- 角色说话要符合当前身份、关系和场景压力。
- 不要让角色说双方早就知道的信息，除非原文本来就是这样写的。
- 忠实改编模式下，优先保留原句。
- 表演提示要短，例如 `低声`、`停顿后`、`压着火`、`没看对方`。
- 不要滥用括号解释心理。能用动作和停顿表达，就少写“愤怒地、悲伤地、震惊地”。

推荐格式：

```text
对白：林晚（低声）：你刚才说的那个人，是不是姓周？
动作：周临把手机屏幕扣在桌面上，没有立刻回答。
音效：手机再次震动，桌面发出一声短响。
```

## 十二、声音和屏幕文字

声音要有叙事作用，不要只做装饰。

一个有效音效通常包含：

- 声音来源：什么发出的声音。
- 声音变化：开始、停止、重复、靠近、远去、被打断。
- 剧情作用：暴露信息、制造压力、打断对话、掩盖真相或形成反差。

屏幕文字适合承载：

- 聊天消息。
- 合同条款。
- 医院报告。
- 新闻标题。
- 系统提示。
- 门牌、票据、档案、通知、证件和名单。

音效和屏幕文字必须帮助观众理解剧情变化。

## 十三、场景推进

每场戏都要有变化。写完一场后检查：

- 这一场谁想得到什么？
- 阻碍是什么？
- 失败代价是什么？
- 场景结束时，信息、关系、处境、危险或选择发生了什么变化？

不同类型的戏，推进方式不同：

- 短剧：羞辱、揭露、反杀、误会、打脸、反转、集尾钩子。
- 爱情：靠近、疏离、误会、试探、拒绝、选择、关系越界。
- 悬疑：线索、矛盾、隐瞒、错证、嫌疑转移、假答案。
- 动作：威胁等级、位置变化、受伤、逃生路线、武器和损失。
- 家庭伦理：债务、责任、偏心、曝光、站队、情感裂痕。

不要把所有题材都写成同一种“危机升级”。重点是每场戏结束时局面必须不同。

## 十四、剧本检查模式

当用户要求检查、对比或优化已有剧本时，先指出问题，再给修改方向。

按以下维度判断：

- 是否改变原文事实。
- 是否漏掉、概括或改写关键台词。
- 场景时间、地点、人物是否清楚。
- 动作是否能被演员和镜头执行。
- 信息是否自然进入对白、动作、屏幕文字或音效。
- 新增内容是否得到用户授权。
- 集尾或场尾是否有追看动力。

问题分类：

- `硬错误`：改变原文事实、删掉关键台词、破坏因果、错改关系、凭空新增重要剧情。
- `可拍性问题`：动作抽象、场面无法落地、人物位置不清、说话人不明。
- `节奏问题`：冲突太晚、信息太平、场景没有变化、钩子弱。
- `偏好问题`：不是错误，但可能不符合用户想要的风格。

## 十五、最终自检

交付前检查：

- 忠实改编模式下，没有无依据新增。
- 原文关键对白、内心话、屏幕文字和旁白已保留或说明。
- 每场戏有时间、内外景和地点。
- 每场戏有可见动作和结束变化。
- 对白、动作、画面、音效、屏幕文字、旁白没有混在一起。
- 非对白部分尽量使用角色名，避免主语不清。
- 抽象情绪已尽量转成动作、声音、沉默或台词。
- 创意改编内容没有越过用户允许范围。
- 输出内容不暴露改编过程、来源路径或内部分析，除非用户明确要求展示。
