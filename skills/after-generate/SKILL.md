# After Generate：成片后衔接与素材裂变入口

## 职责

你负责在一个视频母版已经存在之后继续推进用户下一步。这里的“母版”可以是刚由当前会话生成并交付的视频，也可以是用户上传/指定的已有成片。

关键目标：**视频产物生成完成并交付的同一轮，Pippit agent 就应主动告诉用户这条视频还可以继续做什么，包括“基于当前成片做投放素材裂变/多版本测试”，并给出具体裂变方向。不要等用户问“还能做什么”，也不要等用户先知道并主动说出“裂变”。**

本 skill 的定位是**薄衔接层**：

- 成片交付的同一轮，主动给用户说明当前视频可继续修改、结束交付，若是营销/投放内容还可做素材裂变，并列出可选裂变方向；
- 再确认用户是否满意当前母版以及下一步选择；
- 不满意时，将反馈路由回最早拥有该内容的原生产链或复刻链；
- 满意或用户愿意继续扩展，且创作目的为营销/投放时，进入素材裂变分支；
- 素材裂变只负责确定不变量、测试变量、变体数量与复用路径；
- 具体结构拆解、复刻规划、视频生成、分段与合并，尽量复用已有能力，不在本 skill 中重写。

## 适用场景

以下请求使用本能力：

- 一个营销/投放视频刚刚生成或交付后，即使用户尚未提到裂变，也需要主动提示“可以基于当前成片做素材裂变/多版本测试”；
- 一个视频刚刚生成或交付后，用户说“继续”“还可以做什么”“多做几版”“投放用”“裂变一下”“做素材矩阵”“做 A/B 测试素材”；
- 用户上传一个已制作完成的视频，希望基于它生成投放变体；
- 用户明确表示当前成片可用，希望换 Hook、卖点、场景、人群、风格、CTA 或口播版本；
- 需要判断成片后续是修改、结束，还是进入素材裂变。

以下请求不使用本能力：

- 还没有任何成片或母版视频；
- 用户从零开始创建营销视频，应使用营销视频创作能力；
- 用户提供参考视频要求做同款、二创或复刻，但尚未生成母版，应使用参考视频复刻能力；
- 用户只要求普通剪辑、压缩、转码或下载，不涉及成片满意度、修改或投放裂变。

## 核心原则

### 1. 视频产物交付同轮必须主动提供下一步入口

如果当前会话刚刚交付视频产物，Agent 应立即学习并使用本 skill，按照本 skill 的成片后提示继续服务用户；不要只完成视频交付就停止回复。

用户通常不知道“素材裂变”能力，不能把触发责任放到用户侧。只要当前上下文刚生成出可用视频产物，且内容是营销/投放/带货/推广场景，Pippit agent **必须在交付视频产物的同一轮回复里**，主动把裂变作为下一步选项之一告知用户，并给出 3～5 个可执行方向。

不要等用户下一轮问“还能做什么”；不要只说“视频已生成”；不要只给下载/查看链接。交付成片时必须同步给出“下一步主动服务”。

默认表达应同时覆盖“修改”和“裂变”，避免只问“满意吗”或只等待用户提出需求：

```text
这版视频已经生成了。接下来你可以这样处理：
1. 先修改当前视频里不满意的地方
2. 当前版本可以作为母版，继续做投放素材裂变（比如换开头 Hook、卖点、场景、人群、CTA）
3. 暂时不继续，直接交付当前版本
```

更推荐在营销/投放视频交付时直接给出裂变方向：

```text
视频已生成。这个版本可以作为投放母版继续放大：
1. 换开头 Hook：测试不同前三秒吸引点
2. 换卖点角度：测试不同购买理由
3. 换 CTA：测试“搜索词/商品卡/评论引导”等转化动作

如果你愿意，我可以先基于当前成片生成 3 条投放变体。
```

如果用户问“还能做什么”“下一步呢”“继续”，应主动解释裂变能力，而不是等用户说出“裂变”：

```text
如果这版能作为母版，我可以继续帮你做素材裂变：保留商品和素材不变，批量生成几个可投放变体，用来测试不同开头、卖点、场景、人群或 CTA。
```

### 2. 先确认母版是否可用

素材裂变只在母版基本可用后进行。若用户对当前成片不满意，先处理修改，不要把错误母版批量扩散成多条变体。

如果刚刚交付成片，默认第一句应把下一步选择说清楚：

```text
这版视频你想先怎么处理？
1. 先修改当前视频
2. 当前版本可以用，继续做投放素材裂变
3. 暂时不继续
```

如果用户已经明确表达“满意”“可以投放”“继续裂变”“多做几版”，可以跳过重复满意度询问，直接进入营销/投放判断或裂变。

### 3. after-generate 不拥有原视频创作逻辑

不要在本 skill 内重新写完整营销视频脚本、复刻方案或生成 Prompt。你只做路由与裂变策略：

- 有营销视频生产产物时，继承已确认的故事脚本、最终生成信息、素材绑定和修改路由；
- 有参考视频复刻反解/规划结果时，继承爆点、关键元素、source_elements、route、content_blocks、生成视频脚本和素材映射；
- 只有最终成片时，把该成片视为参考视频，按参考视频反解能力取得结构，再做裂变；
- 需要实际生成变体时，复用已有生成/复刻规划能力，按照其返回的片段顺序执行，不自行二次拆分。

### 4. 投放裂变默认一次只改变一个主变量

除非用户明确要求大改或自由发散，否则每条变体只改变一个主测试变量，保持其它关键条件不变。这样用户才能判断投放结果来自哪个变量。

默认不变量包括：商品事实、品牌/商品名、已验证卖点、用户满意的主体表达、已确认素材身份、核心 CTA 路径、比例和合规边界。

默认变量包括：Hook、卖点角度、证明方式、场景/人群、角色表达、视觉风格、口播/字幕、CTA 表达。

### 5. 不新增未经验证的事实型主张

裂变可以改表达方式和测试角度，但不得凭空增加价格、折扣、排名、认证、功效、成分、背书、限时资格、库存等事实型卖点。没有上游证据时，只能做安全定性表达或询问用户补充依据。

## 工作流

### 0. 入口校验：确认母版存在

进入本 skill 前，必须能在当前上下文中定位一个母版视频：

- 刚刚生成并交付的最终成片；
- 用户上传或指定的成片；
- 已有视频生成结果路径；
- 可访问的视频素材。

如果没有母版视频，说明需要先生成或提供一个视频，再进入成片后续流程。

### 1. 在视频产物交付同轮主动告知可选路径

读取[成片后路由](references/post-generate-routing.md)。

当检测到刚刚生成/交付了营销视频成片时，无论用户是否已经明确下一步，都应在交付视频的同一轮主动告知：

- 可以修改当前视频；
- 可以直接交付；
- 也可以基于当前视频做素材裂变/多版本测试，并给出具体方向。

此时 user-agent 或用户不需要先提出“裂变”，也不需要先问“还能做什么”。如果本 skill 的表现要被评测，应重点观察 Pippit agent 在视频产物交付的同一轮是否主动提出这个入口。

### 2. 满意度与下一步选择

判断用户当前意图：

- 明确满意并要求裂变：进入第 2 步；
- 明确不满意或提出修改：路由到修改；
- 未说明：主动给出“修改 / 裂变 / 结束”下一步选项；
- 明确结束：简短收尾。

修改路由时不要自行孤立改 Prompt。根据母版来源选择：

- 来源于营销视频创作链：回到故事脚本 / 最终生成信息 / 素材 / 成片的最早受影响节点；
- 来源于参考视频复刻链：回到反解 / 规划 / 素材映射 / 生成片段中最早受影响节点；
- 来源不明且只有成片：把成片作为参考视频，先反解再判断如何修改或复刻。

### 3. 判断是否营销/投放视频

若创作目的或上下文明确包含投放、广告、带货、推广、商品、品牌、App、服务、CTA、素材矩阵、A/B 测试等信号，视为营销/投放视频。

若不确定，用一句话询问，并同时说明如果是投放就可以继续裂变：

```text
这条视频后续是准备用于投放/推广吗？如果是，我可以基于当前母版继续做素材裂变；如果不是，我就按普通修改或交付处理。
```

若确认不是营销/投放，不主动推进素材裂变，可提供普通后续选择：修改、下载、换尺寸、加字幕、结束。

### 4. 选择结构来源

进入裂变前，确定可复用的结构来源，优先级如下：

1. **营销视频生产结构**：存在已确认故事脚本、最终生成信息、素材绑定、视频片段或项目上下文；
2. **参考视频复刻结构**：存在反解 manifest、Plan 结果、关键元素、source_elements、route、content_blocks、生成视频脚本；
3. **仅有最终成片**：将母版视频作为参考视频，调用参考视频反解能力取得结构，不自行脑补源结构。

不要因为只是为了裂变就重跑已有有效结构。已有结构仍可信时，直接继承。

### 5. 进入素材裂变分支

读取[素材裂变规则](references/material-fission.md)。

先用一句话把“为什么可裂变”讲清楚，再向用户给出可裂变方向，而不是空泛地问“你想裂变什么”。默认提供以下选项：

```text
这条视频已经有商品、人物和基础表达，可以把它当作投放母版继续裂变：保留商品事实和主体素材，只改变一个测试变量，生成多条可投放版本。
```

1. 换开头 Hook：保留主体内容，只测试前三秒吸引点；
2. 换卖点角度：同一商品/服务，测试不同购买理由；
3. 换证明方式：演示、前后对比、达人体验、场景结果等；
4. 换场景或人群：同一主张面向不同使用场景/受众；
5. 换表达风格：UGC、剧情、品牌感、教程感、测评感等；
6. 换 CTA 或口播收束：测试不同转化动作或话术；
7. 自由发散：由 Agent 基于母版设计一组投放变体。

若使用 `dynamic_questionnaire`，每个候选问题必须包含自定义/其他兜底项，并允许用户补充自由文本。

默认建议：先生成 3 条变体，保持原比例、商品事实和主体素材不变，每条只改变一个主变量。

### 6. 生成裂变任务说明

在调用下游能力前，用简洁语言确认：

- 当前母版中保留什么；
- 本次要测试哪个变量；
- 计划生成几条变体；
- 是否保持原比例；
- 是否会改口播、画面或素材。

如果用户选择自由发散，必须明确这是授权下游规划工具提出具体方向；不要把 Agent 自己设想的内容说成用户要求。

### 7. 复用既有能力生成变体

按结构来源选择执行方式：

- **营销视频结构来源**：把裂变变量路由到原营销视频链的最早受影响层，复用其故事脚本、最终生成信息、素材检查与生成确认规则；
- **参考视频复刻结构来源**：把当前母版或原反解结果作为参考来源，按复刻链的反解/Plan/Checker/生成规则执行；
- **仅有最终成片**：先对母版做反解，再按复刻链执行素材裂变变体。

多条变体生成时，保持每条变体的测试变量可解释。不要把中间 JSON、临时裁剪视频、内部媒体路径展示给用户。

### 8. 交付裂变结果

交付时按变体说明，而不是只给文件：

```text
这次基于母版生成了 3 条投放变体：
1. Hook 反差版：测试前三秒停留
2. 卖点证明版：测试可信演示
3. CTA 强转化版：测试点击商品卡动作
```

只交付最终可用视频或视频集合，不交付失败片段或内部中间产物。

## 结束条件

满足以下任一条件即可结束：

- 用户选择不继续；
- 用户确认当前成片已满足需求且不做裂变；
- 用户当前请求不是营销/投放，也没有修改诉求；
- 裂变所需素材、事实或母版不可获得，并已说明阻塞点；
- 下游生成或规划能力返回不可恢复错误。
