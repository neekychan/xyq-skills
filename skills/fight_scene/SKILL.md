# 武打动作片段 Skill

本 Skill 的参考文件路径：`/workspace/.skills/fight_scene/references/`

## 一、任务边界

本 Skill 默认交付一个完整、连续的动作片段：

1. 每次用户轮次只允许调用一次 `sandbox_generate_video`，一次调用只生成一段。
2. 当前模型单次生成上限已经明确渲染为 `{{.max_video_duration}}` 秒。新片缺省使用这个数值，编辑缺省保持原片合法时长；禁止根据模型名称、用户目标总时长或经验另猜上限。
3. 普通需求不主动拆段。只有用户明确要求多段、下一段、续上，或在超长问卷中主动选择逐段生成时，才跨用户轮次逐段处理。
4. 禁止生成角色图、音色、storyboard、creative_design，禁止同轮多段生成、`render_video` 与拼接。
5. 单次生成内部可用多镜头或连续阶段。任何 `sandbox_generate_video` 调用都计入唯一一次机会，包括返回参数错误、安审失败或其他失败的调用；失败后必须停止，禁止修改参数重试。

## 二、输入任务模式

先根据用户措辞与上传素材确定模式，模式影响 Prompt 首句：

| 模式 | 用户信号 | Prompt 开头 |
|------|----------|-------------|
| 新片参考 | 用这张图里的人打斗、参考这个造型生成新片 | 定义 `@图片N` 或 `@视频N` 中的主体与静态特征，再生成全新动作片段 |
| 视频编辑 | 把这段视频改成、给原视频加上、替换原动作 | `严格编辑<视频1>，将其中的……修改为……，未提及内容保持不变` |
| 视频延长 | 续写、接着打、延长这段、下一段 | 先截取上一成片末尾 5 秒，再用 `延长<视频1>，从<视频1>末尾的可见姿态和空间状态继续……` |
| 纯文本生成 | 无上传素材 | 直接定义主体、服装、武器、场景与动作体系 |

数量合法且与任务相关的上传素材，以及问卷最终选中的素材，必须直接传入唯一一次视频调用。图片放入 `ImageList`，普通参考或编辑视频放入 `VideoList`，音频放入 `AudioList`。续段时以截出的末尾 5 秒替代上一整段进入 `VideoList`。重要素材按 Prompt 首次引用顺序排列。

编辑和延长是特殊任务语法。Prompt 首句中的 `<视频1>` 必须保留尖括号字面量：编辑使用 `严格编辑<视频1>`，延长使用 `延长<视频1>`；禁止改成 `@视频1` 或“参考<视频1>”。`@视频N` 只用于新片参考。

## 三、主类型路由

先选一个主类型。跨风格需求最多再加载一个主类型 Ref，避免多套规则互相争夺。

| 主类型 | 触发信号 | 对应 Ref |
|--------|----------|----------|
| 现代写实 | 拳击、MMA、擂台、咏春、泰拳、空手道、街头格斗、写实近战 | `references/fight-modern.md` |
| 古代写实 | 古装、真实武侠、传统武术、刀剑枪棍、竹林、客栈、屋顶追斗 | `references/fight-period.md` |
| 玄幻超能 | 仙侠、剑气、法术、元素、暗黑神话、超级能力、酷炫特效 | `references/fight-fantasy.md` |
| 特摄 | 特摄、皮套、骑士、战队、怪人、巨大化、变身、微缩城市 | `references/fight-tokusatsu.md` |
| 动漫动画 | 动漫、赛璐璐、水墨、三渲二、3D 国漫、美漫、火柴人、漫画格 | `references/fight-animation.md` |
| 科幻异形 | 机甲、怪兽、生化体、赛博义体、外骨骼、能量刃、太空战士 | `references/fight-scifi-creature.md` |
| 游戏化格斗 | 血条、技能条、KO、街机横版、第三人称 ACT、游戏实机、像素格斗 | `references/fight-game.md` |
| 动作变体 | 道具喜剧、跑酷追击、枪斗、节奏卡点、单人炫技、环境机关 | `references/fight-stunt.md` |
| 变身显圣 | 变身秒杀、一击秒了、人前显圣、觉醒碾压、扮猪吃虎、变身AOE清场 | `references/fight-transform.md` |

判定补充：

- “武打、武侠、功夫”且没有现代信号时，优先古代写实。
- “格斗、搏击、拳击”优先现代写实。
- 视觉风格决定主 Ref。例：“赛璐璐仙侠”读取动画 + 玄幻；“水墨机甲”读取动画 + 科幻异形。
- 用户明确第一人称、真 POV、主观视角、第一人称游戏或头戴相机时，在主 Ref 之外追加 `references/fight-pov.md`。泛称“游戏视角”只路由 `fight-game.md`，不自动判定为第一人称。
- 变身显圣与特摄的分界：诉求核心是“变身后碾压秒杀、旁观者震撼”走变身显圣；诉求核心是“皮套英雄与怪人来回交手”走特摄，即使含变身。用户只说“变身打怪兽”且无碾压信号时，问卷确认对战结构。变身显圣可与国风、科幻、特摄画风叠加，此时以 `fight-transform.md` 为主 Ref。

## 四、关键确认

向用户收集任何创作参数只有一条通道：`dynamic_questionnaire`。禁止在回复文本中罗列问题、请用户"提供以下信息"或以其他文字形式提问；用户输入为空、只有打招呼或引导语、或只有一个模糊意图时，同样走问卷，把全部缺失维度一次组卷（需要角色素材时用单选题让用户在"AI 生成角色"与"我来上传参考图"之间选择），而不是用文字引导用户补充。

类型初判后、搜索和创作前，先读取 `references/fight-questionnaire.md`。问卷是缺省路径：存在缺失、冲突、非法参数、超长取舍或素材超量时，用至多一次 `dynamic_questionnaire` 集中确认，跳过是少数例外。跳过问卷的唯一合法条件：主类型、对战结构、动作体系、场景、主导镜头、打击与特效尺度六个强制维度都能从用户原话或素材可见内容指认来源；核对在内部完成，不输出核对过程。任何一项要靠“默认”“推荐”“无需确认”补位即触发问卷；拿不准某项是否已明确时，按缺失处理并发起问卷。题材词只能提供主类型来源：“仙侠”“功夫”等词不构成场景、主导镜头或打击尺度的来源，这三项用户未明示时必须问卷。触发问卷后逐行核对按需选题表，全部命中维度一次组卷、题目与命中行一一对应（核对不输出）。完成关键确认之前不发起 `pippit_omni_search`。普通需求优先单段，只有用户明确选择多段才进入续段流程。

| 问卷题数 | 推荐项位置 | selected 设置 | emoji |
|---------|-----------|--------------|-------|
| 仅 1 题 | options 第一位 | 所有选项显式 `selected: false`，禁止 true | 每个选项必带 |
| ≥ 2 题 | 每题 options 第一位 | 每题推荐项在选项对象内 `selected: true`，其余不设 | 不要求 |

所有时长文案和问卷选项必须逐字使用本文件已渲染的上限 `{{.max_video_duration}}` 秒。调用视频工具前核对 `Duration ≤ {{.max_video_duration}}`，不允许先试错再改值。

## 五、执行流程

静默执行纪律：五维来源核对、命中行核对、采纳手法提炼、差异化核对与生成前自检全部在内部完成，不输出清单、勾选、声明、规划或 Prompt 正文，禁止写成任何 md、txt 或临时文件。唯一例外：生成前按 `fight-prompt.md` 第三节在回复中输出一张分镜预算表。与用户只保留简短自然的交互——每步至多一两句话说明正在做什么。读完 Ref、自审通过后直接调用视频生成。

### 步骤 1：检查素材与锁定约束

1. 有上传素材时先用 `sandbox_read` 查看每个文件，记录主体、服装或皮套、武器、主色、材质、体型比例和场景锚点。
2. 区分新片参考、编辑、延长三类素材任务，并判断当前轮属于独立单段、多段首段还是多段续段。
3. 编辑请求先读取 `fight-edit.md` 并检查源片时长；续段请求先读取 `fight-continuation.md` 并定位上一成片候选。把编辑区间、续段候选与其他缺失项合并到第四节的至多一次问卷。
4. 无需确认时直接进入下一步。问卷禁止与其他工具并行。

### 步骤 2：编辑或续段素材预处理

编辑模式严格执行 `fight-edit.md`，只在用户确认后处理超长、过短或非整数时长源片。续段模式严格执行 `fight-continuation.md`，先截上一成片末尾 5 秒，再以 `延长<视频1>` 生成当前下一段。新片与多段首段跳过。

`<视频1>` 的尖括号是延长任务语法的一部分，必须原样保留，禁止改写成 `@视频1` 或“参考视频1”。

### 步骤 3：搜索可落地灵感

调用 `pippit_omni_search`，优先 `Type=inspiration`。检索词优先从下表取；需要更贴题时按“动作类目 + 核心题材”两段式自拟，禁止叠加角色、兵器或场景第三层限定；无结果时换另一个表内词或同义主题重试一次。

| 主类型 | 首选检索词 |
|--------|-----------|
| 现代写实 | 功夫格斗、街头格斗 |
| 古代写实 | 武侠打斗、古装武打 |
| 玄幻超能 | 仙侠战斗、玄幻打斗 |
| 特摄 | 特摄战斗、怪兽大战 |
| 动漫动画 | 动漫打斗、国漫战斗、水墨打斗 |
| 科幻异形 | 机甲格斗、怪兽大战 |
| 游戏化格斗 | 格斗游戏、游戏实机 |
| 动作变体 | 功夫喜剧、跑酷追逐、枪战动作 |
| 变身显圣 | 变身战斗、人前显圣 |

- 用户明确要求热点时再补一次 `Type=hotspot`。普通续段不搜索，只有用户要求新打法、风格或热点时例外。
- 搜索后在内部提炼至多 3 条能落进具体镜头或阶段的手法，融入本次设计；提炼过程与清单不输出。搜索结果与需求无关时直接创作。禁止照搬案例全文或具体 IP，禁止把 Ref 示例内容当作搜索所得。

### 步骤 4：按需加载 Ref

构造 Prompt 前并行读取 `fight-rules.md`、`fight-prompt.md` 和主类型 Ref。命中真第一人称时追加 `fight-pov.md`；明确跨风格时可追加第二个主类型 Ref，主类型 Ref 总数最多 2 个。

### 步骤 5：规划当前段动作弧线

按 `fight-prompt.md` 在内部完成战斗命题、角色差异、空间地图、强度曲线、镜头、段落与目标映射，并确认主体外观、场景、决定性动作三项与已加载类型 Ref 示例明确不同，禁止落回示例写法。规划过程不输出，唯一对外产物是按 `fight-prompt.md` 第三节填写的分镜预算表（回复文本）；禁止把规划、storyboard 或 Prompt 写入任何沙盒文件。默认单段开场即交锋、全程密集攻防、结尾不强求胜负；明确多段的非最终段停在稳定可续姿态。

### 步骤 6：唯一一次视频生成

参数合法性和素材上限以 `fight-rules.md` 为唯一来源。编排后的专业 Prompt 通过 `Prompt` 参数直接传入，禁止透传原话，禁止先写文件再用 `PromptPath` 引用；`Ratio` 缺省 16:9；新片与续段时长缺省 `{{.max_video_duration}}`，编辑缺省原片合法时长。素材按 Prompt 引用顺序进入对应 List，无素材传 `[]`；续段尾片固定为 `VideoList` 第一项，用户音频用 `@音频N` 绑定用途。`OutputPath` 使用 `output/fight_scene.mp4`，目录无需预先创建；不要设置 `UseRunPrompt=true`。

调用 `sandbox_generate_video` 前，静默逐项核对 `fight-rules.md` 失败前自检清单，其中 `Duration` 与本文件已渲染的 `{{.max_video_duration}}` 做数值比较；核对不输出，全部通过后直接发起调用。规划与调用之间禁止插入 `sandbox_write`、`sandbox_bash` 或任何回显确认；生成只能由 `sandbox_generate_video` 工具本身发起，禁止用脚本模拟或代替。本次调用是唯一一次机会，工具返回任何错误都立即停止。

### 步骤 7：交付并结束

`sandbox_generate_video` 成功返回后立即调用 `present_sandbox_file`，使用工具实际返回路径，设置 `interrupt=true`；中间最多允许一次 `todo_write` 状态更新，禁止插入其他工具。交付后立即结束，不追加总结、追问或返工建议。
