# 单段视频流程

仅当根 Skill §0.4 判定为单段视频时加载，直通与常规构造都走本文件。本文件是单段路径的唯一流程权威：负责入口复核、直通分叉、Prompt 构造、一次生成、按需渲染和质检交付。根 Skill 负责路由判定、体裁分类、铁律与加载规则；Prompt 写法由 `storyboard/` 下的 ref 负责。

全文出现的"单次生成上限"均指根 Skill §0.4 声明的本次运行单次生成上限秒数，禁止在本文件内改写或另行推断。

## Workflow 与知识清单

严格按 Step 1 → Step 7 执行。每个 Step 在实际使用前才读取本表列出的知识；未命中的条件知识不得预加载。

| Step | 目标 | 必读知识 | 条件知识 | 产物 / 退出条件 |
|---|---|---|---|---|
| 1. 入口复核 | 确认单段路径成立，锁定硬约束与真实上传素材 | 无 | 无 | 硬约束账本完整；总时长仍未超过单次生成上限 |
| 2. 直通分叉 | 判定是否直通，选定执行体 | 无 | 无 | 命中直通 → 按 Step 2 写好 Prompt 后**直接跳 Step 5**；未命中 → 进 Step 3 |
| 3. Prompt 知识 | 加载本次 Prompt 所需写法 | `storyboard/prompt-craft.md` | 见 Step 3 触发表 | 当前任务所需知识已加载 |
| 4. 素材绑定与 Prompt 构造 | 写成一条可直接生成的完整 Prompt | 用 Step 3 已加载知识，不新增 | 用户上传分镜图读 `storyboard/storyboard-to-video.md` | Prompt、素材列表、Duration、Ratio 一致且自检通过 |
| 5. 生成 | 说明方案并完成一次视频生成 | 无 | 无 | `assets/{project}/shot_01.mp4` 真实存在 |
| 6. 按需渲染 | 一次完成字幕与已有 BGM 合成 | 无 | 无 | 无需渲染则沿用单段文件；需要时产出 `output.mp4` |
| 7. 质检与交付 | 验证实际最终视频后交付 | `review/quality-control.md` §二 | 用户要求重做/改镜头读 §一 | 最终文件存在且质量复核通过 |

**直通命中时的加载禁令**：只读本文件，**Step 3 整步跳过，不读任何知识 ref**——含 `prompt-craft.md`、`dialogue-rules.md`、体裁分册及 ref 内部的"未加载时补加载"条款。这些文件通篇是改写与密度指令，读入即诱导重写用户脚本；直通所需的口型句式与固定尾注已内联在 Step 2 中。

## 全流程约束

本文件及各阶段加载的 refs 是常规单段路径的唯一依据。根 Skill 的 §1.0 核心铁律、§1.0b 保真铁律、§1.2 交互控制、§1.2b 意图识别在本流程内继续生效，本文件不复制、不改写。

1. 单段视频只表示**一次** `sandbox_generate_video` 调用，不限制 Prompt 内部的画面阶段、切镜和场景转场
2. 禁止创建 `creative_design.md` 或 `storyboard.md`，禁止生成参考素材（例外见 Step 4）
3. 禁止因镜头多、动作多、场景多或剧情复杂改成多次生成
4. 生成前不设停顿确认门，用简明方案说明代替（根 Skill §1.0b 第 7 条）

## Step 1：入口复核

1. 复核单段路径成立：**单段/多段判定只看根 Skill §0.2 的 scope + 时长，不看剧情复杂度**。`sandbox_generate_video` 单次调用就能在单次生成上限内完成多个分镜、切镜、转场和多句台词——只要 scope ≤ 单段且总时长 ≤ 单次生成上限，无论剧情多复杂，都走单段流程。"有故事线""有镜头切换""有冲突转折""场景跨度大"都不构成走多段流程的理由
2. 确认硬约束账本已覆盖风格、总时长、语言、字幕、BGM、视频比例、素材使用；未提及字段保持"未指定"
3. 若内容或用户选择变化后总时长超过单次生成上限，停止本流程并读取 `workflow/multi-segment.md`；读取成功后该文件成为唯一 active workflow，本文件立即失效。已完成的上游说明不重复确认

## Step 2：直通分叉

用户输入已构成根 Skill §0.1 完整内容描述（含时间轴/分镜表、逐段画面描述或完整剧本）→ 命中直通。用户只写了一句话、一个想法或一段简短描述**不构成直通**；判不准 → 进 Step 3 走常规构造。

命中直通时用户脚本就是生视频提示词，禁止重写重组。**用户给出完整内容描述 = 内容取舍已由用户完成**，"Prompt 做减法"与密度适配规则不适用于用户原文，禁止压缩、合并、删减、重排用户原文的镜头、描述与音效。**缺失的维度（风格、外观细节、运镜、音效）一律留白交给视频模型发挥，不问卷、不补写**——Agent 自补的风格词、运镜、外观描述比模型默认发挥更易翻车；时长/比例缺失仍按创作设置与工具默认取值。按脚本所在位置二选一执行，写好后**直接跳 Step 5 生成**：

**程序直传（默认）**：完整内容描述就在当轮用户消息里，且当轮除脚本外至多附带简短引导语或参数说明 → 调用时 `UseRunPrompt: true`、`Prompt` 传空字符串，系统自动把当轮用户消息全文逐字作为生视频提示词——不抄录、不转写、不补任何内容，脚本再长也零漂移。用户素材照常传入 ImageList/VideoList/AudioList（Prompt 为空，无需 `@` 引用），`Duration`/`Ratio` 照常按硬约束账本与创作设置传参。

**抄录直通（回退）**：完整内容描述不在当轮消息里（脚本在此前轮次，当轮是确认、问卷答复或重做指令），或当轮混入大段与画面无关的对话、修改意见、多项任务 → 不开 `UseRunPrompt`，从对话中定位用户脚本原文逐字抄入 `Prompt`，只做三类转写适配，超出即越权：

1. 声音标记转写（文本逐字不动）：台词套口型句式 `[角色]嘴唇随每个字清晰地一开一合，说：{台词}。说完嘴唇合拢`，同画面不说话的角色补 `嘴唇紧闭不说话`，画外音/旁白不写口型；音效/环境音转 `<声音描述>` 标记嵌在原对应画面位置
2. 技术参数对齐硬约束账本，末行写 `时长：N秒，比例：X:Y`；原文内部参数矛盾以用户末次明示为准
3. 末尾补固定尾注：`不要生成水印，不要生成logo，保持无字幕`＋`五官清晰不变形、人体结构正常、服装发型一致`＋`4K超高清、画面稳定无模糊、电影质感`。用户已写明的同类约束以用户版本为准、不重复不改写；BGM 只按用户明示处理，未提则不加任何 BGM 约束

抄录直通提交前自检：产出 Prompt 中出现用户原文没有的实体名词、外观描述、色调词、机位/运镜词 → 越权补写，删掉后再提交（三类转写产物与固定尾注除外）。

两种模式下台词预计算与超载拦截照常执行（根 Skill §0.2）；生成前说明压缩为两三句话（参数确认 + 按用户脚本直接生成），禁止逐段复述用户内容或输出层级分析。

## Step 3：加载 Prompt 知识

**直通命中时本步整体跳过。** 同一阶段命中的多个 ref 必须在单条消息内并发发起 `sandbox_read` 一次性读完，禁止读一个想一下再读下一个的串行方式。

| 优先级 | 触发条件 | 读取知识 |
|---|---|---|
| P0 | 所有常规单段视频 | `storyboard/prompt-craft.md` |
| P0 | 有角色台词、旁白或内心独白 | `storyboard/dialogue-rules.md` |
| P0 | 用户上传分镜图并要求据此生成视频 | `storyboard/storyboard-to-video.md`（直传铁律与轻 Prompt 适用，格→段装箱一节不适用） |
| P1 | 命中根 Skill §1.2b 体裁分类 | 对应的一个 `storyboard/*-prompt.md` |
| P1 | 视频编辑/延长、首帧或首尾帧锁定、运镜复刻，或需要现成任务骨架 | `storyboard/prompt-patterns.md` |

P0 命中项全部加载；P1 按用户显式要求和本次生成的直接必要性取舍。每阶段建议不超过 3 个 ref，信息密集场景最多 4 个；被丢弃的 ref 只在内部自审中记 `⚠️ 未加载 {文件}`，不写入交付给用户的正文。

## Step 4：素材绑定与 Prompt 构造

**素材绑定**（直通同样执行）：积极使用用户已提供的素材，放入 ImageList 并用 `@图片N` 语法引用，列表顺序与 Prompt 中的 `@` 编号严格一致。VideoList、AudioList 同理。

用户上传含人物的图片时，默认意图是**使用图中人物形象**，而非复刻背景场景；仅当用户明确要求使用原图场景时，才同时作为场景参考。用户上传分镜图时直接进入 ImageList，图中已有的角色、场景、道具不再重复生成。

> 例外：仅当用户素材质量过低或缺少必要主体时，才生成一张参考图辅助。

**Prompt 构造**：分镜表里的多个时间段（0-3s/3-6s…）用画面阶段 + 切镜词在同一条 Prompt 内表达，模型能在单次调用内完成分镜切换和场景转场。

**Duration 取值**：`Duration = 声音文本耗时下限 + 不与说话并行的独立动作所需时间（无则为 0）+ 0.5s 收束`；无声音文本时 = 独立画面段落数 × 4-6s 取低档。禁止硬凑到单次生成上限注水，也不得短于声音文本承载下限。音频驱动（MV）与体裁 ref 明定的功能性时长按对应 ref 取值；用户明确要求舒缓/留白时收束值放宽至 1-2s。声音文本耗时下限引用根 Skill §0.2 台词时长预计算结果，禁止手算或按固定语速重新估算。

**用户写的镜头数/时间段 ≠ 调用次数**（根 Skill §0.2 段数解耦）：同一场景的连续镜头合并为一次调用，不同场景但总时长未超过单次生成上限的也合并为单次调用；用户写的多个时间段写进同一条 Prompt 的画面阶段描述。**但仍须按 `prompt-craft.md` 的密度规则适配 Prompt**——用户描述中超出模型能力的部分（如单段 5 个以上动作、复杂手部交互、多人紧密肢体接触）先简化非核心细节、阶段化表达或降低执行难度，禁止把复杂度本身当作增加调用次数的理由。

调用生成工具前逐项检查，任一项不通过先修 Prompt 或素材映射，禁止带病调用：

1. **需求覆盖**：主体、场景、顺序、动作、镜头、风格、声音、时长、比例、素材用途和结尾均有落点
2. **文本保真**：有台词、对白或旁白时保持原话、原顺序、原语言，并按 `dialogue-rules.md` 检查口型或旁白结构
3. **素材一致**：每个 `@` 引用都有对应列表项和明确用途，无原始文件名、错号或未使用的上传文件
4. **密度可执行**：已删除 Agent 自产的冗余修饰和不可拍文学描述，但未删用户硬约束
5. **字幕与音乐**：普通字幕不写进视频 Prompt；用户提供的独立 BGM 文件留给 Step 6 的 `render_video`
6. **任务模式**：仅编辑、延长或首帧/首尾帧锁定任务传对应 `TaskType`，普通生成不传

## Step 5：生成

生成前先输出简明方案说明（参数确认 + 画面预期），在同一条消息中调用工具，不设停顿确认门。

只调用一次 `sandbox_generate_video`，参数按根 Skill §二 工具调用规范；`OutputPath` 取 `assets/{project}/shot_01.mp4`。

安审失败立即按根 Skill §1.0 停止，不改词、不删素材、不自行重试。其他失败必须先报告实际错误并保留调用参数，禁止把失败状态当作产物完成。

## Step 6：按需渲染

角色台词和旁白人声由视频生成模型在本次生成中直接产出，禁止再用 `sandbox_generate_audio` 逐句覆盖。

- 没有成片级字幕或独立 BGM 文件：`shot_01.mp4` 即最终视频
- 用户明确要求普通字幕：调用一次 `render_video`，传入 `show_subtitle: true`
- 用户提供独立 BGM 文件：在同一次 `render_video` 中传入；若同时要求字幕，一次完成两个诉求
- 需要渲染时输出 `assets/{project}/output.mp4`，禁止先后多次重拼

用户只提出"配一段 BGM"但没有提供音乐文件时，不从零生成音乐，按 `review/post-delivery.md` §D 降级说明。

## Step 7：质量复核与交付

视频产生后、交付前读取 `review/quality-control.md` §二，至少确认：

1. 最终文件真实存在且可作为视频产物交付
2. 时长、比例、主体、核心动作、结尾和用户素材使用符合硬约束账本
3. 台词/旁白完整，无截断、重复或语言漂移
4. 无意外字幕、水印、logo、主体复制或明显肢体崩坏

Prompt 或参数存在明确修复点时，按 `quality-control.md` 修正后重新生成；禁止无修改地盲目抽卡。只有拿到实际最终视频路径后才可宣布完成。

交付后给出 2-3 个编号建议（根 Skill §1.2 下一步建议规则）：①满意则结束 ②修改画面/动作 ③换个风格试试。用户随后提出的修改诉求按根 Skill §0.3 编辑回合重新分流。
