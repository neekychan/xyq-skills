# 多段视频流程

仅当根 Skill §0.4 判定为多段视频时加载。本文件是多段路径的唯一流程权威：负责创意设计、参考素材、分镜规划、分段生成、拼接合成和素材组织。根 Skill 负责路由判定、体裁分类、铁律与加载规则；创意设计由 `creative_agent` 在隔离上下文中完成，Prompt 写法由 `generate_shot_video_prompt_plan` 在隔离上下文中加载 storyboard ref 完成。

全文出现的"单次生成上限"均指根 Skill §0.4 声明的本次运行单次生成上限秒数，禁止在本文件内改写或另行推断。

## Workflow 与知识清单

严格按 Step 1 → Step 5 执行。每个 Step 在实际使用前才读取本表列出的知识；禁止在创意设计阶段提前读素材生成或分镜规划 ref。

| Step | Owner | 目标 | 必读知识 | 条件知识 | 产物 / 退出条件 |
|---|---|---|---|---|---|
| 1. 创意设计 | `creative_agent` | 产出创意脚本 | 主 Agent 不读取任何 creative ref | 创意助手旁路时整步跳过 | `creative_design.md` 落盘且通过自审 |
| 2. 参考素材 | 主 Agent | 过单段回退闸门与积分闸门，再做风格锚点、参考图与音色锚定 | `assets/ref-image-design.md`（两道闸门都通过后才读） | 多段+重复角色读 `assets/character-lock.md` | 积分不足 → 停止并交还用户；否则素材路径全部写回创意脚本并过创意与素材确认门 |
| 3. 分镜规划 | `generate_shot_video_prompt_plan` | 全片分段、Prompt 构造、素材映射和内置 review | 主 Agent 不读 `storyboard/` 下任何 ref | 无 | `storyboard.md` 产出且通过结果自审与用户确认 |
| 4. 分段生成 | 主 Agent | 按所选策略生成全部分段 | 无 | 无 | 各 `shot_NN.mp4` 真实存在 |
| 5. 拼接合成 | 主 Agent | 合成最终成片并质检 | `review/quality-control.md` §二 | 用户要求重做/改镜头读 §一 | `output.mp4` 存在且质量复核通过 |

## 全流程约束

本文件及各阶段加载的 refs 是多段路径的唯一依据。根 Skill 的 §1.0 核心铁律、§1.0b 保真铁律、§1.2 交互控制、§1.2b 意图识别在本流程内继续生效，本文件不复制、不改写。

1. 两道停顿门必设：创意与素材确认门（Step 2 末尾）、`storyboard.md` 确认门（Step 3 末尾）。用户明确要求跳过确认时按根 Skill §1.2 确认门原则降级为简明说明、不停顿
2. 分阶段加载，禁止提前读：各阶段只读本阶段 ref
3. 修改任何产物后，必须先回写事实源文件，再继续下游步骤

**逐镜头模式**（用户明确表示"一步步来""先做第 X 个镜头""一个一个来"）：严格遵循用户节奏，每轮对话**只完成用户要求的单个镜头**；**禁止在用户未要求时自动合成最终视频**；每完成一个镜头后展示效果并等待用户决定下一步。

## Step 1：创意设计

**IMPORTANT - 创意助手旁路**：上下文表明当前处于创意助手模式、已有 `plan.md` 时，**整个创意设计 Step 1 跳过**——不写 `creative_design.md`、不读体裁 creative ref、不发散构思、不跑创意自审、不走创意确认门。`plan.md` 已是用户在创意助手阶段确认过的创意成品，直接作为下游的创意脚本使用。此后 Step 2 素材生成、Step 3 分镜规划中，凡是原本读取 `creative_design.md` 的地方一律改读 `plan.md`（素材绑定信息也从 plan.md 提取；plan.md 未列素材即视为"需本流程生成"）。进 Step 2 前只做一次台词护栏（不改 plan.md 内容）：用 `count_chars.py` 校验 plan.md 全部台词/旁白耗时下限累加，若 > 用户指定时长 → 按根 Skill §0.2 台词超载拦截出问卷让用户定（延长/删减），用户未定前不进 Step 2；未超载或用户未指定时长则直接进 Step 2。素材阶段自审门等 Step 2 内既有门禁照常执行，不受旁路影响。

无 `plan.md`（常规模式）：创意设计一律由创意 SubAgent 完成，主 Agent 不判创意层填充度、**不读取任何 creative ref**，直接调用 `creative_agent`。禁止跳过创意设计直接做分镜。

**`background`**（逐项填写，用户原文逐字转录不得概括）：

```text
项目目录：assets/{project}/
用户需求原文：{用户输入逐字转录，含全部台词与要求；有问卷结果时附在末尾}
素材清单：{upload/xxx — 一句话用途说明，每行一个 | 无}
总时长：{N秒 | N秒左右 | 未指定}
视频比例：{比例 | 未指定}
语言/字幕/BGM：{用户明示内容 | 未指定}
单段时长上限：{{ .max_video_duration }}秒
体裁提示：{根 Skill §0.2 命中的体裁 | 无}
```

**`task`**：`基于 background 产出创意脚本，写入 assets/{project}/creative_design.md，完成后返回文件路径。`

SubAgent 返回后，主 Agent 用 `sandbox_read` 回读 `creative_design.md`，按下方要求自审；SubAgent 返回的「未解决项」非"无"时，在自审中优先处置。

**落盘要求**（`creative_agent` 产出的验收标准，自审时逐条核对，不达标用 `sandbox_edit` 修正或要求重做）：

- `creative_design.md` 必须包含整体风格、用户硬约束、故事线、剧本要素（角色/物品/场景）、素材绑定关系、剧本设计
- `整体风格` 是风格的唯一落点，必须覆盖硬约束账本中的用户指定/问卷确认风格；`用户硬约束` 小节写入总时长、语言、字幕、BGM、视频比例、素材使用，未指定字段写"未指定"，禁止补成默认值
- **同角色多形象仅在本多段流程生效**：剧情要求同一角色以多个显著不同外观跨场次出现时，按 `creative/creative-design-format.md` 为该角色定义恰好一个基础形象、身份锚点、各变化形象的保留项/变化项与出现场次；每场明确当前形象，未标时回退基础形象。表情、姿势、光线、小配饰或局部颜色变化不算独立形象
- 用户原文中的台词/对白/旁白必须逐字保留；动作描写必须在剧本设计中按原顺序完整承接，写入 Prompt 时保留主体、动作链、顺序和结果
- 用户上传素材必须以 sandbox 路径写入 `素材绑定关系` 表中对应角色/场景/物品的参考图片、参考视频、参考音频素材列；用户上传了素材时默认用途——角色照片默认直接用作角色参考图，场景图默认用作场景参考，视频默认用作动作/构图/动态参考，音频默认用作音色/声音参考；仅当用户素材质量过低或主体不完整时才在备注标注"仅供风格参考，需生成角色参考图"，风格差异不是降级理由

**产出**：`assets/{project}/creative_design.md`，包含整体风格、用户硬约束、故事线、剧本要素、素材绑定关系、剧本设计，并在 `素材绑定关系` 表中以 sandbox 路径列出参考图片、参考视频、参考音频素材。

**IMPORTANT - creative_design.md 写完后必须自审**：用 `sandbox_read` 回读 `creative_design.md`。自审强度按创意层填充度分级：**创意层=满 → 跑①②、③不适用**——②天然豁免用户原文的镜头指令，只会命中 agent 自产的连接/过渡句；对用户叙事结构做③类改写属越权。**创意层=部分/空 → ①②③ 全跑**：

**① 用户要求保真（最高优先级）**：
- **硬约束账本核对**：`整体风格` 与 `用户硬约束` 小节必须共同覆盖用户原始输入和问卷结果。用户指定或确认过的风格必须落到 `整体风格`；总时长、语言、字幕、BGM、视频比例、素材使用要求必须逐项写入 `用户硬约束`。用户未提及的字段必须保持"未指定"，禁止写成默认值、推荐值或 Agent 偏好
- 用户指定的时长是否被遵循（总时长不超出、不大幅缩短）；`剧本设计` 首行是否写了 `总时长预算`，各场 `预估时长` 加总是否 ≤ 预算（超出 → 砍场或压场，禁止扩预算）
- **总时长预算来源复核（未指定时长时强制）**：用户未指定总时长时，`总时长预算` 必须等于根 Skill §0.2 内容量估时结果，**禁止用"用户写的段数×每段秒数"反推**。若预算超过单次生成上限，逐场核对独立画面段落数——同一主体/同一支舞/同一动作的多视角多机位不计入独立段落（根 Skill §0.2 段数解耦）。核对后独立段落 <3 个 → 预算必须拉回单次生成上限以内的单段，用 `sandbox_edit` 改写 `总时长预算` 与场次结构。这道复核与 Step 2 单段回退闸门前后对称，防止段数反推虚高的预算绕过闸门
- **风格/比例/声音落点**：硬约束账本中已指定的风格必须落到 `整体风格`，视频比例必须落到 `用户硬约束`；未指定字段保持"未指定"，禁止补默认值。语言必须与硬约束账本一致；字幕只记录需求，不写进剧本动作或台词；BGM 只记录需求或"未指定"，禁止把 BGM 当作角色台词、旁白或画面内容
- **信息丢失检查**：回溯用户原始输入，逐项核对主体对象、场景设计、用户原文时间线、片段顺序、指定动作、指定镜头/景别、场景元素、声音/BGM、氛围、结尾方式是否都落入 `creative_design.md`。遗漏任一明确要求 → 用 `sandbox_edit` 补回
- **冲突新增检查**：检查 `creative_design.md` 是否新增了与用户输入冲突的信息，包括主体被替换、片段顺序改变、动作链改变、风格/色调相反、BGM/音效相反、场景元素被替换、结尾方式改变。发现冲突 → 删除或改回用户要求。Agent 自产补充只允许填补未指定缺口
- **台词总耗时校验**：将 creative_design.md 中全部台词/旁白（含 Agent 自产）传入 `count_chars.py`，耗时下限累加必须 ≤ 总时长预算。超出时：超出部分源于 Agent 自产文案 → 当场压缩至装得下（创意层是修改文案的唯一合法阶段，分镜层无权改写；压缩只精简措辞，不得删除核心叙事节点，压缩后必须再次调用 `count_chars.py` 确认达标）；源于用户原文台词 → 按根 Skill §0.2 台词超载拦截出问卷。**禁止带着超载的台词量进入后续阶段**
- **台词/对白保真**：回溯用户原始输入，逐句核对——用户原文中出现的角色台词和对白必须在 `creative_design.md` 中完整保留。**"不需要旁白"/"纯音乐+环境音"等声音设计选择只影响 Agent 额外添加的旁白，不得作为删除用户原文台词的依据**。发现缺失用户原文台词 → 用 `sandbox_edit` 补齐
- **用户素材保真**：用 `sandbox_bash` 执行 `ls upload/` 确认用户实际上传了哪些文件，逐个核对 `creative_design.md` 的 `素材绑定关系` 表。用户明确指定用途时，每个上传文件必须绑定到对应角色、场景、物品、动作或时间范围；用户未指定用途时，才按本阶段默认用途绑定。路径必须正确（`upload/文件名`）。发现文件未引用或绑定错误 → 用 `sandbox_edit` 补齐或修正
- **多形象保真**：逐个多形象角色核对——恰好一个基础形象；各变化形象保留身份锚点且确有显著外观差异；每个形象至少绑定一个实际场次；每场 `出场形象` 与素材绑定行一致；各形象默认共用角色级音色，只有用户或剧情明确要求且已写入 `音色例外` 时才允许变化。缺失或冲突 → 用 `sandbox_edit` 修正，禁止把同一角色拆成多个角色规避校验

**② 镜头级信息越界扫描**：通读 `剧本设计` 的动作描述与 `整体风格`，命中景别/机位/运镜/切镜/剪辑转场/逐秒区间（判据见 `creative/creative-design-format.md` 细节下沉）→ 用 `sandbox_edit` 改写为"观众看到的画面 + 情绪效果"，删去"用什么镜头怎么拍"。用户原文明确指定的时间线或镜头指令除外——属用户要求，逐字保留，禁止扫掉

**③ 叙事质量**：
- 起承转合弧线是否完整，每集是否落在钩子上
- 相邻场次是否有信息增量（同质场次必须合并）
- 角色动机和情绪弧线是否连贯

不达标时用 `sandbox_edit` 原位修正 `creative_design.md`。**禁止修改用户提供的旁白和台词文案**，**禁止跳过自审直接进入素材生成**。

**IMPORTANT - 创意设计定稿推送（不停顿）**（创意助手旁路时跳过——plan.md 已是确认过的创意成品）：**①②自审全部跑通后**，用 `present_sandbox_file` 推送 `creative_design.md`，并用一两句话说明素材计划，**不发确认问卷、不停顿等待**，随即进入 Step 2。创意确认合并在 Step 2 末尾的「创意与素材确认门」一次完成——先把创意和参考素材连续做完，再让用户一起确认。

## Step 2：生成参考素材（三轮）

**IMPORTANT - 单段回退闸门（本步第一个动作，读任何 ref、生任何素材之前强制执行）**：进入 Step 2 后，**第一件事必须是输出一行时长判定**，格式固定（用用户语，不出现内部文件名/参数名）：`时长判定：创意方案定稿总时长 X 秒，单次生成上限 N 秒，X ≤/> 上限 → 一次生成完成/分段制作`。判定前禁止读 `ref-image-design.md`、禁止 `ls anchors`、禁止任何 `sandbox_generate_image/audio`。

- **X ≤ 单次生成上限 → 立即重新路由到单段流程**：停止本流程并读取 `workflow/single-segment.md`，读取成功后该文件成为唯一 active workflow，本文件立即失效。跳过本步全部自产素材生成（参考图、音色锚定音频一律不生）、跳过 `generate_shot_video_prompt_plan`。用户上传的原始素材仍进 ImageList，仅 agent 自产参考图被跳过。已过创意确认门，回退后不重复确认，按单段生成前的简明说明直接推进
- **X > 单次生成上限 → 进入下方积分闸门**，两道闸门都通过后才做本步素材生成
- **无论问卷/创意阶段此前是否被当作"多段/N 段"处理，本闸门只认定稿时长**：定稿时长未超过上限就是单段，用户写的段数/视角数与问卷选项均不推翻本闸门（根 Skill §0.2 段数解耦）

**IMPORTANT - 积分闸门（判定为"继续多段"后的第一个动作，生成任何素材之前强制执行）**：按创意脚本的 `总时长预算` 调用 `check_credit_quote` 问价：

```
check_credit_quote(ToolName: "sandbox_generate_video", Duration: {总时长预算秒数})
```

`Resolution` 无明确指定时不传（由会话设置决定）；创意脚本绑定了用户参考视频时传 `ReferenceDuration`（参考视频总时长秒数）。返回是纯文本，直接读，不解析字段：

- 返回「当前积分是否不足所需的 80%: 是」或明示积分不足 → **停止流程**：不读 `ref-image-design.md`、不生成任何参考图与音色锚定、不进 Step 3。用用户语说明积分可能不够，并把返回中的「按当前余额估算最多可生成」秒数转述为可行时长建议，等用户决定充值或缩短时长后再继续
- 返回余额充足、免费、商业化未启用或问价不可用 → 照常继续本步
- **一次问价定论，禁止主动重试**：本闸门只调用一次 `check_credit_quote`。返回不足时**禁止改小 `Duration`、补写或改写 `Resolution`、增删参数后重问**来换一个"够"的结论——那是绕过闸门，不是解决问题；工具报错或超时同样不重试，按「问价不可用」继续本步。对返回数值有疑问时如实告知用户，不自行重算
- **禁止把返回文本原样转述给用户**（含模型名、清晰度等内部参数），只说积分够不够和可行时长。报价只代表调用那一刻、余额会变动、实际消耗可能更高，禁止把问价结果表述为扣费承诺或积分返还依据

**创意助手模式适配**：本步及 Step 3 中所有「读 `creative_design.md` / 从中提取角色场景 / 写回素材绑定表」在创意助手旁路下一律以 `plan.md` 为创意脚本——从 plan.md 语义提取需要参考图/音色的角色与场景；若同一角色跨场次存在多个显著形象，同样提取唯一基础形象、身份锚点、各变化形象及出现场次。生成素材后把路径写回 plan.md 的素材相关位置（plan.md 无素材绑定表时，在文末追加一个「素材清单」小节逐行记录 `实体/形象 → 路径`）。分镜规划工具只从创意脚本读取素材绑定，写回后必须重新回读确认路径完整。下文出现 `creative_design.md` 处按此对应替换，不再逐句标注。

**第 0 轮**：获取**风格概览图**，落盘 `style_anchor.png`——每个项目只获取一次，跨集复用；已有落盘锚点则跳过直接读取。获取策略：先查 `creative/style-master.md` 速查表中匹配风格行的「预置锚定图」列（有路径 → cp 到项目目录）；未命中或无预置图时走原有生成流程（出候选 → 确认 → 落盘）。**本轮阻塞**：落盘前禁止发起第 1 轮生成调用，二者不得同批并行。

**第 1 轮**（第 0 轮落盘后才可发起）：并行生成普通参考素材、多形象角色的基础形象与角色级音色——

①**参考图生成**：根据 `creative_design.md` 中的角色、场景、道具（道具仅限已通过 `creative/creative-design-format.md` §物品准入而单列者，角色随身武器/配饰不生成 prop 图，其形象并入对应角色形象四视图），只为**没有用户素材**的普通实体与多形象角色的基础形象用 `sandbox_generate_image` 并行生成参考图（每张 ImageList 传入 `@style_anchor`），存入项目目录。普通实体采用语义化英文命名：个体角色 `assets/{project}/character_xxx_sheet.png`、群像/类型角色 `assets/{project}/character_xxx_group.png`、场景 `assets/{project}/scene_xxx.png`、道具 `assets/{project}/prop_xxx.png`；多形象角色的唯一基础形象命名 `assets/{project}/character_xxx_base_sheet.png`。**本轮禁止生成变化形象**，必须等基础形象通过质量自检。用户上传的角色照片默认直接用作普通角色或该多形象角色的基础形象；用户明确绑定到某个变化形象时才按其指定绑定，不得擅自改作基础形象。仅当 `creative_design.md` 的 `素材绑定关系` 表中明确标注"仅供风格参考，需生成角色参考图"时，才生成对应参考图：个体角色按四视图生成；群像/类型角色按 `assets/ref-image-design.md` 的群像例外生成群像类型图。引用用户素材生成参考图时，必须把用户原图传入 ImageList 并在 Prompt 中用 `@图片N` 引用，标注"参考该图的角色形象/体型/特征"。生成完成后，用 `sandbox_edit` 将新参考素材完整路径补充到 `creative_design.md` 的 `素材绑定关系` 表中对应角色形象/场景/物品行。

②**音色锚定音频生成**：当有台词/旁白角色出现在 ≥2 个不同段时，与参考图并行调用 `sandbox_generate_audio` 生成音色锚定音频。

- 触发判定：逐角色检查 `creative_design.md` 剧本设计——该角色/旁白在几个场次有台词？≥2 个不同场次 → 需要音色锚定。仅出现在 1 个场次的角色不需要，单段视频不需要
- 旁白贯穿多段也触发，角色名用"旁白"
- 调用方式：`sandbox_generate_audio({ Lang: "zh", Type: "tts", Text: "你好，我是{角色名}的配音音色参考。", VoiceDesc: "{creative_design.md 中该角色的音色描述}", OutputPath: "assets/{project}/voice_{角色名}.mp3" })`。旁白 OutputPath 用 `assets/{project}/voice_narrator.mp3`
- 与参考图同为项目级素材，跨集复用
- 音色锚定音频与参考图之间无依赖，完全并行
- 生成完成后，用 `sandbox_edit` 将新音频路径补充到 `creative_design.md` 的 `素材绑定关系` 表中对应角色/旁白行的参考音频素材列
- 同一角色无论有多少形象，默认只生成一份角色级音色锚定，所有形象行写入同一个 `voice_{角色名}.mp3`。仅 creative_design.md 已记录明确 `音色例外` 时，才为对应形象额外生成 `voice_{角色名}_{形象名}.mp3`；禁止 Agent 仅因外观变化自行换声

**第 2 轮：生成变化形象**——第 1 轮的基础形象逐张通过身份、完整性和风格自检并写回素材绑定关系后，才为没有用户素材的变化形象调用 `sandbox_generate_image`。每张变化形象必须在 ImageList 中传入该角色的基础形象（启用风格锚时同时传入 `@style_anchor`），Prompt 明确"与基础形象是同一角色，严格保留身份锚点，只改变 creative_design.md 列明的变化项"，文件命名 `assets/{project}/character_xxx_{appearance}_sheet.png`。同一角色的多个变化形象可并行，不同角色也可并行；禁止变化形象互相引用或串行派生，避免代际漂移。生成完成后逐张写回对应「角色形象」行。

**IMPORTANT - 生成任何参考图前，必须先用 `sandbox_read` 加载 `assets/ref-image-design.md`**（前提：已过单段回退闸门且判定为"继续多段"；判定为单段时本步整体跳过，不读本 ref）（纯场景只读 §〇+§二，纯人像只读 §〇+§一）。不读此文件就生成参考图 = 无法区分个体四视图与群像类型图、没有物理白描、没有风格锚定，角色一致性会崩。多段+有重复角色时同时加载 `assets/character-lock.md`。**本步骤只读这两个 ref，不要提前加载 prompt-craft 等分镜规划阶段的文件。**

**IMPORTANT - 参考素材生成后必须自审**：第 1、2 轮参考图/音频补写完成后，先暂停分镜规划，**禁止调用 `generate_shot_video_prompt_plan`**。用 `sandbox_read` 回读最新 `creative_design.md`，逐项核对：

1. **参考图质量自检**：逐张检查新生成参考图，确认主体完整、身份/物种/服饰/道具与 `creative_design.md` 对应实体一致，风格与 `style_anchor` 一致；个体角色参考图必须能支撑后续身份一致性（四视图/三视图齐全、正侧背信息清楚）；群像/类型角色参考图必须能支撑群体造型一致性（2-4 个不同个体、年龄层/服饰时代/发型气质一致、五官和身形有轻微差异、不像复制粘贴）；场景/物品参考图必须无主体缺失、严重畸形、文字水印、拼贴错乱。引用用户素材生成的参考图还必须保留用户素材中的可见外貌/体型/特征。质量不达标 → 重新生成该参考图，禁止把劣质图写入下游分镜。
2. **creative_design.md 写入自检**：每一张通过质量自检的新参考图，都必须写入 `creative_design.md` 的 `素材绑定关系` 表中对应角色/场景/物品行的参考图片素材列；不得只在对话或工具返回中出现。缺失 → 用 `sandbox_edit` 补齐后重新回读检查。
3. **路径完整性自检**：`creative_design.md` 中所有参考图片、参考音频路径都必须是可解析的完整 sandbox 路径（如 `assets/{project}/character_xxx_sheet.png`、`assets/{project}/character_xxx_group.png`、`upload/xxx.png`），禁止只写 `character_xxx_sheet.png`、`xxx.png`、`voice_xxx.mp3` 这类裸文件名；禁止写 URL 或说明文本替代路径。发现裸文件名/错误目录/路径不匹配 → 用 `sandbox_edit` 改成实际完整路径。
4. **多形象一致性自检**：每个多形象角色的基础形象必须先于变化形象生成或确认；每张变化形象必须保留身份锚点、显著落地其变化项，且路径写入对应形象行；表情/姿势/光线等轻微状态不得冒充变化形象。所有形象行默认使用相同参考音频路径，只有已记录的明确音色例外可不同。失败只重生成或修正对应变化形象，不得改动已通过的基础形象。

四项全部通过后，自审修正后必须重新回读 `creative_design.md` 验证一次。

**IMPORTANT - 创意与素材确认门（自审通过后，进入 Step 3 前，禁止跳过）**：**必须停止所有工具调用**，按以下顺序执行（生成类工具已自动向用户展示参考图/音频，无需重复推送）：

1. 调用 `dynamic_questionnaire` 发送确认表单，包含以下选项：
   - 选项 1：**确认创意和素材，继续制作**（默认选中）
   - 选项 2：**我想修改创意**——提示用户在输入框中描述希望调整的内容（如剧情、角色、结局、时长）
   - 选项 3：**我想调整素材**——提示用户在输入框中描述希望调整的内容（如角色形象、场景样式、配音音色）
2. **等待用户回复后**再继续：用户确认 → 进入 Step 3；用户要求修改创意 → 用 `sandbox_edit` 修改 `creative_design.md`（波及素材绑定时同步重生成对应素材）后重新执行本确认流程；用户要求调整素材 → 按意见重新生成对应素材（沿用 `@style_anchor` 与命名规则，更新 `素材绑定关系` 表）后重新执行本确认流程

创意助手旁路下本门只确认素材（plan.md 已确认过，选项 2 省略）；本步无任何自产素材且创意层=满时免设本门，直接进入 Step 3。用户明确要求跳过确认时按根 Skill §1.2 确认门原则降级为简明说明、不停顿。

## Step 3：分镜规划 + Prompt 构造（由分镜规划工具执行）

本步骤调用 `generate_shot_video_prompt_plan`。工具在隔离上下文中读取完整创意脚本和分镜阶段 ref，完成全片分段、Prompt 构造、素材映射和内置 review。主 Agent 只负责准备最新创意脚本并发起调用；禁止手写 `storyboard.md`，禁止在调用前加载任何 storyboard ref。

**调用前准备**：

1. 用 `sandbox_read` 读取最新创意脚本文件（常规模式 = `assets/{project}/creative_design.md`；创意助手旁路 = `plan.md`）
2. 确认参考图、参考视频、参考音频路径均已写入创意脚本的素材绑定信息中
3. 有同角色多形象时，确认每个场次已标明出场形象、每个形象都有唯一图片路径，且同一角色各形象默认共用音色路径，任何例外均已在创意脚本中明确记录；否则禁止调用分镜规划工具
4. 确认视频比例已写入创意脚本；比例未确定时先补齐，禁止调用工具后再猜测

**调用方式**：

```text
generate_shot_video_prompt_plan(
  creative_design_path: "{assets/{project}/creative_design.md|plan.md}",
  max_shot_duration: {{ .max_video_duration }},
  output_storyboard_path: "assets/{project}/storyboard.md",
  ratio: "{16:9|9:16|4:3|3:4}"
)
```

每个成片任务只调用一次该工具，禁止把完整创意脚本拆成多批调用，禁止复用 `output_storyboard_path` 做续写。`max_shot_duration` 传当前单次生成上限且只能是工具支持的 15 或 30 秒；运行时上限不是 15/30 时停止并请求确认。`ratio` 必填，取创意脚本中的已确认比例。

**工具产出**：`assets/{project}/storyboard.md`（含分段总览表 + 每段完整 Prompt + 素材映射 + 内置 review 结果）。Markdown 中每个 `shot_NN` 小节对应一次 `sandbox_generate_video` 调用；`总览` 表提供 `Shot`、`Duration`（比例为 storyboard.md 顶部单行，全片统一），每个分镜小节提供 `ImageList`、`VideoList`、`AudioList`、`Prompt`。

**IMPORTANT - storyboard.md 结果自审（用户确认前，禁止跳过）**：收到 `storyboard.md` 路径后，先暂停视频生成类工具，**禁止调用 `sandbox_generate_video`**。只允许用 `sandbox_read` / `sandbox_edit` 完成自审修正，再进入用户确认。

**职责边界**：Prompt 怎么写（构造规范、分段、运镜、台词嘴型、格式合规）由分镜规划工具及其内置 review 负责，**主 Agent 不重复审 Prompt 写法、不读 `storyboard/` 下任何 ref**。主 Agent 只审一层——storyboard 是否与用户原始输入或 `creative_design.md` 冲突（工具只读取创意脚本 `creative_design.md`/`plan.md`，没见过用户原始输入）：

1. 用 `sandbox_read` 读取 `storyboard.md`，回溯用户原始输入逐项核对，全部满足才放行：
   - **用户输入冲突检查**：`storyboard.md` 不得改变用户原始输入中的主体、片段顺序、动作链、焦段、景别、机位、运镜路径、方向、速度、焦点、轴线、时间点、声音/BGM、风格氛围、结尾方式。
   - **creative_design.md 承接检查**：`creative_design.md` 中已确认的用户额外要求、场次、台词、动作、用户镜头指令、素材绑定、声音要求必须在 `storyboard.md` 中有对应段落或 Prompt 落点。
   - **多形象映射检查**：每个 shot 必须只传入并绑定该段实际出场的角色形象；形象切换发生在 shot 内时才同时传入切换前后两张形象图并在阶段中明确切换点。不同形象仍用同一个角色名，默认使用同一份音色路径；仅创意脚本已声明的音色例外可切换音色，禁止误拆成两个角色或擅自换声。
   - **允许合并但不允许丢失**：用户写的多个片段/镜头可以因时长和生成能力合并到同一个 shot 内，但合并后必须在 Prompt 的阶段描述中保持原顺序和核心动作。
   - **账本约束检查**：总时长对应 `总览` 加总和各段 `Duration`；比例对应顶部「视频比例」和实际调用 `Ratio`；风格对应 `通用尾注` 或各段 Prompt；语言对应台词/旁白原文；字幕明确要求只对应后续 `render_video.show_subtitle`，不得在 storyboard 的段 Prompt 中添加旁白字幕、台词字幕或对白字幕；BGM 只核对用户明确要求的项，未指定时不新增 storyboard 或 render 参数要求，沿用默认逻辑；用户上传素材均被引用，且 Prompt、ImageList、VideoList、AudioList 中的绑定与用户声明的用途、对象、场景、动作或时间范围一致，无编造路径。
2. 任一项缺失或冲突：优先用 `sandbox_edit` 原位修正 `storyboard.md` 后重新核对。若冲突来自 `creative_design.md` 已经丢失或改错用户信息，则回退修正 `creative_design.md`，再重新调用分镜规划工具。**禁止反向删改用户确认过的台词文案或硬约束去迁就工具产出**。
3. 若发现的是 Prompt 写法层问题（文学词、形变、分段不当等非用户需求项）：小改动主 Agent 直接用 `sandbox_edit` 修 `storyboard.md`；大改动重新调用分镜规划工具让其重做。一处缺失若同时跨需求层与写法层（如某段台词丢失且分段不当），先 `sandbox_edit` 补回用户原文，再按上述处理写法问题。

**IMPORTANT - 等用户确认（与创意确认同级，禁止跳过）**：`storyboard.md` 自审通过后，**必须继续停止视频生成类工具，禁止调用 `sandbox_generate_video`**，按以下顺序执行：
1. 用 `present_sandbox_file` 将 `storyboard.md` 推送给用户审阅
2. 简要说明素材使用情况：哪些素材直接复用了用户上传文件，哪些参考图由 Agent 生成
3. 调用 `dynamic_questionnaire` 发送确认表单，包含以下选项：
   - 选项 1：**并行生成，开始制作**（默认选中）——所有段同时生成，速度最快但段间衔接效果最弱
   - 选项 2：**逐段生成·尾帧参考**——按顺序逐段生成，每段参考上一段的尾帧画面，衔接效果更好，速度稍慢
   - 选项 3：**逐段生成·视频参考**——按顺序逐段生成，每段参考上一段尾部 3 秒视频，衔接效果最好，但速度最慢且消耗更多积分
   - 选项 4：**我想修改分镜**——提示用户在输入框中描述希望调整的内容
4. **用户选择策略 2 或策略 3 时**，追加一次 `dynamic_questionnaire` 询问逐段确认偏好：
   - 选项 1：**自动连续生成**（默认选中）——全部段自动依次生成，中途不停顿
   - 选项 2：**每段确认后再继续**——每段生成完后展示结果，等你确认后再生成下一段
5. **停在这里，等待用户回复**。在用户回复之前，禁止执行任何后续步骤。用户选择"确认分镜" → 进入 Step 4；用户选择"我想修改"并输入修改意见 → **主 Agent 自行用 `sandbox_edit` 修改 storyboard.md**（小改动不需要重新调用分镜规划工具），修改后重新执行结果自审和本确认流程

## Step 4：按用户选择的生成策略执行

按 `storyboard.md` 的 `shot_NN` 小节顺序逐项调用 `sandbox_generate_video`。每段从 `总览` 表读取 `Duration`、从 storyboard.md 顶部「视频比例」行读取比例（全片统一），从对应 `shot_NN` 小节读取 `Prompt`、`ImageList`、`VideoList`、`AudioList`，输出路径按顺序命名为 `assets/{project}/shot_01.mp4`、`assets/{project}/shot_02.mp4`。**默认所有段并行生成**——大多数情况下一轮即可完成。

**IMPORTANT - 通用尾注拼接（铁律）**：storyboard.md 若含 `## 通用尾注` 小节，其内容是全片每段共用的质量约束、只写了一次。调用 `sandbox_generate_video` 时，实际传入的 Prompt = 该 `shot_NN` 小节 `Prompt` 原文 + 换行 + `通用尾注` 全文，**每段都拼、逐字拼、不改写不省略**。漏拼会让该段丢失水印/无字幕/BGM/风格约束。无 `通用尾注` 小节（单段视频或旧格式）则直接用段 Prompt，不额外拼接。

**策略 1：并行生成（默认）**

所有段同时并行生成——大多数情况下一轮即可完成。

**仅当 storyboard 中存在 `⇐NN` 标记时**，才分两轮：
1. 生成前按段号抄出全片衔接序列，若出现相邻两个 `⇐`（`⇐` 段依赖了另一个 `⇐` 段）→ 先修 storyboard（后一个 `⇐` 改 `—` 并补环境锚点）再执行
2. 先并行生成所有 `—` 段
3. `—` 段完成后，用 `sandbox_bash` 截取被依赖段的尾帧（**必须逐字复制以下命令，只替换路径，禁止添加或修改任何参数**）：
   ```bash
   ffmpeg -sseof -0.1 -i assets/{project}/shot_NN.mp4 -frames:v 1 -y assets/{project}/shot_NN_lastframe.png
   ```
4. 将尾帧加入 `⇐` 段的 ImageList（第一张），Prompt 开头追加 `@图片1 作为该次视频前的画面状态`，并行生成所有 `⇐` 段

衔接机制详见 `storyboard/storyboard-format.md`「衔接机制」。`⇐` 只接紧邻前一段、不连续两个 `⇐`，视频生成最多两轮。

**策略 2：逐段生成·尾帧参考**

按段号顺序逐段生成。每段完成后截取尾帧，作为下一段的画面状态参考：
1. 生成 shot_01
2. 截取 shot_01 尾帧：`ffmpeg -sseof -0.1 -i assets/{project}/shot_01.mp4 -frames:v 1 -y assets/{project}/shot_01_lastframe.png`
3. 生成 shot_02：ImageList 加入 `shot_01_lastframe.png`，Prompt 中用 `@图片N 作为该次视频前的画面状态` 引用（**不是**"作为首帧"——模型参考前段状态但不锁定首帧构图）
4. 依此类推直到最后一段

**每段确认模式**（用户选择"每段确认后再继续"时）：每段生成完成后，展示该段视频产物，调用 `dynamic_questionnaire` 询问：
- 选项 1：**继续生成下一段**（默认选中）
- 选项 2：**重新生成本段**——重新调用 `sandbox_generate_video` 生成同一段
- 选项 3：**我想调整后续分镜**——在输入框中描述调整内容，Agent 修改 storyboard.md 后继续

**策略 3：逐段生成·视频参考**

按段号顺序逐段生成。每段完成后截取尾部 3 秒视频，作为下一段的动态状态参考：
1. 生成 shot_01
2. 截取 shot_01 尾部 3 秒：`ffmpeg -sseof -3 -i assets/{project}/shot_01.mp4 -c copy -y assets/{project}/shot_01_tail.mp4`
3. 生成 shot_02：VideoList 加入 `shot_01_tail.mp4`，Prompt 中用 `@视频N 作为该次视频前的状态` 引用
4. 依此类推直到最后一段

**每段确认模式**同策略 2。

## Step 5：拼接合成

**台词人声来源（铁律）**：角色台词/旁白的人声由 `sandbox_generate_video` 在生成每段视频时按 Prompt 中的 `{台词}` 直接产出，**已自带口型同步的配音**。视频生成后**禁止**再用 `sandbox_generate_audio` 逐句 TTS 配音、**禁止**加载 `ffmpeg-media-processing` 或用 ffmpeg 把外部音轨合成/覆盖进成片——这会造成人声重复、口型错位。`sandbox_generate_audio` 仅用于素材阶段的音色锚定（Step 2 ②，喂给视频模型做音色参考）。成片音频处理只走 `render_video`：拼接各段，不做人声合轨。

**渲染工具分工**：拼接、成片级字幕、BGM 等渲染类操作**一律走 `render_video`**（系统链路支持最好），禁止用 ffmpeg 替代；ffmpeg 仅用于截尾帧、ffprobe 探参、`review/video-partial-edit.md` 定义的区间切分等 `render_video` 不覆盖的低频操作。

各镜头生成调用未报错即视为成功，用 `render_video` 按顺序拼接：

```
render_video(
  video_paths: ["assets/{project}/shot_01.mp4", "assets/{project}/shot_02.mp4", ...],
  output_path: "assets/{project}/output.mp4"
)
```

成片产生后、交付前读取 `review/quality-control.md` §二完成出片自检；用户随后提出的修改诉求按根 Skill §0.3 编辑回合重新分流。

## 素材复用与一致性

- **IMPORTANT**：生成新镜头前，**必须**先用 `sandbox_bash` 执行 `ls assets/{project}/` 查看已有参考素材，确认哪些可以复用。**禁止跳过此步骤直接生成**
- `style_anchor.png` 是**项目级共享素材**：整个项目（含多集）只生成一次，禁止每集重新生成。**例外：用户要求变更风格时（根 Skill §0.3 创意（风格）编辑），style_anchor 作废重生，连带重生所有参考图**
- 同一角色的同一形象、同一场景在不同镜头中必须使用同一张参考图；角色切换形象时只切换到 `creative_design.md` 已绑定的对应形象图，禁止临时生成或混用其他形象
- 用户上传的图片/视频优先作为参考素材使用
- 音色锚定音频（`voice_*.mp3`）与参考图同级管理：项目级共享，跨集复用，同一角色在不同镜头、不同形象中默认使用同一个角色级音色文件；仅创意脚本明确记录的音色例外可使用对应例外文件

## 多集项目文件组织

当用户需要在一个项目内制作多集内容时：

- **所有参考素材一律放项目根目录**（不管哪集引入），确保跨集共享和复用
- **每集的 shot 和 output 放各自的子目录**（`ep01/`、`ep02/`...）
- agent 查找可用素材时只需 `ls assets/{project}/`，不用递归搜索

```
assets/{project}/
  creative_design.md         # 全局创意设计
  storyboard.md              # 全局分镜生视频参数
  style_anchor.png           # 风格概览图（跨集复用）
  character_hero_sheet.png   # 共享参考素材
  scene_tavern.png
  ep01/
    creative_design.md
    storyboard.md
    shot_01.mp4
    output.mp4
  ep02/
    creative_design.md
    storyboard.md
    shot_01.mp4
    output.mp4
```

单集项目不需要建 ep 子目录，shot 和 output 直接放项目根目录。
