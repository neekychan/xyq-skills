# 质量管控

## §一 镜头修改协议（KEEP/CHANGE）

> 用户要求重做/修改某个镜头时读本节。

### 红线（高频翻车点）

| 错误写法 | 后果 | 正确写法 |
|---------|------|---------|
| 从零重写整个 prompt | 丢失原始创意意图，新结果可能更差 | 用 KEEP/CHANGE 协议保留原始意图 |
| 不读取原始参数就重新生成 | 参考图、风格、角色描述全丢 | 先 sandbox_read tasks/ 读取原始调用参数 |
| 直接交付修改版不做对比 | 用户无法判断是否改进 | 必须展示修改前后对比 |

### 强制规则

1. **先读后改**：重新生成前必须用 `sandbox_read` 读取原始镜头的调用参数（tasks/ 目录）
2. **KEEP/CHANGE 分离**：明确区分保留部分和修改部分，保留部分逐字引用
3. **对比确认**：修改完成后必须同时展示修改前后的视频，等用户确认后才重新合成

### KEEP/CHANGE 协议

当用户要求修改已有镜头时，按以下模板构建：

```
=== KEEP（原始意图，逐字保留） ===
场景：{从原始 prompt 复制}
角色：{从原始 prompt 复制}
运镜：{从原始 prompt 复制}
时长：{原始 Duration}
参考图：{原始 ImageList}
风格：{从原始 prompt 复制风格关键词}
质量约束：{从原始 prompt 复制}

=== CHANGE（用户修改请求） ===
修改内容：{用户原话}
影响范围：{情绪/动作/场景/光影/时长 等}
```

然后基于 KEEP 内容重建 prompt，将 CHANGE 内容作为修改叠加。

### 四类常见修改及处理方式

| 修改类型 | KEEP 范围 | CHANGE 范围 | 处理要点 |
|---------|----------|------------|---------|
| 情绪/氛围调整 | 角色+场景+运镜+时长 | 光影+配色+BGM | 查 `creative/style-master.md` 替换情绪参数 |
| 角色表演调整 | 场景+运镜+光影+时长 | 动作描述+表情 | 细化肢体动作和表情描写 |
| 场景替换 | 角色描述+运镜+风格+时长 | 场景描述+场景参考图 | 需新增场景参考图 |
| 运镜/景别/机位调整 | 角色+场景+风格+时长 | 运镜描述+景别+机位 | 新运镜从 `prompt-craft.md` 运镜指令表取标准写法 |
| 时长调整 | 角色+场景+运镜+风格 | Duration 参数+动作密度 | 时长变长→增加动作；时长变短→精简动作 |

上表 KEEP 范围是默认值：**用户点名修改的字段一律移出 KEEP、划入 CHANGE**，不受表中默认归属限制。

### 执行流程

```
1. sandbox_read tasks/{对应镜头的调用记录}
   → 获取原始 Prompt、ImageList、VideoList、Duration 等参数

2. 构建 KEEP/CHANGE 块
   → KEEP: 逐字引用原始内容中不变的部分
   → CHANGE: 记录用户修改请求

3. 重建 prompt
   → 在 KEEP 基础上应用 CHANGE
   → 保留所有原始参考图（ImageList 不变，除非场景替换）

4. 调用 sandbox_generate_video 生成修改版
   → 新文件命名：shot_XX_v2.mp4

5. 展示对比
   → present_sandbox_file 展示原始版和修改版
   → 等待用户确认

6. 用户确认后
   → 用 sandbox_bash 验证所有镜头文件存在
   → 调用 render_video 重新合成
```

### 特殊场景处理

#### 用户说"重新生成"但未指定修改内容
- 意图是**抽卡**（用相同参数再生成一次，期望不同结果）
- 复用完全相同的 prompt 和参数，不做任何修改
- **禁止将原产物放入 ImageList/VideoList**——那是参考素材位置，不是重新生成目标

#### 用户要求修改多个镜头
- 逐个应用 KEEP/CHANGE，每个镜头独立处理
- 所有修改完成后统一做一次 render_video 合成
- 如果修改了角色外观（如换装），后续所有含该角色的镜头都需要重新生成

### §一 失败模式

| 失败 | 后果 | 修法 |
|------|------|------|
| 不读原始参数 | 丢失原始参考图和风格 | 先 sandbox_read 原始调用记录 |
| 把原产物当参考图传入 | 严格编辑而非重新生成 | 区分"重新生成"和"编辑"的意图 |
| 不做对比直接交付 | 用户无法判断质量 | 同时展示前后版本 |
| 修改一个镜头后不重新合成 | 最终视频仍是旧版 | 用户确认后重新 render_video |

### 关键帧辅助策略

**衔接机制（标准流程，非本策略）**：storyboard 中标记了 `⇐NN` 的段会在生成时截取前段尾帧作为画面状态参考——这是分镜阶段确定的标准衔接流程，详见 `storyboard/storyboard-format.md`「衔接机制」和 `workflow/multi-segment.md` Step 4。

**以下关键帧策略仅在用户要求修改镜头时使用**，不在首次生成时主动启用。纯参考图生视频的质量上限更高，关键帧方式的效果很依赖生图质量。

**方式一：使用上一个镜头的尾帧作为当前镜头首帧**
用于未标 `⇐` 但修改后发现空间衔接不佳的段。用 ffmpeg 截取尾帧：
```bash
ffmpeg -sseof -0.04 -i assets/{project}/shot_01.mp4 -frames:v 1 assets/{project}/shot_01_lastframe.png
```
然后在 Prompt 中使用：`@图片1作为该次视频前的画面状态，参考@图片2的角色形象，场景参考@图片3...`

**方式二：生成当前镜头的关键帧图片**
用 `sandbox_generate_image` 生成当前镜头的关键画面构图（角色位置、姿态、场景布局），再作为首帧或画面参考传入视频生成。适用于需要精确控制空间关系或多人站位的镜头。

可以在一次调用中同时使用首帧参考和画面参考：
```
@图片1作为该次视频前的画面状态，@图片2作为后半段画面参考，
参考@图片3的角色形象，场景参考@图片4...
```

## §二 出片自检（交付前定位表）

> 视频生成完成、交付用户前读本节。

### 强制规则

多镜头视频合成后，在交付用户前逐维排查症状。命中任一症状按下表定位到对应 ref 修复。

### 交付前定位表

| 症状 | 修复去处 |
|------|---------|
| 技术质量异常（意外字幕/水印、肢体崩坏、模糊、时长不符） | `prompt-craft.md`「质量约束」与红线表 |
| 角色不一致（面部变人、换装、同画面复制人物、中途变脸） | `character-lock.md` |
| 风格漂移（画风不统一、配色/色温跳变、参考图与视频不符） | `ref-image-design.md` 风格锚定 |
| 台词/旁白问题（音色不统一、台词截断/重复、多段 BGM 冲突、音效不匹配） | `dialogue-rules.md`；多段拼接约束见 `prompt-craft.md` |
| 开场结尾无力（无钩子、无情绪落点、镜头逻辑断裂） | 对应体裁 ref（短剧起手/收尾见 `creative/short-drama.md`） |
| 结尾"咔哒"截断音 | 小概率问题，提示用户可用剪辑工具处理 |

### 失败归因

当自检发现问题时，按以下分类定位原因：

| 类别 | 典型表现 | 处理方向 |
|------|---------|---------|
| **Prompt 问题** | 画面与描述不符、缺少关键元素 | 修改 prompt 描述，参考 ref 速查表 |
| **参考图问题** | 角色不一致、场景混入人物 | 重新生成参考图 |
| **参数问题** | 时长不对、比例错误、分辨率低 | 调整 Duration/Ratio/Resolution |
| **模型能力限制** | 肢体崩坏、运动不自然、恐怖谷 | 降低动作密度/换景别/换风格规避 |
| **拼接问题** | 衔接处跳变、色温突变 | 使用首帧策略或统一光影描述 |

### 快速决策

```
自检不合格
  │
  ├─ 单个镜头问题 → 重新生成该镜头（参考本文件 §一 镜头修改协议）
  │
  ├─ 风格/一致性全局问题 → 检查 creative_design.md 和参考图是否统一
  │
  ├─ 音频问题 → 检查每段 prompt 的音频指令是否一致
  │
  └─ 模型能力限制 → 不重试，告知用户限制并建议替代方案
```

## 协同

- 角色一致性修复 → `assets/character-lock.md`
- 情绪/风格修复 → `creative/style-master.md`
- Prompt 编写规范 → `storyboard/prompt-craft.md`
- 成片后诉求路由（删段/换序/回退/超分/降级边界）→ `review/post-delivery.md`；镜头修改完成后的重拼义务与衔接链重截判定见其 §B1
