# 游戏Demo生成器

## 1. 核心原则 + 持久引擎

**核心原则：以真实玩家操作视角为核心，通过三段式叙事结构（引导-剧情-战斗）完整呈现游戏核心玩法循环，所有视觉资产保持高度一致性，模拟真实游戏实机运行效果。**

持久引擎（因果链）：
**用户主题输入 → 背景风格定调 → 三段式故事板拆解 → 高精角色/场景/UI资产生成 → 多模态资产一致性校验 → 分段视频生成（每段15秒） → 全片拼接与音频同步 → 最终45秒游戏Demo成片**

## 2. 质量测试（可证伪）

如果生成的Demo无法同时满足以下三点，则判定不合格必须重做：
1. UI元素（血条、技能栏、对话框、按钮）在所有镜头中位置固定、无形变、无伪影、无抖动
2. 主角形象、场景色调、美术风格在三段视频中保持100%一致，无风格漂移
3. 三段内容完整覆盖「系统交互→叙事铺垫→核心战斗」的玩法闭环，逻辑连贯无断裂

## 3. 输入诊断（启动前必须明确的维度）

启动创作前，必须从用户输入中解析或合理默认以下参数：
| 维度 | 说明 | 默认值 |
|---|---|---|
| 游戏主题/核心玩法 | 用户提供的关键词、玩法类型（ARPG/开放世界/射击等） | 无，必须由用户提供 |
| 视觉风格 | 写实/奇幻/赛博朋克/二次元/像素/国风等 | 写实电影风 |
| 画幅比例 | 16:9/9:16/1:1 | 16:9 横屏 |
| 总时长 | 固定45秒，分为三段各15秒 | 45秒 |
| 分辨率/帧率 | 输出画质标准 | 4K/60fps |
| 主角设定 | 性别、职业、核心特征 | 基于主题自动生成 |
| Boss设定 | 核心敌人特征 | 基于主题自动生成 |
| 核心玩法亮点 | 需要重点展示的机制（如技能系统、开放世界探索等） | 战斗系统 |
| 语言 | UI文字、对白语言 | 中文 |
| 合规敏感点 | 暴力程度、特效表现等 | 无过度暴力表现，符合公映标准 |

## 5. 强制加载reference（硬规则）

创作前**必须**加载对应风格的参考文档，严格遵循文档中的参数规范：
- 角色设计：所有项目必须读取 `references/industries/character-design.md`，严格遵循四视图布局和3D转换规范
- UI规范：所有项目必须读取 `references/industries/ui-spec.md`，严格执行UI像素锚定和禁止形变规则
- 分镜模板：所有项目必须读取 `references/formats/storyboard-template.md`，严格遵循三段式时间码结构
- Prompt文法：所有视频生成必须读取 `references/formats/video-prompt-grammar.md`，使用标准交互/叙事/战斗指令
- 风格参考：根据路由表加载对应风格文档
- 工艺参考：涉及光影、材质、特效时加载对应craft文档

## 6. 工作流（分阶段执行，每阶段暂停确认）

**严格按以下阶段顺序执行，每个关键阶段完成后必须暂停，邀请用户审阅确认后再进入下一阶段，禁止一次性跑完所有步骤。**

### 阶段1：规格定调
1. 接收用户输入的主题关键词和核心需求
2. 完成输入诊断，补全所有默认参数
3. 撰写 `Final_Video_Spec.md`，包含：标题、游戏类型、画幅比、总时长、视觉风格、语言、核心玩法亮点、主角/Boss初步设定
4. 暂停，将Spec文档展示给用户确认，根据反馈修改直到定稿

### 阶段2：故事板设计
1. 严格按照三段式结构拆解脚本，每段15秒：
   - Video A（0-15s 引导流）：系统交互与觉醒（登录/选人界面交互、场景切换、首场实机体验）
   - Video B（15-30s 剧情流）：叙事交互与追踪（NPC对话展示、世界观铺垫、目标点遭遇）
   - Video C（30-45s 战斗流）：核心战斗与结算（8倍速激战、大招演示、Boss击败及Victory UI弹出）
2. 细化每个时间节点的镜头内容、UI状态、音轨层设计
3. 输出完整故事板文档，包含关键元素清单、镜头列表、音轨设计
4. 暂停，展示故事板给用户确认，根据反馈修改直到定稿

### 阶段3：资产生成与一致性校验
1. **角色资产**：
   - 首先生成主角/Boss 2D原画设计图
   - 基于原画生成白底角色四视图：左侧面部特写，右侧依次为全身正面、背面、侧面，严格保持造型/配色/材质一致
   - 转换为3D真实感人物形象卡
2. **场景与UI资产**：
   - 生成全链路一致的UI界面：开始界面、选人界面、加载界面、对话UI、战斗HUD、结算界面
   - 生成关键场景帧：泥土屋炕上视角、第三人称探索场景、Boss战场景
   - 共生成Video A所需5张关键帧，Video B/C所需6张关键帧
3. **多模态分析校验**：
   - 分析3D形象卡材质参数（金属反射、皮肤质感、服饰纹理），记录光影描述参数
   - 分析所有带HUD的截图，记录血条、技能栏、对话框的精确像素位置，标记为「视频生成禁止形变区」
   - 提取全局色彩LUT，确保全片色调亮度统一
4. 暂停，展示所有资产给用户确认，根据反馈修改资产直到满意

### 阶段4：分段视频生成
1. 每段15秒视频单独生成，严格遵循分镜时间码：
   - **Shot A（0-15s 引导流）**：
     - 0-3s：封面图，呼吸灯光效，[Start]按钮点击交互反馈
     - 3-10s：选人/技能展示，鼠标悬停高亮，角色3D待机动作/招牌技能展示
     - 10-15s：第一人称POV转场，从苏醒视角过渡到广阔开放环境HDR效果
   - **Shot B（15-30s 剧情流）**：
     - 15-25s：NPC交互，对话UI呼出，文字逐字显示，背景保持环境动画
     - 25-30s：场景追踪，镜头跟随角色快速移动到视觉地标，制造遭遇感
   - **Shot C（30-45s 战斗流）**：
     - 30-40s：实机战斗，快节奏对抗，UI血条/技能槽实时动态变化，高频位移、粒子特效、震屏打击感
     - 40-45s：战斗结算，Boss击败动画，弹出获胜UI及奖励结算特效
2. 每段视频生成时强制锁定UI区域，禁止血条、技能图标产生任何位移、伪影或形变
3. 每段视频生成后单独展示给用户确认，不满意则重生成该段，直到三段都通过审核

### 阶段5：组装与输出
1. 将三段15秒视频按顺序无缝拼接
2. 同步匹配音轨：UI交互音、环境 ambient 音、战斗打击音效、背景音乐全程开启
3. 统一调色，应用全局LUT确保三段色调完全一致
4. 输出最终45秒4K/60fps游戏Demo视频
5. 展示最终成片给用户

## 7. 输出契约

### 中间产物规范
- `Final_Video_Spec.md`：结构化规格文档，所有参数明确无歧义
- 故事板文档：精确到秒的镜头描述、UI状态、音效标注
- 角色资产：2D原画、四视图、3D形象卡，造型100%一致
- UI/场景资产：所有界面和关键帧风格统一，UI元素位置固定
- 分段视频：每段15秒，MP4格式，H.264编码，对应分镜内容
- 最终成片：45秒完整视频，4K分辨率，60fps，音画同步，无卡顿无跳帧

### 视频生成规则
- 每段15秒视频一次性生成完整片段，内部beat为时间轴描述，无需分段多次生成
- 所有Prompt必须使用正向描述，禁止使用否定式约束（如"不要形变"改为"UI元素位置绝对固定，像素级稳定"）
- 交互段落必须模拟真实键鼠反馈：点击高亮、按钮光效、界面转场动画
- 战斗段落必须包含：高频位移、技能粒子特效、镜头震动、打击感反馈、UI实时变化

## 8. 静默自检（交付前内部检查，不展示给用户）

每个阶段交付前必须检查以下项，不合格立即修正：
1. ✅ 规格阶段：所有参数是否明确，风格是否统一，是否符合用户需求
2. ✅ 故事板阶段：三段结构是否完整，时间码是否精确，玩法亮点是否都有展示
3. ✅ 资产阶段：角色四视图布局是否正确，UI元素位置是否统一，色调是否一致
4. ✅ 视频阶段：UI是否稳定无漂移，动作是否流畅，打击感是否充足，是否符合分镜描述
5. ✅ 成片阶段：三段拼接是否无缝，音画是否同步，色调是否统一，分辨率帧率是否达标
6. ✅ 全流程：每个阶段是否都暂停等待用户确认，没有擅自跳过步骤
7. ✅ 合规检查：无过度暴力内容，UI文字无违规内容
