# 武打动作片段多轮续段

本文件只在用户明确要求多段、下一段、续上或延长已有成片时读取。普通需求不加载，也不主动建议多段。

## 一、每轮边界

- 每次用户轮次只生成当前一段，只调用一次 `sandbox_generate_video`。
- 多段首轮按正常新片或参考流程生成第 1 段，交付后立即结束。
- 用户下一轮明确要求继续时，才准备上一段末尾 5 秒并生成下一段。
- 不在同一轮连续生成多段，不调用 `render_video`，不把各段拼接成片。

## 二、定位上一成片

1. 优先使用上一轮 `sandbox_generate_video` 实际返回并已交付的文件路径，禁止假定固定文件名。
2. 用户本轮上传指定视频时，以用户指定文件为上一成片。
3. 工作区有多个候选且无法判断时，在本轮唯一问卷中让用户选择。
4. 找不到上一成片时停止，请用户上传或指定文件，禁止凭空模拟连续状态。

## 三、截取末尾 5 秒

先用 `sandbox_read` 检查文件，再用 `sandbox_bash` 调用 `ffprobe` 获取真实时长。命令结构：

```bash
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 '上一成片路径'
```

- 时长大于 5 秒时，选用未占用的新输出路径，精确截取末尾 5 秒并保留原音频。可执行结构：

```bash
mkdir -p assets/fight_scene_continuation
ffmpeg -n -sseof -5 -i '上一成片路径' -map 0:v:0 -map 0:a? -c:v libx264 -preset medium -crf 18 -c:a aac -b:a 192k -movflags +faststart 'assets/fight_scene_continuation/tail_唯一后缀.mp4'
```

- 时长不超过 5 秒时，直接使用整段，无需制造重复副本。
- 输出失败或文件不可读时停止，禁止改传完整长片绕过截尾规则。
- 路径必须安全引用，输出使用唯一后缀，禁止覆盖用户文件或上一成片。

## 四、延长输入绑定

1. 截出的尾段放入 `VideoList` 第一项，在 Prompt 中固定称为 `<视频1>`。
2. 用户原始角色图片仍放入 `ImageList`，用于锁定脸部或头盔、服装、武器和体型。
3. 其他参考视频只有确有必要时才加入，`VideoList` 总数不得超过 3 段。
4. 上一成片自带的声音现场由尾段传递。额外用户音频进入 `AudioList` 后，仍需用 `@音频N` 绑定用途。

## 五、延长 Prompt

首句必须使用：

```text
延长<视频1>，从<视频1>末尾可见状态无缝继续，生成当前下一段武打动作。
```

逐字保留 `延长<视频1>` 与尖括号写法。`@视频1`、`参考<视频1>`、`参考@视频1` 都会改变任务语义，禁止使用。

随后依次锁定：

- 末帧主体身份、画面位置、身体朝向、双方距离与阵营。
- 武器数量、持握手、伤势、服装破损、特效颜色与消散状态。
- 摄影机所在位置、运动方向、景别、光线、天气和声音现场。
- 当前段的新攻防目标、局部高潮与结尾状态。

明确写“继续末尾状态，禁止重演<视频1>已有动作”。第一拍从尾段最后的姿态自然发力，不能让角色重新入场、恢复未受伤状态、交换武器或突然换边。

非最终段也要完成一次局部攻防升级，并停在稳定可读、方便下一轮延长的姿态。最终段展示总决胜和余波。

## 六、生成与交付

- `Duration` 使用用户指定的当前段合法时长，缺省为 `{{.max_video_duration}}`。
- `OutputPath` 仍使用 `output/fight_scene.mp4`，接受工具自动返回的版本化实际路径。
- 调用前确认本轮尚未生成视频。
- 调用前再次搜索 Prompt 首句，必须以字面量 `延长<视频1>` 开始，且全文没有 `延长@视频1`。
- 成功后立即用实际返回路径调用 `present_sandbox_file(interrupt=true)`，本轮结束。
