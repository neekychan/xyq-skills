# Retro Source Restyler

## 目标

把用户上传的视觉素材转写成可直接用于图像模型或视频模型的中文成品提示词，让结果看起来像：

- 2004 年前后的 PC 老游戏截图
- 早期 Source 引擎 / Half-Life 2 / Garry’s Mod 场景
- 老电脑 3D 游戏实机画面
- 旧引擎过场动画或录屏
- 现实素材被重新建模成可游玩的老游戏世界

这个 skill 的核心不是“做旧”，而是“重建模”。

## 支持输入

支持以下输入类型：

- 单张图片
- 多张图片
- 人像照、街景照、建筑照、产品图、海报、截图
- 单段视频或多段视频
- 视频截图、关键帧
- 图片 + 视频混合参考
- 图片/视频 + 文本描述混合输入

## 触发规则

以下意图应直接触发本 skill：

- 变成老游戏画风
- 做成老电脑游戏风
- Source 引擎风
- HL2 风格
- GMod 风格
- 早期起源引擎感
- 低多边形、低模、降模
- 旧游戏地图感
- 廉价游戏资产感
- 不是滤镜，要像重新建模
- 把这张图做成老游戏截图
- 把这段视频做成老游戏录屏
- 把动作改成 GMod 早期过场感

如果用户只说“老游戏风”，默认理解为：
- 2004 年左右
- 早期 Source 引擎
- Half-Life 2 / Garry’s Mod
- 低多边形 + 低清贴图 + 生硬光照

不要默认理解成像素风、PS1 风、街机风或动漫游戏风，除非用户明确指定。

## 核心原则

### 1. 先保真，再风格化

优先保留原素材的：

- 主体身份
- 构图
- 视角
- 镜头距离
- 场景布局
- 空间关系
- 关键道具和建筑轮廓
- 视频中的动作逻辑、镜头运动和主要时序

不要把主体改没，不要随意换叙事，不要完全重写场景。

### 2. 理解为“重新建模”，不是“加滤镜”

生成提示词时，要把素材理解成：

- 真实人物、建筑、树木、道路、道具被重建为低多边形 3D 模型
- 真实材质被替换成低分辨率、略模糊、略脏、略重复的旧游戏贴图
- 真实光照被替换为生硬、略混乱、略不自然的早期引擎照明
- 整体画面变成一个可游玩的老游戏关卡或老游戏录像场景

不要把任务写成：

- 复古滤镜
- VHS
- 胶片颗粒
- 旧照片效果
- 轻度做旧调色
- 普通摄影后期

### 3. 默认锚定早期 Source 引擎

默认美术方向应接近：

- Half-Life 2
- Garry’s Mod 早期地图
- 2004 年左右 PC 3D 游戏

宁可粗糙一点、旧一点、土一点，也不要现代、精致、高级。

## 默认视觉拆解

### 建模特征
- 所有人物、树木、石头、建筑、道路、家具、道具都具有明显低多边形感
- 轮廓偏硬，几何块面感明确
- 人物和物体边缘可略显僵硬
- 人物可带轻微 NPC 感，但不能丢失识别度

### 材质贴图
- 低分辨率贴图
- 略模糊、略脏、细节有限
- 局部有轻微重复贴图感
- 像旧时代游戏素材库中的廉价资产

### 光照效果
- 生硬、略不自然
- 阴影与亮部关系可稍微别扭
- 像早期 Source 引擎的旧式照明
- 不要现代电影级布光
- 不要高端 CG 渲染感
- 不要精致 PBR 材质表现

### 画面气质
- 像真实运行中的老电脑游戏截图或录屏
- 略有旧地图拼装感
- 略有粗糙、廉价但可信的旧时代 3D 资产感

## 视频专项规则

当用户上传视频，或目标明显是视频生成 / 视频编辑时，额外遵循以下规则：

### 1. 把视频理解为“老游戏录屏 / 旧引擎过场”
输出应更像：
- 老电脑游戏实机录像
- 旧引擎过场动画
- GMod 式角色演出片段
- Source 地图中的实时演出

而不是“把视频某一帧做旧”。

### 2. 保留运动信息
尽量保留：
- 主体动作
- 动作顺序
- 镜头推进、拉远、平移、跟拍、摇摄
- 主要时序
- 场景切换逻辑
- 表演节奏

然后把这些运动重解释为：
- 旧游戏角色动画
- 老引擎镜头移动
- 关卡内演出或录屏式运动

### 3. 抑制现代影视感
视频提示词里要避免：
- 电影级景深
- 广告片质感
- 高精度现代角色动画
- 超真实皮肤、毛发和材质
- 次世代游戏渲染
- 现代 Unreal / Unity 高级 CG 风格

## 多素材处理

### 多图输入
先判断每张素材的角色：

- 主体参考
- 场景参考
- 动作 / 表情 / 服装参考
- 构图参考
- 风格参考

默认优先级：
1. 主体识别
2. 构图与场景结构
3. 动作与镜头逻辑
4. 统一老 Source 引擎风格

### 图 + 视频输入
默认理解为：

- 图片负责锁定主体外观、服装、关键元素
- 视频负责动作、节奏、镜头运动与表演
- 最终统一为早期 Source 引擎世界中的画面

## 输出策略

默认输出完整结构，方便用户直接使用或继续修改。

如果用户明确说：
- 直接给我 prompt
- 只要成品提示词
- 别解释

则只输出最终成品提示词，不附加分析。

如果用户上传的是视频，且目标明显是视频输出，就优先输出适配视频模型或视频编辑模型的版本，不要误写成静态图片提示词。

## 默认输出格式

### 单图 / 多图

#### 成品提示词
输出一整段可直接使用的中文提示词，明确要求把素材重新建模为 2004 年左右早期 Source 引擎 / Half-Life 2 / Garry’s Mod 风格的老游戏截图，而不是简单滤镜。

#### 保留要求
- 保留原素材主体与关键识别特征
- 保留构图、视角、镜头距离和场景布局
- 保留主要物体的位置关系

#### 负面约束
- 不要现代 3D 渲染
- 不要电影感
- 不要高清材质
- 不要动漫风
- 不要插画风
- 不要只做滤镜化处理
- 不要把主体改没

### 视频

#### 视频成品提示词
输出一整段适配视频生成或视频编辑模型的中文提示词，明确要求把原视频重建为早期 Source 引擎风格的老游戏录屏或旧引擎过场动画。

#### 运动保留要求
- 保留原视频主体与动作识别
- 保留主要动作顺序
- 保留镜头运动趋势和主要调度
- 保留关键时序结构和场景空间关系

#### 风格负面约束
- 不要现代电影级渲染
- 不要广告片质感
- 不要超高清材质
- 不要动漫化动作表现
- 不要仅叠加复古滤镜
- 不要改掉原动作逻辑

### 混合素材

#### 素材理解
先简要说明：
- 主体参考是什么
- 场景参考是什么
- 动作 / 镜头参考是什么
- 最终风格目标是早期 Source 引擎 / HL2 / GMod 老游戏感

#### 成品提示词
输出整合后的完整提示词。

#### 保留要求
按主体、场景、动作分别列出。

#### 负面约束
列出不允许偏移到的方向。

## 写法要求

写提示词时尽量按这个顺序组织：

1. 先定义任务本质  
   把原素材重新建模为 2004 年左右早期 Source 引擎风格的游戏截图或游戏录像，而不是滤镜。

2. 再写保留项  
   主体、构图、视角、场景布局、动作逻辑、镜头运动。

3. 再写风格锚点  
   早期 Source 引擎、Half-Life 2、Garry’s Mod。

4. 再写建模、贴图、光照、旧地图感  
   说明低模、低清贴图、生硬光照、廉价资产感、旧关卡感。

5. 最后补负面约束  
   防止结果跑向现代 CG、动漫、插画、广告片或摄影滤镜方向。

## 最终标准

好的输出应该满足：

- 一眼看出是早期 Source 引擎 / HL2 / GMod 风格
- 一眼还能认出原素材主体和场景 / 动作关系
- 核心是“降模重建”，不是“滤镜做旧”
- 图片像老游戏截图，视频像老游戏录屏或旧引擎过场
- 不容易漂移到现代 3D、动漫、插画、电影 CG 或广告片方向
