# 剧情短片制作确认规则与红线

## 一、阶段逻辑与依赖

本 Skill 严禁一次性完成所有步骤。必须在以下每个关键阶段停下来，与用户确认后再继续：

1. **统一项目制作单完成后**：`Project_Brief.md` 的剧本理解、内容定位、参考手法、角色与旁白、场景、关键对话、动作节点和制作规格确认。
2. **元素资产生成后**：画面角色、关键地点/场景、关键道具参考图，以及角色/旁白各自的声音资产确认。
3. **故事板生成后**：`storyboard.md` 分镜、内部剪辑节奏、画面实体、音频实体、关键元素引用和 audio_layers 确认。
4. **镜头视频生成后**：各镜头视频确认。
5. **音频层生成后**：旁白/对话、BGM、音效确认。
6. **最终交付**：合成视频完成后推送，停止自动推进并等待用户反馈。

在继续之前，使用卡片或 `dynamic_questionnaire` 邀请用户审阅。收到明确确认前，不得进入下一依赖步骤。

## 二、每一步确认协议

每一步确认门必须包含：本步骤产物文件或媒体清单、用户需要审阅的关键点、缺失信息/冲突/风险、“确认继续”和“需要修改”两个选项、下一步名称，以及未确认时禁止调用下一阶段工具的说明。

确认不是可选总结，而是流程控制条件。任何阶段只要生成了文件、元素资产、故事板、镜头视频、音频层或最终合成结果，都必须先向用户展示并等待确认。

## 三、权威来源与依赖关系

| 信息类型 | 唯一权威来源 |
|---|---|
| 剧情、角色、旁白、场景、台词、内容定位、参考手法、制作规格 | `Project_Brief.md` |
| 已确认视觉和声音资产 | 元素资产记录 |
| 镜头方案、画面实体、音频实体、内部剪辑和已确认镜头结果 | `storyboard.md` |
| 后期旁白、BGM、音效和混音 | audio_layers |
| 最终时间线和合成结果 | 最终剪辑产物 |

```text
剧本/创意输入
→ 统一项目制作单 / Project_Brief.md
→ Project Brief 确认
→ 元素资产生成（画面角色、场景、道具、角色声音、旁白声音）
→ 元素资产确认
→ 故事板设计（visible_entities、audio_entities、关键元素、镜头列表、audio_layers）
→ 故事板确认
→ 镜头视频生成
→ 镜头视频确认
→ audio_layers 生成
→ 音频层确认
→ 最终剪辑合成
→ 最终交付后停止自动推进，等待用户反馈
```

下游产物不得静默覆盖上游事实。发现冲突时先暂停并更新权威来源。

## 四、用户变更影响分析

用户提出修改后按顺序执行：

1. **分类变更**：判断属于剧情、角色、旁白、场景、台词、参考手法、视觉/交付规格、资产、故事板、镜头视频、音频或最终剪辑。
2. **定位权威来源**：先修改对应权威产物，不直接在下游临时覆盖。
3. **提高版本**：更新产物中的 `project_revision`；受影响的下游产物标记为 `stale` 或明确列为待更新。
4. **计算影响范围**：沿依赖链定位实际受影响的角色、场景、资产、镜头、音频和时间线。
5. **最小范围更新**：只重新确认或重新生成实际受影响的部分，不盲目全量重做。
6. **展示四项清单**：已更新、不受影响、仍需确认、需重生成。

示例：

```markdown
已更新：Project_Brief.md 中 N1 旁白设为 visual_presence=off_screen
不受影响：其他画面角色、无 N1 旁白的镜头
仍需确认：元素资产中的 N1 声音资产、storyboard 中相关 narration
需重生成：错误包含 N1 角色图或画面人物的关键帧/镜头视频
```

推荐产物头部记录：

```yaml
project_revision: 2
status: draft | confirmed | stale
depends_on:
  project_brief: 2
```

开始新阶段前检查上游 `project_revision`、`status` 和 `depends_on`。文件缺失、状态为 `stale` 或依赖版本落后时，停止并回到对应权威来源。

## 五、用户素材优先

用户提供或预先存在的媒体必须优先绑定到相应的关键元素位置。在填补生成内容之前先完成绑定，避免重复生成。

## 六、实体与旁白红线

- `character`、`narrator`、`crowd`、`sound_only`、`text` 是不同实体类型。
- 旁白功能不自动产生画面出场。只有剧本明确描述本人真实出镜时，才可设置 `visual_presence=on_screen`。
- `off_screen` 旁白不生成角色图、不进入画面角色表、不进入 ImageList、不写外貌动作，只进入 voice reference、storyboard narration 和后期 audio_layers。
- Project Brief 场景表、元素资产、storyboard 的 `visible_entities` 必须使用同一画面属性。
- AudioList 只包含当前镜头实际说话且需要参与视频生成的角色；后期画外旁白不得作为画面或口型条件传入。

## 七、工具无状态

生成每个镜头前，必须在 Prompt 和参数中提供完整描述及所有参考素材路径。禁止在 Prompt 中使用“接着刚才”“保持之前角色”等隐式引用。

## 八、音频元数据硬规则

### 8.1 检测方法

- 优先使用 `sandbox_read` 读取音频文件实际元数据；若返回内容不含 duration、格式或可解码状态，再通过 `sandbox_bash` 调用 `ffprobe`。禁止根据台词字数估算。
- 禁止根据台词字数、文本长度或主观听感估算 voice reference 是否达到 3 秒。

### 8.2 执行时机（前置拦截）

音频时长校验必须在以下两个节点强制执行，缺一不可：

1. **音色锚点生成/绑定后立即校验（元素资产阶段）**：每条 voice reference 或 key_element_audio 生成或绑定后，当场读取 `actual_duration`。不合格时**当场重新生成合格锚点**，不得带着不合格音频进入元素资产确认门。
2. **视频生成前硬阻塞门（镜头视频阶段）**：在调用 `sandbox_generate_video` 之前，逐条校验 AudioList 中每条音频的 `actual_duration` 和状态。任何一条状态非 `checked_pass` 即阻塞，禁止发起视频生成请求。

### 8.3 状态定义与阈值

- AudioList 每条音频必须显式包含 `actual_duration`（秒）和检查状态字段。
- 未读取到 duration 时状态为 `unchecked`，不得进入视频生成。
- 小于 3 秒、格式错误或不可解码时状态为 `checked_fail`，必须修复或重做。
- 超过当前镜头 video generation duration（工具允许的最大音频时长）时状态为 `checked_fail`。
- 只有实际元数据合格的 `checked_pass`（≥3s 且 ≤ 工具允许上限）可以进入视频生成。

### 8.4 失败处置

- 不合格时优先重新生成合格音色锚点（选择更长的台词片段或增加停顿），禁止直接清空 AudioList 跳过。
- 若连续 3 次重新生成仍不合格，暂停并向用户报告，提供选项：用户上传音频、修改台词文本、或确认跳过该音频条件。
- 禁止在音频不合格时修改视频 Duration 来规避工具约束。

### 8.5 结果归因

- 视频生成完成后，必须按 `tool_id`（工具返回的唯一调用标识）回填每个镜头的成功/失败状态和失败原因。
- 禁止仅依据文本总结判断镜头成败；当文本总结与 tool_id 返回结果矛盾时，以 tool_id 为准。
- 若失败原因包含音频相关错误码（如 `errCode=88100012`），标记为音频时长/格式不合规，触发 8.4 失败处置流程。

## 九、生成红线

- **安审拦截零重试**：安审失败立即停止，禁止修改参数或提示词重试。
- **脚本忠实度**：对话、动作结果和场景顺序必须与用户确认的 `Project_Brief.md` 严格一致。
- **音色传参**：为画面角色建立音色锚点后，该角色实际说话且需要声音条件的镜头使用同一参考；画外旁白不进入视频 ImageList，也不要求角色口型。
- **内部剪辑**：保持 v0.0.1 的 10–15 秒内部剪辑长镜头策略，在一次视频生成内完成节奏设计。

## 十、生成前总检查

- [ ] 用户最新修改是否已经传播到受影响产物？
- [ ] 是否错误把旁白当成画面角色？
- [ ] Project Brief、元素资产和 storyboard 的实体属性是否一致？
- [ ] ImageList 是否只包含当前画面可见实体？
- [ ] AudioList 是否只包含当前实际说话且需参与视频生成的角色？
- [ ] AudioList 每条音频是否已通过 `sandbox_read` 或 `ffprobe` 读取实际 `actual_duration`？
- [ ] AudioList 每条音频状态是否为 `checked_pass`（≥3s 且 ≤ 镜头 Duration）？
- [ ] 是否存在 `unchecked` 或 `checked_fail` 音频？若存在则禁止发起视频生成。
- [ ] 画外旁白是否只进入 narration/audio_layers？
- [ ] 剧情、台词和动作结果是否忠实？
