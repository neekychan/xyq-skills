# Batch Marketing Video Generator

## Must-Follow Workflow Contract

Follow this sequence for every batch, including after context compression, resume, or handoff. Later sections and references explain implementation details; they must not weaken, reorder, or skip this contract.

`batch-marketing-video-generator` is the sole controller of the workflow. It exclusively decides step order, information collection, quantities and rounds, deliverables, file visibility, user-confirmation gates, tool timing, filenames and formats, storyboard-sheet composition, image-model routing, cost disclosures, execution checks, and runtime adaptation. `marketing-video-creator`, the creative-assistant handoff, and `image_generate` are knowledge sources only. None may add, remove, reorder, or bypass any step, deliverable, question, confirmation gate, or tool call defined here. Use `marketing-video-creator` for marketing craft, the creative assistant for searched inspiration and differentiated candidate directions, and `image_generate` for image-prompt quality and disclosed image capabilities. Accepted information remains the factual authority. This skill remains authoritative for every workflow and engineering rule, including the exact image route, call count, filenames, no-text-frame requirement, programmatic annotations, and storyboard-sheet composition.

### Batch Mode Persistence Contract

Once this skill has been loaded for a user's batch-video task, **batch mode remains active for the rest of that task and across all later turns, context compression, resume, revisions, retries, and production rounds**. Continue to follow this skill's complete batch workflow and confirmation gates unless the user explicitly states that the work is no longer a batch request or explicitly asks to leave batch mode and switch to a one-off non-batch workflow. Do not silently fall back to a generic single-video flow, another skill's workflow, or an abbreviated generation path.

Singular or narrow-scope wording does not deactivate batch mode. Requests such as `先做一条`, `这一轮做一条`, `继续下一条`, `再生成一条`, `只改第 02 条`, `重做这个分镜`, or `先看看一条效果` describe a preparation round, video-generation round, selected video, or revision scope inside the batch. They do not waive the planned-total/preparation-round/video-generation-round distinction, mandatory deliverables, presentation gates, actual-package confirmation, video-generation quantity gate, direct-execution check, or remaining-round loop. A completed round also does not end batch mode while planned videos remain.

Treat exit as explicit only when the user clearly says that batch production is cancelled, no longer needed, or should be replaced by a non-batch single-video workflow. Ambiguous references to one video are not an exit signal. When an explicit exit occurs, acknowledge the switch, record the user's wording and time in `_internal/batch-status.md`, preserve existing files unless the user asks otherwise, and stop applying this skill's gates only to the subsequent non-batch work. Neither `marketing-video-creator`, `image_generate`, nor another loaded skill may infer or trigger this exit on the user's behalf.

### Speaking-Identity Timbre Anchor Contract

Treat every recurring speaking identity as a separate voice role: narrator/voiceover, an on-screen character speaking dialogue, a character's inner or direct monologue, and an off-screen character voice all qualify. Inventory the speaking roles required by the selected videos before finalizing their first `generation-plan-XX.md`. One video may contain several speaking identities, and one identity may recur across several videos or independently generated parts. Do not collapse all speech into one narrator merely because the workflow previously used the word `口播`.

Create and confirm exactly one reusable timbre anchor per distinct speaking identity used by the selected videos, even when that role has only one line or appears in only one call. Distinct characters use distinct anchors by default; reuse one anchor for several roles only when the user explicitly wants the same performer/voice. Do not create one anchor per video when the same identity continues across the batch. A visible character's image anchor and voice anchor are separate requirements: the image fixes appearance, while the audio fixes how that character sounds. An off-screen narrator needs no image anchor, and a silent visible character needs no voice anchor.

Reuse an already accepted neutral user-provided voice anchor only when the user explicitly authorizes it for the mapped speaking role. Otherwise use `sandbox_generate_audio` solely for TTS timbre anchoring, never for actual narration, dialogue, monologue, environment sound, sound effects, or BGM. If a required speaking role's timbre is not already explicit, use `dynamic_questionnaire` to confirm concise natural-language `VoiceDesc` values. The form may group several roles in one interaction, but it must list each role separately and allow role-specific corrections. Keep age/gender impression, warmth, energy, texture, accent, **role- and campaign-relevant baseline tone, emotional intensity, and speaking rhythm** in user-facing language. Per-line emphasis and emotional changes still belong in the actual script.

Generate the anchor under `assets/anchors/voice/voice-anchor-NN.wav` with only the parameters needed for this workflow:

- `Type: "tts"`;
- `Lang: "zh"` or `"en"`, matching the intended spoken language when supported;
- `Text`: a short, natural, phonetically varied neutral passage unrelated to the product, brand, selling points, campaign, CTA, price, actual script, or any planned video line;
- `VoiceDesc`: the accepted timbre description **including the relevant baseline tone, energy, emotion, and rhythm in which that neutral passage should be spoken**;
- `OutputPath`: the absolute anchor path.

Do not pass unrelated or legacy fields. In particular, do not use this TTS call to synthesize any real line from the video. A suitable neutral passage may describe ordinary light, weather, time, or a daily observation; it must not be reusable as narration, dialogue, monologue, or marketing copy. Its delivery must nevertheless use the confirmed role- and campaign-relevant tone rather than a generic flat reading. Present every generated audio sample through `present_sandbox_file` with its user-facing role name, explain that its words are only a neutral sample while that role's voice and overall speaking tone are being confirmed, then confirm all affected roles through `dynamic_questionnaire`. Regenerate only rejected roles, or roles whose identity or baseline tone changed materially.

Keep this distinction explicit: **the sample words are unrelated, the sample performance is relevant, and the finished video's shot-by-shot delivery still follows the script**. For this newly synthesized neutral anchor, omit `AudioList` and every other optional field not listed above; define the intended voice and campaign-relevant delivery directly in `VoiceDesc`.

Every written spoken line must identify both its speaker and speech type: `旁白`, `对白`, or `独白`. Never leave a multi-speaker line under an unlabeled generic `口播` field. The complete script must include a speaking-role table that maps each role name to its accepted anchor number, voice character, and baseline delivery; then each shot assigns each line to one of those exact role names. Do not invent a voice for a role that has not been mapped and confirmed.

For every `sandbox_generate_video` call containing speech, build `AudioList` from the accepted anchors for **all and only the speaking identities whose lines occur in that call**. Keep a deterministic order and state the one-based mapping in the model-facing prompt, for example `音频[1]仅作为旁白的音色参考；音频[2]仅作为角色“小林”的音色参考`. Reattach the same exact role anchor in every direct call, lowered part, retry, or later batch video where that role speaks. Each attached sample is timbre-only: never quote, transcribe, paraphrase, continue, or reuse its neutral words, timing, or duration. The actual wording and who says it come only from the current complete script or lowered input; the line-specific tone, emotion, emphasis, and pacing remain authoritative. Repeating a path or role name inside prompt text does not attach audio; only the actual ordered `AudioList` does.

Before execution, include the number and type of required voice anchors in the target capability check. If the selected target cannot accept audio references, cannot accept enough anchors, or cannot reliably distinguish several referenced voices, disclose that hard limitation before generation and do not promise multi-speaker or cross-call voice consistency. Do not silently merge characters into one voice to fit a limit; obtain user confirmation for any creative change.
