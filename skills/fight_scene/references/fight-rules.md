# 武打动作片段红线与强制规则

本文件在构造视频 Prompt 前加载。

## 一、单次生成红线

1. 当前用户轮次只能调用一次 `sandbox_generate_video`，一次调用只生成当前一段。
2. 单段新片、参考生成或续段未指定时长时显式使用 `{{.max_video_duration}}` 秒；视频编辑默认沿用源片时长。
3. 不生成前置角色图，不把 storyboard 写成文件或图片（分镜预算表按 `fight-prompt.md` 以回复文本输出），不在同一轮拆分生成，不合成。
4. 普通需求保持单段。只有用户明确选择多段时才跨用户轮次逐段生成，每轮仍只生成一次。
5. 单段复杂需求通过删减次要人物、次要招式和铺垫完成压缩，保留核心对决、标志动作与结局。
6. 一个 Prompt 内可以包含多个镜头；一镜到底时只写连续阶段，禁止出现切镜词。
7. 工具调用无论成功或失败都占用这一次机会。参数报错、安审失败和其他失败后立即停止，禁止修正后再次调用。
8. 生成只能由 `sandbox_generate_video` 工具本身发起，Prompt 用 `Prompt` 参数直接传入。禁止把规划、自检或 Prompt 写成任何 md、txt 等沙盒文件，禁止使用 `PromptPath`、为生成预建 `output` 目录、回显确认或用脚本模拟调用。编辑与续段按对应 Ref 做的 ffmpeg 素材预处理不受此限。

### 生成参数契约

- `Duration` 为整数，准确上限以 `SKILL.md` 已渲染数字为准。上限 30 秒时支持 2 至 30 秒；上限 15 秒时支持 4 至 15 秒。
- `Ratio` 只允许 `16:9`、`9:16`、`4:3`、`3:4`、`21:9`。
- `ImageList` 最多 9 张，`VideoList` 最多 3 段，`AudioList` 最多 3 段。素材超量时使用执行流程中的唯一一次问卷选定本轮子集，禁止静默截断。
- 每项素材都要在 Prompt 中有明确用途。音频按列表顺序使用 `@音频1`、`@音频2`、`@音频3` 绑定到音色、节奏、音乐或音效，禁止只传列表不引用。

## 二、用户素材与形象锁定

### 上传素材的默认权限

- 数量合法且与任务相关的原素材，以及问卷最终选中的素材，直接进入对应 List，禁止用重绘素材替代。
- 只从素材可见内容提取身份锚点，不臆测被遮挡部分。
- 未经用户明确要求，保持主体脸部或头盔、体型比例、发型、服装或皮套轮廓、主色、纹样、材质、武器和画风。
- 可增加动作、镜头、环境反馈与用户要求的特效，不主动增加变身、换脸、换装、机械化、年龄变化或物种变化。

### 视频编辑保留项

- Prompt 首句逐字使用 `严格编辑<视频1>`，尖括号是任务语法，禁止改成 `严格编辑@视频1` 或“参考视频1”。
- 编辑模式默认保持源片时长、原声音、字幕、UI、已有文字、logo、镜头节奏和未被点名的画面内容。
- Prompt 只描述用户要求修改的对象、原特征与新特征，禁止套用新片默认尾注去删除原片已有元素。
- 只要求“不新增随机文字、水印或 logo”。用户明确要求移除已有元素时再执行。
- 源视频长于当前模型上限时，生成前确认要编辑的片段与合法时长。

### 特摄素材最高优先级规则

用户上传特摄人物、皮套英雄或怪人素材时：

1. Prompt 开头逐项锁定头盔几何、面罩或复眼、胸甲、腰带或装置、肩甲、主辅配色、纹样和身高比例。
2. 全片保持同一套皮套和装甲材质，禁止露出皮套下的人脸。
3. 用户没有明确要求变身时，全程维持上传形态。
4. 用户明确要求变身时，只允许一个清楚的形态变化节点；变化前后分别定义外观，列出至少两个保留的身份标志。
5. 大幅旋转、遮挡、爆炸、烟尘和特效高亮之后，再次写出头盔与胸甲锚点，防止形象漂移。

### 多主体素材绑定

- 分别定义“主体A、主体B、主体C”，每个主体固定 2 至 4 个静态特征。
- 主体为动物拟人或其他非人角色时，按同样方法固定物种、头身比例、毛色或表皮特征与服饰，动作幅度符合其身体结构。
- 每个主体固定武器、持握手、特效色和战斗策略。
- 同框精确描述最多 3 个角色。更多敌人用统一轮廓的背景群体表达，不逐个定义。
- 用户点名的具名角色超过 3 个时，逐镜头轮换聚焦，同一镜头内精确描述不超过 3 个，其余角色在该镜头退为背景轮廓或画外。
- Prompt 末尾要求主体不互换、不复制、不融合，服装和武器不跳变。

### 攻击目标绑定

- 每个动作句都显式保留“主体X攻击主体Y，主体Y如何应对”的主客体关系。
- 除非用户明确要求自伤、失控或误伤，攻击主体和目标主体不得相同。
- 2v1、2v2 和群战先建立阵营表与当前主交锋对，后续镜头按该映射执行。
- 写完 Prompt 后搜索每个主体标签附近的攻击动词，核对目标是否写错、漏写或中途换阵营。
- 少用“他、对方、敌人”一类代词，高密度交锋直接重复主体标签。

## 三、空间连续性

每个镜头或连续阶段都要能回答：谁在哪里、面朝哪里、相距多远、下一步如何到达新位置。

### 必须锁定

- 起始站位：画面左侧、右侧、前景、后景或镜头正前方。
- 朝向：双方互相面对；2v1 中同阵营角色共同面向目标。
- 距离：贴身、近距、中距或远距，距离变化必须由冲刺、退步、击退、翻滚或跃迁造成。
- 环境几何：地面材质、墙柱、桌椅、台阶、车辆、竹林或建筑等可互动对象的位置。
- 切镜后重新说明站位，避免角色突然换边。

### 多人协同

- 2v1 选择一种明确关系：前后夹击、控制后输出、击飞接力、掩护换位。
- 1v多突出主角移动路线和逐个击倒的节奏，避免所有敌人同时贴在主角身边。
- 群战优先中全景或过肩视角，保留空间纵深。

## 四、动作可执行性

### 一组攻防的最小闭环

每组有效攻防必须包含：

1. 攻击方发力与动作路径。
2. 防守方格挡、闪避、截击或反制。
3. 明确接触点或明确擦身而过。
4. 受力方向、重心变化与脚步结果。
5. 双方进入下一组动作前的可见姿态。

“激烈交锋、拳拳到肉、招式凌厉”只能定调，不能替代动作闭环。密集交换时可把五项合并进一句压缩闭环（攻击、防守、接触反馈各有着落即可），只有决定性命中才完整展开。

### 动作粒度

- 每个镜头一条连续攻防链：至少 3 次可见接触、招式轮换不重复，密集往返用压缩闭环一句带过，交换次数不设上限；链内不切换武器、形态或插入大招流程。远程法术对轰以一次“投射—拦截—反制”闭环计一次可见接触。
- 攻防不脱手：交换之间禁止“后跃拉开距离”“悬浮蓄力”“重新凝聚”“再次对峙”类脱离重整过渡，收势直接衔接下一击，被击退方立即回身反扑；每个攻击动词带速度修饰（疾、急、瞬间、毫不停顿），无速度词的动作会被执行成慢速。远程对轰范式的中远距对射不算脱手，但结印凝聚必须与位移、防御或压制并行，独立悬浮蓄力仍禁止。
- 描述“连续刺击逼退、横挡后借力旋身反击”一类因果关系，避免逐帧角度和厘米级轨迹。
- 高难动作留出完整起势、腾空、落地和恢复，避免同一拍塞入多次翻转、换武器和大招。
- 默认第一镜头就是进行中的交锋，空间信息随动作带出。用户明确要求登场铺垫时，允许不超过全片六分之一的静止蓄势开场；静势速胜曲线的蓄势占比按 `fight-prompt.md` 强度曲线执行。

### 防守匹配

- 徒手攻击可用前臂架挡、抱架、闪避、截腿、擒抱或步法卸力。
- 冷兵器攻击用兵器格挡、护具抵挡、闪避或缴械，避免无设定的徒手接刃。
- 远程与法术攻击用护盾、同类能力抵消、掩体或明确位移闪避。
- 重击命中后必须出现身体反馈；只写武器格挡会让角色像静止木桩。

### 武器连续性

- Prompt 开头锁定武器长度、形状、数量、持握手和备用手状态。
- 镜头结束时的持握与姿势必须能衔接下一镜头开头。
- 武器脱手、换手、折断、合体或召回都需要明确动作原因。
- 禁止同一把武器无原因复制、消失、穿过身体或突然改变尺寸。

## 五、打击感分级

### 写实克制

适用于拳击、MMA、真实古代武打和运动竞技：

- 发力：支撑脚蹬地、转髋、沉肩、腰背带动或重心下压。
- 接触：皮肤、护具、布料或兵器短暂压缩、震颤、摩擦。
- 受力：后仰、侧偏、架势被打开、退步、踉跄、靠墙卸力。
- 镜头：命中瞬间一次短促微震或短暂停顿，随后迅速恢复可读性。
- 环境：汗滴、尘土、积水、木屑、碎瓷、衣摆等小尺度反馈。
- 声音：破风、闷响、鞋底摩擦、急促呼吸和环境回声同步出现。
- 禁止每一拳都产生光波、地裂、夸张倒飞或大面积飞溅。

### 电影夸张

适用于动作片、特摄与风格化真人：

- 允许更明显的身体位移、镜头冲击、火星、烟尘和局部结构破坏。
- 决定性重击只安排一次最强反馈，前面保留层级。
- 角色受击后仍需遵循明确方向和惯性，不使用无原因瞬移。

### 玄幻拉满

适用于仙侠、超能、机甲与怪兽：

- 先写清楚肉身或武器动作，再附着特效。
- 每个角色固定“颜色 + 材质 + 形态 + 运动轨迹”四项特效身份。
- 特效从身体、武器或接触点生长，禁止角色站立不动、独立光团替角色交锋。
- 大招写完整因果：蓄势、成形、推进、碰撞、防御变化、环境余波、角色落点。
- 全片只保留一个场景级爆发，避免每镜头都毁天灭地。

## 六、镜头与动作冲突检查

以下组合禁止同时出现：

| 冲突 | 处理 |
|------|------|
| 一镜到底 + 快切或跳切 | 保留一种主导语法；一镜到底只用顺势推进、绕柱、遮挡、穿门、环绕 |
| 真第一人称 + 无过渡第三人称正脸 | 保持主观视角；只有镜面反射或用户明确要求时短暂看见主角 |
| 写实无特效 + 每拳冲击波 | 改为衣料、汗尘、脚步、护具和镜头微震 |
| 复古低帧赛璐璐 + 全程高帧丝滑 | 保留有限动画、关键姿势与冲击帧的风格一致性 |
| 只要环境声 + 史诗 BGM | 按用户声音偏好保留一项 |
| 慢动作 + 每一招都慢放 | 默认全程无慢放；仅千钧一发闪避可极短慢放一次 |
| 角色过多 + 每人复杂连招 | 精确角色减至 2 至 3 个，其余作为背景威胁 |

## 七、复杂度预算

一个“主要动作节拍”包括一组会改变位置、武器、形态、目标或胜负状态的事件：

- 2 至 8 秒：最多 2 个主要动作节拍。
- 9 至 15 秒：最多 3 个主要动作节拍。
- 用户选择的时长高于 15 秒且当前模型允许时：最多 5 个主要动作节拍。
- 目标切换、武器切换、形态变化各自计为一个新节拍。
- 成组并发元素（多重投射物、分身、虚影群）整组计一个节拍，每镜至多一组、全片至多两组，其中场景级爆发仍只保留一次。
- 单片最多一次形态变化、一次终结技；慢动作默认不用，仅千钧一发闪避可极短一次。
- 招式交换次数不计入节拍；独立的建立与收势镜头也不计入，但合计不超过全片四分之一。

## 八、视觉与声音底线

- 默认无旁白、少台词。战吼或短句不超过 10 个汉字，并在动作中说出。
- 音效用 `<>`，台词用 `{}`，音乐用 `（）`，字幕用 `【】`。
- 新片参考、纯文本和续段中，用户未要求字幕时保持无字幕。编辑模式保持原片已有字幕与文字。
- 默认保持非血腥的电影级冲击，避免断肢、内脏和持续血液喷溅。
- Prompt 全文不出现“血”字（游戏 UI 的“血条”除外）：暗黑或魔道能力用暗红魔气、赤黑煞气、深红邪焰表达，环境比喻改用“残阳似火”一类无血字写法。
- 人脸、手指、肢体数量保持稳定，关节方向合理。
- 不新增水印、logo、随机文字或界面元素。编辑模式保留原片已有元素，游戏化类型按用户要求保留指定 UI。

## 九、失败前自检

调用视频工具前在内部静默逐项确认，不输出核对过程与勾选结果；任何一项不通过先修正再调用：

- [ ] 本轮此前没有调用过 `sandbox_generate_video`
- [ ] `Duration` 已与 `SKILL.md` 渲染的上限做数值比较，不依赖模型名猜测
- [ ] 数量合法且任务相关的素材、问卷选中素材全部直接绑定，特摄形象无主动变化
- [ ] 主体数量、身份、武器、左右手和特效色固定
- [ ] Prompt 的主体外观、场景与决定性动作未与已加载 Ref 示例的写法重合
- [ ] 每镜头有清楚站位和距离变化原因
- [ ] 每组攻防有防守、接触、受力和下一姿态
- [ ] 每句攻击的主体和目标正确，无自我攻击、阵营互换或目标漂移
- [ ] 分镜预算表已输出，各镜秒数之和等于 Duration，主要动作节拍（含成组并发元素）没有超过对应预算
- [ ] 打击反馈符合写实、电影夸张或玄幻三档中的一档
- [ ] 场景级爆发不超过一次（法相显形、剑阵完整展开、地形级对撞各计一项）
- [ ] 主导镜头语法只有一个，全程无慢动作或仅千钧一发闪避极短一次
- [ ] 高潮镜头或高潮阶段含镜头处理与余波落点，结尾停在完整接触反馈或稳定姿态
- [ ] 每个交锋镜头至少 3 次可见接触且招式轮换，开场第一句即接触，无叙事设定句和抽象声明词
- [ ] 攻击动词带速度修饰，交换之间无“后跃拉开、悬浮蓄力、重新凝聚、再次对峙”类脱离重整句，全局段含节奏基调
- [ ] `Duration`、`Ratio`、素材数量全部符合生成参数契约
- [ ] `OutputPath` 逐字等于 `output/fight_scene.mp4`，未为生成预建 `output` 目录，未把规划、自检或 Prompt 写入任何 md、txt 等沙盒文件
- [ ] Prompt 将通过 `Prompt` 参数直接传入，未使用 `PromptPath`，规划完成后直接调用、中间无其他工具调用
- [ ] `ImageList`、`VideoList`、`AudioList` 三个键全部显式出现，无素材的键传 `[]`，有素材的与 Prompt 引用顺序一致，音频已用 `@音频N` 绑定用途
- [ ] 新片尾注禁止新增字幕、水印与随机文字；编辑尾注保持源片未提及内容
