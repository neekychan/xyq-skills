# 需求挖掘:把想法变成完整的技能规格

当用户带着的只是一个想法（"我想要一个能……的技能"）而非成形的技能文字时，使用本指南。目标是高效地访谈他们，并收敛到一份完整、可生成脚手架的规格说明。

## 目录

1. 原则
2. 五个维度（完整问题清单）
3. 逐轮措辞示例
4. 应对"我不知道"——默认建议
5. 草稿确认总结
6. 完整范例

## 1. 原则

- **访谈，而非审问。** 每一轮最多问 2–3 个问题，按维度分组。
- **杠杆最高的优先。** 触发场景和预期输出通常能解锁其余一切;在问步骤和边缘情况之前先问这两项。
- **先推断，再确认。** 如果上下文已暗示了答案，就陈述你的假设而非提问（"我假设输入是一段粘贴进来的文本——对吗?"）。
- **绝不打转。** 如果用户答不上来，提出一个默认值并继续。不要重复问同一个维度。
- **快速收敛。** 一旦五个维度都有了可落地的答案（一个经过推敲的默认值也算），就停止。

## 2. 五个维度（完整问题清单）

一个技能在以下每一项都有可落地的答案后，即可生成脚手架。

### ① 触发场景 → 喂给 `description`
- 这个技能应在何时启动?用户当下试图做什么?
- 是否有特定的任务类型、文件类型、关键词或意图应当激活它?
- 是否存在某种应当明确**不**使用它的情形?

### ② 输入 —— 用户每次提供什么
- 用户会给这个技能什么?（文字请求、上传文件、链接、参数?）
- 如果是文件:什么格式?单个还是多个?大致多大?
- 哪些输入是必需的、哪些是可选的?

### ③ 预期输出 —— 交付物
- 这个技能应当产出什么?（文档、总结、表格、生成的文件、执行的动作?）
- 输出应采用什么格式 / 结构?（Markdown、飞书文档、表格、纯文本?）
- 有没有一个"好"输出的模板或示例可供参照?

### ④ 步骤 / SOP —— 工作如何完成
- 带我走一遍你手动做这件事的步骤。
- 哪些步骤是固定顺序的，哪些可以变动?
- 是否有决策点 / 分支（"如果 X 则……"）?
- 是否有步骤依赖外部查询、计算或阅读参考资料?

### ⑤ 约束与边界 —— 护栏
- 这个技能绝不能做什么?
- 它通常在哪里出错 / 有哪些需要留意的边缘情况?
- 有没有语气、长度、语言或格式方面的规则?
- 有没有数据敏感性或范围方面的限制?

## 3. 逐轮措辞示例

每一轮保持 2–3 个问题。典型的推进节奏:

**第 1 轮（触发 + 输出）:**
> "几个问题来界定范围:
> 1. 这个技能应在何时激活——用户通常想做什么?
> 2. 它完成后应交回什么，以何种形式（图片、视频、纯文本……）?"

**第 2 轮（输入 + 关键步骤）:**
> "明白了。接下来:
> 1. 用户每次会给它什么——文字请求、上传参考图、视频，还是别的?
> 2. 带我走一遍你手动产出那个输出的过程——主要步骤。"

**第 3 轮（约束 + 边缘情况）:**
> "快好了:
> 1. 有没有它绝不能做的事，或者任何语气/长度/格式规则?
> 2. 这类任务通常在哪里出错——需要防范哪些边缘情况?"

灵活调整:如果用户的第一条消息已经回答了某个维度，就去掉那个问题。

## 4. 应对"我不知道"——默认建议

当用户不确定时，给出一个具体的默认值并继续推进。示例:

| 维度 | 若用户不确定，默认为…… |
|-----------|-------------------------------|
| 触发 | 从陈述的目标推断;围绕该意图来组织 description。 |
| 输入 | "用户的一段自由文本请求"，除非提到了文件。 |
| 输出 | 散文类任务用 Markdown 文档;对比类用表格;用户在飞书办公时用飞书文档。 |
| 步骤 | 从人会怎么做推导出的简单线性 SOP。 |
| 约束 | 标准护栏:不跑题、匹配用户语言、不编造数据、保持输出精简。 |

明确陈述该默认值，以便用户提出异议:"没有强烈偏好?那我默认用 Markdown 总结——如果你更想要表格，说一声。"

## 5. 草稿确认总结

在生成脚手架（第 3 步）之前，把一切复述为一份紧凑、结构化的总结，并请求确认:

```
这是我将要构建的内容——请确认或更正:
- 技能名称: <hyphen-case>
- 触发时机: <场景>
- 接收的输入: <输入>
- 产出: <输出 / 格式>
- 步骤: 1) … 2) … 3) …
- 不做 / 需注意: <约束>
```

只有在用户确认之后（或在一份已经完整的总结上用户已明确示意"直接开始"之后），才进入 `init_skill.py`。

## 5b. 创意类技能的追加维度（视频/图片技能）

当用户要创建的是**视频、图片、广告、品牌片、短剧电商、UGC** 等创作类技能时，在通用五维之外，再敲定下面这些维度——它们直接喂给“黄金架构”的八个支柱（见 `creative-skill-patterns.md`）。同样遵守“先推断、给默认、绝不打转”。

| 追加维度 | 喂给架构的哪一支柱 | 若用户不确定，默认为…… |
|-----------|----------------------|------------------------------|
| 思维引擎链 | 核心原则 / 持久引擎 | 从“受众压力 → 产品真相 → 证据 → 转化”推导一条因果链 |
| 质量测试 | 可证伪质量测试 | “若没有这个产品，关键转折无法以这种方式发生” |
| **目标市场 / 语种（必问）** | 输入诊断 / 市场本地化 / **决定产物语言** | 未指明则按线索推断主市场；产物语言必须随之确定 |
| 格式与平台 | 路由表 | 短视频默认 9:16、TikTok/Reels；品牌片默认 16:9 hero + 9:16 改编 |
| 目标产物形态 | 输出契约 | 视频默认 15s、带时间戳 beat；图片默认写肖像/画幅规则 |
| 生成模型（可选，**默认不追问**） | frontmatter 的 `image_model` / `video_model` | **默认不问、不设置**，走平台默认模型；仅当用户主动点名模型时才按 `model-catalog.md` 处理 |
| 需要的 craft 层（可选） | references/craft（仅按需建） | **默认不追问、不建 craft**；仅当用户主动强调工艺，或上传文件已含灯光/运镜/声音等信息时才展开 |
| 合规敏感点 | 静默自检 | 健康/金融/酒精/博彩/儿童/可持续/AI 真实性/网红披露按需保守处理 |

> ⚠️ **“目标市场 / 语种”是必问项，且直接决定产物语言。** 产出技能的 SKILL.md 与所有 references 必须用该市场的工作语言书写（中国大陆/中文 → 全文中文；US/英语 → 全文英文），不得中英混杂、不得直接照抄骨架里的另一语言样例。访谈中若用户未明确市场/语种，要么据线索合理推断并在产物中保持语言一致，要么直接问清，**不要默认产出英文**。

访谈推进时把这些并进既有轮次：第 1 轮加“目标市场/语种 + 格式/平台”，第 2 轮加“目标产物形态”，收敛轮加“质量测试 + 合规敏感点”。**craft 工艺层默认不主动追问**——除非用户主动强调，或上传文件已含工艺信息，才在第 2 轮顺带确认。**生成模型同样默认不追问**——只有用户主动点名模型时才处理（见 `model-catalog.md`）。

## 6. 完整范例

**用户:** "我想要一个能帮我做商品营销短视频的技能。"

**第 1 轮（触发 + 输出 + 市场/格式,杠杆最高）:**
> "1. 它应在何时启动——每次你说'给这个商品做营销视频'并给我商品图时?
> 2. 目标市场和平台是哪一个（决定成片语言与画幅）——比如抖音中文竖屏,还是 TikTok 英文竖屏?"

**用户:** "对，我给商品图就启动。抖音中文竖屏。"

**第 2 轮（市场已明确;为输入与产物补默认值）:**
> "那我默认产出 9:16、≤15s 的中文竖屏成片。输入我按『商品卖点(自由文本) + 商品图(一张或多张)』来接,可以吗?"

**用户:** "可以。卖点我会给，商品图一般 1-2 张。"

**收敛 → 确认总结:**
```
这是我将要构建的内容——请确认或更正:
- 技能名称: product-marketing-video-maker
- 触发时机: 用户请求为商品制作营销视频，并提供卖点和商品图
- 接收的输入: 商品卖点（自由文本）+ 商品图（一张或多张）
- 目标市场 / 语种 / 画幅: 中国大陆抖音 / 中文 / 9:16 竖屏 / ≤15s
- 产出: 一支营销视频，分节 = 开场吸睛 / 卖点展示 / 行动号召（CTA）
- 步骤: 1) 把卖点解析进三个分桶并匹配商品图 2) 为每一节编写分镜脚本（画面+文案+时长） 3) 合成视频 4) 展示给用户
- 不做 / 需注意: 控制在 15 秒以内、契合品牌调性、不夸大或编造卖点中没有的功效与承诺
```
