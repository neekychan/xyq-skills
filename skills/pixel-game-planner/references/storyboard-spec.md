# 故事板与分镜规范

## 核心原则

像素游戏短片不是电影分镜，而是"可玩的游戏画面片段"。故事板必须遵守：

- 横版卷轴视角
- 主角从左向右推进
- 关卡目标明确
- 每个镜头只做 1-2 个动作
- 动作像低帧率逐帧动画
- 有 UI 反馈
- 有道具或敌人互动
- 有明确结尾
- 不做复杂电影调度
- 不做 3D 旋转镜头
- 不做真实人物表演

## 5 秒图生视频故事板

5 秒视频适合一个简单动作闭环。

### 方案 1：走路 + 捡金币
| 时间 | 画面 |
|------|------|
| 0-1 秒 | 主角待机，金币闪烁 |
| 1-3 秒 | 主角走两步靠近金币 |
| 3-4 秒 | 主角拾取金币 |
| 4-5 秒 | 金币消失，UI 金币数 +1，角色短暂停顿 |

### 方案 2：跳跃 + 平台
| 时间 | 画面 |
|------|------|
| 0-1 秒 | 主角站在平台左侧 |
| 1-3 秒 | 主角低帧率跳起 |
| 3-4 秒 | 落到右侧平台 |
| 4-5 秒 | 角色待机，屏幕轻微闪烁 |

### 方案 3：挥剑 + 击退小怪
| 时间 | 画面 |
|------|------|
| 0-1 秒 | 主角和小怪对峙 |
| 1-3 秒 | 主角挥剑 |
| 3-4 秒 | 小怪被击退并闪烁 |
| 4-5 秒 | 分数增加，主角胜利待机 |

## 15 秒像素短片结构

| 时间段 | 内容 |
|--------|------|
| 0-3 秒 | 展示关卡和角色 |
| 3-7 秒 | 角色移动或遇到敌人 |
| 7-11 秒 | 收集道具或触发机关 |
| 11-15 秒 | 通关动作 / UI 分数变化 / 结尾定格 |

## 标准分镜表模板

每个视频项目必须输出以下分镜表：

| 字段 | 说明 |
|------|------|
| 镜头编号 | 01, 02, 03... |
| 时长 | 该镜头持续时间 |
| 画面 | 当前镜头画面描述 |
| 角色动作 | 主角正在做什么 |
| 敌人动作 | 敌人正在做什么 |
| 道具 | 涉及的道具 |
| 关卡 | 关卡名称 |
| UI | UI 状态与变化 |
| 镜头滚动 | 固定 / 轻微向右 / 屏幕闪烁 |
| 音效 | 该镜头配合的音效 |
| 用到资产 | @PX-HERO-01 等 |
| 视频提示词 | 该镜头的完整视频提示词 |

## 动作库

分镜中优先使用以下动作：

### 主角动作
- 主角待机
- 主角走两步
- 主角小跳跃
- 主角挥剑
- 主角发射像素弹
- 主角捡金币
- 主角打开宝箱
- 主角拿钥匙
- 主角踩平台
- 主角进入传送门
- 主角胜利定格

### 敌人/道具/环境动作
- 小怪左右巡逻
- 小怪被击退
- 金币闪烁
- 宝箱打开
- 平台上下移动
- 机关门打开
- UI 分数增加
- 屏幕轻微闪烁
- 关卡标题出现

### 不建议使用的动作
- 复杂格斗
- 真实跑酷
- 连续翻滚
- 电影级推拉摇移
- 大幅度绕场
- 3D 旋转
- 真实人物表演
- 复杂面部表情
- 大量粒子特效

## 视频生成方式

- ≤15s 的视频用一次生成即可拿到完整成片
- 上面的 beat 分镜（0-3s/3-7s/…）是同一次生成内部的时间轴描述，不等于要多次调用
- 只有成片超过 15 秒时，才拆成多个 ≤15s 片段分别生成，再做后处理拼接
