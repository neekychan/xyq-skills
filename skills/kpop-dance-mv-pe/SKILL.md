# K-pop 团体舞蹈 MV Prompt Engineering Skill

## 目标与统一边界

在用户明确要制作 K-pop 团体舞蹈短 MV 时，先依据新音频输出简练的音频理解、推荐生成方案、时间轴和问卷；确认后在后台生成高精度 PE，直接提交给 2.5 模型单支成片，不走复杂 storyboard 或多段拼接链路。

- 单支视频时长必须 `≤30 秒`，画面核心是固定成员共同完成编舞、队形、C 位切换和受控成员镜头。
- 不把任务扩写成“偶像 + 剧情 + 关系线”，不以对白、剧情推进或人物关系为主。
- 首轮只展示：音频理解摘要、推荐生成方案、时间轴设计、问卷确认。
- 主提示词、控制点、负向词和关键帧引用须在后台完整生成并随任务提交，默认不在聊天正文展开。
- 只有用户明确索要“提示词／PE”时才展示后台实际 PE。
- 无新参考视频时，“高复刻”仅指达到既有舞蹈参考案例同等级的提示词细度、编舞控制、成员表现设计、人物稳定和镜头约束，不承诺逐镜头一比一复刻。
- 全片只保留一组固定 roster；默认禁止伴舞、观众、路人、背景人群及镜面／屏幕重复人体。
- 对口型是可选项：`不对口型`，或`仅 C 位／当前主角在可靠歌词镜头对口型`；不得默认全员强制对口型。

## 适用与不适用

优先使用：
- 用户上传新音频并要求女团、男团或混合团体 K-pop 舞蹈短 MV。
- 用户要求团舞、刀群舞、打歌舞台、多人直拍式表演，或“按之前女团舞蹈标准”“同款 K-pop 团舞 prompt”。
- 用户需要可直接投喂 2.5 视频模型的提示词包，而不是 >30 秒复杂 MV 流程。
- 打歌舞台以多人编舞、队形、C 位切换和成员表现为核心，而非主唱持麦的现场 Live。

不用于：
- 以剧情推进、人物关系或对白为主的偶像混合叙事。
- 以单人舞蹈、手势舞、单人直拍或颜值时尚展示为主的内容。
- 以说唱压场、舞台 Live 演唱或 CG 概念视觉为主的内容。
- >30 秒的多段 MV 生产流程。

## 输入边界与默认值

必需输入：
- `audio_path`，或用户明确指定的待分析音频片段。

可选输入：
- 歌词／字幕文本、人物参考图、场景参考图、参考视频及目标时间段。
- 指定人数、性别表达、服装方向、画幅、舞蹈风格、场景 archetype、对口型模式。

默认值：
- 画幅默认 `16:9`。
- 不锁死 6 人。未指定人数时，从 `4 / 5 / 6 / 7` 人中按音频能量、空间、画面密度和编舞可读性推荐。
- 无强约束时优先稳定档：`4–5` 人、浅纵深队形、30 秒内 `1–2` 次大队形切换。
- 只给音频时，主动设计人数、固定 roster、团体风格、成员分工、编舞、造型和场景，再交问卷确认，不得跳过。
- 未给人物图时，为 `M1–Mn` 每人设计至少 2 个互不重叠的身份锚点。
- 未指定场景时，按音频推荐 A／B／C 中最匹配的一类并解释原因，不得永远套用 A；都不合适时推荐其他自定义。
- 未选择对口型时，在问卷中给出推荐；没有可靠歌词时推荐不对口型。

## 音频来源与准入

- 用户上传或明确提供可用音频时，直接使用。
- 用户只给歌曲／BGM 名，或明确要求找音乐，且没有可用的 `audio_path`／`video_path` 时，调用 `pippit_omni_search`；`SearchType` 必须为 `mv_music`，`Query` 只做最小清洗，不得擅自添加歌手、版本、语种、年代或曲风。
- 将返回的候选音频提供给用户确认。
- 用户选定后统一绑定为 `canonical_audio`。
- 音频来源记录为 `uploaded_audio` 或 `copyright_music_asset`；版权库音频记录 `asset_id`、版本和选定片段。
- 无已确认可用音频，不进入生成。

### extract_lyrics 调用

- 在 `canonical_audio` 已确认并取得可访问的 `audio_path` 后，音频含人声或当前任务需要歌词信息时，调用 `extract_lyrics`，传入该 `audio_path`，获取歌词文本及对应时间戳。
- 将返回结果作为原有音频理解流程的输入，用于识别歌词关键词、歌词句段、hook、高潮及现有的画面或口型时间映射。
- 纯器乐或无歌词音频跳过该调用；工具未返回歌词时，继续按照原有音频结构分析流程执行，不阻断后续生成。

## 工作流程

### 1. 音频理解

先分析音频，再设计画面。至少提取：
- 总时长，以及前奏、铺垫、预副歌、hook、副歌、停顿和结尾收势。
- BPM 体感、鼓点密度、强弱拍、重拍、音色变化、能量抬升位置。
- 最适合作为群舞高潮、动作爆点、C 位切换、主唱镜头和 ending pose 的位置。
- 情绪更偏态度、甜辣、自信、力量、青春、暗黑或未来感中的哪一类。
- 歌词可用性，以及“不对口型”或“仅 C 位／当前主角在歌词镜头对口型”的建议。

把动作爆点、队形迁移、C 位交接、成员近景、镜头切换、剪辑、灯光和 LED 变化映射到明确的重拍、hook 入口、句尾或停顿；不得机械平均切段，也不得让动作、镜头、灯光各自随机卡点。

### 2. 参考视频高精度复刻

问卷必须提供“没有／上传视频／提供链接”，用户已提供时直接处理：
- 先取得真实可分析的视频文件；链接不可访问、不可下载或只有页面文本时，要求用户上传，不能假装看过。
- 用户指定时间段时只分析该区间；否则分析完整视频，并结合新音频时长选择复刻范围。
- 使用 `analyze_media` skill 提取：准确人数、固定 roster、身份锚点、造型、成员分工、队形与 C 位切换、主唱镜头、对口型比例、编舞动作、场景物理、地面支撑、纵深灯光、景别、运镜、剪辑重拍、高潮和 ending pose。
- 把人物数量、roster 身份、核心造型、关键队形、场景物理和镜头纪律列为必须复刻的硬锚；时间点、镜头密度和动作组合按新音频乐句、重拍与 hook 重排。
- 基于拆解结果改写本轮推荐方案、时间轴和后台 PE，不得分析后仍沿用通用模板；硬锚同时进入主提示词、控制点和负向词。
- 用户后补视频或链接时暂停生成，旧确认自动失效；按首轮简练格式重新展示修订方案、时间轴和问卷，重新确认后再生成。
- 用户只说“参考风格”而非高精度复刻时，才只继承视觉与镜头语法；否则按人物、队形、动作、场景和镜头高精度复刻。
- 成片后逐项对照人数、身份、关键队形、高潮动作、场景和镜头；缺失关键硬锚时不得宣称复刻完成。

### 3. 推荐生成方案

主动给出一版可修改方案，至少包含：
- 推荐人数及选择 `4 / 5 / 6 / 7` 人的理由。
- 固定 roster `M1–Mn`：逐人列出至少 2 个互不重叠、稳定可追踪的身份锚点。
- 身份锚点必须具体覆盖发型层次、发色深浅、耳饰、手套、外套层次、气质位、站位习惯中的两项或更多，不能只写抽象的“成员不同”。
- 团体整体风格：冷艳力量、甜辣、未来机能、暗黑酷飒、青春元气等。
- 成员分工：中心位、主舞位、风格位、表情位／镜头位；人数较多时补副中心、队形平衡位、活力位／视觉位。
- 表情位必须承担近景感染力、眼神、面部表情管理和镜头记忆点，不能只给名称而无可见表现。
- C 位是随乐段切换的表演位置，不是新人物身份；写清谁在何时成为当前 C 位／主唱、触发拍点和回归全员队形的方法。
- 编舞方向：刀群舞、groove、力量爆发或甜辣轻快；写清肩颈控制、手部细节、步伐推进、甩头转身、wave、定点停顿、地面动作是否出现，以及高潮动作核心。
- 队形切换：至少一次明确的 A 队形到 B 队形迁移、拍点、换位前后确认镜头和高潮队形变化。
- 对口型：明确“不对口型”或“仅 C 位／当前主角在可靠歌词镜头对口型”；其他成员维持自然呼吸、眼神和表情。
- 造型：服装、妆容、发型和配色；跨场景沿用同一已声明版本。
- 场景：A／B／C／其他、多视觉状态、地面支撑、空间纵深、灯光层次、真实物理和转场方法。
- 额外人物：明确不允许 backup dancers、观众、路人、镜面／屏幕重复人像或任何第 `N+1` 个人形。

人数推荐规则：
- 节奏强、空间大、需要完整队形层次时，优先 `5–7` 人。
- 旋律聚焦、镜头贴脸、强调个人辨识度时，优先 `4–5` 人。
- 无额外约束时优先中密度稳定方案，不把推荐写成唯一正确答案。
- 默认避免高遮挡、三层以上纵深、包围中心位和连续交叉穿插。

### 4. 时间轴设计

按音乐结构选择三至五段，不平均切分：
- 三段式：建立段 → 群舞高潮段 → 收尾段。
- 四段式：建立段 → 单人／小队铺垫段 → 群舞高潮段 → ending pose。
- 五段式：建立段 → 单人亮相段 → 预热／抬升段 → 群舞高潮段 → 收束段。
- 音频一开始就是强 hook 时，压缩铺垫并尽快进入群舞主段。

每段写明：
- 音频证据和重拍映射。
- 可见 roster、当前 C 位／主唱、对口型状态。
- 队形、动作、动作幅度和段尾姿态。
- 场景状态、地面关系、景别、构图、运镜、灯光／LED。

切分门禁：
- 切点优先落在乐句边界、强拍、hook 入口、歌词句尾或动作停顿。
- 高潮必须留足长度承载完整动作短句、动作爆点和至少一次清晰队形变化。
- 大队形切换前后预留人数确认镜头，不把换位埋在碎切里。
- 非高潮可有固定 roster 内的单人／小队亮相或特写，但不能压过高潮群舞。
- 镜头不能切得比动作完成更快。

### 5. 后台生成与提交

方案经问卷确认后，在后台生成固定结构的 prompt package，将主提示词、控制点、负向词和关键帧引用合并进视频任务并提交。聊天正文不重复展开技术内容。

## 三套可复用场景 archetype

每轮按音频、表演密度和视觉目标推荐其一，也允许自定义。A 或 B 也须通过区域、灯光、LED 内容、机位和构图变化形成至少两种可辨识状态，避免整支视频只有单一背景。

### A｜极简白红黑高反射盒子摄影棚
- 视觉：白／红／黑几何盒体，高反射地面与墙面，硬边轮廓、干净负空间、平面色块和镜面高光。
- 适配：重拍清晰、停顿利落、造型图形感强、动作需要精确显形。
- 状态：白色主盒、红色光区、黑色负空间切换；反射只表现材质，不复制成员人体。
- 镜头：正面大全景、中全景、低机位和少量构图特写，突出线条、队形与定点爆发。

### B｜专业打歌舞台
- 视觉：高亮 LED、深色反射地面、真实舞台纵深、强逆光、轮廓光和受控频闪。
- 适配：副歌强、能量高、需要正式回归舞台和 C 位爆发。
- 状态：LED 图形、色彩、逆光和频闪随乐段升级，但保持同一舞台物理布局、地面支撑与灯位逻辑。
- 镜头：导播式大全景／中景／当前 C 位或主唱近景；先以全景证明队形，歌词点切成员，及时回中全景恢复舞蹈可读性。

### C｜多外景 Y2K performance
- 视觉：住宅、车库、公寓、坡道、停车区或街角等真实空间，保留透视、自然光方向、材质尺度、地面接触和生活化纵深。
- 适配：groove 明显、青春轻快、Y2K、松弛街头感或音色层次丰富。
- 状态：以动作匹配、方向匹配、遮挡或句尾硬切跨场景；保持同一 roster、脸、造型版本、地面接触和动作连续，不借换景重生人物。
- 镜头：中全景跟随、侧向平移、固定广角和少量成员近景；仍以 performance 为核心，不发展剧情关系线。

推荐逻辑：
- 强几何重拍、干净停顿、造型感优先：A。
- 强副歌、舞台爆发、导播镜头和主唱分配优先：B。
- 松弛 groove、青春 Y2K、跨空间节奏层次优先：C。
- 用户参考场景的真实硬锚优先；A／B／C 都不合适时推荐其他自定义。

## 人物、人数、队形与镜头纪律

### 精确 N 人与 N+1 防护
- 确认 `N` 人后，后台 PE 第一条硬约束写为：`全片只能出现 N 个独立人体实体；每个时点画面中的人体总数不得大于 N`。
- 主提示词、固定 roster、身份锚点、控制点、负向词和关键帧里的 N 必须一致。
- 开场第一帧让 N 人全身清晰可数；禁止“中心位先单人出现，其余成员快速加入”等易增生 N+1 的写法。
- 偶数人数禁止以单中心为核心的 V 字构图。4 人优先一字横排、2×2、双前双后，不写“1 个中心 + 两侧对称展开”。
- 直接生成而无团队首帧时，减少进出画和复杂交叉；单人表现用镜头靠近固定成员，不用新增人物构图。
- close-up、小队、C 位和主唱镜头只能从固定 roster 抽取，切回群舞仍是同一批成员。

### 队形确认与 C 位切换
- 换队形只改变位置，不改变人物身份；C 位切换只改变当前视觉中心，不重置 roster、脸或角色。
- 中心位、副中心位、两翼位、后排平衡位换位后仍须可追踪，禁止中心位漂移成另一个人。
- 队形切换落在强拍、hook 入口、句尾或动作停顿。
- 每次大队形切换前用全景／中全景数清成员，切换后保留 `0.5–1.5s` 稳定确认镜头。
- 一次只完成一组清晰迁移，避免一小段连续乱跳多个队形。
- 成员交叉、遮挡、前后排交换时优先保证人物追踪；减少高遮挡、三层以上纵深和连续穿插。
- 关键换位禁止大幅环绕、绕背、穿人运镜、鞭甩、强运动模糊和多人同时完全出画，不依赖出画再入画完成换位。

### 主唱镜头、可选口型与舞蹈可读性
- 只有用户确认对口型且歌词可靠时，才在词头、关键词、短句或 hook 安排当前 C 位／主角对口型。
- 不要求全员同步开口，不让口型覆盖完整群舞动作或破坏换位可读性。
- 主唱镜头遵循“全景定位 → 中景／特写表演点 → 中全景回归队形”。
- 选择不对口型时，只做自然呼吸、眼神、表情和动作卡点，不伪造嘴型。
- 大全景和中全景承载完整动作、队形与换位；特写只短促强调歌词、表情位近景感染力或 C 位爆点。
- 高潮至少保留一个可读的完整动作短句；镜头、动作、剪辑、灯光共用同一音画重拍映射。

### 地面动作、纵深灯光与场景物理
- 出现跪地、蹲撑、手撑地、滑步或起身动作时，写清手脚接触点、重心转移、摩擦与起落顺序，避免悬浮、穿地和肢体失衡。
- 场景必须有足够地面面积、真实尺度和安全动作空间支撑 N 人群舞，不让布景侵占落脚区。
- 灯光须建立前中后景层次、人物轮廓和舞台纵深，不用失控频闪、死黑后排或随机光向掩盖队形。
- 跨区域／跨外景保持透视、光向、地面接触、动作方向和材质尺度连续。

## 分镜关键帧图片预览模式

用户选择预览时，先生成 `3–5` 张关键帧方案：
1. 恰好 N 人、全身可见、无遮挡、无镜面重复的开场团队首帧。
2. 预热／小队／当前 C 位或主唱镜头。
3. 高潮群舞与动作爆点。
4. 关键换位后的 N 人确认帧；关键换位前后必须各有一帧，用来锁定同一批成员只发生位置变化。
5. ending pose。

每张写明时间点、可见 roster、当前 C 位、队形、构图、景别、动作、对口型、场景、地面、灯光、服装和情绪。可见成员只能来自固定 roster，人数不得超过 N；close-up 必须指明成员编号并要求后续回到同一批成员。

确认后的关键帧是硬参考，不是装饰：
- 通过 `ImageList` 绑定团队首帧及其余关键帧。
- 主提示词显式要求以关键帧为视觉锚点，继承 roster、造型、场景、构图和队形逻辑。
- 控制点要求各段映射对应关键帧，不生成新成员、新服装、新场景或新队形逻辑。
- 负向词加入忽略关键帧、人物不一致、服装／发型重置、队形／构图丢失、成员身份漂移。

## 后台主提示词模板

```text
生成一支时长 {duration}s、比例 {ratio} 的高完成度 K-pop 团体舞蹈短 MV，按 2.5 模型单支直接成片，不做多段拼接。全片只能出现 {member_count} 个独立人体实体，每个时点人体总数不得大于 {member_count}；固定 roster 为 {member_roster}。所有队形、C 位、主唱、close-up 和小队镜头只从该 roster 抽取。每位成员以具体的发型／发色、耳饰／手套、外套层次、气质位和站位习惯保持可区分、可追踪；脸、体态、发型、妆造、服装和配饰全片稳定。禁止伴舞、观众、路人、背景人群、镜面／屏幕重复人体或任何第 {member_count+1} 个人形。画面核心是 {group_style} 的团体编舞、清晰队形、C 位切换和成员表现，不发展剧情与关系线。中心位负责高潮主爆点，主舞位负责技术完成度和卡点，风格位负责 {style_role_keyword} 气质，表情位负责近景眼神、面部感染力和镜头记忆点。{keyframe_reference_clause}

按 {audio_beat_map} 执行 {timeline_execution}。动作爆点、A 到 B 队形迁移、C 位交接、当前主唱镜头、剪辑、灯光和 LED 共同对齐明确的重拍、hook 入口、句尾或停顿。编舞围绕 {dance_design} 展开，高潮必须有多人整齐群舞、足够动作幅度、完整可读动作短句、动作爆点和清晰队形变化。队形切换只能是位置迁移，不能重置人物身份；换位前后用全景／中全景确认 N 人并保留稳定确认镜头。C 位按 {center_switch_plan} 切换，位置变化不改变身份。

口型模式为 {lip_sync_mode}：不对口型时只做自然呼吸、眼神和表情卡点；仅 C 位／当前主角对口型时，只在 {lyric_sync_scope} 的可靠歌词镜头执行，禁止全员强制开口。主唱镜头按“全景定位—中景／特写—中全景回归”执行，不能压过群舞。场景采用 {scene_archetype_and_states}，按 {transition_design} 保持同一 roster、动作方向、造型版本、真实透视、光向与地面接触连续；地面、纵深、灯光层次和真实物理必须足以支撑 N 人群舞。地面动作明确接触点、重心、摩擦和起身顺序。镜头以大全景和中全景保证舞蹈可读，只在歌词点、表情位感染力或 C 位爆点短促切近景；关键换位禁止绕背、穿人、鞭甩、强模糊和多人同时出画。结尾按 {ending_design} 收束，成片达到可直接发布的正式 K-pop MV 完成度，而非 rehearsal。
```

## 控制点模板

```text
控制点：
1. 全片只能出现 {member_count} 个独立人体实体，每个时点人体总数不得大于 N；固定 roster、编号和身份锚点贯穿所有段落。
2. close-up、小队、C 位和主唱镜头只能从固定 roster 抽取；禁止第 N+1 人、伴舞、观众、路人及镜面／屏幕重复人像。
3. 发型、发色、耳饰、手套、外套层次、妆容、脸和体态保持稳定；换队形只改变位置，C 位切换只改变视觉中心。
4. 中心、副中心、两翼和后排平衡位换位后仍可追踪，不得换脸、互换身份、中心漂移或重生角色。
5. 偶数人数禁止单中心 V 字；4 人只用横排、2×2、双前双后等无单中心门禁构图。
6. 每次大队形切换前后用全景／中全景确认人数，切后保留 0.5–1.5s 稳定确认。
7. 高潮必须有多人整齐群舞、足够动作幅度、完整动作短句、动作爆点和至少一次清晰队形变化。
8. 成员分工须可见，尤其表情位的近景感染力、眼神和表情管理不能缺失。
9. 动作、C 位交接、主唱镜头、剪辑、灯光／LED 必须共同对齐音频重拍、hook 或句尾，不机械平均切。
10. 主唱镜头按全景定位—中景／特写—中全景回归，不让团舞退化成个人秀。
11. 口型仅执行已确认的“不对口型”或“C 位／当前主角可靠歌词镜头对口型”，禁止默认全员开口。
12. 关键换位优先全景／中全景，禁止绕背、穿人、鞭甩、强模糊、多人同时出画和出画再入画换人。
13. 场景按 A／B／C／其他执行并有至少两种可辨识状态；变化不得破坏地面支撑、纵深灯光、透视与人物连续。
14. C 类跨外景保持 roster、脸、体态、造型、动作方向、自然光逻辑、材质尺度和地面接触。
15. 地面动作必须有可信接触点、重心转移和起落，不悬浮、不穿地、不肢体失衡。
16. 非高潮单人／小队时长不压过群舞主段；镜头不能快过动作完成，画面能量逐段抬升且高潮明显强于前段。
17. 非关键换位的高能点可适量使用推进、低机位抬拍、快速前移或受控环绕，但不得打断完整动作展示。
18. 用户人物图、场景图或关键帧只能在不破坏群舞构图、精确人数和身份一致性的前提下映射。
19. 关键帧模式下严格继承人数、身份、造型、场景、构图、C 位和队形逻辑，各阶段有可识别映射。
20. render 前检查开场、C 位切换、主唱镜头、每次换位／场景切换前后、高潮和 ending pose；失败即重生成。
```

## 三阶段对话展示与场景问卷

### 阶段一：方案确认

严格保持简练，只展示：

```text
一、音频理解摘要
- 时长、乐句／hook、重拍、情绪、高潮
- 群舞、C 位切换、主唱镜头与口型建议

二、推荐生成方案
- 人数、理由与固定 roster 具体身份锚点
- 团体风格、成员分工、编舞与队形
- C 位／主唱镜头、口型模式
- 场景 A／B／C／其他、造型、地面、纵深灯光与镜头

三、时间轴设计
- 各段音频证据、roster、C 位、动作、队形、场景、景别与重拍映射
```

紧接问卷，不在问卷前后展示 PE；默认勾选推荐项：
1. 参考视频：没有／上传视频／提供链接；若提供，记录目标时间段，默认按高精度复刻处理。
2. 人数、固定 roster、团体风格、成员分工与身份锚点：采用推荐／调整。
3. 场景：A 极简白红黑高反射盒子／B 专业打歌舞台／C 多外景 Y2K performance／其他自定义；默认选择本轮音频推荐项。
4. 编舞、地面动作、队形密度、C 位切换、主唱镜头、造型：采用推荐／调整。
5. 对口型：不对口型／仅 C 位或当前主角在可靠歌词镜头对口型。
6. 生成方式：直接生成视频／先生成分镜关键帧图片预览／我要调整。

即使用户预先说“直接生成”或“不改”，首轮结构仍保留问卷，让采用的默认选择可见；随后按默认项执行。

### 阶段二：确认后执行
- 用户确认直接生成时，只回复：`方案确认，开始生成 {duration}s 团舞 MV。`
- 随即把后台完整 PE 提交给视频生成任务，不在聊天正文重复 PE。
- 用户选择关键帧时，先生成 `3–5` 张供确认；确认后将其作为硬参考生成视频。

### 阶段三：成片完成

```text
MV 已生成完成。

成片信息
- 时长与比例
- 结构摘要
- 成员与整体风格
- 场景摘要

如果想调整，可以直接说明人数、编舞强度、场景风格或需要重做的时间段。
```

### 用户明确索要 PE 时
- 将后台实际使用的主提示词、控制点、负向词和关键帧引用集中放进**一个代码框**。
- 禁止拆成“五、六、七、八、九”等多段正文，禁止分成多个代码框，禁止在代码框外重复同一 PE 内容。

## 用户解释口径

- 只给新音频、没有新参考视频时，说明这是“同等级精度的舞蹈类高复刻 prompt”，不是逐镜头复刻。
- 没给人数、成员风格或编舞方向时，先主动给一版可修改的推荐方案，再通过问卷确认；不得把推荐伪装成唯一正确答案。
- 用户在问卷中选择“直接生成”时，立即生成，只回复简短状态句；不要再次展开问卷，也不要把后台 PE 输出到正文。
- 需求很泛，例如只说“根据音频生成 MV 片段”时，默认走稳定优先档：固定 roster、固定人数、无额外人物、少量大队形切换，而非长时高密度群舞。
- 用户选择关键帧预览时，说明关键帧不是附加装饰，而是后续视频 PE 的硬参考；确认后由主提示词、控制点和负向词共同引用。
- 用户说“就按之前那个标准”时，默认保留六个核心锚点：多人群舞主表达、清晰队形变化、强节奏卡点、镜头服务舞蹈、成员表现有分工、全片只有固定一组成员。
- 用户问为何限制镜头或队形时，解释这是为了让动作、换位和身份可读，并防止 N+1、串脸与角色重生成，不是为了削弱舞台冲击力。
- 用户问为何偶数人数不用单中心 V 字时，解释该构图天然暗示“1 个中心 + 对称两翼”，容易与精确偶数人数冲突；改用横排、2×2 或双前双后。
- 用户问为何口型可选时，解释团舞主表达优先；无可靠歌词或全员强制口型会增加嘴型错误并抢走动作、队形和换位可读性。

## 成片验收与质量门禁

输出和 render 前逐项检查：
- 总时长 `≤30 秒`；首轮只有摘要、推荐方案、时间轴和问卷，完整 PE 已后台生成。
- 定位始终是多人／团体偶像舞蹈，而非剧情、Live、单人秀或 rehearsal。
- 人数不是默认锁死 6，而是按音频推荐；确认后的 N 在 roster、提示词、控制点、负向词、关键帧完全一致。
- 固定 roster 与每位成员的具体身份锚点已显式列出；发型／发色、耳饰／手套／外套层次、气质位／站位习惯可追踪。
- 开场精确 N 人且无额外人物；不存在单人开场后增员；偶数人数未使用单中心 V 字。
- 成员分工、表情位近景感染力、编舞方向、动作幅度、地面动作和高潮爆点可见。
- 群舞高潮、A 到 B 队形迁移、C 位切换、换位前后人数确认和 ending pose 已写清。
- 镜头先保证完整动作与队形，再服务成员特写；主唱／C 位镜头回到同一 roster。
- 动作、队形、C 位、镜头、剪辑、灯光／LED 已按音频重拍映射，不机械平均切。
- 场景确实按音频推荐，不固定套 A；问卷含 A／B／C／其他，且至少有两种可辨识视觉状态。
- 地面支撑、纵深灯光、空间尺度和真实物理成立；C 类跨场景保持 roster、造型、动作和物理连续。
- 口型遵循用户选择，未默认全员对口型；无可靠歌词时未伪造嘴型。
- 参考视频已真实取得并分析，硬锚已改写进方案、时间轴、主提示词、控制点和负向词，并按新音频重映射。
- 关键帧模式已先产出可读方案；主提示词、控制点和负向词共同引用已确认关键帧。
- 用户索要 PE 时只出现一个代码框，未拆“五、六、七、八、九”。
- render 前检查开场、每次 C 位／场景／队形切换前后、高潮和 ending pose；出现 N+1、身份重复、换脸、动作断裂、队形散掉、不同步、无爆点、表情僵硬、高潮无队形变化、造型变化、动作幅度不足、rehearsal 感或场景物理跳变时判失败并重生成，不得宣称成功。
