# 对话链路蒸馏：把一段曲折的创作轨迹提纯成更好的 SOP

当用户在**已经跑通一段创作**（多轮生图 / 生视频，中间走了弯路，但最终完成交付）之后，触发"创建技能"时，使用本指南（分支 C）。目标不是复述当时的操作，而是从这条真实但曲折的轨迹里，**逆向工程出一条比原过程更短、更稳的标准作业流程**，并把用户当初 N 轮试错的教训前置成技能的默认参数与质量门。

## 目录

1. 取向与红线
2. C1 · 轨迹重建
3. C2 · 主干 / 弯路分离
4. C3 · 弯路 → 护栏（最关键的一步）
5. C4 · 泛化
6. C5 · 复述确认（替代访谈）
7. C6 · 脚手架 + 编写
8. 会话隔离的坑
9. 完整范例

## 1. 取向与红线

- **蒸馏而非转录。** 信息已全部在对话历史里，只是"脏"。你的动作是提纯，不是搬运，更不是访谈挖掘。
- **弯路是金矿。** 每一次"被否 + 原因"都是新技能最有价值的护栏。不转化就等于丢掉了用户付出的试错代价。
- **给还原、不审问。** 分支 A 靠提问补全缺失信息；分支 C 信息已在，**验证优先于挖掘**——把重建结果给用户校正，只在泛化边界模糊处补一两个定向问题。
- **狠泛化。** 技能要能干"下一个同类任务"，不是复读这一次的具体题材。
- **默认只交付 SKILL.md。** 不创建 `references/`，轨迹中的成功路径、护栏和专业信息全部内联进 SKILL.md；只有用户明确要求 references 时才允许创建。
- **不打包本次产物。** 见第 8 节——会话隔离下新技能读不到本次的图片 / 视频。
- **Skill 调用保留规则（强制）。** 蒸馏对话轨迹时，收集所有 `load_skill` 调用中的 Skill 名称，去重并排除 `skill-creator`。产出技能必须为每个被加载的 Skill 原样写入：`使用 skill 加载工具加载 \`${skill名称}\``。不得省略、改写或展开该 Skill 的内部流程；交付前检查所有名称均已写入。

## 2. C1 · 轨迹重建

扫描本轮之前的对话，把每一次创作动作抽成**结构化动作日志**。只记决策点，不逐字搬运对话（轨迹很长时尤其重要，避免爆上下文）。每条动作记录四要素：

```
动作 N
- 意图：这一步想得到什么
- 输入 / prompt / 参数：实际喂进去的内容（保留关键 prompt 措辞与参数）
- 产出物：生成了什么
- 用户裁决：接受 / 拒绝 —— 若拒绝，记录明确原因（"手部畸形""节奏太慢""风格不对"）
```

**要点：** 拒绝原因是后续 C3 的原材料，务必抓准；用户没明说原因时，从"下一步他改了什么"反推。

> 🔒 **C1 动作日志仅供内部推导,绝不展示给用户。** 日志里记录的内部工具名 / 参数键 / 服务名 / 路径,只用于你自己分离主干与弯路;**一旦进入 C5 复述或任何对用户可见的输出,必须先脱敏**:`load_skill` 保留 Skill 名称;其余所有调用只保留「意图 + 能力 + 结果裁决」三要素,删除内部工具名、参数键、服务名、路径与配置名。这是本类泄漏的直接防线——曾出现过把带内部工具名的原始动作复述给用户的事故。

**遇到 Skill 调用步骤：** 按第 1 节规则登记固定句式，产出物记为“由该 Skill 驱动完成”，裁决照常记录；不要读取或展开其内部内容。

## 3. C2 · 主干 / 弯路分离

给每条动作打标：

- `on-path`：通向最终交付物、被保留的动作。
- `detour`：被否 / 被弃 / 被推倒重来的动作。

然后抽出**制胜路径（winning path）= 能复现最终交付物的最小有序动作子集**。制胜路径就是新技能 SOP 的骨架；detour 全部进入 C3 做护栏提炼。

> 注意：制胜路径是"最小"子集——当时可能因为探索保留了一些冗余步骤，蒸馏时要砍掉。目标是"如果重来一次、且已知所有教训，最短怎么走"。

## 4. C3 · 弯路 → 护栏（最关键的一步）

把每一条 detour 的"被否 + 原因"转化成下列三类资产之一。这一步就是"更好的 SOP"的来源。

| 弯路类型（被否原因） | 转化成的护栏 | 落到技能的哪个支柱 |
|---|---|---|
| 生成质量缺陷（手部畸形、多指、文字乱码、面部崩坏） | **默认 prompt 条款 / 负向约束**——让第一次生成就带上当初试了几轮才补的修正 | 输出契约 / prompt 文法 reference |
| "不满意"但说得出标准（节奏太慢、主体不突出、氛围不对） | **可证伪的质量测试 / 静默自检项**——把"什么算不满意"固化成硬标准 | 可证伪质量测试 / 静默自检 |
| 走错方向后掉头（选错画幅、选错风格、选错时长） | **默认参数 + 路由决策**——某类输入直接走对的分支，不再试错 | 输入诊断 / 路由表 |
| 反复微调才收敛的操作（视频调了 2–5 轮才对） | **参数化的收敛策略**——写清"先定 X 再调 Y"的顺序，减少往返轮次 | 工作流 SOP |

**核心公式：** 每一个"用户当初花 N 轮才发现的教训" → 变成新技能"第一次就默认带上"的一条规则。

## 5. C4 · 泛化

当时那次跑的是一个**具体题材**（某商品、某风格、某市场）。要把它抽象成可复用的技能：

- **固定流程 vs 可变输入**：哪些步骤每次都一样（进 SOP），哪些是每次任务的输入（进输入诊断）。
- **输入诊断**：技能每次运行需要用户提供什么（卖点 / 参考图 / 目标市场 / 时长……），列出生产前要明确或合理假设的维度。
- **输出契约**：固定字段 spec / 带时间戳的分镜 beat 结构。
- **保密红线照旧**：正文以能力方式描述（生成一张图片、把文件展示给用户），不点名内部工具；工具只在 frontmatter 的 `tools` 字段声明。
- **模型字段按需**：默认**不设置** `image_model` / `video_model`。仅当轨迹中用户明确点过某个生成模型（或本轮明确要求指定模型）时，才把它规范成合法取值写进 frontmatter（取值与反问话术见 `model-catalog.md`）；不在支持清单内则反问用户改选，不要就近替换。正文里仍不得出现模型名。

## 6. C5 · 复述确认（替代访谈）

分支 C **不跑分支 A 那种引导式访谈**。取而代之：把重建结果作为草稿给用户确认——**不是提问，是给一份还原让用户改**。因为 agent 对"哪几个弯路才是关键教训"的判断可能有偏差，必须让用户校正。

> 🔒 **复述确认稿是脱敏后的技能规格,不是 C1 原始动作日志的转录。** 稿中出现的每一步都以能力表述(生成一段视频 / 拼接片段 / 把文件展示给用户),严禁把 C1 里记录的内部工具名、参数键、服务名、路径带进确认稿。

复述确认模板：

```
我把刚才的创作过程还原并提纯成了下面这条 SOP——请确认或更正：

【制胜路径（提纯后的最短流程）】
1) …
2) …
3) …

【从弯路提炼的护栏（新技能第一次就默认带上）】
- 因「<当时被否原因>」→ 默认加入「<prompt 条款 / 质量门 / 默认参数>」
- 因「…」→ …

【每次任务的可变输入】
- <输入 1>、<输入 2>……

【泛化范围】
- 这次是 <具体题材>，技能我打算做成 <通用 / 某垂类专用>——对吗？
```

只在**泛化边界模糊**处补定向问题（例如"这次是美妆品类，技能要做成美妆专用还是通用商品？"），不要退回到全维度访谈。用户确认后进入 C6。

## 7. C6 · 脚手架 + 编写（与分支 A 汇合）

1. 跑 `init_skill.py <skill-name> --distill`，默认只生成 SKILL.md。
2. 把制胜路径、弯路护栏、输入诊断、输出契约和自检全部内联进 SKILL.md。
3. 只有用户明确要求 references 时，才在初始化命令追加 `--with-references`。
4. 运行 `quick_validate.py <skill-name> --distill`；若用户明确要求 references，同样追加 `--with-references`，然后打包交付。

> 相较普通创意技能，分支 C 产物的增量价值在于那批"常见坑 / 质量门"——写进技能时让它们显性成为默认约束，而非埋在散文里。

## 8. 会话隔离的坑

沙箱**会话隔离**：新技能在用户侧运行时读不到本次对话里那些满意的图片 / 视频。因此：

- **绝不**把本次的最终产物当素材打包进技能（打了也读不到）。
- **正确做法**：把"这些产物为什么好"蒸馏成 **prompt 条款 + 质量描述**内联进 SKILL.md。例如不要塞那张满意的图，而要写清"这张图之所以过关，是因为构图 / 光线 / 主体占比达到了 X"，让技能下次能复现这个标准。

## 9. 完整范例

**对话轨迹（重建后）：**

```
动作 1 意图：生成商品主图  产出：图 A  裁决：拒绝（模特手部畸形）
动作 2 意图：重生主图（prompt 补"自然手部、五指清晰"）  产出：图 B  裁决：接受
动作 3 意图：由图 B 生成 15s 商品视频  产出：视频 v1  裁决：拒绝（开场 3s 太平、没有 hook）
动作 4 意图：调整（前 3s 加特写推镜 + 卖点字幕）  产出：视频 v2  裁决：拒绝（节奏仍偏慢）
动作 5 意图：再调（整体加快、卡点到 BGM 重拍）  产出：视频 v3  裁决：接受
```

**C2 制胜路径：** 生主图（带手部约束）→ 由主图生 15s 视频（开场 3s hook + 卡点节奏）。

**C3 弯路 → 护栏：**
- 图 A 手部畸形 → prompt 模板默认写入"自然手部、五指清晰"负向约束。
- 视频 v1 开场太平 → 输出契约固定"0–3s 必须是抓眼球 hook（特写推镜 + 卖点字幕）"。
- v1/v2 节奏慢 → 工作流写明"生成前先定 BGM 节拍，画面卡点对齐重拍"，静默自检加一条"节奏是否卡点"。

**C4 泛化：** 固定流程 = 主图→视频；可变输入 = 商品图 + 卖点 + 目标市场；技能定位 = 商品营销短视频（通用）。

**C5 复述确认：** 按第 6 节模板给用户，确认"做成通用商品营销视频技能"后进入脚手架。
