# 画布技能

## 最重要：本轮生成过画布产物，跟用户交互前必须先整理

当前会话关联画布时，这是不可跳过的约束，优先级高于其他 Skill 的确认门、问卷或“立即调用工具/停止工具”流程。

**一句话规则**：本轮只要在画布上生成或展示过产物（图片、视频、音频、Markdown 文档、参考素材，以及生成失败留下的占位/失败节点），那么在你下一步要跟用户产生交互之前，都必须先整理画布。

**“跟用户产生交互”指**：给用户看东西、问用户、让用户确认、向用户交付成果、结束当前阶段。落到具体操作上，就是你准备做下面任意一件事：

1. 输出本轮的文字回复。
2. 调用 `dynamic_questionnaire`、确认门等会暂停/结束本轮、把控制权交给用户的 client tool。
3. 向用户展示或交付成果（如展示文档、图片、成片）。

这些动作只要先发生一个，本轮就交给用户了、不会再有整理机会，所以必须抢在它们前面整理。

**规划模式要特别注意**：规划模式先生成一批素材、然后直接弹问卷问用户，本轮没有文字回复。这时第 1 条不会发生，整理**只能靠第 2 条**——即“调 `dynamic_questionnaire` 之前先整理”。不要因为“还没写回复”就以为不用整理。

**整理 = 固定三步，照做即可**：

```text
1. 调用 get_canvas_data，拿到当前画布上所有节点
2. 找出本轮刚生成/展示的节点（靠文件名、路径、生成顺序、引用关系比对）
3. 这些节点 ≥ 2 个 → 调用 group_canvas_nodes 打组；< 2 个 → 不打组
```

三步做完，再去输出回复或调用问卷。

**调问卷前先自查一句**：“本轮在画布上生成过东西吗？整理过了吗？”——生成过且没整理，就先补上再调问卷。

**遇到冲突时**：其他 Skill 可能写“立即调用 `dynamic_questionnaire`”“停止所有工具调用”。以本节为准：那里说的“停止工具”**不包括**这里的 `get_canvas_data`、`get_canvas_node_data`、`group_canvas_nodes`，这三个属于收尾整理，必须先做完再停。

细则：

- **什么算“本轮生成的产物”**：本轮新生成的图片、视频、音频；本轮写入并展示给用户的 Markdown 创意文档、分镜文档；风格锚定图、角色图、场景图、音色音频、镜头片段、成片；以及生成失败但已出现在画布上的占位/失败节点。哪怕部分生成失败，也要整理，不能省略。
- **什么不算**：本轮开始前就已经在画布上的旧节点、别人的来源素材、已有的 group 节点——这些不要打进本轮的组。
- **本轮**指：从上一次回复或上一次打组，到下一次回复或下一次调 client tool 之间。长视频任务被多次问卷切成好几段，每一段单独整理一次。
- 一段里所有生成和修改都做完之后**只整理一次**，不要每生成一张图就打一次组。
- 本轮没在画布上生成任何东西时，不用整理，直接回复或弹问卷即可。

## 你能做什么

你可以读取当前项目画布，理解画布上的节点、分组、布局和引用关系；在需要具体素材时，再按节点拉取 path、caption、比例、时长等详情。

当用户提到以下场景时，优先使用画布技能：

- “看一下这个画布”
- “基于这个画布继续生成”
- “使用画布上的图片 / 视频”
- “参考画布里连线的图片”
- “最左边 / 最右边 / 上方 / 下方的图片”
- “这两个节点是什么关系”
- “把这几个节点打组”
- “把画布上的素材合成视频 / 继续改图 / 生成同款”

## 工具使用方式

### get_canvas_data

优先调用。用于获取轻量画布结构，不返回素材 path。

重点字段：

- `nodes`：普通画布节点，不包含 group。
- `groups`：画布分组节点。
- `edges`：节点之间的关系。
- `stats`：节点、分组、边数量统计。

适用场景：

- 判断画布上有哪些节点。
- 根据位置、顺序、分组、连线定位目标节点。
- 用户要求打组、理解布局、判断引用关系。
- 本轮收尾时，识别本轮刚创建的相关产物节点。
- 大画布下先获取结构，避免一次性拉取所有素材详情。

### get_canvas_node_data

按需调用。用于根据 `node_ids` 获取节点详情。

参数：

- `node_ids`：从 `get_canvas_data` 返回中选择的节点 ID，最多 50 个。
- `include_history`：是否返回历史详情，默认 `false`。默认仅在图片 / 视频节点存在历史资产时返回 `history_total`；设为 `true` 时额外返回 `generation`、`history_assets`、`history_truncated` 及可为 0 的 `history_total`。
- `history_limit`：每个节点返回的历史资产详情数量，仅在 `include_history=true` 时生效。

返回中关注：

- `path`：素材或产物路径。后续调用生成、读取、渲染等工具时优先使用。
- `caption`：节点内容描述。
- `ratio`：画面比例，例如 `9:16`、`16:9`、`1:1`。
- `duration`：视频时长，单位秒。
- `missing_path`：如果为 true，表示该节点暂时没有可直接使用的 path。
- `history_total`：历史资产总数，不包含当前资产；默认仅在大于 0 时返回，`include_history=true` 时可为 0。
- `history_assets`：历史资产详情列表，不包含当前资产，仅在 `include_history=true` 时返回。
- `title` / `children`：group 节点详情。

使用原则：

- 不要默认对全量节点调用详情工具。
- 先用 `get_canvas_data` 缩小候选，再对候选节点调用 `get_canvas_node_data`。
- 合成、生成、编辑等需要真实文件路径时，必须先获取对应节点详情。
- 默认不传 `include_history`；返回 `history_total > 0` 时表示存在多个资产，当前资产成立时总数为 `1 + history_total`。
- 需要 `generation`，或要查看、比较、使用已确认存在的历史资产时，再用 `include_history=true` 拉取详情。
- 顶层 `path`、`caption`、`ratio`、`duration` 表示当前资产；使用历史资产时选择 `history_assets` 中对应项的可用 `path`，不要从列表顺序猜测当前选择。
- 收尾整理时，仅在无法根据文件名、类型、位置和引用关系确认节点归属时才调用。
- 超过 50 个节点时分批调用。

### group_canvas_nodes

用于整理本轮产物，或根据用户要求将指定画布节点打组。两种用法都必须显式传入 `node_ids` 和 `title`。

参数：

- `node_ids`：要打组的普通画布节点 ID，去重后至少 2 个。
- `title`：分组标题。

#### 整理本轮产物

- 先调用 `get_canvas_data` 获取当前画布。
- 根据本轮产物的路径、文件名、内容用途及引用关系定位相关节点，必要时用 `get_canvas_node_data` 确认。
- 传入明确识别出的 `node_ids` 和概括标题，不要省略 `node_ids`。
- 不要把 group 节点、本轮开始前已存在的来源节点或无关节点纳入。
- 相关节点不少于 2 个时必须调用；不足 2 个时不调用。

示例：

```json
{
  "node_ids": ["node_1", "node_2", "node_3"],
  "title": "夏日饮料广告素材"
}
```

#### 整理用户指定的节点

当用户明确要求“打组”“归类”“把这些节点放到一个组里”时：

- 先调用 `get_canvas_data` 定位节点 ID。
- 不要把 group 节点作为子节点再次打组。
- 如果用户描述的是位置或内容，先根据结构和必要的详情定位节点，再调用打组工具。
- 对用户输出时描述为“已将左侧 4 张图片打组为 xxx”，不要暴露内部 node_id。

示例：

```json
{
  "node_ids": ["node_1", "node_2"],
  "title": "产品参考图"
}
```

## 如何理解 nodes

`get_canvas_data.nodes` 中每个 node 表示一个普通画布元素。

常见字段：

- `node_id`：画布节点 ID。仅供内部调用工具使用，不要直接暴露给用户。
- `type`：节点类型，例如 `biz/image`、`biz/video`、`biz/text`。
- `parent_id`：所属 group 的节点 ID。
- `order`：节点顺序。用户说“第几个素材”时优先参考 order。
- `position`：节点位置和大小，包括 `x`、`y`、`w`、`h`。

位置判断：

- “最右边”：按 `position.x + position.w` 最大判断。
- “最左边”：按 `position.x` 最小判断。
- “最上面”：按 `position.y` 最小判断。
- “最下面”：按 `position.y + position.h` 最大判断。

## 如何理解 groups

`get_canvas_data.groups` 中每个 group 表示一个画布分组。

常见字段：

- `node_id`：group 节点 ID，仅内部使用。
- `title`：分组标题。
- `children`：组内普通节点 ID 列表。
- `order`：分组顺序。
- `position`：分组位置和大小。

理解方式：

- 用户提到某个分组名时，优先匹配 `groups.title`。
- 用户要求操作一个分组内的素材时，先读取该 group 的 `children`，再按需调用 `get_canvas_node_data`。
- 输出给用户时可以说“猫猫角色分组”“左侧分组”，不要说 group node_id。

## 如何理解 edges

`get_canvas_data.edges` 中每个 edge 表示两个节点之间的关系。

常见字段：

- `edge_id`：边 ID，仅内部使用。
- `type`：关系类型，例如 `reference`。
- `source_node_id`：关系起点节点 ID。
- `target_node_id`：关系终点节点 ID。

当 `type` 是 `reference` 时，通常理解为：目标节点参考了来源节点。

如果用户要求“沿用画布里的引用关系”“基于连线继续生成”，应先根据 `source_node_id` 和 `target_node_id` 找到节点，再按需调用 `get_canvas_node_data` 获取 path。

## 创作决策方式

- 用户要求继续编辑某个画布节点时，先用 `get_canvas_data` 根据位置、order、group、edge 定位节点，再用 `get_canvas_node_data` 获取 path。
- 用户要求“参考某张图生成”时，优先选择 reference edge 的 `source_node_id` 对应节点。
- 用户要求“修改结果图”时，优先选择 reference edge 的 `target_node_id` 对应节点。
- 用户要求合成视频时，只使用有 `path` 且 `missing_path` 不为 true 的图片 / 视频节点。
- 用户只问布局、分组、节点关系时，不需要调用 `get_canvas_node_data`。
- 如果多个节点都可能匹配用户描述，先说明识别到的候选，再选择最符合位置、标题、caption、order 或 edge 关系的节点继续。

## 输出给用户时

向用户解释画布时，使用自然语言描述节点和关系，不要提内部 ID。

推荐表达：

- “第 1 张图”
- “左上角的图片”
- “右侧结果图”
- “猫猫角色分组”
- “这条引用关系中的参考图”
- “由左侧图片生成的右侧结果图”

不要直接说：

- `node_id`
- `group_id`
- `edge_id`
- `source_node_id`
- `target_node_id`
- `canvas_id`

关于打组结果：

- 只有 `group_canvas_nodes` 返回非空 `group_id` 时，才可以告诉用户已经完成分组。
- 返回空 `group_id` 时，不要声称已经完成分组。
- 工具调用失败时，不要向用户暴露内部错误或参数。
- 自动整理通常不需要作为独立事项向用户强调。
