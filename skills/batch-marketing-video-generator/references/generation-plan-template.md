# generation-plan-XX.md Template

Use this structure for each mandatory `generation-plan-XX.md`. The user-visible name is "脚本". Each file is a complete, self-contained executable virtual-machine prompt for one finished video. For visual mode, create it after the optional same-suffix complete storyboard image has been generated and inspected and bind that actual image. For script-only mode, create it after all required references are resolved, omit every storyboard-image dependency, and make every shot visually self-sufficient. The current environment must execute the confirmed actual package directly when compatible and may lower it only when a hard capability constraint requires adaptation.

Create this file only when its video is selected for the user-confirmed preparation round, every applicable SKU's product-consistency gate is complete, its visual-storyboard mode has been explicitly decided, and every narrator/character speaking identity plus its accepted neutral voice anchor has been resolved when the video contains narration, dialogue, or monologue. Do not prepare scripts for remaining videos in advance.

Rules:

- This file is the user-confirmed complete executable virtual-machine script. Do not include planning commentary, status/logs, user authorization notes, target-runtime parts, model limits, or alternative ideas.
- Use the accepted information, confirmed storyboard, and this video's conversation-confirmed exploration direction as authoring inputs.
- Translate all source content needed for generation into explicit instructions inside this file. The finished file must not name, link to, or tell the model to read any other `.md` file.
- Do not rely on a filename written inside prompt text. Direct execution must pass the actual applicable references and, only for a confirmed visual package, the actual paired complete sheet; lowered execution must pass only the actual target-specific media applicable to each call.
- For every direct or lowered video call, treat its actual `ImageList` as the exclusive set of model-visible reference images. The video model cannot use visual information from an image merely because the agent inspected it, the script names it, a prior call received it, or its appearance was paraphrased from an omitted file. Attach every image whose visual identity, geometry, styling, composition, or continuity the call must follow; when a hard limit forces omission, do not claim that omitted image is still being followed.
- The six blocks above illustrate the format; use every shot in the complete duration-driven finished video. Add or remove blocks accordingly. Neither the image route nor the video model's per-call limit may rewrite the confirmed story count.
- Give each timed shot an explicit purpose, shot size, subject/character action, camera behavior, transition or closing method, product placement, voiceover, and sound-effect or music cue.
- Narration, character dialogue, and character monologue are spoken audio only. Do not generate subtitles, captions, dialogue bubbles, title cards, or added screen text unless the user explicitly overrides this batch requirement. - A distinct recurring speaking identity uses a distinct neutral TTS anchor by default. The anchors are not prerecorded narration/dialogue/monologue. Their words must be unrelated, but each recorded performance must fit that role and the accepted campaign baseline. The complete script must map ordered `音频[N]` entries to exact role names, say every attached audio is timbre-only, forbid all sample words/timing, and make the written speaker assignments, lines, and delivery directions authoritative.

## Video Tool Invocation Contract

The video model cannot read sandbox files. `PromptPath` works because `sandbox_generate_video` reads that one file in its engineering layer and forwards the file contents as the actual model prompt. It is not a model-facing file reference.

Use one of these two transport modes:

1. Preferred `PromptPath` mode: set required `Prompt` to `""`; set `PromptPath` to the absolute path of the complete `generation-plan-XX.md` or lowered `generation-input-part-YY.md`. The file must exist, be non-empty, and already contain the complete self-contained prompt.
2. Direct-text fallback: omit `PromptPath`; read the complete file in the engineering layer and put its full text in `Prompt`.

Never set `Prompt` to `完整指令见 PromptPath 文件`, `完整指令见 generation-plan-XX.md`, `参见脚本文件`, a filename/path, a summary, or any equivalent placeholder. When `PromptPath` is present, do not duplicate or summarize the prompt in `Prompt`; keep `Prompt` empty. Omit `UseRunPrompt` in both modes.

Every `sandbox_generate_video` call also provides integer `Duration`, `OutputPath`, and `Ratio`. Attach all applicable reference images through `ImageList`; attach the actual complete or same-part storyboard image only when it exists and belongs to the confirmed mode or target adaptation. A path mentioned inside the prompt file does not attach that image, and only images in this call's `ImageList` contribute reference-image information. For any call containing speech, attach the accepted neutral anchors for every role speaking in that call through deterministic ordered `AudioList`, and map each one-based `音频[N]` to the exact role in the prompt. Every sample is only for its mapped role's timbre, never for words or duration; actual speaker assignments, narration/dialogue/monologue lines, and related delivery come from the current script. Do not use `sandbox_generate_audio` to create actual video lines, BGM, sound effects, or environment sound.

## Internal Runtime Lowering Template

This section applies only after the actual package is confirmed, its video is selected by the separate video-generation-round quantity gate, and a direct-execution check finds a concrete incompatibility. It does not create another user-visible deliverable. Create `_internal/runtime/video-XX/generation-input-part-YY.md` only for target-specific calls required by that incompatibility. Create a same-suffix `_internal/runtime/video-XX/storyboard-input-part-YY.png` only when an opted-in source sheet is being adapted or the selected target has a disclosed hard image-input requirement.

First test direct use of the actual package against all current execution constraints, checking storyboard-image support only when the package has one. When the environment supports the full duration, ratio, actual references, optional complete storyboard image, script size, and generation mode, skip this section entirely and execute the package directly. If adaptation is required but one video call can still produce the whole video, create one internal target unit. Create multiple parts only when a disclosed hard per-call constraint requires them, and use the minimum viable count. Never split merely because the story has many shots, Seedream used multiple raw contact sheets, the user skipped a grid, or a narrative boundary is available.
