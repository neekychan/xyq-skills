## 〇、拟人化层级判定（先于一切创作决策）

从用户意图反推层级，**全程锁定一级，禁止混搭**。

| 用户信号 | 层级 | 形态边界 | 默认画风 |
|---------|------|---------|---------|
| 记录日常/治愈/ASMR/真实质感 | **L1 真实动物** | 四足，只做动物行为，无人类动作 | **真实/写实** |
| 让宠物说话/祝福/摆姿势/卡点 | **L2 真实形体+拟人神态** | 形体仍是动物，允许表情、口型、前爪简单动作 | **真实/写实** |
| 摆摊/做饭/打工/穿衣/用工具 | **L3 直立拟人** | 两足直立、穿衣、爪持道具操作 | **真实/写实** |
| Q版/卡通形象/吉祥物/品牌 IP | **L4 卡通 IP** | 3D 卡通/插画体，圆润造型 | 3D 卡通/插画 |

**层级由用户意图决定，不由 Agent 自行添加的服装/道具升级**。用户说"猫看书"→ L1/L2（四足趴在桌前），不要因为 Agent 自己给猫穿了衣服就升到 L3。

**画风默认真实（重要）**：萌宠视频大部分要的就是"真的猫真的狗"，**默认写实/真实画风，不要自作主张加"3D卡通动画风格"**。只有两种情况用卡通：① **用户明确要求**卡通/动画/Q版；② L4 卡通 IP。L1/L2/L3（含 Vlog/口播/日常/直立拟人）一律真实画风——写实直立拟人模型已能稳定生成，不需要用卡通规避，也不要为了避免直立而把 L3 需求降级成 L2。

## 一、视频类型路由

| 类型 | 触发信号 | 对应 Ref |
|------|---------|---------|
| **A Vlog** | 日常/记录/一天/旅游/上班/打工/通勤 | `references/pet-vlog.md` |
| **B 短剧** | 短剧/剧情/故事/冒险/对话/冲突/连载 | `references/pet-drama.md` |
| **C 口播** | 说话/祝福/拜年/口播/念台词 | `references/pet-talk.md` |
| **D 段子** | 搞笑/段子/卖惨/反转/整蛊 | `references/pet-comedy.md` |

判定模糊时默认 A（Vlog）。

## 二、关键确认（层级和类型判定后、开始创作前）

用 `dynamic_questionnaire` 确认以下信息（已从用户输入中明确的项跳过不问）：

**0. 目标情绪（最上位，先于风格/分镜锁定，决定全链路）**：
- **能从用户需求原文映射出情绪的 → 直接锁定，问卷里不再出现情绪这道题**（映射命中就是"已明确"，等同已上传照片会跳过角色题）：上班/搬砖/加班→心疼，温情/温馨/陪伴/等主人→治愈，搞笑/整蛊/恶搞→好笑，旅游/日常/vlog→放松，塞腮帮/囤货/呆→呆萌。命中任一关键词就锁定，别为"再确认一下"多问。映射到的情绪写进后续的情绪锚点（§四步骤4）。
- **只有原文完全没有情绪倾向时才问这道题**：选项给**贴合本题材的 2-3 个合理情绪**（如宠物旅游给"放松治愈/搞笑逗趣/呆萌可爱"），把最贴切的放第一项。**禁止机械把全部 5 种情绪都列上**——给旅游 vlog 塞"心疼打工"这种与题材无关的选项，既突兀又会误导。判据：某个情绪选项放进这个题材成立吗？不成立就删掉。
- ⚠️ 情绪一旦在此锁定，`pet-rules.md` 情绪杠杆表和 §四步骤4 的杠杆都必须服从它；**不要在"风格"这类问题里用"搞笑风/治愈风"变相重选情绪**，那会绕过本项把情绪带偏。

**1. 角色形象来源与人设**：
- 用户已上传动物照片 → 角色来源题跳过，直接用作参考；**但在同一问卷里加一道选填文本题问人设**：「你家宠物有什么性格特点、小习惯或喜好？（选填，如：爱睡懒觉 / 怕水 / 听到零食袋响就飞奔 / 睡觉必须肚皮朝天）」——主人提供的真实习惯是最强的个性化素材（"我家猫也这样"的细节最有共鸣），按 `pet-rules.md` 个体人设规则落进分镜
- 未上传 → 必须确认：
  - 选项 A：**上传你的宠物照片**（推荐，角色一致性最好；同时附上面的人设选填题）
  - 选项 B：**帮我生成一个角色形象**（描述你想要的动物品种和外观）——选 B 或用户未填人设时，由你在设计角色时**一并设计 2-3 个个体特点/习惯**（同样按 `pet-rules.md` 个体人设规则）
- 选了 A 但推进到生成素材步骤时仍未见到上传文件 → 不要停下反复等待或事后反复建议"重新上传替换"：直接改用 `sandbox_generate_image` 生成角色形象继续推进，向用户说明一次"未检测到上传，已先用生成形象继续"即可，交付后不再提起

**2. 发声方式**（B 短剧、C 口播必确认；**A Vlog 为叙事向多段（≥30s）时也必须确认**——长片纯画面+叫声的信息密度撑不住叙事，容易空）：
- 用户已明确 → 跳过，锁定为说人话。**已明确判定**：凡出现"说/念/祝福/告诉/宣布"等说话动词 + 具体内容的表述都算已明确，如"让猫说话""念台词""猫说生日快乐""鹦鹉拜年""狗吐槽主人"——不要再问一遍发声方式
- 未明确 → 确认（选项必须带后果说明，让用户基于后果选）：
  - 选项 A：**说人话**（口型同步，配合人声配音，剧情表达力最强）
  - 选项 B：**内心 OS 独白**（仅 A Vlog 提供此项：画面里主角不开口，画外音吐槽心声——最像真人 vlog 的语言层，一句心声顶十个表情）
  - 选项 C：**只发动物叫声**（喵喵/汪汪等原声，剧情表达能力较弱，**纯叫声无法自动生成字幕，需你在发布前自行添加字幕补全剧情理解**）

确认结果影响后续全链路：
- 发声方式=说人话 → Prompt 中写 `{台词}`，需 L2 以上层级
- 发声方式=内心 OS → Prompt 中对应镜头写「画外音内心独白：{台词}」——**台词必须用 `{}` 包裹**（`{}` 是触发语音生成的台词符号，丢了独白不会发声，只会被当画面描述），并注明主角嘴部不做说话口型；独白要短、口语化、带吐槽感，不逐镜配、挑情绪节点配
- 发声方式=叫声 → Prompt 中剧情需要发声的地方写对应动物叫声（如 `<喵喵叫声>`）。**字幕无法自动生成**（`render_video` 的 `show_subtitle` 基于 ASR，只能识别人声，无法将叫声转为剧情台词），需用户自行后期添加。选此项时必须向用户说明：纯叫声的剧情表达能力有限，观众需要靠字幕理解剧情，请在发布前自行添加字幕

**其他维度**（风格/比例/时长）如有缺失，合并到同一次问卷中一起补齐，不要多次提问。
- **比例默认 9:16**：萌宠视频主要面向抖音/小红书竖屏消费场景，用户未指定比例时直接用 9:16，不要因为"风光/大场景更适合横屏"等审美判断擅自改成 16:9；用户明确要求横屏或宽画幅时才用 16:9
- **Vlog 时长要给足**：Vlog 是叙事密集型（收拾行李→路上→打卡→美食→晚安，见 `pet-vlog.md`），单段 15s 装不下一个像样的 vlog。用户没指定时长时，**vlog 默认按完整叙事给足（40-60s 多段），不要默认成 15s 单段**；若想让用户参与，可在问卷里给时长选项（如"短版≈15s 只拍精华 / 完整版 40-60s 含完整一天"），但**默认倾向完整版**。其他类型（口播/段子）无此要求，按 §三时长预算走。

## 三、进入点判定与分流

**scope 自检**：能否在一次 `sandbox_generate_video` 调用内完成？

| 判定 | 路径 |
|------|------|
| 时长 ≤{{.max_video_duration}}s **或** 同一场景（同地点+同时间+同角色组） | **单段流程**（§四） |
| 时长 >{{.max_video_duration}}s **且** 有真正的场景切换 | **多段流程**（§五） |

> **同一场景禁止拆段（零例外）**：同一地点、同一时间、同一组角色的戏份，无论几个镜头，都合并为一次 `sandbox_generate_video`，用画面阶段（镜头1/镜头2）分隔。拆段会增加角色漂移风险、并可能导致 render_video 漏调、成片不交付。只有"场景切换（地点/时间/角色组变化）"或"时长超上限压不下去"才拆。

**时长预算**：
- 用户指定 → 用用户的
- 未指定 → 默认 {{.max_video_duration}}秒单段，仅台词耗时超限或独立画面段落 ≥3 个时才建议更长

**核心铁律**：
- 用户指定的时长是第一公民；**未指定时 Duration 必须 = {{.max_video_duration}}s，禁止因"台词短/画面简单"自行缩到 10s/15s**——时长用满画面更从容、节奏更丰富，用满上限是默认行为
- 调用次数最少化：能一次完成的绝不拆两次
- ≤{{.max_video_duration}}秒禁止拆段（零例外）；同一场景禁止拆段（见 §三）
- Prompt 做减法：优先核心画面，其次运镜，最后环境
- 安审失败立即停止，禁止重试

## 四、单段流程

一次 `sandbox_generate_video` 调用，**无需 creative_design.md**。

1. **搜索灵感**：用 `pippit_omni_search` 搜索参考内容，根据需要选择搜索类型：
   - `inspiration`：平台内优质创意案例（**首选**，创意质量高，适合找 Prompt 写法和灵感）
   - `hotspot`：第三方热点源（适合蹭热点话题、追趋势）
   - `text`：泛联网搜索（内容较泛，用于补充特定知识点——典型场景：旅行 vlog 查目的地真实景点/美食，见下方"地名触发"）

   **关键词策略按类型区分**（`inspiration`/`hotspot` 是标签匹配，`text` 是真实搜索引擎）：
   - `inspiration`/`hotspot`：严格用 **"萌宠/宠物"+主题词** 两段式（如"萌宠打工""萌宠职场""萌宠治愈"），**不要用具体动物品种做核心词**（如"柴犬""橘猫"），**也不要再叠加第三个词**（如体裁词/场景词）——两段式命中率最高，三段式会显著降低命中率。反例：✗"萌宠生日祝福口播"（三段式，多叠加了体裁词）→ ✓"萌宠生日"或"萌宠祝福"。只有用户需求本身就是"品种梗"（如"柴犬表情包"）时才把品种放进去
   - `text`：完整语义查询，可以长（如"柴犬拟人打工上班创意视频""萌宠短视频创意 打工人 搞笑"），越具体命中的案例越贴合
   - **地名触发（旅行/出行类强制）**：用户需求中出现具体地名/目的地（如"山西""西藏""青岛"）时，**必须额外用 `text` 搜一次「{地名} 旅游特色 景点 美食」**，从结果中拿到当地**真实存在的标志性景点和特色食物**，供后续分镜取材（景点快切选哪几个地标、小吃同框吃什么、夕阳晚饭吃什么当地菜）——题眼专属细节是旅行 vlog 记忆点的主要来源，**禁止凭模型记忆编造景点/美食**，搜到什么用什么
   - **无结果必须换一版关键词重试一次**（inspiration/hotspot 换主题词表达方式，text 换查询角度）——这是强制步骤，不是可跳过的建议，重试仍无结果才可放弃。

   **关键词格式（强制）**：`query = 萌宠/宠物 + 情绪词`，情绪词**必须用 §二步骤0 已锁定的那个情绪**（心疼→心酸、治愈→治愈、好笑→搞笑…），不在此另选、不退回纯题材词，**否则重搜**——例如已锁定心疼就搜"萌宠 心酸/打工人共情"，禁止搜"萌宠打工"（丢了情绪）或"萌宠 搞笑"（换了情绪）。纯题材词或错情绪词会高效采集到错误方向的弹药（喜剧素材撑不起心疼片）。

   **提炼产物（强制，搜完立即产出，否则不许进入下一步）**：搜索返回后，先逐条判断相关性（主题/场景/动物/情绪是否匹配用户需求），丢掉不相关的；再从剩余结果中**提炼至少 2 条具体可复用的手法**，按此格式写进你的推理（多段流程写入 `creative_design.md` 的「灵感来源」）：
   > - 手法1：来源=结果N，提炼=（具体构图/台词梗/节奏/行为设计，如"偷吃后装作无事发生的身体诚实型反差"），用在=（本片哪个镜头/哪句台词）
   > - 手法2：来源=结果N，提炼=……，用在=……

   **禁止虚构引用**：`来源=结果N` 不仅编号要真实存在，还必须**逐字摘录该结果里支撑这条手法的原文片段**（如 `来源=结果3「三亚沙滩狗狗踩浪」`）——摘不出对应原文，就说明这条手法是你自创的，如实改标"原创"，不许把自创点子伪装成搜索来源。若整次搜索无可用产出，写"无可提炼产出，以下手法为原创"。

   **选梗标准**：优先选**画面最具体、最反直觉**的梗（"腮帮子卡进栏杆缝""体重秤从50g跳到80g"这类一看就有画面的），而不是最平的那条；**禁止把画面梗抽象成概念词**（把"卡进栏杆缝"提炼成"行动受限"就丢掉了梗本身）。禁止写"参考了叙事框架"这类结构性借鉴——必须是能落到某个镜头/台词的具体手法。若所有结果都无可提炼手法，才允许换词重试后放弃。**这一步是搜索的兑现动作：不产出提炼条目，等于没搜。**
2. **加载 ref**：`sandbox_read` 并行读取 `references/pet-rules.md` + `references/pet-prompt.md` + 对应类型 ref
3. 用户上传了动物照片 → 放入 ImageList；§二确认选择生成 → 先 `sandbox_generate_image` 生成参考图再放入
4. 结合搜索到的灵感 + 类型 ref 示例 + §二确认的发声方式构造 Prompt。**构造前先写死三行锚点**（否则重写创意），情绪锚点最前——它决定后面所有选择：
   > **情绪锚点**：目标情绪=（**直接用 §二步骤0 已锁定的情绪，不在此重选**）；杠杆=（按该情绪从 `pet-rules.md` 情绪杠杆表取**对应那一行**，不许跨行选，如目标心疼就取"逞强+付出无回报"、禁止取喜剧向杠杆）；引爆点=第N镜的[具体画面或台词]。
   > **事件锚点**：本片事件=3-5 条「作用力→反应」（作用力=不受主角控制的人/物/规则/时间，须在画面或声音层可感知，可由动物配角出演；判据：具体可拍、与目标情绪同向），每段/每镜标注消耗哪条。**没有事件锚点不许写分镜；只能写成「主角很X」的纯状态镜头全片 ≤2**（判别式见 `pet-rules.md` 强制规则10）——情绪不是演出来的，是事件挤出来的。
   > **差异化锚点**：差异化方向=（从类型 ref 的反转/反差方向选一个），落在=（哪个镜头/哪句台词）；人设梗=（品种性格 + **个体习惯/喜好**（用户问卷提供的优先，按 `pet-rules.md` 个体人设锚定，含"出现两次"回环）如何体现在**行为节奏**上，且服从上面的目标情绪——目标是心疼就别用佛系）。
   >
   > **双问自检**（任一"仍成立"就是没做到差异化，重写）：① 换个品种，记忆点还成立吗？② 换个题眼（如"第一次坐飞机"→"第一次坐高铁"）分镜不用改也成立吗？禁止拿"时间线/空间线"当差异化方向。
   三行锚点定稿后，先按 `pet-prompt.md`「分镜预算表」填表（先分秒数再填动作），再写镜头描述；构造完 Prompt 后按 `pet-prompt.md` 末尾的**生成前自检清单**逐项核对（分镜预算表/情绪引爆/收尾钩子/运镜/BGM/音效/台词/防崩尾注/Duration）。
5. `sandbox_generate_video` 成功返回后，**下一个动作必须是** `present_sandbox_file`（`interrupt=true`）——这是交付的唯一标志，不调等于任务未完成，禁止在此之后再做总结或追问

**流程终止**：`present_sandbox_file(interrupt=true)` 调用后，本次任务即完整结束。之后不要再输出"还有什么需要调整""推荐重新上传素材"之类的总结或反复建议——已用当前素材完整交付，等待用户主动提出修改，不要自己找话题延续对话。

## 五、多段流程

### 第一步：创意设计

1. **搜索灵感**：用 `pippit_omni_search` 搜索（`Type=inspiration`），关键词与提炼要求同 §四步骤1（两段式关键词、相关性判断、**至少 2 条提炼产物**）。提炼条目写入 `creative_design.md` 的「灵感来源」章节。
2. **加载 ref**：`sandbox_read` 并行读取 `references/pet-rules.md` + `references/pet-prompt.md` + 对应类型 ref
3. 结合提炼的灵感 + 类型 ref 指引构建 `creative_design.md`。**开头先写死三行锚点**（情绪锚点 + 事件锚点 + 差异化锚点，格式与自检同 §四步骤4，情绪锚点最前），双问自检（换品种 / 换题眼仍成立则重写）
4. 创意设计**先不单独推送确认**——留到第二步素材齐了，和角色图**合并成一个确认门**一起给用户（避免"先 present 创意、又 present 图"两个松散推送，用户要看的是"创意 + 长什么样"的整体）

### 第二步：生成参考素材

1. **加载 ref**：`sandbox_read` 读取 `references/pet-assets.md`
2. 未上传照片 → `sandbox_generate_image` 生成角色参考图
3. 台词角色 ≥2 段 → `sandbox_generate_audio` 音色锚定
4. 素材路径写入 `creative_design.md` → 自审
5. **确认门（硬停，必须等用户回复才进第三步）**：创意设计 + 角色参考图都齐了，分两步：
   - **先展示**：`present_sandbox_file` 把创意文档和角色图一起推送给用户看（展示用，`interrupt` 可不设）。
   - **再用表单确认（强制，这是确认门的落点）**：紧接着调 `dynamic_questionnaire` 让用户结构化确认，**不要只靠 present 等自由文本回复**。表单示例：
     > 标题：确认创意与角色形象
     > 单选题「创意方向和角色形象是否满意？」→ 选项：`满意，开始生成视频` / `角色形象要重新生成` / `创意方向要调整`（可再附一道文本题「想调整的地方（选填）」收集具体意见）
   - **核心铁律：未收到 `dynamic_questionnaire` 里用户选择"满意，开始生成视频"之前，禁止调用 `sandbox_generate_video`**——生成视频耗时耗算力，必须在用户经表单对创意+形象点头后再进行，绝不能 present 完就自顾自往下生成；若用户选了"重新生成/调整"，按其意见回到对应步骤（重生角色图 / 改 creative_design）后再次走确认门

### 第三步：批量并行生成视频（用户确认后）

1. 按 `creative_design.md` 场次 + 类型 ref 中的 Prompt 模板**为每一段构造好完整 Prompt**——每段构造前先按 `pet-prompt.md`「分镜预算表」填表（各镜秒数之和 = 该段 Duration），构造完按 `pet-prompt.md` 末尾**生成前自检清单**逐项核对
2. **每段必须传入**（生成了却不传，等于没做，调用前对照检查）：
   - ImageList：角色参考图（每段都传同一张，保证一致性）
   - AudioList：**只要该角色生成过音色锚定，此段就必须传**（Prompt 中用 `@音频N` 引用并标注音色）——第二步做了音色锚定，第三步却忘传是最容易出现的疏漏
3. **并行生成（默认，非逐段串行）**：各段之间无依赖关系，**在同一轮内把所有段的 `sandbox_generate_video` 一次性发出并行执行**，输出 `assets/{project}/shot_01.mp4`、`shot_02.mp4` ...。禁止"生成一段→等它回来→再构造下一段"的串行做法——那样白白拉长交付时间。仅当某段 Prompt 需依赖前一段的实际产出时才串行该段

### 第四步：拼接合成

`render_video` 拼接 → `present_sandbox_file`（`interrupt=true`）。**流程终止**：同单段流程——推送后任务完整结束，不要反复总结或建议返工。
