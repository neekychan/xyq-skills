# 武打动作片段关键确认

本文件在类型初判后读取。只确认会改变整段动作设计、生成合法性或素材使用方式的参数。

## 一、调用条件

问卷是缺省路径：出现下列任一情况时，调用一次 `dynamic_questionnaire` 集中收齐，拿不准是否命中时按命中处理。问卷是向用户提问的唯一形式，禁止在回复文本中罗列问题或请用户"提供以下信息"：

- 用户输入为空、只有打招呼或入口引导语、或只有"做个武打视频"级别的模糊意图。
- 主类型、对战结构、动作体系、场景、主导镜头或打击与特效尺度缺失，且无法从素材可靠推断。
- 同时要求互斥镜头语法，如真第一人称与展示主角全身、一镜到底与高速快切。
- 用户时长超过 `{{.max_video_duration}}` 秒，但没有明确选择压缩单段或逐段生成。
- 时长低于当前模型下限，或画幅不在支持列表。
- 素材超过 9 图、3 视频或 3 音频，需要确定本轮子集。
- 编辑源片超过上限、低于下限或时长不是整数，需要用户授权合法区间、裁短、补足或停止。
- 用户要求变身、换装或进化，但变化节点与目标形态不清楚。

跳过问卷前，在内部逐项确认六个强制维度——主类型、对战结构、动作体系、场景、主导镜头、打击与特效尺度——各自的来源（用户原话或素材可见内容），核对过程不输出；任何一项找不到来源即触发问卷，“默认”“推荐”“无需确认”不构成来源，题材词只提供主类型来源、不构成场景、主导镜头或打击尺度来源。主类型为变身显圣时，对战结构对应威胁形态，动作体系对应触发媒介与覆甲机制，按 `fight-transform.md` 可变维度取材组卷。触发后逐行核对第二节按需选题表，把全部命中维度一次组卷，题目与命中行一一对应，禁止只挑部分维度。禁止为了增加互动重复询问已经明确的内容。

## 二、按需选题

| 维度 | 触发条件 | 推荐项与可见后果 |
|------|----------|------------------|
| 角色来源 | 无上传素材且用户未描述角色 | AI 生成角色：本轮直接创作，形象由类型风格决定；可选“我来上传参考图”，选择后本轮等待用户补充素材 |
| 主类型与子风格 | 只有“做段打斗”等模糊意图 | 写实古代武打：重物理接触、克制特效；其余选项贴合用户已有线索 |
| 对战结构 | 人数与目标缺失 | 1v1 决胜：空间和身份最稳定；可选 1v多、2v1、单人炫技、以静制动一招制敌 |
| 动作体系 | 徒手、兵器或能力缺失 | 根据主类型给 2 至 3 个互斥打法，并说明动作密度与稳定性 |
| 打击与特效尺度 | 强度缺失 | 电影级拳拳到肉：接触和受力清楚、无血腥；玄幻可选特效拉满，写实可选克制实战 |
| 主导镜头 | 镜头语法缺失 | 可读性多机位：交锋中开场，机位角度轮换、攻防清楚可读；可选一镜到底、真第一人称、动量跟随 |
| 镜头冲突 | 同时出现互斥要求 | 真第一人称或外部跟拍二选一；一镜到底或多机位快切二选一 |
| 场景 | 场景缺失 | 给 2 至 3 个贴合类型的具体场景，每项说明环境如何参与打斗 |
| 画幅 | 用户给出不支持的画幅 | 16:9：横向位移与双人站位更清楚；可选 9:16、4:3、3:4、21:9 |
| 超长处理 | 超过上限且未明确多段 | 压缩为单段精华：当前轮直接完成，不主动拆段；可选逐段生成，每个后续用户轮次续一段 |
| 当前段落 | 明确多段但起点不清 | 从第 1 段开始；已有上一段时选择要续写的最近成片 |
| 形象变化 | 用户提出变化但节点不清 | 保持当前形象；明确要求变化时再选节点和目标形态 |
| 素材子集 | 图片、视频或音频超量 | 优先保留主体身份参考与上一段尾片，其余由用户选择；每项说明未选素材本轮不会进入模型 |
| 变身秒杀设计 | 主类型为变身显圣且触发媒介、威胁形态或情绪基调缺失 | 按 `fight-transform.md` 可变维度各给 2 至 3 个互斥选项；触发媒介说明覆甲观感，威胁形态说明清场规模，情绪基调说明收尾方式 |
| 编辑区间 | 编辑源片超过上限 | 选择与修改目标最相关的合法整数时长区间，或文本填写精确起止时间；说明本轮只交付该区间 |
| 编辑补足 | 编辑源片低于下限 | 补足到模型最短时长：结尾复制末帧并延续或淡出原音频；可选停止并提供合法源片 |
| 编辑取整 | 编辑源片不是整数时长 | 向下裁短或向上补足到合法整数秒，每项标出具体增减时长 |

特摄或用户上传角色素材默认保持当前形象。用户未提出变身、换装、改造时，不询问形象变化，也不主动添加。

## 三、问卷格式

- 调用前用一句话说明确认目的。
- 问卷含两道或更多问题时，每道单选题把推荐项放在第一位，在该选项对象内设置 `selected: true`；其余选项省略 `selected` 或设为 false。
- 问卷只有一道单选题时，每个选项带一个 `emoji`，每个选项都显式设置 `selected: false`，推荐项仍放第一位。单题场景严禁出现 `selected: true`。
- `selected` 禁止放在 question 层级。
- 选项描述必须写清动作可读性、素材稳定性、特效尺度、时长或画幅等后果。
- 使用可执行视觉词，禁止用具体影视、动漫、游戏 IP 或创作者姓名充当风格捷径。
- 所有缺失和冲突合并到这一轮问卷，问卷返回后不再补问第二轮。
- 只有素材超量一个问题时，使用 radio 提供若干个数量合法的“素材包”，每个包列清包含项；禁止用默认可能超限的全选 checkbox。

## 四、参数合法性

- 当前模型的准确上限取自 `SKILL.md` 已渲染的数字，优先级最高。禁止根据模型名或用户目标总时长推断上限。
- 当 `SKILL.md` 显示上限 30 秒时，时长为 2 至 30 秒整数；显示上限 15 秒时，时长为 4 至 15 秒整数。
- 支持画幅只有 `16:9`、`9:16`、`4:3`、`3:4`、`21:9`。
- 素材上限为 9 图、3 视频、3 音频。上一段末尾 5 秒在续段时占用一个视频名额。

非法参数必须在生成前解决，禁止消耗唯一一次生成机会去试错。

调用问卷前静默做结构自检（不输出核对过程）：`questions` 长度为 1 时，逐项确认所有 option 同时具备一个 `emoji` 和 `selected: false`；长度大于等于 2 时，逐题确认推荐项位于 options 第一位且在该选项对象内设 `selected: true`，其余选项不带 `selected: true`。任何模式下 `selected` 不得出现在 question 层级。
