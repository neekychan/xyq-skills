# 分镜图生图与视频生成 Prompt 模板（五大一级用途 + 二级呈现形式）

本指南在**分镜规划阶段**加载，用于基于 `creative/storyboard-sheet.md` 已确定的分镜一级用途类型、完成度与输入（文字分镜描述 + 参考素材图），构造分镜生图与后续视频生成的 Prompt。目标：
- 为 5 大一级用途分别提供：**判定关键词与边界 → 分镜结构建议 → 分镜生图 Prompt 骨架 → 一致性规则 → 视频生成策略与 PE 模板**，每类下含若干二级呈现形式；
- 明确每类分镜的输出结构与占位符；
- 在生成分镜图前就把人物/场景/产品/标注方式的一致性风险压下去。

## 文件结构约定（统一写法）

为保证各一级用途写法一致、便于维护，本文件对每个一级用途统一采用如下结构，**不再为个别二级呈现形式单独内联整套模板**：

1. 每个一级用途章节只写**一套代表性骨架**（适用要点与判定关键词 → 分镜结构建议 → 生图 Prompt 骨架 → 一致性与避坑 → 视频生成策略），作为该类的通用范式。
2. 该一级用途下的**全部二级呈现形式**统一在章节末尾的「PE 模板索引」中列出，指向 `templates/` 下的独立模板文件；需要某个二级呈现形式的细化骨架时，按索引打开对应模板文件即可。
3. 因此「影视导演镜头表」「漫画·条漫分镜」等都作为**剧情叙事类的二级呈现形式**，只在 PE 模板索引中引用，不在正文里再写一遍完整模板。
4. **模板继承结构化规则（重要）**：打开 `templates/` 下任何二级呈现形式模板时，其内联 Prompt 骨架仅提供该呈现形式的画面/版式细节；本文件「结构化分镜执行规则」（逐格状态卡、三层门禁、must_show/must_not_show、低保真→精修双阶段、单格质检与重绘、修改影响范围、shot plan 一致性、双版本输出）与对应垂类校验器**默认叠加生效，且优先级高于模板**。模板骨架未列出的结构化字段（绑定事件 ID / 本格新信息 / 出现-禁止出现主体 / 人物位置朝向 / 参考图 ID / 单格验收规则等），一律以本文件为准补齐，无需改动模板文件本身。

## 红线（高频翻车点）

| 错误写法 | 后果 | 正确写法 |
|---------|------|---------|
| 未写清分镜类型与用途，只给一段宽泛描述 | 模型自由发挥，分镜形态与后续视频用途不匹配 | 先按 5 大一级用途之一明确分镜类型，再用对应小节的骨架写 Prompt |
| 不给宫格数/镜头数，或与目标时长严重不匹配 | 分镜节奏混乱，后续视频规划难以落位 | 明确宫格数/镜头数，按一级用途类型给出结构骨架（开头/发展/收束） |
| 不写完成度/标注需求 | 生成结果在“草稿线稿”和“成品插画”之间随机漂移 | 显式写完成度（草稿/精修/成品渲染）和是否需要序号/文字说明/分镜参数 |
| 有参考素材图却不引用 | 角色/场景/产品跨格漂移 | 用户提供的角色图/场景图/产品图必须在 Prompt 中引用并要求严格保持一致 |
| 文本信息塞满画面，无留白 | 成片文字密集难以阅读 | 每格只写一个核心信息点，标题+1–2 行短句即可 |
| 多人物/多场景不写站位与场景变化 | 角色站位前后打架，空间关系错乱 | 每格写清“谁在画面左/中/右、面朝方向”，场景切换要显性标注 |

## 通用编写规则

1. **只选一个一级用途骨架**：每次生成分镜图只使用下方「剧情叙事/营销转化/知识讲述/动作分解/音乐 MV」中的一个一级用途小节，并在该小节内部选择一个具体二级呈现形式，禁止跨一级混搭多个骨架。
2. **从输入字段向占位符一一映射**：creative 层问卷与文字分镜描述中的字段（题材、主角、宫格数、画幅、完成度、标注开关、参考图等）必须全部映射到对应占位符，不得自行虚构。
3. **参考图优先**：用户提供参考素材图时，所有生图与视频 Prompt 都走「参考图生图/生视频」链路，并在 Prompt 中明确“严格保持参考图中的角色/场景/产品一致”。
4. **分镜顺序强约束**：用「第1格/第2格…」或统一编号体系（S1、L1、A1 等）明确顺序，禁止只写一段连续文本。
5. **统一中文输出**：除非用户特别要求英文/双语，分镜说明默认用中文。
6. **完成度与用途分离**：骨架中的“一级用途类型”字段只写 5 类之一（剧情叙事/营销转化/知识讲述/动作分解/音乐 MV），二级呈现形式用单独字段记录（如影视导演镜头表/漫画分镜/科普演示/产品讲解等），完成度始终用单独字段。
7. **目标模型以用户选择为准**：所有生图、生视频的目标模型**一律以用户指定为准**；用户未指定时，才使用本文件各小节给出的 seedance 推荐型号作为默认值，不得用默认型号覆盖用户的明确选择。
8. **其余默认值统一来自** `creative/storyboard-sheet.md` 的「默认参数速查表」，用户已指定时一律以用户为准。

## 结构化分镜执行规则（生图前后强制）

> 本节把 `creative/storyboard-sheet.md`「分镜结构化设计层」的门禁与链路，落地为执行层的**逐格状态卡 + 质检重绘 + 一致性检查**。剧情叙事类与动作/VFX 类为完整落地对象（P0），其余垂类按同一框架执行（P1，至少满足状态卡 ★ 字段与 must_show/must_not_show）。

### 统一分镜结构表与逐格状态卡（生图前必做）

在生成任何图像分镜前，必须先基于 `creative/storyboard-sheet.md` 已确认的核心链路表，生成一张**逐格状态卡**并展示给用户确认。单格生图 Prompt 的人物、空间、动作**只能引用状态卡字段**，不得自由发挥（压制“并行生图导致跨格不一致”）。

逐格状态卡**核心字段**（剧情/动作类为必填，其余垂类至少填 ★ 项）：

- ★ 格号（S/A/M… 编号）与**绑定事件 ID**（剧情事件/动作链/卖点/信息/乐段节点）
- ★ 本格新信息（观众新知道什么；与上一格不得完全重复）
- ★ 场景区域（具体空间，如“客厅沙发旁/玄关门口/门外楼道”）
- ★ 出现人物/主体 + **禁止出现**人物/主体
- ★ 空间坐标（画面区位 + 前景/中景/背景景深 + 朝向）+ 姿态
- 起始状态 / 结束状态（情绪、动作、位置）
- 出场时机（首次出场 / 退场 / 状态转换标记）
- ★ must_show（必须出现元素） / must_not_show（禁止出现元素）
- 上一格承接（因果/时间/空间/情绪） + 下一格铺垫
- ★ 参考图 ID（角色/场景/产品/界面）
- ★ 角色锁 ID（四视图设定稿锁定参考，逐镜头传入）
- ★ 单格验收规则（图像生成后必须满足的判断条件）

> 字段策略：状态卡在内部保存**全量字段**用于 QA；写入生图 Prompt 时按垂类挑选最关键的 ★ 字段（约 10–12 项），其余用于质检，避免 Prompt 过长。

**逐格状态卡呈现模板（Markdown 表格，向用户展示确认时必用，禁止文本平铺）：**

| 格号 | 事件ID | 本格新信息 | 场景区域 | 空间坐标(区位/景深/朝向) | 出现主体 | 禁止出现 | 姿态/动作 | 起始→结束状态 | must_show | must_not_show | 角色锁ID | 参考图ID | 单格验收规则 |
|------|--------|-----------|---------|------------------------|---------|---------|----------|--------------|-----------|--------------|---------|---------|-------------|
| S1 | E01 | 母亲在等人回家 | 客厅餐桌旁 | 右侧/中景/侧身朝右 | 母亲 | 儿子 | 坐、摆碗筷 | 期待→怅然 | 母亲、两副碗筷 | 儿子、厨房灶台 | lock_mom | ref_mom_01 | 画面无儿子且含两副碗筷 |

> 动作/VFX 类在此表追加列：起始姿态 / 结束姿态 / 攻击方 / 防守方 / 动作方向 / 与上一格承接 / 禁止跳变。

### must_show / must_not_show 规范化

- 所有垂类逐格说明必须包含两行：`必须出现：{关键角色/场景元素/关系证据}`、`禁止出现：{不应出现的人物/场景/道具/空间位置}`。
- 示例（剧情）：S1–S7 禁止儿子出现；S8 必须出现门框、打开的门、楼道逆光、儿子在门外，禁止厨房灶台等错误空间；S10 才允许儿子进入室内拥抱。
- 漫画类：`禁止出现：由图像模型直接生成的中文对白气泡文字`——气泡文字一律由脚本后处理叠加。

### 低保真草图 → 精修分镜双阶段策略

1. 先基于逐格状态卡生成**低保真草图/关键帧试样**（线稿/简单色块），验证故事、动作、空间与人物关系；
2. 用户确认低保真分镜后，基于**同一状态卡**用更强模型逐格生成**无字高清单帧精修图**；
3. 再由脚本拼接成宫格分镜图并叠加文字层/编号/气泡，仅在**人看版**中展示。
- 完成度耦合：草稿/线稿档可直接出低保真；精修/成品档必须经过低保真阶段，除非用户在 creative 层已显式声明跳过并接受风险。

### 单格质检与自动重绘

每个已生成单帧图在进入宫格拼接前，必须按其状态卡逐项验收：

- 格数与编号是否与结构表一致（无缺格、无重复号）；
- 出现/禁止出现人物是否正确；人物位置、空间区域、动作方向是否符合状态卡；
- must_show 是否出现、must_not_show 是否未出现；
- 是否与其它格出现明显重复画面；
- 是否出现应由后处理叠加的中文文字/气泡；
- 是否严格引用最新参考图（角色/场景/产品特征一致）。

任一项失败：标记该格为**失败格**，不得拼接，自动基于状态卡重写单格 Prompt 并重绘，直至通过或达到预设重试上限（超限则回报用户）。

### 修改影响范围（执行层处理）

收到修改需求时：① 解析修改类型（视觉细节 / 人物位置或情绪 / 故事线或链路 / 参考图）；② 按 `creative/storyboard-sheet.md`「分镜修改与影响范围判定」表决定重算范围；③ 禁止在用户重写完整故事逻辑后仍保留尾部旧格不重算。

### 分镜格 ↔ 视频分镜段一一对应与首帧规则

- **一一对应**：默认令“宫格数 = 视频分镜段（shot）数”，1 个单格 = 1 个视频 shot = 1 张首帧；用户明确指定宫格数 / 镜头数时以用户为准。
- **单格图作首帧**：每个视频 shot 生成时，必须用其对应的**视频参考版单格图（干净无字）作为首帧图（第一帧）**进行图生视频，保证每段起始画面与分镜完全一致。
- **切分与时长自检**：生成前自检每个单格承载内容与该 shot 目标时长是否匹配（单格动作过多、信息过密、时长过长或过短均为不匹配）；若不匹配，**暂停并与用户确认**是否自动调整（增减宫格 / 拆分或合并 shot / 调整时长），不得擅自改动。

### 视频 shot plan 与分镜一致性检查

- 每个视频 shot 必须：绑定至少一个事件 ID / 动作链节点 / 卖点 / 信息 / 乐段节点；标明覆盖的分镜格范围（Sx–Sy）；写明段尾状态（角色位置、姿态、视线、手中道具、情绪、空间锚点）。
- 自检：核心链路中每个关键事件至少被一个 shot 承接；shot 不得创造链路中不存在的核心剧情；连续 3 个 shot 不得同一镜头功能/景别/构图；角色不瞬移、道具不凭空出现、同一动作结果不重复演两次。
- 视频阶段引用的参考图必须是**最新确认的无字分镜单格图集合**，不再笼统写“图片1”。

### 人看版 vs 视频参考版（双版本输出）

用户要求“先出分镜图再生成视频”时，默认输出两版：

- **人看版**：带编号、文字说明、必要镜头参数、台词/旁白/卖点文案/知识点标题等文本层；
- **视频参考版**：干净无字、无气泡、无编号，仅保留画面与构图信息，用于参考图生视频。

视频生成 Prompt 必须显式引用**视频参考版**分镜图的路径/ID。

### 视频生成通用规则（所有用途共享）

1. **分镜确认后才能生成视频**：无论分镜图来自用户上传还是当前流程新生成，必须先向用户展示分镜图/分镜表（含文字分镜表和图像分镜图），收集用户对分镜是否满意的明确反馈（如“确认分镜，开始生成视频”/“我想修改分镜”），用户未确认前禁止调用 `sandbox_generate_video`。
2. **分镜段/时间段 → 视频段一一对应**：文字分镜中的每个分镜段/时间段都要在视频中有对应画面；可以在格与格之间插入过渡镜头，但不得跳过任何一格。
3. **风格/画风双向一致**：视频的视觉风格、画风、色调和光影必须与分镜图保持一致；视频 Prompt 中不得更换风格关键词，只能在同一风格体系内调整运镜和剪辑节奏。
4. **一级用途类型决定连贯性策略**：剧情类强调故事节奏与镜头语言连贯；营销类强调卖点节奏与信息曝光次数；知识类强调知识点顺序与信息可读性；动作类强调动作连续性与关键帧完整呈现；音乐 MV 类强调乐段、节拍与画面节奏的同步。
5. 视频 Prompt 编写一律遵循 storyboard/prompt-craft.md 的结构与红线：Prompt 只写摄像机能拍到的视觉指令，按“素材绑定 → 一句话概述 → 画面阶段 → 质量约束”分层组织，并使用其中的运镜指令表与空间关系构建规则。
6. 只要某段包含台词或旁白，必须额外加载 storyboard/dialogue-rules.md：用固定句式写口型动作，并依据 count_chars 工具的耗时区间校验台词/旁白是否装得下，禁止人工估算。
7. 生视频前确保出现主体已有参考图和锁定卡：参考图的设计与生成按 assets/ref-image-design.md，角色/动物/产品的一致性按 assets/character-lock.md 的“主角四视图 + 逐镜头传参 + 视觉锁定由参考图承担”执行。
8. 完成所有镜头的视频生成与拼接后，在交付用户前按 review/quality-control.md「交付前定位表」逐维排查症状，不合格则回溯到分镜或 Prompt 修改。

### 生成链路建议：单图高清 + 脚本拼接 + 脚本渲染文字

1. 先输出结构化分镜元信息：基于文字分镜表整理每格的场景、角色、动作/知识点/卖点以及（如需要）景别/机位/运镜/单镜头时长等镜头参数。
2. 再按镜号逐个调用图像模型生成“无字高清单帧”分镜图：Prompt 中只描述画面内容、角色与场景风格，**禁止要求模型绘制中文文字、镜号、字幕或对白气泡**。
3. 由脚本按分镜表拼接为多宫格/条漫/表格版式，并在图像上叠加所有文字内容（镜号、对白、旁白、卖点文案、知识点标题、歌词等）以及必要的镜头参数信息。
4. 最终的多宫格分镜图作为视频生成的蓝本，后续视频 Prompt 仅引用画面信息，不再让图像模型生成大量中文长文本，从而提升画质与文字清晰度。
- **最高清输出**：宫格图与每一张单格图一律以当前可用的最高分辨率 / 最佳画质档位输出（highest resolution / best quality），不得为省算力降档；单格图是视频首帧来源，清晰度直接影响成片。

> 优先在彩色插画/写实/3D 档采用上述链路；草图/线稿档可以直接生成宫格图，但仍推荐用文字分镜表做结构化约束。

### 排版与版式规范（宫格 + 文字层）

1. **默认宫格行列布局**（用户未强制指定时）：
   - 4 宫格：2×2
   - 6 宫格：2×3
   - 8 宫格：2×4
   - 9 宫格：3×3
   - 12 宫格：3×4 或 4×3
   - 16 宫格：4×4
   - 25 宫格：5×5  
   禁止在单格内部再让模型自行划分小宫格；如需更复杂网格，应由脚本拼接完成。
2. **画面与文字比例建议**：画面为主、文字为辅；单格中文字区域一般不超过画面高度的 1/3，避免遮挡主体。
3. **字号与行数控制**：按照最终导出分辨率估算，建议中文正文字号不低于总宽度的 1%–1.3%；单格正文行数 ≤2–3 行，过长文案拆到多格或转脚本表格。
4. **文字排版规则**：脚本叠加文字时必须自动换行、避免文字溢出画布或压住关键主体；镜号建议用高对比色块或角标标注，位置统一。
5. **必须单页拼接，禁止多页拆分**：无论宫格数多少，所有分镜格必须由脚本拼接到**同一张分镜图**上输出，禁止拆成多页/多张图。宫格数较多或单格信息较多时，通过加大画布尺寸、调整宫格行列布局、压缩文案、缩小镜号字号或简化非主体细节来解决，而不是分页。

## 五大一级用途（按用途加载对应分册）

判定用户/创意脚本的一级用途后，**只加载命中的一个分册**（含该用途的适用判定、分镜结构、生图 Prompt 骨架、一致性避坑、校验器、视频生成策略与 PE 模板）：

| 一级用途 | 判定关键词 | 分册 |
|---------|-----------|------|
| 剧情叙事类 | 故事/短剧/漫画/绘本/情节推进 | `storyboard/sheet-genre-story.md` |
| 营销转化类 | 产品/卖点/种草/带货/品牌广告 | `storyboard/sheet-genre-marketing.md` |
| 知识讲述类 | 科普/教学/知识点/信息图/讲解 | `storyboard/sheet-genre-knowledge.md` |
| 动作分解类 | 动作教学/健身/舞蹈/手工/步骤演示 | `storyboard/sheet-genre-action.md` |
| 音乐 MV 类 | MV/歌词/音乐可视化 | `storyboard/sheet-genre-mv.md` |

用途不明时按内容主驱动判定：情节推进 → 剧情；卖点转化 → 营销；信息传递 → 知识；动作还原 → 动作；音乐驱动 → MV。跨用途混合时以主用途分册为准、次用途只借骨架措辞。

分册是本文件的组成部分：其他文件中凡指向本文件某一用途章节（骨架/校验器/视频策略/执行模板）的引用，一律落在对应分册；指向「结构化分镜执行规则」等通用章节的引用仍在本文件。

## 协同

- 本文件的一级用途与二级呈现形式须与 `creative/storyboard-sheet.md` 中的 5 大一级用途模型一一对应，一侧变更需同步调整另一侧。
- 分镜用途判定、完成度、输入要求（文字分镜描述 + 参考素材图确认逻辑）与问卷字段 → `creative/storyboard-sheet.md`
- 分镜结构化设计层（核心链路 / 事件链 / 人物关系矩阵 / 资产 Registry / 三层门禁 / 修改影响范围）定义 → `creative/storyboard-sheet.md`；本文件负责其执行层落地（逐格状态卡 / 垂类校验器 / 质检重绘 / shot plan 一致性 / 双版本输出）
- 视频 Prompt 通用规范 → `storyboard/prompt-craft.md`
- 角色一致性与参考图设计 → `assets/ref-image-design.md`、`assets/character-lock.md`

## 分镜专业 QA 自检清单

- [ ] 用途与呈现形式对齐（未把漫画/影视级当一级）
- [ ] 结构与节奏匹配时长（宫格数、镜头数与目标时长大致对应）
- [ ] 专业字段完整（每格至少包含编号+画面+景别+情绪目的，高专业版补充机位/运镜/单镜头时长）
- [ ] 角色与场景跨格一致（外观、服装、空间结构不随意漂移）
- [ ] 动作与空间方向连贯（打斗守轴线、运动段不乱跳，MV 画面对齐主歌/副歌等乐段）
- [ ] 文字与画面匹配，且所有中文文字由脚本或后期叠加，不直接由图像模型生成
- [ ] 所有参考素材（角色图/场景图/产品图/PPT 等）均在 Prompt 中显式引用并锁定一致性
- [ ] 用途负面约束满足（剧情非纯表情包，知识非纯剧情，营销多数格能看到产品，漫画有对白气泡，动作以连续动作为核心）
- [ ] 目标模型以用户选择为准（用户已指定时不被默认型号覆盖）
- [ ] 与视频生成链路兼容（含台词段均按 storyboard/dialogue-rules.md + count_chars 完成耗时校验）
- [ ] 交付方案支持局部修改（失败格/镜头可单独重生，无需整体推倒重来）
- [ ] 已生成并确认垂类核心链路表（剧情=故事线 / 动作=动作链等），且逐格状态卡字段与链路一一映射
- [ ] 每格状态卡核心字段完整：绑定事件 ID / 本格新信息 / 场景区域 / 出现与禁止出现 / 位置与朝向 / 参考图 ID / 单格验收规则
- [ ] must_show / must_not_show 已写入 Prompt，并在单格质检环节逐项执行
- [ ] 涉及 ≥2 人时已填人物关系矩阵，逐格关系证据取自矩阵（非仅“同框/站位”）
- [ ] 低保真草图 → 精修双阶段流程正确执行；用户未确认跳过时不直接生成成品级图
- [ ] 单格质检已执行，失败格已按状态卡重绘而非直接拼接
- [ ] 视频 shot plan 每段绑定事件 ID 与分镜格范围，且引用最新版无字（视频参考版）分镜图
- [ ] 修改需求已按「影响范围判定」决定重算/重绘范围，未保留应重算的旧格
